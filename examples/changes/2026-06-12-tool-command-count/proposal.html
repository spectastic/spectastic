Update REQ-TOOL-001 to reflect lifecycle expansion

Under review

1 · Intent

This proposal is itself evidence the discipline is working: the prior archive applied only the deltas listed, leaving a legitimate drift in REQ-TOOL-001 visible rather than silently absorbing the consistency fix. That's small-batches discipline doing its job. Now we close the drift with a focused proposal.

Concretely: REQ-TOOL-001 says "four Claude Code slash commands — /spectastic.constitution, /spectastic.specify, /spectastic.plan, /spectastic.tasks". The shipping lifecycle now includes /spectastic.propose, /spectastic.archive, and /spectastic.triage. The requirement needs to name all seven.

2 · Scope

In scope

  • One MODIFY delta on REQ-TOOL-001 naming all seven slash commands.
  • One small infrastructure edit on apply: bump the spec's <spec-budget words="…"> attribute from 2,500 to 3,000 to accommodate the Change-management section that landed last archive.

Out of scope

  • Touching any other requirement. Other drift, if any, gets its own proposal.
  • Adjusting REQ-LIFECYCLE-001's template count — it already reads "five lifecycle templates" after the prior archive, which is correct.

3 · Approach

Single MODIFY delta. The new body lists all seven commands in lifecycle order. The budget attribute is not a requirement so it can't be a delta — it gets adjusted on apply as a small infrastructure side effect, captured in the archive commit message.

Why a small proposal rather than just editing the spec directly: the spec lifecycle says spec evolution MUST happen via change-proposal artifacts (REQ-CHANGE-001). Even a one-delta update gets a proposal. The discipline is the point.

4 · Deltas

What changes: name all seven shipping slash commands, not just the original four.

Spectastic MUST ship seven Claude Code slash commands across the lifecycle — /spectastic.constitution, /spectastic.specify, /spectastic.plan, /spectastic.tasks, /spectastic.propose, /spectastic.archive, /spectastic.triage — that drive the templates without introducing a separate CLI.
