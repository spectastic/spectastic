1 · Intent

This is the second time the discipline has paid off the same way: a prior commit added a shipping verb, and rather than silently absorb a requirement update at the same time, the spec was left in a state where REQ-TOOL-001 contradicted reality. The contradiction is the signal that a follow-up proposal is owed. This proposal closes it.

Concretely: REQ-TOOL-001 currently names principles · spec · plan · tasks · propose · apply · triage as the seven shipping slash commands. With /spectastic.implement now landed, eight commands ship. The requirement needs to name all eight.

2 · Scope

In scope

  • One MODIFY delta on REQ-TOOL-001 naming all eight shipping commands.

Out of scope

  • No infrastructure-level side-effects on this apply (unlike 2026-06-12-tool-command-count which also bumped the spec-budget). The current budget at 3,000 words has room for the rephrased requirement.
  • No edits to other requirements. Other drift, if any, gets its own proposal.

3 · Approach

One MODIFY delta. The new body names all eight commands in lifecycle order: principles · spec · plan · tasks · implement · propose · apply · triage. The verb ordering matches the lifecycle string used in the README, index, and TL;DR everywhere else.

The pattern repeats: every time we ship a new verb, the requirement that enumerates verbs drifts. Two ways to handle this long-term — (a) keep counting verbs as drift and closing it each time, (b) rephrase REQ-TOOL-001 to not enumerate (e.g. "ship the commands listed in commands/"). Option (b) is tempting but loses the discipline of naming what's intentionally in the shipping set. Sticking with (a) for now; revisit if the churn rate climbs.

4 · Deltas

What changes: add /spectastic.implement to the enumerated list, bumping the count from seven to eight.

Spectastic MUST ship eight Claude Code slash commands across the lifecycle — /spectastic.principles, /spectastic.spec, /spectastic.plan, /spectastic.tasks, /spectastic.implement, /spectastic.propose, /spectastic.apply, /spectastic.triage — that drive the templates without introducing a separate CLI.
