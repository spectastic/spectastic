Currency Converter

A rate you can trust more than you can trust the network.

Version 1.2.0 Ratified 02 Jun 2026 Amended 11 Aug 2026 Owner example-co/design Read time Illustrative artifact. Part of a worked exemplar for the visual-spec survey. The project, the team and the API are fictional. This file uses only vocabulary that exists in spectastic today; the artifacts under visual/ do not.

1 · Principles

P-1 · A stale rate is labelled, never hidden

Any rate older than the freshness window MUST be shown with its age, in text as well as colour. Showing an old number as though it were current is the only defect in this product that costs a user money. Forward-only: binds from v1.0.0.

P-2 · The network is optional; the app is not

Every screen MUST have a defined appearance with no network. Offline is a first-class state, not an error dialog. Forward-only: binds from v1.0.0.

P-3 · Accessibility floors are measured, not asserted

Tap target, contrast ratio and layout under the largest Dynamic Type size MUST be expressed as values a test can read, not as prose in a design file. Forward-only: binds new and amended specs from v1.1.0.

P-4 · The contract is the source of the states

Every documented error response MUST map to a designed screen state, and the mapping MUST be recorded where a reviewer can see it. States that no response implies MUST still be authored. Forward-only: binds new and amended specs from v1.2.0.

P-5 · No telemetry before consent

No analytics event MUST fire before the consent decision is answered, and no payload MUST carry personal data. A tracking plan may be written earlier; it may not be wired. Forward-only: binds from v1.0.0.

2 · Governance

Decision style
Owner. Amendments require the owner's approval.
Amendment process
A change proposal targeting this file. Bump the version — MAJOR for a principle removed or redefined, MINOR for one added, PATCH for wording.
Versioning
Semver. v1.0.0 is the founding ratification.
Binding
Forward-only. A principle binds specs authored or amended from the version named on it; it does not reopen work already accepted under an earlier version. The same rule governs the token set.
