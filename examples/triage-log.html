Timer rolls 59→00 then flickers 59 for one frame

Implementation code

Debugging the minute-roll flicker, root cause was an implementation drift; fixed by removing a stray - 1 in TimerLabel.swift:14; regeneration passes (spec & plan already capture the correct behavior).

Expected
Display flips 59 → 00 cleanly at minute roll.
Actual
Briefly displays 59 again for one frame after 00.
Spec
FR-002 says "seconds value MUST advance monotonically" — correct as written.
Fix
TimerLabel.swift:14 — remove - 1, add regression test.
let seconds = (totalSeconds % 60) - 1 /* off-by-one drift */ let seconds = totalSeconds % 60
Deep dive — none required

No cross-spec contract touched; no project-wide invariant; no hotfix-now needed.

Times wrong by one hour after spring-forward

Spec upstream

Debugging the DST off-by-one, root cause was a spec gap — timezone behavior was never captured as an NFR; regeneration fails (the same LLM session would make the same wrong choice from the current spec).

Expected
Recorded splits show identical wall-clock duration before/after DST roll.
Actual
Splits crossing 02:00 on 9 Mar 2025 are off by exactly 1h.
Diagnosis
Spec FR-005 stores split times in local wall-clock; nothing forbids it, so the implementer used Date() instead of monotonic clock.
Fix
Amend spec: new NFR-002 — "split timestamps MUST use a monotonic clock; display MUST format in user's locale at render time."
Deep dive — cascade required
Cascade
Re-run /spectastic.plan and /spectastic.tasks against amended spec.
Cross-spec
None — DST is local to this feature.
Constitutional
Maybe. Other time-handling features (export timestamps, scheduled records) likely have the same gap. Worth a separate /spectastic.constitution amendment proposing a "monotonic clock" principle.
Scope
In scope — DST handling is implied by FR-005 even if not stated.
Hotfix now?
Yes — ship the code patch this release; the spec amendment lands next cycle to prevent recurrence.

Offline mode broken — splits never persist

Plan upstream

Debugging the offline persistence loss, root cause was a plan gap — spec required offline operation but the plan picked a backend that requires connectivity; regeneration fails.

Expected
Splits taken offline survive app restart.
Actual
Splits taken offline disappear on restart; only online splits persist.
Diagnosis
Plan §4 chose CloudKit as the only store. Spec FR-008 requires "MUST function with no network." Plan violates spec.
Fix
Amend plan §4 — switch primary store to local SQLite, treat CloudKit as a sync layer. Spec is correct as written.
Deep dive — cascade required
Cascade
Re-run /spectastic.tasks; persistence-layer tasks change shape.
Constitutional
No — this is local to the persistence choice.
Scope
In scope.
Hotfix now?
No — affects a small fraction of users; the plan amendment is the right path.

Compositor renders glass material with banding

Platform external

Debugging the visual banding on the glass-style toolbar, root cause is a platform defect — reproduces in Cmd-Shift-3, in an unmodified Apple SCStream sample, and in QuickTime; regeneration paradoxically passes because no in-stack knob can mitigate it.

Expected
Toolbar glass renders cleanly under capture.
Actual
Horizontal banding visible in any captured output that touches the glass.
Diagnosis
macOS WindowServer compositor bug. Project's spec binds us to the platform path (no fallback).
Fix
Release-notes entry + Apple Feedback Assistant filing. No code patch.
Deep dive — constitutional amendment proposed

This is the third platform defect this year. Without a documented protocol, the response is improvised per incident.

Proposed principle
"Platform defects: file with vendor, document as known limitation, refuse synthetic substitution, refuse non-platform fallback (forbidden by platform-binding)."
Cascade
Update constitution.html; re-validate all platform-bound specs.
External tracker
Apple FB-92874311 (filed 12 Jun 2026).
Hotfix now?
N/A — no fix exists in our layer.

Protocol

Five required Tier-1 fields, in order:

Each card MUST include a headline in Y-statement form: "Debugging X, root cause was Y; fixed by Z; regen pass|fail."

Each card MUST state Expected, Actual, and Diagnosis (one sentence — cause, not symptom).

Each card MUST declare a single layer attribute (spec | plan | implementation | cross-spec | constitution | platform) and a regeneration test result (pass | fail).

Each card MUST include a concrete Fix — artifact path + one-line proposal. For implementation gaps, a <spec-diff> pointing at the offending line.

The deep-dive <details> block SHOULD be filled only when at least one of: cross-spec contract touched, project-wide invariant implicated, deferred scope exposed, or hotfix-before-amendment sequence required.

Cards MAY append a single <spec-question> if a decision is owed to the human before the fix lands.
