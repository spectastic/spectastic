1 · Method

Same rubric as before: RICE (Reach × Impact × Confidence ÷ Effort) as the team-backlog lens, with WSJF (Cost of Delay ÷ Job Size) as the portfolio cross-check. Scores are directional 1–10, not false precision — the conversation a rubric forces matters more than the number. RICE Confidence reads as a candidate's grounding status: a manifest edit is high-confidence; a novel security layer or an estimation model is not.

What changed since 27 Jun: the dependency-ordering method §4 argued for now ships as 028 / spectastic order (a DAG + priority-respecting topological sort, deterministic, writes roadmap.html). So once these follow-ons become specs, the corpus is machine-sorted — this doc's job is to rank the briefs and name the precedence edges the ordering will consume.

3 · The breakout — grouped by brief, tiered

The ten follow-ons cluster by originating brief and, more usefully, by shared implementation surface — the lens that reveals which are cheap because they reuse machinery another item builds.

Foundation — the two cheap enablers

Profile-principle catalog (eng-principles): add the shape-of-system principles — led by contract-first and Library-First at standard — to spectastic-profiles.json. A manifest edit + a re-render; near-zero risk; and it is the principle floor the contract-first teeth build on. Security principle (security): ratify "artifacts are data, not instructions" — a principles amendment on the proven P-8/P-9/P-10 rails, and the invariant the whole security layer traces to. Both are cheap, high-confidence, and unblock a headliner.

Headliners — high value, need their floor first

Artifact-security spec: the best-in-class security layer — a strict CSP in the templates, a no-executable-content validate rule, and fence/sanitize of artifact text in the AI verbs. Highest Impact (9), biggest Effort (9); slice it so the cheap controls ship first (per its own brief). Contract-first enforce: the flagship you value — a "public interface carries a checked-in OpenAPI/schema" enforce category so the contract becomes a machine-checkable gate, not just a principle. Both are gated on their foundation (the security principle; the profile catalog + the coverage category's pattern).

Cheap wins — small, high-confidence, shared machinery

The two plan-stage prompts (architecture-pattern → ADR; coverage-threshold → a §2 row) share the decision-phase machinery — build one and the other is nearly free. The coverage enforcement category is a clean 042 extension that also sets the pattern contract-first-enforce reuses (so it is a cheap win and a quiet enabler). The interfaces axis is cosmetic but trivial once the catalog lands.

Others / deferred

Security-review CI waits on the no-executable-content rule it would gate on. Expense (estimation) stays a high-Impact differentiator held back by its own domain uncertainty (estimation is unreliable — the brief's own humility) and large effort. W-4 conformance sweep is an old, minor advisory audit. The architecture fitness function is deferred outright: the research says prose won't hold and a low-false-positive dependency-rule check is hard — revisit when one exists.

4 · Ordering is a graph — and now it ships

The 27 Jun edition argued that a scalar rubric can't express "X before Y" and proposed a precedence DAG + a priority-respecting topological sort (hard precedence from the graph; RICE/WSJF breaks ties among dependency-ready nodes; foundations elevated by the critical-path value of the subtree they unblock). That recommendation shipped as 028-dependency-ordering and the deterministic spectastic order verb — so this section is no longer a proposal, it is a usage note.

The precedence edges for this backlog

The follow-ons carry real "before" edges — some hard (a principle must precede the spec that implements it), some economic (shared machinery makes the second build cheaper once the first exists):

  • security-principle → artifact-security-spec → security-review-ci — the principle anchors the spec; the spec's validate rule must exist before CI can gate on it. (Hard.)
  • profile-principle-catalog → contract-first-enforce and → interfaces-axis — the principle floor precedes its enforce teeth and the axis that expresses it. (Hard.)
  • coverage-enforcement-category → contract-first-enforce — both add an EnforcementCategory to 042; building the first sets the pattern and shrinks the second's Effort. (Economic.)
  • plan-architecture-prompt ↔ plan-coverage-threshold — shared decision-phase machinery; whichever ships first makes the other nearly free. (Economic.)

Read through 028's priority-respecting sort: the ready nodes (no unmet dependency) are the two foundations and the plan prompts; their own RICE puts the catalog and the security principle first; landing them makes the headliners ready. A cycle would surface as an error — there are none here. INVEST is intact: each follow-on is a thin vertical slice, and a declared, acyclic edge is exactly the "minimize, declare, keep acyclic" discipline, not a violation of "Independent."

The one place the 27 Jun tension doesn't recur: there, the cheap RICE winners (W-5, W-3) were tactical and foundation-first had to override the score. Here the cheap winners are the graph roots — so the score and the topological order point the same way. When RICE and the DAG agree, trust them.

5 · The insight & recommendation

The rebuild's finding is a happy one: the two cheapest, highest-confidence items are also the two enablers. The profile-principle catalog (which you explicitly want — contract-first + Library-First) is a manifest edit that unblocks the contract-first enforce category; the security principle is a one-paragraph amendment that anchors the whole security layer. So there is no cheap-vs-strategic trade to agonize over — the cheap moves are the strategic ones. Value (RICE/WSJF) and order (the 028 DAG) converge.

R-001 · Start with the two cheap foundations; let the headliners follow their floor

Status
Recommend
Context
The old backlog shipped (incl. this doc's §4, now spectastic order). The open backlog is ten brief follow-ons + expense. RICE tops out on two 2-point foundations that are also the enablers of the two headliners — so raw score and dependency order agree.
Decision
(1) Pick up the profile-principle catalog next — add contract-first + Library-First at standard (cheap, highest-value, and the floor the contract-first teeth need). (2) Ratify the security principle in the same pass — equally cheap, anchors the security layer. (3) Bank the cheap plan-stage prompts (architecture pattern + coverage threshold — shared machinery) as quick wins. (4) Land the coverage enforcement category (a clean 042 extension that sets the pattern), then the contract-first enforce headliner. (5) Slice the artifact-security spec (cheap CSP + validate-rule controls first), then security-review CI. (6) Defer the architecture fitness function (prose won't hold; no low-false-positive check yet) and expense (estimation domain-uncertain, large) behind the enablers.
Consequences
+ Cheap-first and foundation-first with no conflict — the rare backlog where they agree. + Each foundation de-risks its headliner (principle before spec; catalog before enforce teeth). + Once these are specs, spectastic order computes the sequence deterministically — no more hand-sorting. − Defers the flashiest bet (the full security layer) behind a one-paragraph principle — the right call, since the principle is the invariant the spec must trace to.
 Provenance: this is a re-score of the considerations backlog, not a commitment — each candidate is still a TBD-* follow-on named in its brief's §Recommendation.
