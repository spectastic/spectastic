The guarantee layer Phase 1 said was aimed at artifact well-formedness is now aimed at architectural decisions. A decision is a structured record with scope, enforcement rule-ids, posture, lifecycle and a reason (112); it is retrieved by path, deterministically, to a log (113); it fails a plan that ignores it and reports coverage (114); it produces a merge verdict that reconstructs from disk with no model and cannot execute a foreign command by construction (115); it is injected before writing as an aid (116); a failure teaches with the decision's own reason plus one Socratic question (117); and the merge verdict explains each violation to a reviewer — the offending code, the decision made readable, the sanctioned path — with no model on the path (118). The position-keeper example proves all eight guardrail behaviors against a real ADR-0007, born from a requirement and tested five features later. The Priya PR now dies twice — at plan and at merge — and the merge death tells the author exactly why and where to go instead.

2 · The Priya PR, killed twice

The scenario Phase 1 said would pass spectastic now fails it at two independent points, both proven in the external position-keeper-guardrails repo (init'd, driven through the lifecycle, a real build) against a real ADR-0007 (D-007) born in feature 2 and tested in feature 7 — and, since 18 Sep, on GitHub: the bypass is an open pull request that the spec-121 managed gate fails on its verdict step and the project's own build fails on the ArchUnit rule:

  • At plan (demo 2). The reconciliation design touches the persistence path without acknowledging ADR-0007; the plan-constraint fails, naming 002-downstream-consumers/D-007 and the governed path — before code is written. Forward-only by design (114): reproducible only while the design is Draft, and the example's demonstrations/README.md says how; the same dogfooding found the constraint fires on the static prefix src for three designs it does not govern (I-087).
  • At merge (demo 3). The bypass committed straight to a branch — a direct UPDATE positions — produces a verdict naming the decision, the rule, and the file:line, reconstructable from disk with no model output.
  • The residual (demo 4). The sanctioned adapter's identical SQL is not flagged (it is in the allowed path); and ArchUnit's type-graph finding — which spectastic never ran — is ingested from SARIF and composes the same decision's reason. Detector and explainer, cleanly split. The SARIF is real since 18 Sep — written by the ArchUnit test on the bypass branch, because ArchUnit ships no emitter of its own (I-086).

3 · What we'd tell Valmis his rubric is missing

Building the layer surfaced four things the eight-item rubric does not name — the first two are the additions this assessment already made, now earned; the last two are lessons the build taught.

  1. Coverage as a reported metric (item 9). The rubric asks that each decision have a check or be marked unenforceable. It does not ask for the proportion to be surfaced. Without the number, the blind spot — "the decision governing positions has no check" — stays invisible until after the incident. The metric is what makes it visible before.
  2. Failure-as-teaching (item 10), and its two halves. A traceable verdict tells a reviewer what fired. It does not make the developer reason about why — nor, we learned, does a terse verdict line even let them act without leaving the diff. Teaching has two halves the rubric collapses into one: the data (the decision's reason, composed deterministically) and the rendering (showing the author the offending code, the readable decision, and where the pattern is allowed instead). 117 built the first; dogfooding the example showed the second was still thin, and 118's verdict --explain closed it — to the clarity floor of the tool's own triage card, still with no model on the path. The lesson for the rubric: "a failure teaches" should name both, because full teaching data behind a one-line render reads as done and is not.
  3. The residual case type-graph tools cannot see. A rubric that assumes ArchUnit-style checks misses the content-level residual: a legitimately-JDBC file writing the forbidden table passes the type-graph rule and is caught only by a content rule. The detector/explainer split — native content + path detection, plus ingested type-graph output, both composing one decision's reason — is the shape the rubric's "deterministic enforcement" should specify, not a single tool.
  4. Forward-only binding. The rubric is silent on what happens to already-shipped work when a new decision lands. Naively, every prior spec that touched the governed area retroactively fails — 97 designs in our own repo. A governance layer needs the forward-only binding principles already use: a new decision binds work in flight, not history the merge verdict is there to catch. We learned this the hard way in 114 (the plan-constraint fires only on Draft designs).

And the honesty the rubric should demand of item 3. "Context injection before writing" reads as a capability you either have or don't. But injection rides an advisory channel — a prompt the model may ignore (T-009, proven live in spec 111's cross-tool spike). The kernel injection into design/tasks is real and tested; the injection at the code-writing moment is a nudge, because the verb that writes code is an orchestration verb with no prompt to inject into. So item 3 is partial by construction, not by omission — and a rubric that scored it "full" would be claiming a guarantee the channel cannot give. The guarantee is the gate; injection only improves the odds the gate stays quiet.

4 · The one remaining partial, and why it stays

Item 3 will not reach "full" by more work on this layer, because the limit is structural: an advisory prompt cannot be a guarantee (P-8 / T-009). The honest closure is not to pretend otherwise but to make the gate — which does not ride the advisory channel — carry the weight. It does: the plan-constraint (114) and merge verdict (115) fire regardless of whether the agent read the injected block, which the gate-independence test proves. Injection is the aid; the gate is the guarantee; and the scoring says exactly that.
