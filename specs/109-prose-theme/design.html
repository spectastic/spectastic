Design · 109-prose-theme

Prose theme

How we will build it.

Status Accepted Spec 109-prose-theme Owner Brian Corbin · @briancorbin Branch spec/visual-slice-095-098 Created 19 Aug 2026 Read time

A token block beside vivid's, a registry entry, and a theme-scoped enhancement in the shared switcher script — extending seams 016 already built rather than inventing any. The single biggest risk is the one a design-time spike already surfaced: the reveal cannot be pure CSS, so this design spends a second amendment against its parent to buy behaviour CSS cannot express.

3 · Data model & contracts

The spec's data model adds no entity — it extends the theme registry and constrains the reveal's one-way transition. Nothing here is persisted beyond the existing localStorage key, and no consumer outside the browser reads any of it.

This feature exposes no interface. A theme is read by a stylesheet and a script inside the same document; there is no request/response surface, no RPC, and no published event. The registry entry is internal to theme-boot.js and is not addressable from outside the page.

6 · Approach

Prose is added the way 016 designed a theme to be added: a [data-theme] block in assets/spec.css overriding theme-owned tokens, and one entry in the THEMES registry in assets/theme-boot.js. Most of the reading shell is tokens — measure, body size, leading, rhythm — and vivid already proves a theme may move the measure. Two pieces need rules rather than tokens: sidenotes fold using the declaration set the narrow-viewport media block already contains, and structured components lose their chrome while keeping their grid.

The reveal cannot be tokens or rules, and the spike above is why. It becomes a small theme-scoped module in assets/spec.js that observes top-level blocks, adds a revealed marker exactly once, and never removes it — with the CSS resting state authored visible so that the unrevealed state exists only while the script runs. The same module owns the header's scroll-up trigger; the pointer and focus triggers stay in CSS, where they belong.

The order of work is not free: FR-001 holds every other requirement behind two amendments to the parent. That is the first task, not a footnote.

8 · Decisions

D-001 · Both parent amendments land before any Prose work

Status
Accepted
Context
Prose collides with two must-tier requirements of 016: FR-002 forbids a theme touching colour, NFR-005 requires a theme be pure CSS and additive. Both texts were read this turn. A third edit surfaced from spectastic validate: 016 defers “a third theme beyond calm and vivid” to TBD, and the parent-child-reciprocity rule reports the missing back-pointer now that this spec claims 016 as parent.
Decision
Author one proposal against 016 carrying all three edits — amend FR-002, amend NFR-005, and repoint that defer-to from TBD to 109-prose-theme — apply it, and only then build. FR-001 makes this the first task. 016 is accepted, so none of the three is an inline edit.
Consequences
+ Parent and theme never disagree, and the reasoning is recorded where a later reader will look. + One proposal, not three, since all three edits serve one slice. − The slice cannot start until a proposal cycle completes. − validate reports the reciprocity error over the whole corpus until it applies; that is the estate agreeing with FR-001 rather than a separate defect, and it clears on apply.

D-002 · The reveal is a theme-scoped enhancement in the shared script

Status
Accepted
Context
The spike in Grounding & evidence established that animation-timeline: view() is scrubbed by scroll position — opacity 0 → 1 → 0 across scroll down and back. Reveal-once and a scroll-up trigger are both remembered state.
Decision drivers
Reveal-once for the reader · cost in parent amendments · behaviour with JavaScript off
Considered options
  • Scroll-driven CSS — + no amendment, pure CSS. − cannot express reveal-once; measured to fade back out.
  • Drop the reveal — + no amendment; ships the shell. − abandons a story the spec commits to.
  • Enhancement in spec.js — chosen — + latches one-way; also supplies the scroll-up trigger. − costs the NFR-005 amendment.
Decision
A module in assets/spec.js that runs only while data-theme is Prose, observes top-level blocks, and sets a revealed marker exactly once per block.
Consequences
+ The reader gets the behaviour the spec asked for. + Calm and vivid never execute it. − Prose is no longer a pure-CSS theme, which is the property NFR-005 protected; the amendment records that trade rather than hiding it.

D-003 · The resting state is visible; the script adds the hidden state

Status
Accepted
Context
NFR-002 requires a fully readable artifact with JavaScript off, and P-4 makes that a principle rather than a preference.
Decision
The stylesheet never hides a block. The script marks the document as reveal-capable when it runs, and only then does the unrevealed state exist. Reduced motion suppresses the effect through the media query the repo already uses.
Consequences
+ The failure mode is a page with no animation, never a page with no text. + A script that throws early degrades to plain visible content. − A reader with JavaScript on sees an unstyled first frame before the marker lands; mitigated by setting it in the same pass that applies the theme.

D-004 · Emphasis opacity floors at 0.75, never below 0.70

Status
Accepted
Context
Computed over the real tokens: light mode binds, giving 5.35:1 at α=0.75, 4.62:1 at α=0.70, and 4.04:1 at α=0.65 — below the floor NFR-001 sets.
Decision
Recessed body text sits at α=0.75, keeping real headroom over 4.5:1; 0.70 is the absolute floor for any text, and nothing text-bearing goes below it.
Consequences
+ The depth layers are measured rather than eyeballed. + A future token retune is checked by the same computation. − The source convention's most recessed layer is not reproducible here at all; it would compute 3.53:1. Prose gets a shallower ladder than the guide describes, on purpose.

D-005 · Sidenotes fold using the declarations that already exist

Status
Accepted
Context
assets/spec.css:2311–2322 already turns a sidenote into a bordered block aside below 1100px.
Decision
Prose applies that same declaration set at every width, keyed on the theme instead of the viewport. The float and the negative gutter margin are unset rather than reinvented.
Consequences
+ One treatment to maintain, already proven at narrow widths. + No new visual language for an aside. − The two triggers must stay in agreement; a change to the narrow-viewport block silently changes Prose, which a test pins.

D-006 · One column: measure and wide-measure unify, as vivid already does

Status
Accepted
Context
assets/spec.css:171–173 — vivid sets both --measure and --measure-wide to one value so every top-level block aligns. Calm keeps the dual-width split.
Decision
Prose does the same at its own reading width, sized so body type at ~20px yields 65–75 characters per FR-003.
Consequences
+ Tables, code and prose share one left edge, which is what makes a long document feel like one column. − Genuinely wide content has less room than in calm; it scrolls within its own container, as it already does.

D-007 · Browser tests, written failing first

Status
Accepted
Context
Pure judgment, and the repo's own scar: a structural check cannot prove a rendered behaviour, and a present-but-broken enhancement passes every one.
Decision
Every requirement is closed by a Playwright assertion over a real artifact — computed measure and leading, the one-way latch across a scroll-down-and-back, contrast on each surface, keyboard reach of every header control, and the reduced-motion and JavaScript-off fallbacks. Each is written red before the code.
Consequences
+ The claims in §5 stay true as the stylesheet moves. + The latch is asserted in the direction the spike showed CSS fails. − Slower than structural checks, and the suite's global reduced-motion setting must be overridden per test, which is easy to forget.

D-008 · The section divider is generated content, not vocabulary

Status
Accepted
Context
The divider was initially deferred with the narrative vocabulary. The spike in Grounding & evidence shows the boundary it marks is already in the document — sections are flat siblings — so unlike a scene divider it needs no element an author must write.
Decision
Render it from main > section + section::before, using the CSS alt-text form so assistive technology receives nothing. Space the glyphs with letter-spacing rather than literal spaces in the content string.
Consequences
+ Satisfies the additive-theme rule outright: no markup, no new element, inert in calm and vivid. + Never appears before the first section, which falls out of the selector rather than needing a guard. − It marks only the boundaries the document already has; an author wanting a break mid-section still cannot have one, which is what stays deferred. − The letter-spacing detail is load-bearing and easy to lose — a hex escape followed by a space silently eats the space, a bug this repository has already paid for once.

11 · Complexity tracking

Anywhere this plan introduces complexity not strictly required by the spec, justify it here. A reviewer should be able to point at any non-trivial choice and find its rationale in this section.

The one real addition is a script module for a theme that was specified as pure CSS. It is not complexity the spec asked for — it is complexity a measurement forced, and the alternative was serving the reader worse. It is bounded in three ways: it runs only while Prose is active, it only ever adds a marker, and the page is fully readable without it. That is the smallest shape the behaviour can take, and D-002 records what it cost.

Grounding the divider turned up a defect in calm rather than in this slice: the h2 section rule at assets/spec.css:497–502 has never rendered, because its :first-of-type exception matches every h2 when each section holds exactly one. It is deliberately not fixed here. NFR-003 forbids this slice from changing how calm renders, and a drive-by fix would change eight rules on every existing artifact under the cover of a theme addition. It is recorded so the next reader finds it on purpose rather than by accident.

The reading shell would have been shippable on its own with no amendment at all. Taking the reveal as well is a deliberate widening, chosen with the trade stated, not a scope creep that happened.

12 · Open questions

None outstanding. The one question that could have blocked estimation — whether the reveal was buildable as specified — was answered by running it rather than by leaving it open, and the answer changed the spec.
