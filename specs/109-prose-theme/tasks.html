Prose theme

Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 109-prose-theme Design design Branch spec/visual-slice-095-098 Created 19 Aug 2026 Read time

22 tasks across five phases. Setup → Foundational → User stories (US1·US2·US3) → Polish. Tasks marked [P] can run in parallel — different files, no dependency. Tests for a story MUST be written and failing before its implementation tasks start. Almost every implementation task lands in one of three shared files (assets/spec.css, assets/spec.js, or one of three test files), which is why fewer tasks here carry [P] than usual — see §Dependencies for exactly which ones share a file.

1 · Execution strategy

Land Setup first — nothing else in this spec is legal without it (FR-001). Then ship US1 alone: a usable reading theme needs neither the reveal nor the header choreography. Layer US2 and US3 on once US1 is verified.

Setup → Foundational → US1 → US2 → US3 → Polish, each story's tests green before the next opens. US3 comes last for a structural reason, not just convention — it extends files US1 and US2 create.

One team on US1, a second on US2, once Foundational lands. US3 is not independent of them — it extends assets/spec.js (US2) and tests/prose.a11y.spec.ts (US1) — so it either waits on both, or one engineer who already holds the context picks it up.

4 · Phase 3a — US1 · Read a long artifact in one pass

Tests (write & fail first)

Write the reading-shell assertions — computed measure, body size and leading; a <spec-sidenote> folded inline rather than floated; a <spec-requirement> card's chrome quieted while its id and structure stay legible; the section divider present between adjacent sections and absent before the first; no horizontal overflow at 1280px and 375px (FR-003, FR-004, FR-005, FR-009). tests/prose.theme.spec.ts
Write the contrast assertion — recessed body text measures at least 4.5:1 in both light and dark mode at the opacity floor D-004 sets (NFR-001). tests/prose.a11y.spec.ts

Implementation

Add the Prose token block — unify --measure and --measure-wide at the reading width, set body size and leading (D-006, FR-003). assets/spec.css
Fold sidenotes and quiet component chrome — reapply the narrow-viewport sidenote declarations at every width; remove card border/elevation while table rows, gauge bars, checkbox state and every id/status pill stay unchanged (D-005, FR-004, FR-005). assets/spec.css
Add the section divider — main > section + section::before, glyphs spaced with letter-spacing (not literal spaces), alt text suppressed via the CSS content form (D-008, FR-009). assets/spec.css
Set the emphasis opacity floor — recessed narration at 0.75, nothing text-bearing below 0.70 (D-004, NFR-001). assets/spec.css
Exercise the reading shell — serve the repo (node scripts/serve-test.mjs) and open a long design or considerations doc with Prose selected, confirming the column, rhythm and dividers read as one pass. Entry point for this story's path.

Closes FR-002, FR-003, FR-004, FR-005, FR-009, NFR-001, SC-005. Also makes SC-001 observable rather than closed — its Meter is a longitudinal review tally over the first 20 reads after Prose ships, not a task any single drain can complete.

5 · Phase 3b — US2 · Feel progress through the page

Tests (write & fail first)

Write the reveal assertions — a block starts hidden and reaches opacity: 1 once scrolled into view; stays at 1 after scrolling back up past it (the one-way latch); every block computes opacity: 1 with reduced motion requested; every block is visible with JavaScript disabled (FR-006, NFR-002). tests/prose.reveal.spec.ts

Implementation

Build the reveal module — observe top-level flow blocks, latch a revealed marker exactly once, run only while data-theme is Prose (D-002, FR-006, FR-007). assets/spec.js
Author the reveal's resting states — every block visible by default; hidden only once the module marks the document reveal-capable (D-003, NFR-002). assets/spec.css
Exercise the reveal — scroll down through a long artifact, then back up, confirming no block disappears once seen. Entry point for this story's path.

Closes FR-006, the reveal half of FR-007, NFR-002, SC-002.

6 · Phase 3c — US3 · Keep the controls without keeping the clutter

Extend the a11y tests with keyboard reach — every header control reachable by Tab, and taking focus returns the header, in both modes (FR-008, SC-003). Depends on T-101 — same file. tests/prose.a11y.spec.ts

Implementation

Add the pointer and focus return rules — :hover and :focus-within on the header, scoped to Prose (FR-008). assets/spec.css

Exercise the header — scroll down, scroll up, then tab through its controls, confirming it recedes and always returns. Entry point for this story's path.

Closes the scroll-up half of FR-007, FR-008, SC-003.
