Prose theme

A third theme tuned for reading an artifact end to end rather than scanning it.

Status Accepted Spec ID 109-prose-theme Owner Brian Corbin · @briancorbin Reviewers Unassigned Created 19 Aug 2026 Principlesv1.9.0 Smallest demoablePick Prose from the theme dropdown on any artifact and read it in a single wide-set column, with each block arriving as you scroll. Read time

The estate's two themes both assume a reader who is scanning — hunting a requirement id, checking a table, diffing a delta. Nothing serves the reader working through a considerations essay or a design end to end. Prose is a third registered theme that widens the measure, enlarges the type, opens the leading, quiets the chrome, and reveals each block as it arrives, so a long artifact reads like an essay instead of a reference card.

1 · Context

016-theme-support registered two themes and deferred a third. Calm holds a narrow measure with marginalia in the gutter; vivid cards everything densely. Both are tuned for a reader who arrives knowing what they want and leaves once they have it.

That is not the only way these artifacts get read. A considerations essay is argued, not indexed. A design is followed decision by decision. Read that way, the current themes work against the reader: the measure is short, the type is small for sustained reading, and the page offers no sense of progress through it.

The conventions that serve this reader are settled: a wide-set column, larger type, open leading, rhythm carried by spacing, and nothing floating over the text. The people served are the ones who read an artifact whole — a reviewer working through a design before a decision, an author re-reading their own argument, a newcomer reading an essay to understand why something is the way it is.

The narrative-depth half of that convention — distinguishing dialogue from narration, scene dividers, pulled-out moments — has no counterpart in an artifact that contains no dialogue and no scenes. It is recorded in §3 as out of scope rather than translated into vocabulary nobody would author.

2 · User scenarios & testing

Each story MUST be independently testable: if you implemented only US1, you would still have a viable MVP.

US1 · Read a long artifact in one pass P1

As a reviewer, I want to read a design or essay in a wide-set, generously led column so that I can follow a long argument without re-finding my place.

Acceptance: Prose sets a 65–75 character measure, ~20 px body type and ~1.8 leading; sidenotes fold inline rather than sitting in a gutter; every artifact type renders without horizontal overflow at 1280 px and at 375 px.

US2 · Feel progress through the page P2

As a reader, I want each block to arrive as I scroll to it so that a long document feels paced rather than endless.

Acceptance: Top-level blocks fade and rise into place on first approach and never fade out again once revealed; with reduced motion requested, or with the effect unsupported, every block is fully visible and legible from the outset.

US3 · Keep the controls without keeping the clutter P3

As a reader, I want the top bar to recede while I read and return when I reach for it so that nothing hovers over the text but navigation is never lost.

Acceptance: The header recedes during downward reading and returns on pointer movement over it, on scrolling up, or when any control inside it takes keyboard focus; it is never the case that a control is reachable by pointer but not by keyboard.

Edge cases

  • A browser without scroll-driven animation support: every block renders visible, and nothing depends on the reveal having run.
  • A saved theme naming no registered theme falls back to the default, per the parent's rule.
  • Printing: the reveal must not leave a block invisible on paper.
  • An artifact that is almost entirely table or checkbox still renders usably, even though it gains little from the theme.

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional

This spec MUST first amend two must-tier requirements of its parent — 016 FR-002, so a theme may modulate the rendered emphasis of text while still redefining no colour custom property, and 016 NFR-005, so a theme may contribute behaviour to the shared switcher script — and no other requirement here MUST be implemented before both amendments land.

Rationale

Prose recesses narration, which changes rendered colour without touching a token; and its reveal needs remembered state, which CSS cannot hold (see FR-007). Both collide with a must-tier parent requirement. Shipping against either unamended would leave parent and theme disagreeing with nothing recording which is right — so the amendments go first, the ordering 073 used against its own parent.

The design system MUST register a third theme, spectastic-prose, labelled Prose, selectable from the existing dropdown in every artifact, with spectastic-calm remaining the default.

Prose MUST set a reading measure of 65–75 rendered characters, body type of at least 20 px, and body leading of at least 1.6, with paragraph separation carried by spacing rather than first-line indent.

Under Prose, marginalia that calm places in the sidenote gutter MUST fold into the single reading column as indented asides, remaining visible without interaction.

Rationale

A single centred column and a 14 rem marginal gutter cannot both hold. Folding inline keeps every word the author wrote reachable in reading order; collapsing sidenotes behind a disclosure would hide content that today needs no gesture to read.

Prose MUST quiet the chrome of structured components — card borders, elevation, fills — while preserving the structure that carries their meaning: tables keep their rows and columns, gauges their bars, checkboxes their state, and every id and status pill stays legible.

Rationale

A requirement card dissolved fully into running text stops being findable, and a reference document that cannot be scanned at all is a worse artifact than a noisy one. The chrome is what the reading theme removes; the structure is what it must not.

Prose MUST reveal top-level flow blocks as they enter the viewport — a fade with a short upward movement — and, once revealed, a block MUST NOT be hidden again by any subsequent scrolling.

Rationale

The source convention fades bidirectionally. On a document that is searched as well as read, fading text back out hides material a reader is scrolling toward, and find-in-page can land on a match nobody can see. Arrival is the part worth keeping.

The reveal and the header's scroll-up trigger MUST be implemented as a progressive enhancement in the shared switcher script, latching each block to revealed exactly once; they MUST take effect only while Prose is the active theme, and MUST require at most 0 markup changes to any document.

Rationale

This requirement is the inverse of its first draft, and a measurement is why. Scroll-driven CSS was specified because it keeps the theme inside 016 NFR-005's pure-CSS rule; a spike then established that animation-timeline: view() is scrubbed by scroll position — a block fades back out on scroll-up — and that the same limit blocks a scroll-up trigger. Both “has been revealed” and “is moving upward” are history, and CSS holds none. So the parent is amended rather than the reader served worse.

The sticky header SHOULD recede while the reader moves forward through the document, and MUST return on pointer movement over it, on upward scrolling, or when any control it carries receives keyboard focus.

Rationale

Receding is the concession to a page with nothing floating over the text; the return triggers are not. A header returning only on hover strands every keyboard reader — hence focus at must while the recede is should. The parent's FR-009 requires the header to exist, not to be conspicuous.

Under Prose, the boundary between two adjacent top-level sections SHOULD carry a typographic divider derived from the existing document structure, requiring at most 0 markup changes, and it MUST be exposed to assistive technology as decoration rather than as content.

Rationale

Deferred at first with the narrative vocabulary, on the reasoning that an artifact has no scenes. Drawn too broadly: its numbered sections are breaks, and that boundary already exists in the document, so no author marks one up. The assistive-technology clause sits at must because a decorative glyph announced as content is a defect.

Non-functional

Every Prose surface MUST hold a contrast ratio of at least 4.5:1 for body text and at least 3:1 for large text and interface controls, in both light and dark mode, with any emphasis modulation applied.

With JavaScript disabled, an artifact MUST render fully readable, and with reduced motion requested the reveal MUST be suppressed entirely, leaving at most 0 blocks hidden from the reader in either case.

Adding Prose MUST change the rendering of the calm and vivid themes in at most 0 respects, and MUST add at most 0 typeface downloads beyond the four families already loaded.

Prose SHOULD add at most 0 network requests and at most 0 build steps, keeping every artifact a single self-contained file.

Out of scope (deferred to other slices)

  • Narrative-depth vocabulary — speech versus narration, pulled-out moments, and a divider at an author-chosen point mid-section. Each needs a new element an artifact would have to author, which the parent's additive-theme rule forbids a theme from demanding. The divider between numbered sections is FR-009 and ships here, because that boundary is already in the document.
  • A per-artifact default, so essays open in Prose unchosen. Needs a defaulting concept the parent lacks, and rules for how it meets a saved preference.
  • Themes that own colour outright. Prose modulates emphasis only; the palette stays mode-owned, as the parent requires.
  • A progress indicator or estimated-time-remaining marker. Related to the pacing US2 asks for, but it is chrome, not typography.

4 · Data model

The feature adds no new entity. It extends one existing set and constrains one existing value.

Entities

Theme
A named visual identity owning typography, structure and — as amended by FR-001 — rendered emphasis, but never a colour token. The registry gains a third member; every member must carry an id unique within the registry and a human label.
Theme selection
The reader's saved choice of exactly one registered theme. A saved value that names no registered theme is not a selection, and resolves to the default.
Reveal state
Whether a top-level block has yet been revealed. It transitions from unrevealed to revealed exactly once and never back, and every block is revealed when the reveal is suppressed or unsupported.

The one-way reveal transition is the invariant that separates this from the convention it draws on, and it is what FR-006 exists to hold. Mode is untouched: theme and mode remain independent, so Prose renders in light and dark alike.

5 · Success criteria

Reviewers who read a long artifact end to end finish it in a single sitting without switching away to a different rendering — share reporting they read it through ≥ 60% (target 85%), from no established baseline.

Meter

Reviewers asked, at review close, whether they read the artifact whole and in which theme; counted over the first 20 designs and considerations documents reviewed after Prose ships, tallied by the author closing each review.

Falsified by

Reviewers selecting Prose, abandoning it partway, and returning to calm to finish — which would mean the theme reads well for a page and stops paying its way over the length that motivated it.

Readers who request reduced motion, or whose browser lacks scroll-driven animation, see every block of every artifact — share of blocks visible 100% (target 100%), from no established baseline.

Observed at

A browser check across each artifact type with the reduced-motion query forced and with the animation feature disabled, asserting no block is left at zero opacity or displaced off its resting position.

Falsified by

Any block still hidden after load under either condition.

Readers navigating by keyboard reach every control the receding header carries — share reachable 100% (target 100%), from no established baseline.

Observed at

A keyboard-only pass over the header in both modes, tabbing to each control from the top of the document.

Falsified by

A control that appears on hover but cannot be reached by tabbing.

Readers with low vision read every Prose surface at conforming contrast — share of surfaces meeting the floor 100% (target 100%), from no established baseline.

Observed at

A computed-contrast measurement of body text, muted text and controls on each Prose surface, in both light and dark mode.

Falsified by

Any surface measuring below 4.5:1 for body text or below 3:1 for a control.

Authors of already-published artifacts see no change to how their documents render in the themes they already use — regressions in calm or vivid 0 (target 0), from 0 today.

Observed at

A rendering comparison of each artifact type in calm and vivid, before and after Prose lands.

Falsified by

Any visible difference in calm or vivid attributable to the Prose work.

6 · Assumptions

The reveal's resting state is authored as visible, with the script applying the unrevealed state only once it is running. A reader with JavaScript off therefore sees every block, which is what makes NFR-002 reachable rather than aspirational.

The four loaded families suffice — the body serif is already a text face — so Prose is a matter of size, measure and leading, not a new typeface.

Modulating opacity rather than defining a colour keeps the theme inside the amended parent contract. If review finds that reading forced, the fallback is depth from type and space alone, which changes no requirement here.

7 · Open questions

None outstanding. Both collisions with must-tier parent requirements are resolved the same way — by amending the parent first (FR-001) — the second of them only after a spike falsified the design this spec was originally drafted around.
