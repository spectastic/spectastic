Design · 051-knowledge-corpus

Knowledge corpus convention

How we will build it.

Status Accepted Spec 051-knowledge-corpus Owner Brian Corbin · @briancorbinxyz Branch 051-knowledge-corpus Created 25 Jul 2026 Read time

Build the corpus as a small pure module in @spectastic/core — a yaml-backed parser over a committed knowledge/ directory of Agent Skills packs — consumed by two existing seams: a new corpus-well-formed schema rule (so a corpus self-validates) and the init bundle mechanism (so a project starts from a working scaffold). The loader returns empty when no corpus exists, so every verb behaves exactly as today. The one risk to watch is the contract: 052–059 all read this frontmatter and index shape, so getting the minimal field set right now is worth more than getting it big.

4 · Approach

Three additions around one new core module, each hanging off a seam that already exists. (1) The corpus module — @spectastic/core/knowledge: a parse.ts that reads a document's ----fenced YAML frontmatter (via yaml) into a typed Provenance, an index.ts that loads a pack's SKILL.md, its references/ documents, and its curated index into a CorpusPack model — and, crucially, returns an empty result when no knowledge/ directory exists (the graceful-absence no-op, D-005). (2) The validate scan — corpusWellFormedFindings() in @spectastic/core/knowledge/validate.ts, folded into spectastic validate the same way scanEnforceWaivers/scanCopyLeak already are (D-003): required frontmatter fields present, and index↔file bidirectional integrity (every index row resolves to a file, every document appears in the index), so SC-001's "every KB-NNN resolves to a file on disk" is a gate, not a hope. (3) The scaffold — a templates/knowledge/ pack (a SKILL.md, an llms.txt-spirit index, and one worked reference document with full provenance) that init writes to cwd, plus a small dogfooded knowledge/ corpus of spectastic's own concepts committed at repo root (FR-007).

The index ships in the llms.txt spirit (FR-004) — a curated markdown map of KB-NNN → title, one-line description, current edition, path — which the corpus-well-formed rule parses for the integrity check. Nothing here is a new mechanism; it is the fence, the bundle, and the rule engine, pointed at a new directory.

5 · Alternatives considered

The one genuinely weighed choice was how to parse the provenance frontmatter — the rest of the plan follows the house patterns directly. Higher is better; the chosen row is marked.

OptionParse correctnessMaintenanceDep-light fitTotal
Minimal flat parser (regex / split-on-first-colon)23510
js-yaml dependency54312
yaml dependency — chosen55313

The minimal parser scores highest on dep-lightness but lowest where it matters most: a silently mis-parsed provenance field becomes a confidently-wrong verified fact — the exact silent-loss failure this whole family warns about. Between the two libraries, yaml edges js-yaml on ESM-native fit (the codebase is ESM) and active maintenance.

6 · Decisions

D-001 · Corpus module lives in @spectastic/core/knowledge

Status
Accepted
Context
The parser + index model is cross-cutting deterministic logic every downstream corpus verb (052–059) will reuse. Core is where such logic lives — packages/core/src/ already holds enforce/, security/, gitignore/. Fat-core / thin-CLI.
Decision
Add packages/core/src/knowledge/ (parse.ts, index.ts, types.ts) with a ./knowledge export subpath (a tsup.config.ts entry + package.json exports).
Consequences
+ Reusable by the schema rule, init, and 052–059 without spawning a binary. + Testable as a pure unit. − One more core subpath to maintain.

D-002 · Parse provenance frontmatter with the yaml dependency

Status
Accepted
Context
No frontmatter/YAML parser exists today and the codebase is regex-first (package.json greps; fence.ts). Provenance correctness is load-bearing — a mis-parse manufactures a false verified.
Decision drivers
Parse correctness · Maintenance burden · Dep-light fit
Considered options
  • Minimal flat parser — + zero new dep, house idiom. − owns every YAML edge case forever; silent mis-parse risk.
  • js-yaml — + robust, battle-tested. − CJS-first, larger, less active than yaml.
  • yaml — chosen — + ESM-native (fits the codebase), actively maintained, zero native deps. − spectastic's first YAML dep.
Decision
Add yaml as a direct dependency of @spectastic/core; pin the version at install (first task).
Consequences
+ Correct, maintenance-free parsing of a load-bearing field. − A new dependency — a P-12 capability surface, recorded in §8 R2 / §9. Corpus text is still fenced (P-11) regardless of the parser.

D-003 · Ship corpus-well-formed as a folded CLI scan, not an HTML schema rule

Status
Accepted
Context
SC-001 requires a corpus to pass validate and every KB-NNN to resolve to a file. Re-grounded at tasks time: packages/schema/src/rules/* is HTML-bound — every rule takes a ParsedDocument (packages/schema/src/rules/no-broken-defer-to.ts:1-2, parser.js's findAll/getAttr). The corpus lives in plain markdown, which never reaches that parser. The exact precedent already exists: packages/cli/src/commands/validate.ts folds non-HTML checks into every validate run as scanX() functions (scanQuarantineMarkers over JSON markers, scanCommandsDrift/scanCopyLeak/scanEnforceWaivers over markdown/config), each backed by a pure finding-function in @spectastic/core/commands/validate.ts, assembled in registerValidate() (validate.ts:226-283).
Decision
Add corpusWellFormedFindings(packs) as a pure function in packages/core/src/knowledge/validate.ts — operating on the already-parsed CorpusPack[] model from D-001's loader, not re-parsing markdown — checking required frontmatter fields, index↔file bidirectional integrity, and KB-NNN uniqueness. The CLI wires it in as scanCorpusWellFormed(cwd) in packages/cli/src/commands/validate.ts, folded into registerValidate() alongside the existing scans. A no-op when knowledge/ is absent (the loader returns an empty pack set). The spec-citation-resolves check stays 053's, on the same folded-scan footing.
Consequences
+ A corpus self-validates via the exact mechanism the codebase already uses for non-HTML checks — no new engine, no schema-rule-registry misuse. + Reuses D-001's parsed model rather than re-parsing. − One more scanX in an already-large validate.ts (525 lines before this addition) — acceptable; 053/058 will add siblings on the same pattern, not a new one each time.

D-004 · Scaffold via the existing prebuild/init bundle mechanism

Status
Accepted
Context
prebuild.mjs already bundles templates/ wholesale into _bundled/; init/bundle.ts resolves and writes the inventory to cwd.
Decision
Place the scaffold under templates/knowledge/ (auto-bundled, no prebuild change) and teach init's write step to emit it. The dogfood corpus (FR-007) is committed at repo-root knowledge/ and is not shipped to downstream projects.
Consequences
+ Reuses a proven, atomic ship path. + Scaffold validates out of the box (SC-002). − init's write logic gains one more known target.

D-005 · Graceful absence = a silent no-op loader; the one-time hint is 054's

Status
Accepted
Context
NFR-001 promises "no corpus ⇒ behave as today, apart from a single one-time hint." The hint is a prompt-surface concern; 054 owns AI-verb prompt assembly. Pure scope judgment — no external fact.
Decision
051's loader returns empty when no knowledge/ exists — zero verb changes, fully testable now. The actual one-time hint + its "shown once" state is built in 054, where the prompt surface lives.
Consequences
+ Keeps prompt-surface/state concerns out of the format slice. + 051 proves absence-is-silent deterministically. − NFR-001's hint clause is only fully demonstrated once 054 lands (noted on both specs).

D-006 · vitest, tests-first; no Playwright

Status
Accepted
Context
051 produces a core parser, a schema rule, init wiring, and markdown — no interactive HTML runtime. A test-style preference; no external fact (n-a).
Decision
Red-first vitest units for the parser, the rule, and the scaffold write. No Playwright — P-7's browser bar targets interactive artifacts, which 051 doesn't ship.
Consequences
+ Fast feedback on the contract that 052–059 depend on. − No end-to-end browser evidence, correctly, because there is no runtime to exercise.

9 · Complexity tracking

Where this plan introduces complexity or deviates from a standing grain, the rationale.

A new dependency against the dep-light grain. yaml is spectastic's first YAML dep. Justified: provenance correctness is load-bearing — a hand-rolled parser silently mis-parsing a field manufactures a false verified, the precise silent-loss failure the corpus family exists to guard against. A single, small, ESM-native, zero-native-dep parser is the proportionate cost. Accountable per P-12 (D-002, R2).

The no-wiki/CMS/knowledge-graph non-goal holds. The corpus is a flat, greppable markdown directory read by agentic search — no query engine, no graph, no CMS, and the vector database is explicitly refused (deferred to 059). "One spec = one file" is untouched; the corpus is a separate, optional directory. Checked, not assumed.
