Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 051-knowledge-corpus Plan plan Branch 051-knowledge-corpus Created 25 Jul 2026 Read time

19 tasks across five phases. Setup → Foundational → User stories (US1 · US2 · US3) → Polish. Tasks marked [P] can run in parallel — different files, no dependency. Tests for a story MUST be written and failing before its implementation tasks start.

1 · Execution strategy

Implement US1 end-to-end — the corpus format, the fence reuse, and the folded validate scan. That alone makes a hand-authored corpus citable and self-checking. Ship, then iterate to US2 (init scaffold) and US3 (dogfood corpus) once US1 is verified.

Setup → Foundational → US1 → US2 → US3 → Polish. Each story closes its conformance before the next opens. Recommended here — the module is small and each story genuinely builds on the loader Foundational lands.

One team on each user story after Foundational. Coordinate at the shared seam — the CorpusPack/Provenance data model (§Foundational) — via the spec and plan, not Slack.
