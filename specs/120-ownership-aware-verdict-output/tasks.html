2 · Phase 1 — Setup

No setup — no new dependencies, no scaffolding. Work begins at Foundational.

3 · Phase 2 — Foundational

Extend the Violation contract — add cause: 'path' | 'ownership' (required) and optional owner/storeCoordinate (FR-001, FR-002, D-001). packages/core/src/guardrail/types.ts
Set cause on every existing Violation literal — the required field forces the suite's fixtures to compile; existing path violations get cause: 'path'. packages/core/test/

4 · Phase 3a — US1 + US2 · The verdict records cause; --explain names the authority

Tests (write & fail first)

Cause on the violation — a non-owner touch records cause: 'ownership' + owner + store coordinate; a path violation and an owner writing outside allowed-in record cause: 'path' with no authority. packages/core/test/guardrail.verdict.resource.test.ts
--explain names the store authority — for an ownership violation the explanation names the owner + store coordinate and routes to that service; it omits the offending file's own directory as "sanctioned" and the consumer's decision coordinate. A path violation's explanation is unchanged. packages/core/test/guardrail.explain.test.ts

Implementation

Set cause + authority in verdictFor — at push time, cause: 'ownership' (+ owner + store coordinate from decision.resource) only when the decision is resource-scoped and the current project is not the owner; cause: 'path' otherwise (path scope, owner-outside-allowed, deny, enforcer). packages/core/src/guardrail/verdict.ts
Render the ownership case in --explain — branch on v.cause: an ownership violation reads "the store <coordinate> is owned by <owner> — route through that service" in place of the sanctioned-path line, and shows the store coordinate, not the decision coordinate. Read the recorded fields; do not recompute ownership. packages/core/src/guardrail/explain.ts
Exercise end-to-end — spawn verdict --explain with a non-owner fixture identity; assert the ownership message names the authority and omits both misdirections. Entry point: spectastic verdict --explain. packages/cli/test/verdict.resource.integration.test.ts

Closes FR-001, FR-002, FR-003, FR-005, SC-001, SC-002.

5 · Phase 3b — US3 · The teaching question fits the failure

Tests (write & fail first)

--teach asks an ownership question — for an ownership violation the question names the store/owner and asks why this service should hold the data, distinct from the layering question; a path violation's question is unchanged. packages/core/test/guardrail.shifu.test.ts

Implementation

Render the ownership question in shifu — branch on v.cause and read v.owner/v.storeCoordinate; no owner comparison. packages/core/src/guardrail/shifu.ts

Closes FR-004, SC-003.

6 · Phase 3c — NFR · Single-source-of-ownership

Closes NFR-001, SC-004.
