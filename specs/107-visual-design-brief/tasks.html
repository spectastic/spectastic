Tasks · 107-visual-design-brief

Design brief

Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Draft Spec 107-visual-design-brief Design design Branch spec/visual-design-brief-107 Created 19 Aug 2026 Read time

15 tasks across five phases. Setup and Foundational are both empty and say so — this slice adds no package, no port and no shared type module beyond what each story already owns (§1). Unlike 106, story-priority order and real build order coincide here: US1 has no dependency on the other two, US2 is independent of both, and US3 depends only on US1 — so document order follows priority without needing to say otherwise. Tasks marked [P] can run in parallel — different files, no dependency. Tests for a story MUST be written and failing before its implementation tasks start.

1 · Execution strategy

Implement US1 end-to-end — a person can read a complete, correctly-labelled brief. Ship. US2 (the reconciliation path, which needs nothing from US1) and US3 (the write, which needs US1) can follow in either order.

US1 → US2 → US3 → Polish. Each story closes its conformance before the next opens. No Foundational phase to wait on — there is nothing shared to build first.

US1 and US2 can start together on day one; nothing in US2 reads US1's output. US3 waits on US1's renderer. Coordinate at the one shared seam — a state's id is its label, verbatim, on both the outbound and inbound side — via the spec, not Slack.

2 · Phase 1 — Setup

Empty, deliberately. No new package (unlike 106’s packages/render), no new dependency, no new port on KernelContext — design.html §2 states this explicitly. There is nothing to scaffold before the stories can start.

3 · Phase 2 — Foundational

Empty, deliberately. The candidate for shared infrastructure — a “label grammar” module — turned out not to exist as code: D-004 settles that a state’s id IS its label, verbatim, so there is no slugging or mapping logic to extract. Every module this slice adds reads through primitives that already ship (fenceArtifactText, the caller-supplied-date convention in types.ts) rather than through anything new. The one thing that keeps the two label-grammar halves honest — a test asserting a label brief-render.ts emits is one state-reconcile.ts matches — is written inside US1’s own test task (T-101), since a Foundational task with nothing to build would be ceremony.

4 · Phase 3a — US1 · Ask in the specification’s own words

Tests (write & fail first)

Assert every declared state reaches the model, untruncated — states, refusals, annotations and addressed contexts for a screen carrying more than projectScreens’s row budget, confirming nothing is dropped (FR-001). packages/core/test/brief-read.test.ts
Assert the brief’s content, in one file — a stated label equals its state’s declared id exactly and nothing else (FR-002); the undeclared-state labelling convention is stated (FR-003); every refusal and annotation appears (FR-006, FR-007); addressed axes and a declined context’s reason are named (FR-008); rendering the same model twice with the same date produces byte-identical strings (NFR-002). One file because these are one function’s properties — 106’s own T-100/T-101 split an equivalent single guard across two parallel tasks targeting one file and a write race destroyed the first agent’s work; this avoids repeating it. packages/core/test/brief-render.test.ts
Assert three structural negatives, in one file — no design tool is named and no network is reached (FR-010, NFR-001); and every existing visual-material reader (materialise-view.ts, screen-naming.ts, coverage.ts, import.ts) is scanned and none treats visual/briefs/ or a .md file as a source of declarations — the one part of FR-011 that is actually testable today, since the requirement is otherwise an absence (design.html D-002’s Consequences already name this as conventional rather than structural). Same shape as 106’s render.no-comparison.test.ts. packages/core/test/brief-generation.no-network.test.ts

Implementation

Implement the complete reader — walks a feature’s declared screens and returns every state, refusal, annotation and addressed context; reads declarations directly rather than widening projectScreens, matching the precedent screen-naming.ts:83–85 already set (D-004). packages/core/src/visual/brief-read.ts
Implement the Markdown renderer — one line per state naming its exact label; the undeclared-state convention stated once; refusals, annotations and addressed contexts rendered; artifact prose fenced via fenceArtifactText (D-005); takes the date as an argument rather than reading a clock (D-003). Depends on T-110’s model shape. packages/core/src/visual/brief-render.ts

Closes FR-001, FR-002, FR-003, FR-005, FR-006, FR-007, FR-008, FR-010, FR-011 (T-102’s testable half; the rest is conventional, per design.html D-002), SC-001. Contributes the pure half of NFR-002; the write half closes with US3. No exercise task: read and render together produce a string, not something a person can yet open — there is nothing to assemble until US3 supplies a write and a CLI entry point (the rule in commands/spectastic.tasks.md that a slice with nothing to assemble owes no such task).

5 · Phase 3b — US2 · A discovered state arrives identifiable

Tests (write & fail first)

Assert an undeclared label is reported and attributed, and nothing is written — a declared id with no matching observed label produces no finding; an observed label matching no declared id is reported by name; the function returns a report and touches no filesystem (FR-004). packages/core/test/state-reconcile.test.ts

Implementation

Implement the comparator — declared state ids in, observed labels in, an undeclared-label report out; pure, no I/O (D-006). packages/core/src/visual/state-reconcile.ts
Wire the comparator into the render subcommand — after a render completes, read the owning spec’s declared state ids from its screens, compare against the labels actually captured this run (written and collision-refused; a template-refused label is noise, not an observation, and must be excluded — 106’s own spike is why), and report any undeclared ones. Orchestration in the CLI rather than a signature change to renderDesign, per P-14’s split (pure functions in core, the CLI composes and writes) — a narrower reading of D-006’s “called from the render path” than literally inside render-capture.ts, settled here since the design left the exact seam open. Depends on T-210. packages/cli/src/commands/visual.ts
Exercise the reconciliation against a real render — spectastic visual:render <spec-id> --from <fixture> against a fixture carrying one label no declared state names, confirming it is reported as undeclared and attributed to the design, and that no declaration changes anywhere in the project. Entry point for this story’s path.

Closes FR-004, SC-004. Contributes to SC-002 by construction — a real captured label binding to its declared state by exact match is exactly what T-215 exercises, though only a genuine human round-trip through a design tool proves the claim in full (spec.html §6, first assumption).

6 · Phase 3c — US3 · What was asked for is still readable later

Tests (write & fail first)

Assert a brief is written once and never rewritten — lands at the dated path; a later run with a different date leaves the earlier file’s bytes untouched; a run whose computed path already exists is refused rather than silently overwritten, the same discipline 106 FR-007 uses for a naming collision (FR-009). packages/core/test/brief-write.test.ts

Implementation

Implement the dated write — computes specs/<id>/visual/briefs/<date>.md (D-001, D-002) and refuses rather than overwrites an existing file at that path (FR-009). packages/core/src/visual/brief-write.ts
Add the visual:brief subcommand — reads the spec’s screens (T-110), renders (T-111), writes (T-310), supplying today’s date as the only clock in the pipeline (D-003). A distinct command from T-211’s change to visual:render, in the same file. Depends on T-110, T-111, T-310. packages/cli/src/commands/visual.ts
Exercise brief generation against a real feature — spectastic visual:brief <spec-id> against the currency-converter exemplar’s 12 declared states, confirming the emitted file opens and names every state’s exact label, and that a same-day re-run is refused rather than silently overwriting. Entry point for this story’s path.

Closes FR-009, NFR-002, SC-002, SC-003.

7 · Phase 4 — Polish

Confirm landing a brief trips no existing scan — validate a project after a real visual:brief run and confirm 0 findings it did not report before, the same check 106’s T-900 ran for renders (SC-003’s neighbour concern). examples/currency-converter
Write the subcommands’ help and refusal text — naming behaviour, never a spec id (P-10). packages/cli/src/commands/visual.ts

US1, US2, US3   → Polish
