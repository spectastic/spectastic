Change proposal · 091-artifact-format

An artifact’s asset references resolve

A must-tier requirement with no enforcement let thirty artifacts ship with no stylesheet, no theme boot and no script — and validate reported every one of them clean.

Status Approved Change ID 2026-09-14-asset-references-resolve Spec 091-artifact-format Author Brian Corbin · me@briancorbin.co.uk Created 14 Sep 2026 Targets 1 requirement (1 added) Read time

Adds REQ-FORMAT-010: a local stylesheet or script an artifact references MUST resolve to a readable file, checked at error severity. REQ-FORMAT-002 already requires that an artifact “open and render correctly when loaded from the local filesystem” — it simply had no enforcement, and thirty artifacts in this repository violated it while validate reported them clean. Image references are deliberately excluded: 094 FR-005 forbids reporting a missing render, at must tier.

An artifact’s asset references resolve

Approved

1 · Intent

REQ-FORMAT-002 has said since it was written that an artifact “MUST open and render correctly when loaded from the local filesystem”. Nothing has ever checked it. On 14 Sep 2026 a sweep of this repository found thirty artifacts whose stylesheet, theme boot and script all pointed one directory level too high — ../assets/spec.css where the file sits two levels up. Every one of them rendered as unstyled text. spectastic validate reported no findings on all thirty, because a reference to a file that is not there is still perfectly well-formed HTML.

They were not found by a check. They were found by accident: two of the thirty happened to fail the REQ-FORMAT-007 browser test, and only because an unstyled <pre> has no overflow-x to contain it — the stylesheet that would have contained it was the thing that had not loaded. The other twenty-eight were invisible to every gate the project has. This is the structurally valid but visually wrong class the verification discipline is built around, and P-8 says the guarantee belongs in the kernel rather than in review. The obligation already exists at must tier; this change supplies the missing half.

2 · Scope

In scope

  • A new REQ-FORMAT-010 obliging a local stylesheet or script reference to resolve to a readable file.
  • A deterministic check behind it — assetResolveFindings in @spectastic/core plus a folded scanAssetResolve in the validate CLI — at error severity, under the rule id asset-resolve.
  • <link href> and <script src>: stylesheet, favicon, theme boot, spec.js. 2,507 such references exist across the validated estate today.
  • An absolute path reported without being resolved — the one containment check contract-resolve contributes that is also right for a browser-resolved href.

Out of scope

  • Image references. <img src> is not checked at all. 094 FR-005 is must-tier and unambiguous — a rendered image “MUST NOT be load-bearing: no check may depend on one being present, and its absence MUST NOT be reported as a finding or made to fail any gate.” The one broken reference the interview’s dry run found anywhere outside specs/ was exactly that: a screen render inside a generated <spec-visual-view> in the currency-converter exemplar. TBD-artifact-image-resolve
  • Cross-artifact <a href> links. The same defect class with a different failure mode — broken navigation rather than a broken render — and it brings fragment targets and links to not-yet-written artifacts with it. TBD-artifact-link-resolve
  • Remote references. An http(s):, data:, # or mailto: value is skipped. Checking a remote URL would put a network round-trip inside validate, which its determinism forbids. never
  • Widening the dogfood glob to docs/**. Those 49 artifacts are clean under this check, but the glob is excluded for reasons inbox I-051 records, and reopening it is that card’s business. TBD-docs-security-scan

3 · Approach

Not a schema rule. PerFileRuleContext hands a rule one parsed document and nothing else — no filesystem — so a rule cannot ask whether a file exists. The project has already answered this shape twice: contractResolveFindings (070 FR-004) and visualResolveFindings (093 FR-010) both live in @spectastic/core and are folded into the CLI as scanContractResolve / scanVisualResolve, each reading from the validate run’s own document cache. This clones that seam rather than inventing a third one, which also keeps it on the right side of the fat-core/thin-CLI boundary: the logic is a pure function of (declarations, filesystem, directory), and the CLI only wires it up.

Walk the AST, never the source text. A regex over the raw HTML would be simpler and wrong. specs/060-course-teaching-payload/design.html documents the course asset convention by writing <link href="${ASSETS}/course.css"> escaped, inside a <code> block — prose about a link, not a link. Parsing makes that case disappear by construction: the walk finds two real <link> elements in that file and neither is the example. The parser also supplies the sourceCodeLocation line and column the finding needs to point at.

Resolution is document-relative, not project-relative, and this is the one place the clone diverges from its models. A declared contract path is relative to the project root, so contractResolveFindings resolves against cwd. An href is resolved by the browser against the document’s own directory — which is precisely the axis the thirty broken artifacts got wrong, all of them at a different depth. Resolving against cwd here would reproduce the bug rather than catch it. The containment sequence is still cloned verbatim: reject an absolute path, reject one resolving outside the project directory, and only then stat.

Cost is one stat per reference on documents already parsed and cached for the run — about four references per artifact. The substring prefilter the sibling scans use does not apply here, because every artifact carries these references; there is nothing to skip.

4 · Deltas

One <spec-delta> per requirement touched. target= links to the live spec. op= is one of added | modified | removed | renamed; a missing or invalid op renders visibly broken.

In an artifact’s source form — the file as authored and committed, before any inlining REQ-FORMAT-001 requires of a published build — every local stylesheet and script it references MUST resolve to a readable file, resolved relative to the artifact’s own directory. A reference that resolves to nothing, or to a directory, MUST be reported as an error, and an absolute path MUST be reported without being resolved. A reference carrying a remote or inline scheme (http:, https:, data:, mailto:, or a bare fragment) MUST NOT be reported. An image reference MUST NOT be checked under this requirement.

Rationale

REQ-FORMAT-002 requires an artifact to render correctly from the local filesystem, and this is the mechanically checkable half of that promise. It is separated out rather than folded into 002 because 002 states an outcome a reader judges, while this states a property a machine decides — and because 002 also carries a network-round-trip clause that has nothing to do with resolution.

Thirty artifacts in the tool’s own repository violated 002 for an unknown period while validate reported them clean, every one by referencing ../assets/ where the file sat two levels up. The failure is silent by nature: a broken reference is well-formed HTML, the browser reports it only in a console nobody reads during review, and the artifact still opens — it simply opens with none of its design. Presence is not resolution.

Why source form, explicitly. REQ-FORMAT-001 requires CSS, JavaScript and SVG to be inlined in the published build, and a build that honours it emits no linked reference at all — on which this requirement is silent, correctly. Naming the scope keeps the two from appearing to disagree, and records the dependency: were inlining ever performed at authoring time rather than at publish, this requirement would lose its subject matter rather than start failing.

Why the resolution is document-relative and not project-relative. That is how a browser resolves an href, and the artifact’s depth within the project is the exact axis all thirty got wrong. It also keeps the check independent of where validate was invoked: a vendored or nested project whose artifacts reach an asset tree above their own root — as examples/currency-converter/ does here — is a legitimate arrangement, and a rule that rejected a reference for leaving the project directory would make that exemplar correct from one root and broken from another. Only an absolute path is rejected on sight, because it cannot survive the artifact being moved or read by anyone else.

Why images are exempt. Not a gap left for later: 094 FR-005 requires at must tier that a rendered image “MUST NOT be load-bearing: no check may depend on one being present, and its absence MUST NOT be reported as a finding or made to fail any gate.” Checking <img> here would contradict it outright, so this requirement is deliberately narrower than its title suggests.

4b · What this change removes

Each entry names one thing this change takes away — a clause dropped from a requirement it retypes, an obligation a sibling loses, a behaviour or affordance no requirement records. An empty register is the answer “this removes nothing”, so the common case needs no editing.

Where a delta removes something itself, its own reason and migration stay authoritative — this register is for what no delta can express.

Nothing. The change is a single ADD: no requirement is retyped, so no clause can be dropped in the retyping, and no sibling requirement loses an obligation. REQ-FORMAT-002 is untouched — deliberately, since retyping a must-tier requirement to fold the check in is exactly how a clause goes missing, and 002 carries a network-round-trip clause that has nothing to do with resolution.

5 · Risk register

Populated by the adversarial risk pass when the proposal triggers the heuristic (touches a must-tier requirement, contains an op="removed" delta, or spans ≥2 topic prefixes). One <spec-risk> per finding. target= is required (missing renders broken). status= defaults to identified; apply refuses until each transitions to accepted, mitigated, or rejected.

The check lands on the artifact while the asset depth is written independently in at least six generators, so this catches the symptom per-file forever and nothing owns the cause — and certifying templates/*.html clean blesses the very prefix that is wrong at every destination a template is copied to.

No task in §6 touches a generator. The depth is hardcoded in core/src/commands/spec.ts (../../assets/), propose.ts (../../../../assets/), verify.ts (const ASSETS = '../../assets'), course.ts ('../../../assets') and cli/src/commands/init/compose.ts; and explore.ts already documents the defect in a comment — “the template lives one deep and previews with ../assets/; the ledger lands two deep … so rewrite on render”.

Accepted as stated, and the scope corrected rather than widened. The certification half is real and is fixed here: the §6 dogfood task no longer claims templates/**, because a template’s reference is correct only in its preview position and passing there means nothing about its destination. The cause half is accepted as out of scope. A gate that makes every occurrence visible at the boundary is worth having before the generators are unified — this one found all thirty in a single pass — and folding a refactor of six generators into the change that adds the check would make both harder to review. Planted as TBD-generator-asset-depth.

REQ-FORMAT-010 enforces the linked asset at must tier while REQ-FORMAT-001 requires at the same tier that linked assets not exist in the published build, so the new check is vacuous on exactly the artifact that reaches a user — and §4b claims no sibling loses an obligation without noticing the dependency.

REQ-FORMAT-001: “All CSS, JavaScript, and SVG MUST be inlined in the published build,” rationale “Linked assets re-introduce the build-and-deploy concerns we are trying to escape.”

Correct, and mitigated in the requirement text. The delta now scopes itself explicitly to the artifact’s source form, names REQ-FORMAT-001 as the reason that scope exists, and records the dependency the finding identifies: if inlining ever moves from publish time to authoring time, this requirement loses its subject matter rather than starts failing. That is a real limit — it supplies no coverage for the published form — and it is now stated in the requirement instead of being discovered later.

The containment clause is lifted from contract-resolve, where the path is author-declared project-relative data, and applied to browser href resolution, where reaching above the project root is ordinary — producing errors that depend on where validate was invoked rather than on whether the artifact renders.

§2 In scope, as drafted: “an absolute path and one escaping the project directory are each reported without being stat-ed.” The counter-example is already committed: examples/currency-converter/ is a nested project whose artifacts all reach the outer asset tree (principles.html → ../../assets/theme-boot.js), and CLAUDE.md records the identical scar one layer down for <spec-contract path=>.

Correct, and the clause is removed. This was a clone taken one step too far. The escape check is right for a declared project-relative path and wrong for an href, and under it the committed exemplar would have been unsatisfiable — correct from the repository root, nine errors from its own. Only the absolute-path rejection survives, which holds regardless of invocation directory. The requirement now states why.

Not one of the delta’s normative keywords was wrapped in <spec-rule>, which would have landed the estate’s first unwrapped must-tier requirement in the spec that defines the artifact format, invisible to every <spec-rule>-based scan.

Contradicts KB-0001@2026-07-25 (spectastic/spectastic · spectastic-concepts · 001-foundations): wrapping each keyword “makes the conformance level machine-greppable as well as human-readable — a validate rule or a downstream tool can find every must-tier requirement without parsing prose.” All 36 keyword wrappers already in specs/091-artifact-format/spec.html follow it.

Correct and fixed — all five normative keywords in the delta are now wrapped. Worth recording that nothing would have caught this: the convention is a committed corpus fact with no validate rule behind it, so an unwrapped keyword is review-caught only. That is the same P-8 shape this proposal exists to close, one level up, and is left as an observation rather than smuggled into this change.

The requirement ships flat error severity with no status dependence, breaking a precedent set twice in this same spec — so an archived proposal, which is a terminal artifact nobody may edit freely, can fail a gate it may never be edited to satisfy.

REQ-FORMAT-009 chose status-dependent scope explicitly (“An artifact that has reached accepted MUST NOT carry an unreplaced template placeholder”), and REQ-FORMAT-005 shipped date-format at warn as a migration-scoped choice. There are ~150 archived proposals under specs/*/changes/archive/, and P-6 puts an artifact in a terminal state behind the change-management surface rather than in-place edits.

Accepted, not mitigated — the limit is real and the severity stays flat. The two cited precedents both scope an obligation that a terminal artifact cannot meaningfully satisfy: a placeholder is authored content, and a date format is a migration. A broken asset reference is neither. It makes the artifact unreadable for anyone who opens it, whatever its status, and an archived proposal that renders as unstyled text is not a stable fact preserved — it is a record nobody can read. Repairing a path also touches no commitment, which is what P-6 actually locks; that reading is what justified repairing all thirty in this repository, roughly ten of them archived or withdrawn, and it is recorded here rather than left implicit. The residual risk is downstream: a project upgrading with a broken reference already inside an archived proposal gets an error it must fix by editing a terminal artifact. That is the honest cost of the choice.
