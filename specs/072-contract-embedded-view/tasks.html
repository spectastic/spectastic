Contract embedded view

Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 072-contract-embedded-view Plan plan Branch main Created 01 Aug 2026 Read time

23 tasks across five phases. Requires 070's reader. This slice has a real layout runtime, so containment is asserted by computed style against a 2000-line fixture — never by the element existing. It also introduces the design system's first height-bounded container, so the CSS carries the pattern for whatever bounds next.

1 · Execution strategy

US1 renders the shape in the design and is independently demoable. US2's drift guard should not lag far behind — an unguarded materialised copy is a second source of truth.

Setup → Foundational → US1 → US2 → US3 → Polish. Recommended. Foundational lands the CSS every story renders through.

Workable in two: the CSS and Playwright half (US1, US3) is genuinely separable from the drift-check half (US2), which touches only core and the CLI.

2 · Phase 1 — Setup

Scaffold the view render fixture — a design page with a short contract, a 2000-line contract for the containment case, one with very long unbroken lines, and a declaration whose file is absent. tests/fixtures/contract-view.html
Add a hostile contract fixture — a contract whose text contains <script>, an inline handler and a javascript: URI, so the escaping claim is tested against a real attack rather than asserted. packages/core/test/fixtures/contract-view/hostile.yaml

3 · Phase 2 — Foundational

The system's first height-bounded container. Every story renders through it, so it lands first and documents its own pattern.

Tests (write & fail first)

Write the failing container tests — assert the view is a bounded block with a computed max-height and overflow: auto, in both themes, and that it is keyboard-focusable with an accessible name. tests/contract-view.spec.ts

Implementation

Add the spec-contract-view CSS block — max-height in rem plus overflow: auto, a projection label line, and a block comment naming the two obligations that travel with bounding (contain both axes; keep the region keyboard-reachable) since this is the first such container. assets/spec.css

Mechanism for FR-003 and NFR-001; the surface every story renders through.

4 · Phase 3a — US1 · The shape is visible in the design

Tests (write & fail first)

Write the failing omission test — assert an absent, unreadable or non-text contract produces no view at all rather than an empty box, per FR-007. packages/core/test/materialise-view.test.ts

Implementation

Call the materialiser from design generation — for each declaration whose path is readable. packages/core/src/commands/design.ts

Closes FR-001, FR-002, FR-005, FR-007, FR-008; contributes to SC-001.

6 · Phase 3c — US3 · A large contract does not run the page

Tests (write & fail first)

Write the failing containment test — for a 2000-line contract, assert the page's own height and horizontal scroll extent are unchanged from the same design without a view, measured by computed style. Presence is not containment. tests/contract-view.spec.ts
Write the failing excerpt tests — assert a contract over the line budget renders an excerpt, sets excerpt=, keeps lines= at the file's real length, and says so visibly. packages/core/test/materialise-view.test.ts

Implementation

Implement line-budget truncation — cap by line count, never mid-line, and mark the result an excerpt per D-006. packages/core/src/contracts/materialise-view.ts

Closes FR-006; contributes to SC-003.

7 · Phase 4 — Polish

Browser-verify in both themes on a fresh origin — open a real generated design and inspect computed styles, using a fresh port so a stale stylesheet cache cannot mask an unstyled render. This exact trap has bitten twice in this repository.
Assert 0 scripts and 0 external requests — a scripting-off render plus a network trace over a generated design, per NFR-002 and SC-004. tests/contract-view.spec.ts
Run the accessibility sweep over the scroll region — confirm no new axe violations, per P-13. tests/contract-view.spec.ts
Check the generation budget — confirm materialising adds under 100 ms for a 5000-line contract, per NFR-003.
Run a full-project validate sweep — confirm 0 new findings across the estate.
