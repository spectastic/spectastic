Design · 072-contract-embedded-view

Contract embedded view

How we will build it.

Status Accepted Spec 072-contract-embedded-view Owner Brian Corbin · @briancorbinxyz Branch main Created 01 Aug 2026 Read time

Materialise, never transclude — the deny-by-default CSP forbids a runtime fetch, so the contract's text is copied into the artifact at generate time and the copy is drift-guarded. Two firsts fall out of that. The stylesheet gains its first height-bounded scroll container (a grep finds zero max-height declarations today), and the staleness check re-reads the file and compares rather than storing a digest — matching verify-view-stale, which documents live re-derivation as a deliberate choice. The view is labelled a projection so it can never be mistaken for the contract.

3 · Data model & contracts

No persisted entity. The view is a derived projection materialised into an artifact, plus one derived judgment about whether it still matches its source.

Conceptual entityPhysical shapeNotes
Projection <spec-contract-view> nested in its <spec-contract>, holding escaped text Carries lines= and, when truncated, excerpt= so the label can state honestly what it shows.
Source contract The file at the parent declaration's path= The only source of truth. Read at generate time; never read by the browser.
Drift judgment Derived — a Finding or nothing Re-read and compare (D-005). Compares the leading lines when the view is an excerpt.

No interface. This slice renders other projects' contracts inside an artifact; it exposes no endpoint, event or schema of its own. The irony is deliberate and worth stating rather than leaving a reader to wonder.

5 · Approach

At design-generation time, for each declaration carrying a readable path=, the materialiser reads the file, escapes it with the existing esc(), truncates it to a line budget if needed, and emits a <spec-contract-view> nested inside the declaration. The element carries lines= (the file's real length) and excerpt= when truncated, so the CSS label can say "projection of api/openapi.yaml · 2000 lines · excerpt" without JavaScript. An unreadable or absent file produces no view at all, per FR-007 — the declaration stands alone rather than rendering an empty box.

The container is the design system's first height-bounded region: max-height in rem plus overflow: auto, which contains both axes and keeps the page from ever scrolling horizontally. Because a scrollable region must be keyboard-reachable, it also gets tabindex="0" and a label — an accessibility obligation that follows from the bounding, not an afterthought. The drift check re-reads the declared file and compares it to the projected text, returning a finding on mismatch; for an excerpt it compares only the leading lines it claims to show.

6 · Alternatives considered

The load-bearing choice is how the contract's content reaches the reader's eye. Scored 1–5, higher is better.

OptionSurvives the CSPWorks with JS offReads in placeDrift-guardableTotal
Runtime fetch() of the declared path115512
An <iframe> pointing at the file135514
A plain link to the file, no embedding551516
Materialise the text at generate time — chosen555419

Reads in place is the criterion that decides this, and leaving it out of an earlier draft made the matrix incoherent — a plain link appeared to win. It cannot: FR-001 and SC-001 ask that a reviewer read the shape without opening another file, which is exactly what a link cannot do. The link row is still worth keeping visible, because it scores a clean 5 on drift where the winner scores 4 — that gap is the trade this slice makes: accept a second copy that can go stale, then pay for it with a guard. Both fetch and iframe are excluded outright by default-src 'none', and the iframe additionally by the no-executable-content rule.

7 · Decisions

D-001 · Materialise at generate time; never transclude

Status
Accepted
Context
templates/design.html:6 sets default-src 'none' with no connect-src, so a runtime fetch is blocked by policy; <iframe> is separately flagged by the no-executable-content rule. The content must therefore be present in the file before the browser opens it.
Decision
Copy the contract's text into the artifact at generate time, and treat the resulting copy as a drift problem to be guarded rather than a rendering problem to be solved.
Consequences
+ Works offline, with scripting off, and inside a tarball. + No policy exception needed. − A second copy of the bytes exists and can go stale, which is precisely what D-005 exists to catch.

D-002 · A nested <spec-contract-view>, not a sibling

Status
Accepted
Context
A view is meaningless without its declaration — it needs the path= to label itself and to be drift-checked. 069's element is already the host, and FR-008 allows one view per declared contract.
Decision
Nest the view inside its <spec-contract>. The pairing is structural, so no for= attribute and no id matching is needed.
Consequences
+ A view can never be orphaned from its declaration or point at the wrong one. + The drift check walks declarations and looks inside, needing no cross-reference. − The declaration element grows a child; its existing CSS must not assume text-only content, which the card's block layout already permits.

D-003 · The container is height-bounded in rem, focusable, and labelled

Status
Accepted
Context
A grep finds zero max-height declarations in assets/spec.css, so this is the system's first bounded region and has no pattern to inherit. FR-003 requires both axes contained. P-13 requires a scrollable region be keyboard-reachable.
Decision
max-height in rem (so it scales with the type scale, not the viewport) plus overflow: auto; tabindex="0" and an accessible name on the container so keyboard users can scroll it.
Consequences
+ Both axes contained; the page never scrolls horizontally because of a long schema line. + Keyboard-scrollable, so the axe sweep and a real keyboard test both pass. − A new CSS idiom enters the system; it is documented in the block comment so the second bounded region copies it rather than reinventing.

D-004 · Projected text is escaped with the existing helper and never highlighted

Status
Accepted
Context
P-11 treats artifact text as data; here the data is a file the tool did not write and cannot trust. packages/core/src/commands/design.ts:180 already exports the esc() the rest of the generator uses. Syntax highlighting is explicitly out of scope in the spec.
Decision
Escape with the existing esc() and emit plain text — no tokenising, no markup injection, no highlighter. A contract containing <script> renders as visible characters.
Consequences
+ NFR-002's "0 scripts added" holds structurally, and the no-executable-content rule stays green against a hostile contract. + No new dependency. − Unhighlighted YAML is less scannable; the spec already accepted that trade.

D-005 · Drift is detected by live re-read and compare, not a stored digest

Status
Accepted
Context
packages/schema/src/rules/verify-view-stale.ts:12-16 documents live re-derivation with no stored fingerprint as a deliberate choice for the directly analogous problem. A grep confirms createHash appears nowhere in the codebase, so a digest would be a new primitive.
Decision
A core contractViewDriftFindings(), folded by a CLI scan, re-reads the declared file and compares it to the projected text. For an excerpt, it compares only the leading lines the view claims.
Consequences
+ Matches the shipped precedent for the same problem, so the estate has one staleness idiom rather than two. + No crypto, no attribute to keep in sync. − Comparison cost is proportional to file size rather than constant; bounded by NFR-003 and trivial at contract scale.

D-006 · Truncation is by line count, and always announces itself

Status
Accepted
Context
FR-006 asks for an excerpt that states it is one. Lines are the unit a reader of a schema thinks in; bytes would cut mid-token and characters would cut mid-line. Pure judgment.
Decision
Cap at a fixed line budget; when truncated set excerpt= and keep lines= at the file's real length, so the label reads "excerpt · 2000 lines" and the full file stays one link away.
Consequences
+ Never cuts mid-line, and the reader always knows they are seeing part. + The drift check has a well-defined leading-lines comparison. − A contract whose interesting part is at the end shows the wrong half; the declaration's path is right there, which the spec accepts.

10 · Complexity tracking

This design normalises line endings; 071 deliberately does not. The two comparisons look alike and are not. 071's D-006 compares bytes exactly, because there a difference means somebody else changed the destination and a false negative would clobber their work. Here a difference means the projection is stale, and a checkout that rewrote line endings has not made anything stale. Divergent rules for divergent consequences — stated here so a future reader does not "fix" the inconsistency.

The first bounded container sets a precedent by accident unless it is documented. With zero max-height in the stylesheet today, whatever this block does becomes the house pattern. The CSS carries a comment saying so, and naming the two obligations that travel with bounding — contain both axes, and make the region keyboard-reachable — so the second one copies the whole pattern rather than just the height.

An excerpt's drift check is weaker than a full view's. It compares only the leading lines the view claims, so an edit past the cut is invisible to it. Closing that would need a digest of the whole file, which D-005 rejects on precedent. The residual is small — the file is one link away and the declaration is still resolve-checked by 070 — and is recorded rather than papered over.
