21 tasks across four phases. Setup → Foundational → User stories (US1·US2·US3) → Polish. Tasks marked [P] can run in parallel. Tests for a story MUST be written and failing before its implementation tasks start.

1 · Execution strategy

Setup → US1 → US2 → US3 → Polish. US1 lands the grid, US2 the decline, US3 the baseline. Each is a separate reason silence would otherwise be ambiguous, which is why they split cleanly rather than by convenience.

US1 alone is a usable grid. Without US2 a decline is indistinguishable from an omission, and without US3 a platform can restyle everything with nothing recording it.

Not applicable. One artifact, one vocabulary, two rules.

2 · Phase 1 — Setup

Extend the shared vocabulary — the four element names and what an axis may select, beside 095's tokens rather than in a second module. packages/schema/src/visual-vocabulary.ts

3 · Phase 2 — Foundational

The reader both rules and the browser check share.

Write the grid reader's tests red — axes returned in document order rather than sorted, contexts belonging to their axis, and a document with no grid returning nothing. packages/schema/test/variant-grid-read.test.ts
Implement the grid reader — pure, no filesystem, and deliberately order-preserving because document order is the resolution order. packages/schema/src/variant-grid.ts

Closes FR-001 in part — the ordering half.

4 · Phase 3a — US1 · One decision, not four documents

Tests (write & fail first)

Write the grid shape rule's tests red — an axis with no name errors, a context with no name errors, a grid with no axes at all is silent because a project may have none. packages/schema/test/variant-grid-shape.test.ts
Write the same-as resolution tests red — a combination naming an axis or context that does not exist errors; one naming real values is silent; and an unwritten combination produces nothing at all. packages/schema/test/variant-same-resolves.test.ts
Write the anti-busywork assertion red — a grid with three axes of three contexts and one authored finding produces exactly 1 finding, not 27. The gap rows must be impossible, not merely absent. packages/schema/test/variant-grid-shape.test.ts

Implementation

Implement the grid shape rule — reading the parsed document it is handed, never re-parsing. packages/schema/src/rules/variant-grid-shape.ts
Implement the same-as resolution rule — every axis and context a recorded combination names must exist, because a reference to nothing reads as diligence and records nothing. packages/schema/src/rules/variant-same-resolves.ts
Register both rules and add their fixtures — the generic harness requires a positive and a negative case for every registered rule. packages/schema/fixtures/
Style the grid, axes and contexts — every scalar surfaced through attr(), and the default context marked so it is legible without counting. assets/spec.css

Closes FR-001, FR-002, FR-006, FR-007, FR-008, FR-009, SC-001.

5 · Phase 3b — US2 · A decline reads differently from an omission

Tests (write & fail first)

Write the decline tests red — a declined context with no reason errors, because a bare flag is the failure the requirement exists to prevent. packages/schema/test/variant-grid-shape.test.ts
Write the rendering test red — a declined context renders visibly differently from a supported one with scripting off, which is the requirement rather than a nicety. tests/visual-variants.spec.ts

Implementation

Require a reason on a decline — carried as content rather than an attribute, so it cannot be an empty string that satisfies a check. packages/schema/src/rules/variant-grid-shape.ts
Style the decline distinguishably — a decline, a support and an absence must be three different readings. assets/spec.css

Closes FR-003, SC-002.

6 · Phase 3c — US3 · A restyle is attributable

Tests (write & fail first)

Write the baseline tests red — a baseline with no verified errors, while verified="none" is legal and renders as a visible gap rather than an absence. packages/schema/test/variant-grid-shape.test.ts

Implementation

Require designed and verified on a baseline — never-verified is a value, so its absence is an error rather than an implicit none. packages/schema/src/rules/variant-grid-shape.ts
Style the never-verified baseline as a visible gap — the requirement is that the gap is visible instead of absent, which is a rendering claim. assets/spec.css

Closes FR-004, FR-005, NFR-001, SC-003.

7 · Phase 4 — Polish

Assert determinism — byte-identical findings across three consecutive runs, and no network read reachable from the reader. packages/schema/test/variant-grid-read.test.ts
Add a project grid template — carrying the resolution-order rule in prose, since it is document order and an author cannot infer that from the markup alone. templates/variants.html
Convert the exemplar's speculative grid — the only project here with an interface, and so the only place the vocabulary can be exercised. examples/currency-converter/visual/
Generate the verify view — with a real captured run. specs/096-visual-variant-grid/verify.html

Closes NFR-002 — determinism and the absence of any network read. Both are properties rather than features, so each is closed by the test that would fail if it stopped being true.
