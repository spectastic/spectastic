Configurable decider

A checkpoint is a role, not a person. Make who decides a configurable knob — human, agent, or panel — with one effort level for how deep the panel goes, and the guardrails that keep autonomy honest.

Checkpoints hard-code who resolves them — a human (AskUserQuestion) or a fixed agent (propose's one-shot critic). This spec (§9.1 of the workflow brief) makes that a Decider role: human (default) · agent · panel, chosen by config that resolves flag > project > default like git.auto. One explicit effort level scales the panel's depth (§3 table). Four guardrails hold when the decider isn't human: never judge your own output, panels use diverse lenses and are capped, irreversible changes escalate to a human, every verdict is logged with its grounds. v1 proves it at propose's adversarial pass; the auto mapping and the roll-out to other checkpoints are siblings (§3).

1 · Context

Propose's adversarial pass runs a single fixed critic; the slicer a fixed median panel; the interviews a human. None is configurable — you can't opt a low-stakes checkpoint down to an agent, or dial a risky one up to a diverse panel, and there's no single control for how hard a checkpoint works.

The brief (§9.1) reframes a checkpoint as "consult the Decider" — a configurable role — with one effort level scaling its depth. It is grounded in the field (Constitutional AI, RLAIF, jury-of-models) and is the prerequisite the brief names before a hands-off pipeline (W-1) can run unattended. It serves the maintainer who wants to opt a checkpoint down when stakes are low and dial rigour up when they're not — deliberately, never silently.

2 · User scenarios & testing

Each story is independently testable: implementing only US1 still yields a viable MVP.

US1 · Choose who decides P1

As a maintainer, I want to set a checkpoint's decider to human, agent, or panel so that low-stakes decisions run without me and risky ones convene real scrutiny.

Acceptance: --decider=agent|panel|human selects the role; absent a flag it resolves from project spectastic.json, then the human default; a panel convenes diverse agents and arbitrates their verdicts.

US2 · One dial for how deep P1

As a maintainer, I want one --effort level to set the panel's depth so that I pick rigour with a single knob instead of per-checkpoint plumbing.

Acceptance: --effort=low|medium|high|xhigh|max sets the voter count + arbitration per the §3 table, resolved by the same flag > project > default precedence.

US3 · The guardrails hold P1

As a maintainer trusting a non-human decider, I want the safety rails the research demands so that autonomy never quietly lowers the bar.

Acceptance: no decider judges its own output; a panel uses diverse lenses and is capped; an irreversible change (removed-op / must-tier) routes to a human regardless of config; every non-human verdict is logged with its grounds on the artifact it touched.

Edge cases

  • Panel of one. panel at an effort level yielding 1 voter degrades to a single agent — no empty arbitration.
  • No provider. Without an AIProvider, agent/panel fall back to human rather than failing.
  • Tie in a categorical vote. A tie escalates one level (toward arbiter, then human), never resolves arbitrarily.

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) per RFC 2119.

Functional — the Decider

A checkpoint MUST resolve through a configured Decider role — human, agent, or panel — not a hard-coded reviewer. Default human; non-human deciders are opted down to, never assumed.

Rationale

§9.1 — AIProvider.ask backs human; subagent backs agent/panel.

Decider and effort MUST resolve by precedence: per-run flag > project spectastic.json > built-in default — the effectiveAuto(cfg, override) shape already shipped for git.auto.

An agent/panel decider MUST be grounded on the constitution (principles.html), the artifact under review, and the plan's grounding ledger — to rule on the merits, not invariants alone.

Functional — the effort dial

An explicit effort level MUST scale the decider's depth per this table (default medium):

low
human-defer, or 1 agent
medium
1 agent (single vote)
high
3-voter panel
xhigh / max
5-voter diverse panel + arbiter + completeness critic

A panel decider MUST arbitrate type-dependently: categorical verdicts by majority vote, numeric verdicts (RICE) by median — matching slice/panel.ts.

Functional — the guardrails (non-negotiable for non-human deciders)

A decider MUST NOT judge its own output — the decider invocation MUST be distinct from any author invocation at the checkpoint.

Rationale

Self-preference bias is measured (§9.1); separating author from decider is the mitigation.

A panel MUST use diverse lenses (distinct prompts), not N identical copies, and MUST be capped at 5 voters.

An irreversible / high-stakes decision — detected by the signals that fire the adversarial pass (removed-op, must-tier) — MUST route to a human regardless of the configured decider.

Every non-human decider verdict MUST be logged with its grounds on the artifact it touched — propose's <spec-risk> gains decider attribution (role, level, grounds), extending the existing register, not a new log.

Non-functional

A decider MUST NOT exceed its effort level's voter cap in agent invocations — bounding cost and concurrent provider calls.

Config resolution SHOULD be deterministic and auditable: identical flags + project config + default resolve to the same decider and effort every time.

Out of scope (deferred to other slices)

  • The --effort=auto signal-mapping (per-verb risk signals → level). Peeled to stay estimable; FR-008's escalation signals are the seed.
  • Wiring the Decider into the other checkpoints (decision-phase interviews, slicer ranking) — v1 proves the verb-agnostic seam at propose.
  • Scaling fan-out width and loop depth by effort (full §9.2 table) — this spec scales the decider's depth; width is 032's.
  • W-1 consuming these dials to run unattended — this spec provides the knobs.

4 · Data model

No new persisted entity — config extends spectastic.json; verdicts extend the existing <spec-risk> register. Three shapes:

Entities

Decider
A role — human | agent | panel — plus its resolved effort level. Backed by AIProvider.ask (human) or subagent (agent/panel).
Effort level
low | medium | high | xhigh | max → a voter count + arbitration mode (FR-004). Default medium.
Verdict
A decider's decision + grounds (role, level, the vote/median tally, the reasoning), recorded on the touched register (FR-009).

The safe-degradation ladder: a tie escalates one level (panel → arbiter → human); a 1-voter panel degrades to a single agent; a missing provider degrades to human. Under ambiguity the bar only moves up, never silently down.

5 · Success criteria

Technology-agnostic, measurable outcomes.

With --decider=panel --effort=high, propose convenes exactly 3 diverse panellists, arbitrates type-appropriately (vote / median), and records the verdict + grounds on each <spec-risk>.

Precedence is observable end-to-end: a per-run flag overrides a project-config setting, which overrides the human default — verified at all three levels.

A removed-op or must-tier change routes to a human even under --decider=panel — the escalation guardrail is observable, not advisory.

Each effort level yields its table voter count — medium→1, high→3, max→5+arbiter — observable by counting panellist invocations.

At the wired checkpoint the author and decider are distinct invocations — no decider is handed its own output to judge.

6 · Assumptions

The existing AIProvider (ask for human, subagent for agent/panel) is a sufficient backing for all three roles; a Decider is a thin abstraction over it, not a new provider.

Propose's adversarial critic (propose.ts) and the slicer panel (slice/panel.ts) are the reference behaviours the seam generalizes — preserved, then hoisted.
