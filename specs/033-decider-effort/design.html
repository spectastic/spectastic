Design · 033-decider-effort

Configurable decider

How we will build it.

Status Accepted Spec 033-decider-effort Owner Brian Corbin · @briancorbinxyz Branch 033-decider-effort Created 09 Jul 2026 Read time

Introduce a Decider abstraction in @spectastic/core — a role (human/agent/panel) over the existing AIProvider (ask/subagent) — resolved by a decider section in spectastic.json with the same flag > project > default precedence as git.auto. Wire it into propose's adversarial pass: the single fixed critic becomes a decider whose effort level sets the panel size, with type-dependent arbitration and the four guardrails as tested invariants. Biggest risk: propose's existing auto-fire is agent-driven, which the global human default must not regress — solved by a checkpoint-supplied default.

4 · Approach

A new packages/core/src/decider/ module owns the abstraction: resolveDecider(cfg, override, checkpointDefault) applies precedence; decide() dispatches by role — human → ai.ask, agent → one ai.subagent, panel → N diverse subagent critics aggregated type-dependently. An effort table maps the level to a voter count (1/1/3/5) + arbiter + cap. Propose swaps its single critic for decide(), seeding a checkpoint-default of agent so today's auto-fire is unchanged; each surviving risk renders with decider=/effort= attributes + a grounds line. Config extends spectastic.json with a decider section read exactly like git.

6 · Decisions

D-001 · Decider is a core role over AIProvider; precedence override > project > checkpoint-default > human

Status
Accepted
Context
AIProvider already exposes ask/subagent (types.ts:113,119); the git layer proves the precedence shape (effectiveAuto, git/index.ts:126).
Decision
A packages/core/src/decider/ module with resolveDecider(cfg, override, checkpointDefault) and a role-dispatching decide(). Precedence: per-run override > project config > the checkpoint's own default > global human.
Consequences
+ Verb-agnostic, reused by 035 with no provider change (FR-001/FR-002).
− A checkpoint-default seam beyond the spec's "global human" wording — see R-1.

D-002 · Config mirrors git — a decider section in spectastic.json

Status
Accepted
Context
loadGitConfig (git/config.ts) is the section-scoped, sync reader pattern; only the smallest config surface is wanted.
Decision
Add loadDeciderConfig(cwd) reading a decider: { role, effort } section, and effectiveDecider(cfg, override) — the exact shape of the git pair. Absent → defaults (role from checkpoint, effort medium).
Consequences
+ Familiar, tiny, fail-fast on typo (NFR-002).
− A second config reader until a general loader is warranted (deferred).

D-003 · Wire into propose; checkpoint-default agent + effort medium preserves 013

Status
Accepted
Context
Propose's adversarial pass is a single subagent critic that auto-fires on risk signals (propose.ts:49-65). The spec's global default is human, which naively would disable that pass.
Decision
Propose seeds checkpointDefault='agent'; effort default medium → 1 critic. Absent any flag/config, behaviour is byte-for-byte 013. --decider=panel --effort=high → 3 diverse critics; --decider=human → skip the auto pass (manual risks).
Consequences
+ No regression; opt-up to panel is additive (SC-001).
− The "human is the global default" wording holds only for checkpoints that don't seed their own — documented, R-1.

D-004 · Type-dependent arbitration; diverse lenses; cap 5

Status
Accepted
Context
slice/panel.ts already medians numeric votes; the risk pass is categorical (which risks survive).
Decision
Panel critics get distinct lens prompts (security / correctness / user-impact / maintainability / cost), capped at 5. Categorical verdicts: a risk survives if raised by a majority of critics; numeric: median (reuse medianRice). (FR-005/FR-007)
Consequences
+ Bias-dampening per the research; bounded cost.
− Lens list is a fixed v1 set; extensible later.

D-005 · Guardrails are kernel invariants; verdicts as <spec-risk> attributes

Status
Accepted
Context
The schema only checks status= (risk-status-required.ts), so extra attrs are safe. P-8 requires the guardrails live in code, not markdown.
Decision
In the core Decider: (a) the decider invocation is always distinct from the drafter (no self-judging); (b) a removed-op/must-tier change forces risks to stay status="identified" for human disposition (never auto-closed); (c) each risk renders decider=/effort= + a grounds line with the vote tally.
Consequences
+ FR-006/FR-008/FR-009 enforced deterministically.
− The escalation signal reuses propose's existing risk heuristic; the general form is 034's.

D-006 · Test-first over a scripted stub

Status
Accepted
Context
Every SC is observable without a network — count panellist invocations, stage ask/subagent, assert precedence + escalation.
Decision
Write failing tests first: precedence (SC-002), voter counts per effort (SC-004), panel@high=3 + arbitration + logged verdict (SC-001), escalation to human under panel (SC-003), author≠decider (SC-005). Extend the existing StubAI counting pattern.
Consequences
+ Behavioural, not structural (P-7).
− n-a grounding: a test-style preference, no external fact.

9 · Complexity tracking

The checkpoint-default seam (D-003) is the one deviation from the spec's plain "global human default." It is required to avoid regressing 013's auto-fire and is documented as R-1; the global human default still holds for any checkpoint that doesn't seed its own.

Grounding gate. All must-tier decisions are verified; D-006 is n-a (test-style). No assumed/unresolved-spike must-tier fact — ready for /spectastic.tasks.
