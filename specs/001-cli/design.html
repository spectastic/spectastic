Design · 001-cli

Spectastic CLI — spectastic init

Single Python file, two-pass execution, atomic writes, no runtime dependencies.

Status Draft Spec 001-cli Principles v1.0.0 Owner Brian Corbin · @briancorbinxyz Branch main Created 12 Jun 2026 Read time

Ship as scripts/spectastic — a single Python 3.9+ file using only the standard library at runtime. Two-pass execution: scan for conflicts, prompt the user (or refuse without --force in non-TTY environments), then write each file atomically via .tmp-then-os.replace. Asset source is discovered via Path(__file__).parent. Tests live in scripts/test_spectastic.py using pytest (dev-only dep). Five load-bearing decisions documented as ADRs.

2 · Technical context

Language
Python 3.9+. Standard library only at runtime.
Test stack
pytest with tmp_path fixture + subprocess. Dev dep only; not required at install or runtime.
Distribution
User downloads scripts/spectastic (+ the assets it references) and runs chmod +x. No package manager in v1.
Storage
None. The CLI is stateless.
Perf target
NFR-001: under 2 s wall-clock for an empty directory. File IO dominates; no network.
Constraints
No runtime deps; no network; no writes outside cwd; non-TTY refuses without --force.

3 · Approach

Two-pass execution. The first pass discovers and reports; the second pass writes. Between them, the user (or --force) gates progress. Atomic per-file writes (.tmp + os.replace) ensure Ctrl-C never leaves a partial file.

5 · Decisions

D-001 · argparse over click

Status
Accepted
Context
NFR-002 mandates stdlib-only at runtime. click would force pip install.
Decision
Use argparse. The CLI surface (init + --force) fits argparse's syntax cleanly.
Consequences
+ Zero install. + Cross-Python compatibility. − Slightly more verbose subcommand definition than click.

D-002 · Atomic per-file writes

Status
Accepted
Context
FR-005 requires no partial state after error or Ctrl-C.
Decision
For each file: write to <target>.tmp, then os.replace(tmp, target). POSIX guarantees rename is atomic within a filesystem.
Consequences
+ Ctrl-C between files leaves earlier files complete, later files untouched. + Cleanup is delete any leftover .tmp. − Cross-filesystem rename is not atomic; not a concern when writing inside cwd.

D-003 · Asset source via Path(__file__).parent

Status
Accepted
Context
The CLI needs to find assets/, templates/, and commands/ at runtime. In dev: scripts/spectastic is co-located with its source-of-truth assets at ../assets/. After download: same layout.
Decision
Resolve the source root from Path(__file__).resolve().parent.parent. No env vars, no embedded base64, no walk-up search.
Consequences
+ Self-locating; works in any cwd. + No config. − User must keep the directory layout intact when downloading; if they move spectastic out of scripts/, the resolver breaks.

D-004 · pytest for tests; CLI runtime stays stdlib-only

Status
Accepted
Context
User chose pytest during the plan-phase interview. NFR-002 still binds the runtime.
Decision
Tests live at scripts/test_spectastic.py using pytest's tmp_path fixture and subprocess.run. pip install pytest is a dev-only step documented in the README. The CLI itself imports nothing third-party.
Consequences
+ Expressive parameterised tests. − One dev dep. − Tests skipped if pytest is absent (acceptable; CI installs it).

D-005 · Strict non-TTY behaviour

Status
Accepted
Context
The conflict prompt loop reads from stdin. In CI or piped input, that loop hangs.
Decision
At startup, check sys.stdin.isatty(). If false and conflicts exist and --force was not passed, refuse with a clear message naming --force as the remedy. Exit code 2.
Consequences
+ Never hangs. + CI failures are loud, not silent. − Adds a small startup check.

8 · Complexity tracking

The .tmp-then-os.replace pattern is mildly more complex than a naive write. It's justified by FR-005's "no partial state" requirement; nothing simpler meets that bar.
