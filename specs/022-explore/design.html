Design · 022-explore

explore — vibe to learn, spec to keep

How we will build it.

Status Accepted Spec 022-explore Owner Brian Corbin · @briancorbinxyz Branch 022-explore Created 24 Jun 2026 Read time

Build the front half as a deterministic core scaffolder + thin CLI wrapper (the verify/course pattern): explore <intent> writes two artifacts under explorations/<id>/ — a git-ignored explore.html ledger and a tracked quarantine.json marker. The marker is the anti-ship gate: the CLI validate scan always errors while it exists (CI blocks merge), and the verb state-gate refuses to advance an exploration. The single biggest risk is the deliberate friction of a branch that stays red until it graduates — accepted as the price of the D-4 guarantee.

4 · Approach

A new extended verb explore <intent> resolves the next NNN-kebab id and calls a deterministic core kernel (packages/core/src/commands/explore.ts) that renders two outputs: the explore.html ledger (intent + built/tried/worked/didn't + a CapturedRun-shaped Run block) and the quarantine.json marker ({ id, intent, status, created }). A thin CLI wrapper writes both under explorations/<id>/ and ensures the .gitignore rule that ignores the ledger but tracks the marker.

Enforcement is two-legged. The CLI validate command scans explorations/**/quarantine.json and emits an error-level finding for every marker whose status is quarantined — so any CI spectastic validate run fails while un-graduated work is tracked (the merge gate). In parallel, the verb state-gate refuses to advance an explorations/ target, so no core verb can walk a quarantined build toward a terminal state. The only exits are graduation (deferred) or deletion.

5 · Alternatives considered

6 · Decisions

D-001 · Engine-in-core scaffolder, thin CLI wrapper

Status
Accepted
Context
Mirror the established kernel pattern (packages/core/src/commands/verify.ts, course.ts): deterministic, stub-free, returns rendered output for the CLI to write.
Decision
explore.ts in core renders the ledger HTML + marker object; packages/cli/src/commands/explore.ts resolves the id, writes both files, and maintains the .gitignore rule.
Consequences
+ Kernel is unit-testable without the filesystem. + Consistent with every other verb. − One more verb pair to maintain.

D-002 · Two artifacts — git-ignored ledger + tracked JSON marker

Status
Accepted
Context
FR-004: the rich ledger stays ephemeral (like --course) but the quarantine signal must be visible to CI. A single file cannot be half-ignored.
Decision
explore.html (rich ledger) is git-ignored; quarantine.json ({ id, intent, status:"quarantined", created }) is tracked and is the machine-readable marker the guard reads.
Consequences
+ Discovery prose stays local; the gate stays enforceable in-repo. + JSON is the cheapest machine read. − A new non-HTML artifact type (precedented by commands.json; see §9). − Risk of a mis-scoped .gitignore (R-4).

D-003 · Two-legged enforcement — CLI validate scan (always errors) + verb state-gate

Status
Accepted
Context
FR-005/FR-006: nothing un-graduated may reach production. Schema Rules are HTML-doc-bound, so a JSON marker cannot be a Rule.
Decision
validate scans explorations/**/quarantine.json and emits an error finding for every quarantined marker (CI fails until graduate/delete). The state-gate refuses to advance an explorations/ target. Always-error, no --strict mode.
Consequences
+ Strongest D-4 guarantee; the merge gate is unconditional. + Deterministic (NFR-001). − The exploration branch is red by design until graduated (R-1). − One finding lives in the CLI, not the schema registry (§9).

D-004 · Reuse CapturedRun for the run record

Status
Accepted
Context
FR-008: the run record's shape is shared with verify.html's Run/Demo block. That shape already exists, typed and exported (packages/core/src/types.ts:470).
Decision
Import CapturedRun; the ledger renders it into <spec-run>/<spec-toggle>/<spec-tests>. Do not define a parallel shape.
Consequences
+ Zero re-capture at graduation; one record, two consumers. + Compile-time coupling surfaces any drift in 021's shape. − Soft coupling to 021-verify-view (R-3).

D-005 · Thin floor in the ledger template — P-1 + P-2 only

Status
Accepted
Context
FR-007: the SDD ceremony is off during explore. The ledger template must not import the spec template's INVEST block, conformance index, or requirement-ID scaffolding.
Decision
templates/explore.html carries only single-file structure (P-1) and semantic <spec-*> tags (P-2): intent, built/tried/worked/didn't, run block. No IDs, no INVEST, no conformance.
Consequences
+ Keeps the vibe fast; graduation adds the ceremony. − The ledger is intentionally not a conformant spec artifact — validate must not hold it to spec rules (it scans the marker, not the ledger).

8 · Risks & mitigations

R-1 is an accepted consequence of the always-error gate (D-003): an exploration branch will fail spectastic validate until it graduates or is deleted. This is intended friction, not a bug — accept it before implementation.
RiskLikelihoodImpactMitigation
R-1 · Explorers surprised that validate/CI is red while exploringMMThe finding message names the cause + the exits ("quarantined — graduate or delete to clear"); document in spectastic.explore.md.
R-2 · JSON marker diverges from the HTML-only ethosHLPrecedented by commands.json; keep the marker minimal + documented; only the CLI scan parses it.
R-3 · CapturedRun shape drifts in 021LMImport the type (compile-time break catches drift); the shape is exported + shared in @spectastic/core.
R-4 · .gitignore mis-scoped (ledger tracked or marker ignored)MMGlob targets explore.html only; a test asserts the marker is tracked and the ledger ignored.

9 · Complexity tracking

The non-trivial choices and why they are acceptable.

JSON marker → CLI-level validate scan. Choosing a JSON sidecar (over an HTML stub readable by extractSpecStatus) moves one finding out of the schema-rule registry and into the CLI validate command, because Rules are bound to a single ParsedDocument. Accepted: the JSON read is trivial and CI-portable (no HTML parse in the gate path), and machine-metadata-as-JSON is already precedented by commands.json. The split is the only divergence from "the rules/ directory IS the schema," and it is contained to one scan.

The ledger is deliberately non-conformant. explore.html omits IDs, INVEST, and the conformance index (D-005). validate must scan the marker, never hold the ledger to spec rules — otherwise the thin floor (FR-007) would be contradicted by the validator.
