Unit edge authoring

Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 080-unit-edge-authoring Design design Branch main Created 02 Aug 2026 Read time

21 tasks across five phases. A task is marked [P] only where no sibling in its phase touches the same file — concurrency is bounded by the file, not by the logic. Tests for a story MUST be written and failing before its implementation tasks start (D-005), with the migration in D-003 the deliberate exception: its tests already exist and must stay green throughout.

1 · Execution strategy

The fit. Setup → Foundational (the shared editor) → US1 (write) → US2 (prompt) → US3 (validate) → Polish. The editor must exist before anything writes through it, and the migration lands with it rather than after, so no third copy is ever committed.

US1 alone is shippable: a maintainer can record a dependency by command. The prompt and the validate rule sharpen it but nothing depends on them.

Not a fit for one author, and the editor is a shared seam every story crosses.

2 · Phase 1 — Setup

Add the config module to the build — a tsup entry and export subpath, so init can import the editor without reaching into core's internals. packages/core/tsup.config.ts

3 · Phase 2 — Foundational

The shared editor, and the migration that stops a third copy existing.

Test indentation detection and preservation — tab, 2-space and 4-space fixtures each survive a one-key edit unchanged outside that key (D-001). packages/core/test/config.edit.test.ts
Test the two policies separately — set-if-absent never overwrites; add-to-set is idempotent and never appends a duplicate. packages/core/test/config.edit.test.ts
Implement the shared config editor — one parse-mutate-write path behind two named policies. packages/core/src/config/edit.ts
Migrate init's two writers onto the editor — behaviour-preserving by construction; the existing init tests are the red line and must stay green untouched (D-003). packages/cli/src/commands/init.ts

4 · Phase 3a — US1 · Record a dependency without hand-editing config

Tests (write & fail first)

Test that a write lands and re-running changes nothing — idempotence asserted on the bytes, not on the parsed value (SC-001). packages/core/test/units.write.test.ts
Test that unrelated keys and formatting survive — a config carrying other sections is altered only where the edge goes (SC-002). packages/core/test/units.write.test.ts
Test each refusal leaves the file byte-identical — self-edge and malformed target, both compared byte-wise before and after (NFR-002). packages/core/test/units.write.test.ts
Test config creation — a project with no spectastic.json gets a minimal one rather than a refusal (FR-004). packages/core/test/units.write.test.ts

Implementation

Implement the edge writer — decide every refusal first, then one call to the editor (D-002). packages/core/src/units/write.ts
Add the write subcommand — a thin register that reports what it wrote or why it refused. packages/cli/src/commands/units.ts

Closes FR-001, FR-002, FR-003, FR-004, NFR-001, NFR-002, SC-001 and SC-002.
