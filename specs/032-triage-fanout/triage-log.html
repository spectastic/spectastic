Cards

The interactive /spectastic.triage slash-command never fans out — only the CLI/core backends do

Spec upstream

Debugging why a dogfooded (and this repo's own) list-intake triage classified items serially, root cause was a coverage gap — 032 built the fan-out core + both backends (ai.chat CLI, ai.subagent Workflow) but never wired the in-host slash-command path everyone actually uses; fixed by a slice that routes interactive list-intake through parallel classifier subagents (with the CLI as the deterministic backend); regeneration fails at the spec — 032's FR-001 names the two backends but not the interactive markdown, so a fresh session re-derives the serial loop.

Expected
Running /spectastic.triage on a pasted list classifies the items concurrently (one classifier per item under the bounded cap), per 032's fan-out design.
Actual
The interactive command follows the serial per-item loop in commands/spectastic.triage.md — no fan-out step — so items classify one at a time. (Observed on the prior 6-item dogfooding triage and confirmed on this list.)
Diagnosis
FR-001 requires fan-out on "the CLI triage verb and a Claude Workflow / subagent script" — both shipped (15/15 tasks; triageFanout + triage-fanout.subagent test). But no 032 task touched commands/spectastic.triage.md, and the "Optional: CLI dispatch" note is advisory + ANTHROPIC_API_KEY-gated — so the in-host path (the default interactive one) never invokes the fan-out.
Fix
A slice (propose against 032, then implement): add an FR that interactive list-intake fans out, and update commands/spectastic.triage.md to instruct parallel classifier-subagent dispatch for a pasted list, routing the shared classification core (triageFanout, backend: 'subagent').
Fixed
The in-host fan-out is documented in commands/spectastic.triage.md — list-intake dispatches parallel spectastic-classifier subagents, the best-effort counterpart to the CLI’s guaranteed triageFanout (FR-009).
Deep dive — principles (P-8 / T-009): markdown fan-out is a nudge, not a guarantee

Principles invariant implicated. Per P-8 and meta-spec T-009, an instruction in command markdown is advisory — telling the model "fan out" cannot force it to. The honest design: the deterministic guarantee of concurrent classification lives in the CLI/core (triageFanout, already built), and the slash-command markdown is a best-effort nudge to route through it. So the slice has two honest parts: (a) the markdown instructs subagent fan-out (UX nudge), and (b) the guarantee stays the CLI/core backend for anyone who needs determinism. No cross-spec contract beyond 032's own core; no hotfix. This is why the card is spec (a missing requirement + slice), not implementation: 032 delivered exactly the two backends FR-001 named — the interactive path was simply out of its declared scope.
