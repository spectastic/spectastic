15 tasks across five phases. Setup → Foundational → US1 (fan out) · US2 (batched gate) · US3 (survive a bad item) → Polish. Tasks marked [P] can run in parallel — different files, no dependency. Tests for a story MUST be written and failing before its implementation tasks start.

1 · Execution strategy

Implement US1 (ordered fan-out) end-to-end and verify. US2 (batched gate) and US3 (failure isolation) harden the same engine.

Setup → Foundational → US1 → US2 → US3 → Polish. Each story closes its conformance before the next opens. This is the recommended order — the three stories share one engine.

Not applicable — one engine, one author. The stories are increments of the same file, not independent surfaces.

2 · Phase 1 — Setup

Create the triage module dir — new triage/ for the extracted core. packages/core/src/triage/

3 · Phase 2 — Foundational

Shared infrastructure no story can ship without. The stub upgrade (D-004) is the prerequisite the plan's grounding surfaced — it comes first.

Concurrency-safe stub — a test AIProvider that keys chat/subagent responses by item content and supports an optional per-item delay, so concurrent calls stay deterministic and SC-001 timing is measurable (D-004). packages/core/test/helpers/keyed-stub.ts
mapPool helper + unit test — mapPool(items, mapper, concurrency) returning results indexed by input position under a hard cap; test ordering + that no more than cap run at once (D-002). packages/core/src/helpers/map-pool.ts
Extract classifyItem — move the prompt builder, parseCard, layer taxonomy, and routing out of characterise into a total function returning {draft, status: ok|hedged|failed} with no ai.ask and no throw (D-003). Single-item path recombines classify+gate to preserve current behaviour. packages/core/src/triage/classify.ts

4 · Phase 3a — US1 · Fan out a pasted list

Tests (write & fail first)

Ordering & determinism test — N items yield N input-ordered cards with sequential I-NNN, identical across repeated runs, regardless of completion order (SC-002). packages/core/test/triage-fanout.test.ts
Slowest-item bound test — with one slow item among fast ones (delaying stub), total wall-clock ≈ the slow item, not the serial sum (SC-001). packages/core/test/triage-fanout.test.ts

Implementation

triageFanout engine — drive classifyItem through mapPool, collect in input order, assign I-NNN/T-NNN in a single post-pass; parameterized by mode: chat|subagent (D-001). packages/core/src/triage/fanout.ts
Wire triageCommand list branch — replace the serial for…await loop with triageFanout; single-item branch unchanged. packages/core/src/commands/triage.ts

Closes FR-001, FR-002, FR-003, FR-007, NFR-001, NFR-003, SC-001, SC-002.

5 · Phase 3b — US2 · Decide the ambiguous ones in one pass

Tests (write & fail first)

Batched-gate test — multiple hedged items resolve via one post-pass after classification; no ask interleaves with the pool; confident items never reach the gate (SC-004). packages/core/test/triage-fanout.test.ts

Implementation

Post-pass gate — collect hedged results, run escalateLayer grouped after the pool drains; the hedge test lives in the shared core, not the backend (FR-006). packages/core/src/triage/fanout.ts

Closes FR-005, FR-006, SC-004.

6 · Phase 3c — US3 · Survive a bad item

Tests (write & fail first)

Failure-isolation test — an injected mid-list failure yields a flagged, gate-routed card for that item and correct cards for every other; N in → N out, no abort (SC-003). packages/core/test/triage-fanout.test.ts

Implementation

Total-function failure handling — classifyItem catches provider/parse errors, returns failed; the engine maps failed to a flagged card routed to the gate (FR-004). packages/core/src/triage/classify.ts

Closes FR-004, SC-003.

7 · Phase 4 — Polish

CLI flags — --concurrency <n> (default 8) and --fanout=chat|subagent threaded into the engine (FR-007). packages/cli/src/commands/triage.ts
Subagent-backend behavioural run — a real multi-item run in subagent mode asserting ordering + isolation, not a structural check (NFR-002, P-7). packages/core/test/triage-fanout.subagent.test.ts
Parity guard + validate — confirm the existing 007 triage tests stay green (single-item byte-for-byte) and spectastic validate is clean. packages/core/test/triage.test.ts
