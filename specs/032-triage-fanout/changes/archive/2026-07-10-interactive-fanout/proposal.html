Add FR-009 — the interactive triage verb fans out

Applied

1 · Intent

FR-001 required concurrent list-intake on "the CLI triage verb and a Claude Workflow / subagent script." Both shipped and are tested. But the interactive slash-command — the in-host /spectastic.triage a user runs in Claude Code — was outside that wording, and its markdown procedure describes a serial loop. So list-intake classified one item at a time in practice (T-001), the exact thing 032 set out to fix, on the most-used path.

2 · Scope

In scope

  • ADD FR-009 (should): interactive list-intake fans out via parallel classifier subagents, with the CLI as the deterministic guarantee.
  • Update commands/spectastic.triage.md's list-intake mode to instruct the parallel dispatch; re-sync .claude/commands.

Out of scope

  • Making the markdown fan-out a guarantee — a skill can't force the model to dispatch subagents (P-8/T-009). The guarantee is the CLI backend, already built; the markdown is a nudge.
  • Re-implementing concurrency — the shared core (triageFanout) already exists; this only routes the interactive path to that behaviour.

3 · Approach

One additive SHOULD delta plus the command-markdown change that realises it. The honest split, per P-8: the deterministic guarantee of concurrent classification is the CLI (spectastic triage --mode list, the already-tested triageFanout); the interactive markdown instructs the model to dispatch one classifier subagent per item (bounded cap), collect, and write cards in input order — the in-host equivalent, best-effort by nature. Serial stays the fallback when subagent dispatch isn't available. No new concurrency code. Adversarial pass did not auto-fire (single should-tier requirement, single topic).

4 · Deltas

What's added: a should-tier requirement bringing the interactive verb into the fan-out.

The interactive /spectastic.triage slash-command SHOULD fan out list-intake — dispatching one classifier per item in parallel (bounded cap) and writing input-ordered cards — rather than classifying serially. Because a slash-command is advisory markdown (P-8, T-009), the deterministic guarantee of concurrency is the CLI backend (FR-001); the interactive fan-out is a best-effort nudge over the same shared classification core.
