What init writes

Withdrawn

1 · Intent

Triage T-026 found that init ships three subagent definitions and installs none. The fix is one line in the bundle walk, and it implements 044 FR-004: "Agent-definition sources MUST be tracked and synced to .claude/agents/, mirroring the commands/ → .claude/commands/ convention." That looked like it needed no proposal. It does, and the regeneration test is why.

FR-002 is the requirement that owns what init writes, and it is exhaustive: "the canonical 16-file lifecycle structure:" followed by a complete list of eight commands, two assets and six templates. Agents are not in it. So an implementer given only the current specs writes sixteen files and no agents — the defect recurs, and two must-tier requirements are in open contradiction: one obliges the sync, the other enumerates a set excluding it.

The enumeration is wrong beyond that. It names plan, renamed to design; it claims two assets against five and six templates against fourteen; and the real scaffold has been 27 files against its 16 since long before this. A requirement listing what ships must be edited whenever anything ships, and nobody edits it. 078 FR-005 was the same shape and was corrected two days ago by removing its list rather than extending it.

SC-001 is worse than stale. It measures the tree byte-identically against "what the Python scripts/spectastic init produces" — a script FR-010 and SC-003 required be deleted at this spec's apply. The criterion has been unsatisfiable since the moment the spec landed, measured against a referent its own siblings removed.

2 · Scope

In scope

  • Removing FR-002's enumeration, so what init writes is the bundle's installed layout rather than a list nobody maintains — and so it stops contradicting 044 FR-004.
  • Re-anchoring SC-001 on a referent that exists, since the one it names was deleted by this spec.
  • The four prose sites repeating "16 files" — §Smallest demoable, §1, US1's acceptance, and the INVEST Testable row. Prose, so no delta can carry them; they land as pre-apply edits, named in §6.

Out of scope

  • Which files the bundle carries. That is prebuild.mjs's decision. Stated carefully after an adversarial pass corrected an earlier draft: prebuild decides what is bundled, the init walk decides what is installed, and they are two deciders — this change makes the second follow the first rather than pretending only one exists. defer-to=never.
  • 004 SC-001's tree count, which moves to 32. A different spec; the kernel folds same-spec deltas only, so it is the sibling propose 2026-08-15-the-tree-grew-by-three, authored alongside this. defer-to=004-npm-publish-workflow.
  • 004 FR-007, which enumerates the bundle as "commands/, assets/, and templates/" and omits agents and the two root manifests. The same defect in a third place, found by the adversarial pass, and deferred rather than reached for. defer-to=TBD-bundle-enumeration.

4 · Deltas

What changes: the enumeration comes out and the bundle's installed layout becomes the referent. The byte-identity guarantee stays and is re-anchored on the repository source rather than the copy.

The subcommand MUST write every file the bundle shipped inside @spectastic/cli designates for installation, at the destination path the bundle declares for it. A verb the bundle designates opt-in MUST NOT be written unless requested. Every written file MUST be byte-identical to its source in this repository.

Rationale

Byte-identity is unchanged and is the half that was never wrong: an installed adapter a reader cannot trust to match its source is worse than none. It is anchored on the repository source rather than "the corresponding path", because in a published package the bundle is the path, and a guarantee that the copy matches itself guarantees nothing.

The enumeration is removed rather than corrected. It named sixteen files — eight commands, two assets, six templates — where the scaffold writes thirty; it named plan, a verb since renamed to design; and it omitted the subagent definitions 044 FR-004 requires be synced, so two must-tier requirements contradicted and an implementer reading this one reproduced the gap (T-026). Correcting the numbers would leave the same requirement one release from wrong again; a list inside a requirement must be edited whenever the thing it lists changes, and it is not.

"Designates for installation" rather than "carries": the bundle holds files it deliberately does not install — two opt-in verbs and two root manifests read at install time. The distinction is the bundle's to draw, which is where it is already drawn.

What changes: the criterion stops measuring against a script this spec deleted, and measures the property that actually matters.

Running spectastic init in an empty temporary directory produces a file tree containing every file the bundle designates for installation, at the declared paths, each byte-identical (modulo trailing-newline normalisation) to its source in this repository, and containing nothing the bundle does not designate.

Rationale

The property is unchanged: a scaffolded project is exactly what the repository ships, with nothing missing and nothing extra.

What changed is the referent. This criterion measured byte-identity against "what the Python scripts/spectastic init produces", and FR-010 and SC-003 require that script be deleted at this spec's apply — so it has been unsatisfiable since the day it landed, measured against something its own siblings removed. Comparison against the repository source is the same guarantee against a referent that exists.

"Containing nothing the bundle does not designate" keeps the exhaustiveness the old count carried. Losing an enumeration should not lose the property that a scaffold has no surprises in it; stating it as a closed set rather than a number is what makes it survive the next file.
