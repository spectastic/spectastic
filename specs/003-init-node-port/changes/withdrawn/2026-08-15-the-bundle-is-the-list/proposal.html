Change proposal · 003-init-node-port

The bundle is the list

A requirement that enumerates what ships has to be edited every time anything ships. This one stopped being edited.

Status Withdrawn Change ID 2026-08-15-the-bundle-is-the-list Spec 003-init-node-port Author Brian Corbin · @briancorbinxyz Created 15 Aug 2026 Targets 1 requirement — 1 modified Read time

FR-002 enumerates what init writes — "the canonical 16-file lifecycle structure", naming eight commands, two assets and six templates. It ships 27: eight commands, five assets, fourteen templates, and one of the eight named commands is plan, a verb renamed to design. The enumeration is the defect, not the numbers, so it comes out — the bundle becomes the source of truth and the requirement describes the relationship instead of the contents.

The bundle is the list

Withdrawn

1 · Intent

Triage meta-spec T-026 found that init ships three subagent definitions and installs none of them, so every downstream project has run /spectastic.propose with no spectastic-critic — the adversarial pass silently absent. The obvious fix is a one-line widening of the bundle walk. It was written and reverted, because nothing requires init to install them: 044 FR-004 obliges the definitions to exist and declare model pins, not to ship. Adding the behaviour by patch would be the tool acquiring a capability nobody specified.

Reading the requirement that does own what init writes turned a small omission into a larger one. FR-002 enumerates: "the canonical 16-file lifecycle structure: eight slash-command files … two asset files … six template files." Against the shipped bundle it is wrong four ways — five assets, fourteen templates, a 27-file total, and one of the eight commands it names is plan, which was renamed to design and no longer exists. A must-tier requirement has been describing a scaffold that stopped existing some time ago.

The estate has met this exact defect before and solved it two days ago. 078 FR-005 enumerated the resource kinds, went one short when a sibling spec added unit, and was corrected by removing the enumeration rather than extending it — because a list inside a requirement must be edited every time the thing it lists changes, and nobody edits it. This is the same requirement shape with the same failure, one spec over.

So the enumeration comes out and the bundle becomes what the requirement points at. That also settles T-026 without deciding it separately: what init installs is what the bundle carries, so the question moves to the bundle's own contents — which is where prebuild.mjs already decides it, and where the agents already are.

2 · Scope

In scope

  • Removing the file enumeration from FR-002, so what init writes is the bundle's contents rather than a list a requirement has to keep current.
  • Keeping the byte-identity guarantee, which is the part of FR-002 that has never been wrong and is what makes an installed file trustworthy.
  • Settling T-026 as a consequence: the agents install because they are bundled, and what is bundled stays the build's decision.

Out of scope

  • Deciding which files belong in the bundle. That is prebuild.mjs's job and this requirement should not re-litigate it — the whole point is that one place decides. defer-to=never.
  • 004 SC-001's "29-file tree", which becomes 32 once the agents install. A different spec, and the apply kernel folds same-spec deltas only, so it needs a sibling propose sequenced with this one. defer-to=004-npm-publish-workflow.
  • The extended verbs. explain and explore are bundled and deliberately not installed by default (--with), which is existing behaviour this change must not disturb — hence "the files it installs by default" rather than "everything bundled". defer-to=never.

4 · Deltas

What changes: the enumeration comes out. The byte-identity guarantee stays, and the default install set is described by its relationship to the bundle rather than listed.

The subcommand MUST write the lifecycle scaffold carried in the bundle shipped inside @spectastic/cli, at the destination layout the bundle declares, excluding any file marked as an opt-in extended verb. Every written file MUST be byte-identical to the file shipping in this repository at the corresponding source path.

Rationale

Byte-identity is unchanged and is the half that has never been wrong: an installed adapter a reader cannot trust to match its source is worse than no adapter.

The enumeration is removed rather than corrected. It named "the canonical 16-file lifecycle structure" with eight commands, two assets and six templates; the bundle ships eight commands, five assets and fourteen templates, and one of the eight it named is plan — a verb since renamed to design. Correcting the numbers would put the same requirement one release from being wrong again, because a list inside a requirement has to be edited every time the thing it lists changes and nobody edits it. 078 FR-005 is the same defect with the same fix, two days old.

"Excluding any file marked as an opt-in extended verb" preserves behaviour rather than adding a rule: explain and explore are bundled and install only under --with. Without that clause this requirement would oblige installing them and quietly change what a default scaffold contains.

A deliberate consequence, and the reason this was written: what init installs is now whatever the bundle carries, so the three subagent definitions bundled since 044 install rather than shipping and being dropped (meta-spec T-026). The question of what belongs in the bundle stays with the build that assembles it, which is the single place it was always decided.

None outstanding.
