Cards

Six files are written after the atomic two-pass, and after the summary that counts them

Implementation code

Debugging SC-001's definition of the scaffold tree, root cause was implementation drift: registerInit performs six writes after executeWrites and after printSummary, so they skip the conflict scan FR-008 requires and are absent from the count the summary prints; fixed by moving them into the plan or by scoping FR-008 to exclude them; regeneration passes — the spec is right and the code drifted.

Expected
Every destination is scanned for conflicts and prompted for in a first pass; only then does any write happen (FR-008), and a pre-existing file at any destination prompts (FR-003). The summary reports what was written.
Actual
packages/cli/src/commands/init.ts:267-304 calls executeWrites(plan) then printSummary(summary), and then writes six more times — writeMarker, applyGitignore, writeProjectConfig, writeSchemaReference, writeCorpusConfig, and the --tools path. None is in the plan, so none is scanned or prompted: applyGitignore appends to an existing .gitignore and setIfAbsent merges into an existing spectastic.json, both silently. The summary is printed before all six, so it undercounts its own run.
Diagnosis
The plan/execute split was built for bundle files and every later feature that needed to write something — 043's gitignore, 063's corpus config, 067's project identity, 087's schema reference — appended after it rather than joining it, each individually reasonable and cumulatively a second unguarded write path. It is not a spec gap: FR-008 already says what should happen, in the words that describe what does not.
Fix
packages/cli/src/commands/init.ts — either fold the six into the plan so one pass governs every destination, or amend FR-008 to scope "the file set" to installed files and say generated config is merged rather than written. The first preserves the guarantee; the second records that it was never claimed for these. Not decidable from the code — it turns on whether prompting to overwrite a .gitignore the tool only appends to is a feature or a nuisance, which is an author's call. Move printSummary after the writes either way; that half has no argument on the other side.
Deep dive — scope-deferred functionality exposed

Surfaced while drafting 2026-08-15-init-installs-the-bundle, whose first draft named .gitignore and spectastic.json in SC-001's definition of the output tree. The adversarial pass observed that doing so makes them part of "the file set" and breaches FR-008 by construction. That draft was rewritten to stop enumerating the tree, which removed the contradiction from the proposal without touching the behaviour underneath — so the defect is filed here rather than absorbed into a proposal about something else.

No cross-spec contract and no invariant. Worth noting that both candidate fixes are cheap and the choice between them is the whole cost.
