Design · 058-corpus-licensing

Corpus licensing

One folded validate rule that classifies a declared license against a permissive allowlist — surfacing everything else, never adjudicating any of it — plus a written policy that names the escape hatch.

Status Accepted Spec 058-corpus-licensing Owner Brian Corbin · @briancorbinxyz Branch main Created 25 Jul 2026 Read time

Add a corpus-license folded validate scan — corpusLicenseFindings(packs) in core, scanCorpusLicense in the CLI — that classifies each document's declared license against a maintained permissive allowlist (SPDX-style): a permissive id is silent; a restrictive one, an unrecognised one, or a TODO warns, so committing paywalled/vendored material is a decision on the record (FR-002). The missing-license case (FR-001) is already met — more strictly — by 051's existing error, so the rule adds no redundant missing-license code. The redistribution policy (FR-003/FR-004) lands as a README section naming by-reference (MCP bridge / origin-url only) as the escape hatch, with the restrictive KB-002 worked example described there and exercised as a test fixture — so the repo's own validate baseline stays clean. Biggest risk: overclaiming legal effect; mitigated by NFR-001's recorded ceiling — the rule flags a declared license, never adjudicates compatibility.

4 · Approach

One rule, one policy. corpusLicenseFindings(packs) walks every loaded corpus document and classifies its provenance.license against a maintained permissive allowlist of SPDX-style identifiers. The classification is deliberately conservative (D-003): a license on the allowlist is silent; anything else — a known-restrictive id, an id the allowlist doesn't carry, or a placeholder like TODO — emits a corpus-license warning, so an unrecognised license is never silently waved through as permissive. The rule reads only the declared string; it never infers a license from content and never asserts legal compatibility (NFR-001, the recorded ceiling). A thin scanCorpusLicense(cwd) folds it into validate, a no-op with no corpus.

What the rule does not do: re-check a missing license. 051 already errors on that (a missing required provenance field), which is strictly louder than the spec's "warn" — so FR-001/SC-002 are met by the existing error, and adding a redundant missing-license warning would only double-report (D-002). The redistribution policy (FR-003/FR-004) is a README section: what may be committed in-repo, what must be held by reference, and the sanctioned by-reference escape hatch (an MCP bridge, or keeping only the origin-url) for material that cannot be redistributed — with the deliberately-restrictive KB-002 described as the worked example. That example is exercised as a red-first test fixture, so the signal is proven without shipping a warning into the repo's own baseline (D-004).

5 · Alternatives considered

OptionNever-silent-unknownNo overclaim (NFR-001)ReuseTotal
A full SPDX license-compatibility engine (adjudicate legal effect)4116
A restrictive blocklist (warn on listed; everything else silent)1449
A permissive allowlist: silent only if listed; restrictive / unknown / placeholder warn55515

A compatibility engine is precisely what NFR-001 forbids — the tool does not adjudicate legal effect. A restrictive blocklist fails the §2 edge case: an unrecognised license would silently pass as permissive, exactly the silent liability this spec exists to prevent. A permissive allowlist is conservative by construction — the burden is on a license being known-safe to go silent — and reuses 053's folded-scan pattern wholesale.

6 · Decisions

D-001 · A corpus-license folded validate scan, mirroring 053's gates

Status
Accepted
Context
scanCorpusGrounding (validate.ts:251) is the established shape for a corpus filesystem check — a thin CLI scan lazy-importing a pure core finding-fn, a no-op on an empty corpus.
Decision
Add corpusLicenseFindings(packs) to @spectastic/core/knowledge and scanCorpusLicense(cwd) to validate.ts, folded into the findings pipeline. Warning severity (FR-002).
Consequences
+ Reuses a proven, tested pattern; unit-testable in-process. + Runs on every validate; no-op with no corpus. − One more folded scan (bounded, no-op when absent).

D-002 · FR-001 (missing license) is met by 051's existing error — no redundant check

Status
Accepted
Context
051's corpusWellFormedFindings already reports a missing license as an error (validate.ts:24, REQUIRED_PROVENANCE_FIELDS includes license) — strictly louder than the spec's "warn".
Decision
The corpus-license rule owns only FR-002 (restrictive / unrecognised / placeholder → warn). FR-001/SC-002 are satisfied by 051's error; SC-002's test asserts a missing-license document produces a finding (the 051 error), not a second warning.
Consequences
+ No double-reporting; the requirement is met more strictly. + One rule, one clear meaning ("this license is restrictive/unknown"). − A reader expecting SC-002's literal "warning" sees an error instead — a deliberate strengthening, recorded here and in the §9 assumption.

D-003 · Classify by a permissive SPDX allowlist; everything else warns

Status
Accepted
Context
The §2 edge case requires an unrecognised license to be "treated conservatively (warn to declare intent), never silently passed as permissive"; the §6 assumption names SPDX-style ids as the classification vocabulary.
Decision
A maintained allowlist of permissive SPDX ids (MIT, Apache-2.0, BSD-2/3-Clause, CC0-1.0, CC-BY-*, ISC, Unlicense, 0BSD, public-domain) → silent. Everything else — known-restrictive, unrecognised, or a placeholder like TODO — warns. Matched by exact id, case-insensitive.
Consequences
+ Conservative: the burden is on a license being known-safe to go silent. + A newly-adapted license: TODO doc (056) correctly warns to declare intent. − The allowlist needs occasional maintenance as SPDX evolves; a false-warn on a genuinely-permissive id not yet listed is a cheap fix (add the id), never a silent miss.

D-004 · The restrictive worked example is a test fixture + a README description

Status
Accepted
Context
No such restrictive document ships today (the spec's deliberately-restrictive worked example is net-new); both shipped docs are permissive (baseline 0 errors, 309 warnings). A restrictive doc in the marketplace-listed finance-settlement pack (057) would contradict its distributability.
Decision
The rule's red-first test writes a temp corpus with a deliberately-restrictive document; the worked example is described in the README redistribution policy. No restrictive document is shipped into the repo's own corpus.
Consequences
+ The repo baseline stays clean (unchanged warning count); the signal is still proven end-to-end in a test. − The worked example is described rather than live-shipped — acceptable, and it avoids a standing self-warning a reviewer would have to be told is intentional.

D-005 · The redistribution policy is a README corpus section

Status
Accepted
Context
The README already carries the corpus family's prose (051–057); FR-003/FR-004 ask for a written policy the convention "carries".
Decision
Add a redistribution-policy section to the README's corpus family: what may be committed in-repo, what must be by-reference, and the sanctioned escape hatch (MCP bridge, or origin-url-only), with the restrictive worked example.
Consequences
+ Co-located with the rest of the corpus story a reader already follows. − A README section is less a standalone reference doc than a dedicated docs/ page — acceptable for a SHOULD, and the family's other prose lives here too.

D-006 · TDD, tests written red-first

Status
Accepted
Context
The rule is deterministic core: a document with a given license in, a finding (or none) out. Every SC is cheaply assertable first, mirroring 053's gate tests.
Decision
Write the failing unit tests before corpusLicenseFindings: a restrictive license warns, a permissive one is silent, an unrecognised/TODO one warns.
Consequences
+ Both MUSTs (FR-002/NFR-001-via-behaviour) get red-first coverage. − None material for a classification rule.

9 · Complexity tracking

Anywhere this plan introduces complexity not strictly required by the spec, justify it here.
