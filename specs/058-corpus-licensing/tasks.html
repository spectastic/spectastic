Corpus licensing

Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 058-corpus-licensing Design design Branch main Created 25 Jul 2026 Read time

11 tasks across five phases. Setup → Foundational → User stories (US1·US2·US3) → Polish. Tasks marked [P] can run in parallel — different files, no dependency. US2 deliberately carries no implementation task — the missing-license case is already met, more strictly, by 051's existing error (D-002).

1 · Execution strategy

Implement US1 end-to-end — the corpus-license rule itself, the only genuinely new code. Ship. US2 (a proving test against existing behavior) and US3 (the written policy) follow.

Setup → Foundational → US1 → US2 → US3 → Polish. Each story closes its conformance before the next opens.

Not applicable at this size — one classification function, one folded scan, and a README section. Use MVP-first or Incremental.

2 · Phase 1 — Setup

Scaffold the new core test file — imports and a fixture writer for a temp corpus pack with a given license; no assertions yet. packages/core/test/knowledge.license.test.ts

3 · Phase 2 — Foundational

The permissive allowlist both this rule's warning path and its silent path key on.

Implement the permissive-license allowlist + classifier — SPDX-style ids (MIT, Apache-2.0, BSD-2/3-Clause, CC0-1.0, CC-BY-*, ISC, Unlicense, 0BSD, public-domain), matched case-insensitively; anything else classifies as not-permissive (D-003). packages/core/src/knowledge/license.ts

4 · Phase 3a — US1 · A restrictive license is loud

Tests (write & fail first)

Test restrictive warns, permissive is silent — a document declaring a known-restrictive license produces a corpus-license warning; one declaring MIT/CC0/etc. produces none. packages/core/test/knowledge.license.test.ts
Test an unrecognised or placeholder license warns — an id absent from the allowlist, and the literal TODO (056's own not-yet-filled marker), both warn — never silently treated as permissive. packages/core/test/knowledge.license.test.ts
Test the finding wording stays descriptive, never adjudicative — the message names the declared license and that it restricts/is unrecognised; it never claims incompatibility or legal effect (NFR-001's recorded ceiling). packages/core/test/knowledge.license.test.ts

Implementation

Implement corpusLicenseFindings — classify every loaded document's declared license; emit one corpus-license warning per non-permissive one. packages/core/src/knowledge/license.ts
Fold scanCorpusLicense into validate — mirrors scanCorpusGrounding's shape; a no-op with no corpus. packages/cli/src/commands/validate.ts

Closes FR-002, SC-001, NFR-001.

5 · Phase 3b — US2 · Every document declares a license

No implementation task — 051's corpusWellFormedFindings already errors on a missing license (a required provenance field), which is strictly louder than this story's "warn" (plan D-002). The task here only proves that's still true; there is nothing new to build.

Tests

Test a missing license produces a finding — a document with no license field in its provenance produces a corpus-well-formed error (051's existing behavior) — confirming FR-001/SC-002 are already met, no corpus-license duplicate needed. packages/core/test/knowledge.license.test.ts

Closes FR-001, SC-002 — via 051's existing error, per plan D-002.

6 · Phase 3c — US3 · A written redistribution policy with an escape hatch

Tests (write & fail first)

Test the README carries the redistribution policy — a structural presence check (the CLAUDE.md-endorsed "cheap backstop" pattern): the README names what may be committed in-repo, what must be by-reference, and the MCP-bridge / origin-url-only escape hatch. packages/core/test/knowledge.license.test.ts

Implementation

Write the redistribution policy README section — what may be committed vs. held by reference, the sanctioned escape hatch, and the deliberately-restrictive worked example (D-004) described (not shipped). README.md

Closes FR-003, FR-004, SC-003.

7 · Phase 4 — Polish

Run the full safety-net verification — the whole vitest + tsc suite, plus a corpus-wide spectastic validate, confirming the baseline stays at zero errors / the same warning count (the rule is a no-op on both shipped, permissively-licensed documents). (repo-wide)
