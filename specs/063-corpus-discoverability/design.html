Corpus discoverability

4 · Approach

Five moving parts, each mirroring an existing one. (1) Config — a config/corpus.ts reader (mirrors config/models.ts) resolving corpus.marketplace (canonical) and corpus.root, with corpus.namespace a deprecated read-alias; init gains the first spectastic.json writer, a create-or-merge that preserves existing sections. (2) Manifest render — renderMarketplaceManifest beside the existing reader, deriving plugins[] from the registry + each pack's SKILL.md. (3) Sync — one syncMarketplaceManifest(root, config) in a new knowledge/publish.ts, non-destructive (hand-edited cells survive), called after every registry write and by publish. (4) publish — a corpus publish subcommand that runs the sync for a corpus missing (or refreshing) a manifest. (5) Portability exemption — packFindings reads a pack's SKILL.md tool-specific: true and returns early, sparing the pack.

5 · Alternatives considered

Option (portability collision)Keeps hard guaranteeExplicit intentSimplicityTotal
Demote pack-not-portable to a warning0134
Only distributable-marked packs get checked2226
Self-declared tool-specific exemption3328

Demoting to a warning loses the guarantee that a genuinely-published domain pack is portable. A distributable-flag inverts the default (everything checked unless opted out) — safer, but noisier and less honest than a pack naming what it actually is. The self-declaration (spec's chosen resolution) keeps the hard check for every portable-claiming pack and only spares a pack that says "my domain is this tool".

6 · Decisions

D-001 · Render + sync the manifest in the fat core, mirroring the registry format

Status
Accepted
Context
The reader already lives in pack-agnostic.ts:156 (readMarketplaceManifest); the registry has parse+render+merge precedents (index-format.ts:110,150). A cross-cutting deterministic generator belongs in core (fat-core/thin-CLI).
Decision
Add renderMarketplaceManifest beside the reader and a syncMarketplaceManifest(root, config) in a new knowledge/publish.ts; derive plugins[] from index.md + each pack's SKILL.md, merge non-destructively over an existing manifest.
Consequences
+ Reuses the proven render/merge shape; + one sync fn, many callers; + no new tsup entry — the new module barrel-exports through the existing single ./knowledge entry, per knowledge/index.ts's own documented convention (corrected at T-002; the original draft assumed a separate subpath mirroring providers/pack-fetcher.ts, which is a different directory with its own real/stub-seam reason for a dedicated entry). − One more file added to an already-large barrel.

D-002 · Corpus config + the first init-writes-spectastic.json path

Status
Accepted
Context
init today only computes projectName: basename(cwd) (init.ts:274) and never emits spectastic.json; config is read section-by-section (config/models.ts). The repo's spectastic.json holds only a hand-authored git section.
Decision
A config/corpus.ts reader mirrors config/models.ts; init gains a create-or-merge writer that adds a corpus section (marketplace = basename(cwd), root = knowledge) preserving any existing section.
Consequences
+ First-class corpus config with one source of truth; + non-destructive to a hand-authored file. − init now writes a config file it previously never touched — must not clobber (tested against a git-only file).

D-003 · corpus.marketplace canonical; corpus.namespace a deprecated read-alias

Status
Accepted
Context
061's corpus.namespace is unbuilt (061/tasks.html Phase 8 unchecked), so nothing ships that this breaks; FR-006 wants one identity.
Decision
corpus.marketplace is the canonical key (manifest name + local-import namespace); corpus.namespace, if present, resolves to it via the reader (deprecated alias, never an independent value). 061's Phase 8 import tasks read corpus.marketplace when they drain.
Consequences
+ No throwaway key churn; + back-compat for anyone who already set corpus.namespace. − Two key names to document until the alias is removed.

D-004 · Tool-specific self-declaration in SKILL.md frontmatter

Status
Accepted
Context
pack-not-portable scans a pack's files via packFindings (pack-agnostic.ts); a pack's SKILL.md is the pack-local, travels-with-the-pack home for a self-declaration.
Decision
A pack sets tool-specific: true in its SKILL.md frontmatter; packFindings reads it and returns early (no portability findings), while a pack without it still gets the hard check. The 057 spec-text amendment is a separate MODIFY propose (out of scope here).
Consequences
+ Explicit, machine-readable, pack-local; + narrows the rule by declaration not blanket (P-9). − The 057 spec text lags the code until its propose lands.

D-005 · Red-first vitest with a manifest-sync fixture

Status
Accepted
Context
Test-style preference; matches the corpus family's convention. No external fact.
Decision
Failing tests first: init writes the config; publish renders a synced manifest; a registry write re-syncs it; pack-not-portable spares a tool-specific fixture pack; re-publish is idempotent. Deterministic, no network.
Consequences
+ Pins the sync + exemption before the edit; + CI-safe. − A bespoke tool-specific + hand-edited-manifest fixture.
