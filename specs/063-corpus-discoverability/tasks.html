25 tasks across five phases. Setup → Foundational (corpus config) → US1 (init writes it) · US2 (synced manifest + publish) · US3 (portability exemption + the meta-repo's own dogfood + the two cross-spec proposes) → Polish. Tasks marked [P] touch a distinct file with no in-flight dependency.

1 · Execution strategy

US1 alone (config at init) is a viable slice — every downstream part reads corpus.marketplace/root, so landing it first de-risks everything after. Then US2, then US3.

Setup → Foundational → US1 → US2 → US3 → Polish. The recommended path — US2's sync needs US1's config resolver, and US3's dogfood needs US2's publish to exist.

Not a fit for US1→US2→US3 (genuinely ordered by dependency), but US3's portability-exemption code (T-300/T-310) is independent of US1/US2 and could run alongside them if staffed.

4 · Phase 3a — US1 · Configure the corpus at init

Tests (write & fail first)

Red test: config resolution — asserts corpus.marketplace/root resolve with defaults absent, an explicit value wins, and a legacy corpus.namespace resolves as marketplace when marketplace itself is unset. packages/cli/test/config-corpus.test.ts
Red test: init writes the corpus section — asserts a fresh spectastic init writes corpus.marketplace = the repo directory name and corpus.root = knowledge, and that an existing hand-authored spectastic.json (e.g. a git-only file) keeps its other sections untouched. packages/cli/test/init/corpus-config.test.ts

Implementation

Implement init's create-or-merge corpus-section writer — reads any existing spectastic.json, adds/preserves the corpus section using the T-010 defaults, and writes it back; a project with no spectastic.json gets one created. Makes T-100/T-101 green. packages/cli/src/commands/init.ts

Verification

Verify SC-001 end to end — run the built CLI's spectastic init in a fresh temp directory and assert the resulting spectastic.json carries the expected corpus section. packages/cli/test/init/corpus-config.test.ts

Closes FR-001, FR-006 (the config half); SC-001. The other half of SC-004 — a marketplace-less local corpus import actually filing under corpus.marketplace at the CLI — depends on 061's own Phase 8 draining against this config reader; that drain is a separate spec's tasks, tracked as a cross-spec follow-on, not fabricated here.

5 · Phase 3b — US2 · A corpus carries a synced marketplace.json

Tests (write & fail first)

Red test: manifest render, no fabrication — asserts renderMarketplaceManifest derives one plugins[] entry per registry row, with description read from the pack's SKILL.md (never invented) and falling back — never erroring — when absent. packages/core/test/knowledge.publish.test.ts
Red test: sync is non-destructive and idempotent — a hand-edited owner/description survives a re-sync, and re-running sync against an already-in-sync manifest produces byte-identical output (NFR-001). packages/core/test/knowledge.publish.test.ts
Red test: corpus publish subcommand — generates a missing marketplace.json for a fixture corpus and exits 0; a second run changes nothing. packages/cli/test/corpus-publish.test.ts

Implementation

Implement renderMarketplaceManifest — beside the existing readMarketplaceManifest, derives the manifest shape from a corpus.marketplace name plus the root registry + each pack's SKILL.md. Makes T-200 green. packages/core/src/knowledge/pack-agnostic.ts
Implement syncMarketplaceManifest + publishCorpus — the non-destructive merge (existing hand-edited cells win, mirroring mergeRegistryRows) and the idempotent write. Makes T-201 green. packages/core/src/knowledge/publish.ts
Wire the sync into every registry-writing path — installPack and registerDocument call syncMarketplaceManifest after writing the registry, so marketplace.json never drifts from index.md (FR-003). packages/core/src/knowledge/ingest.ts
Add the corpus publish subcommand — a new corpus publish CLI command calling publishCorpus against the resolved corpus.root. Makes T-202 green. packages/cli/src/commands/corpus.ts

Verification

Verify SC-003 end to end — register a new pack via corpus import and assert marketplace.json now lists it, matching index.md, with no manual edit; a follow-up corpus publish changes nothing. packages/cli/test/corpus-import.test.ts

Closes FR-002, FR-003, FR-004, NFR-001, NFR-002; SC-003.
