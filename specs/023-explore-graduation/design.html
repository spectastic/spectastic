Design · 023-explore-graduation

explore --graduate — the back half of the loop

How we will build it.

Status Accepted Spec 023-explore-graduation Owner Brian Corbin · @briancorbinxyz Branch main Created 26 Jun 2026 Read time

Graduation is an AI-coupled extract leg (read the build + its run record into a Draft spec + plan, the run's proven facts seeded as verified rows in the plan's §3 evidence ledger) feeding a pure deterministic transaction kernel (flip the quarantine marker to graduated, archive the exploration). Extract runs first; the irreversible transaction runs last with the quarantine-lift as the final write — apply's fold-before-rename atomicity, so a failure leaves the exploration quarantined and refusable. Biggest risk: the extract reading a build into honest requirements — bounded by seeding from the real run record, the full-rigor gates downstream, and stub-provider tests.

4 · Approach

Two legs, in the established house shapes. Extract (AI-coupled, the spec/plan pattern): the explorer classifies (spike | tracer-bullet), then the build and its captured run record are read into a Draft specs/<id>/spec.html — the demonstrated behaviour becomes stories/requirements/SC and plan decisions, the run's proven facts become verified rows in the plan's §3 evidence ledger, and what the build never answered is interviewed exactly as a cold /spectastic.spec + /spectastic.design would (reusing both re-entry interviews, D-007). Transaction (pure deterministic kernel, the explore/apply pattern): given the written spec + plan + the classification, it archives explorations/<id>/ → explorations/archive/<id>/ (deepening the ledger's relative paths) and flips the marker quarantined → graduated with the classify stamp. (The restore-task generation, former D-006, split to TBD-explore-restore.)

The quarantine-lift is the last write — the point of no return for shippability. Everything fallible (the AI extract, the spec/tasks writes, the archive move) happens before it, so a failure leaves the id still refused (the gate + validate still bite). On failure a best-effort rollback removes a partial specs/<id>/ so a retry is clean (it would otherwise be refused by FR-003). This is the all-or-nothing guarantee of NFR-001 / SC-003.

6 · Decisions

D-001 · --graduate <id> is a mode of the explore command

Status
Accepted
Context
FR-001 mandates a mode, not a new verb; explore is already an extended verb (commands.json) with a single .command('explore') registration (packages/cli/src/commands/explore.ts:15-57).
Decision
Add .option('--graduate <id>') and relax the positional to [intent]; the action requires exactly one of intent (scaffold) or --graduate (graduate) and branches accordingly.
Consequences
+ One loop under one verb, no new packaging seam, installs with --with explore. − The command action gains a mode branch.

D-002 · Two legs: AI-coupled extract + a pure transaction kernel

Status
Accepted
Context
The explore kernel is pure — CLI owns fs/date/id (packages/core/src/commands/explore.ts:1-19); the extract reads a build into requirements, so it is AI-coupled like spec/plan.
Decision
A pure graduateTransaction kernel (marker flip, archive plan, ledger path-deepen, classify record) in @spectastic/core; the extract leg runs as in-host Claude (slash) or via an injected AIProvider (CLI).
Consequences
+ The irreversible/deterministic core is unit-testable without an LLM (the apply.fold pattern). − Two code paths for the AI leg — the established house pattern for every AI-coupled verb.

D-003 · All-or-nothing: extract + writes first, quarantine-lift last

Status
Accepted
Context
NFR-001 / SC-003 forbid a half-graduated, silently-shippable state; apply sets the precedent (foldProposalTasks before fs.rename, this session).
Decision
Order the fs commits so the marker-flip (the point that un-refuses the id) is the last write: extract → write spec.html + seeded tasks.html → archive move → flip marker. On any prior failure, a best-effort rollback removes a partial specs/<id>/ so retry is clean.
Consequences
+ No silent-ship window — a failure leaves the id quarantined and refusable. − FS rollback is best-effort, not transactional (the residual: a crash between the archive move and the flip, narrowed by their adjacency); accepted in §9.

D-004 · Evolve the marker; the gate and validate need no change

Status
Accepted
Context
gateOnQuarantine (state-gate.ts:75) and quarantineFinding (explore.ts:113) both return null for any status !== 'quarantined'.
Decision
Widen QuarantineMarker.status to 'quarantined' | 'graduated' and add classify?: 'spike' | 'tracer-bullet' and graduated?: string (date). The marker stays in explorations/archive/<id>/, frozen.
Consequences
+ Zero change to the gate/validate logic — they are already status-generic. − The shared marker type widens; exploreScaffold keeps writing the 'quarantined' literal.

D-005 · Lift deepenArchivePaths into a shared util

Status
Accepted
Context
The archived ledger sits one level deeper, so its ../-relative links need +1 ../ — exactly what apply.ts's deepenArchivePaths already does.
Decision
Extract deepenArchivePaths from apply.ts into packages/core/src/archive-paths.ts and import it from both apply and graduate.
Consequences
+ One path-deepen implementation, tested once. − A small, mechanical refactor of apply.ts (covered by the existing apply tests).

D-006 · Restore tasks via the seeded /tasks flow (superseded — moved to TBD-explore-restore)

Status
Superseded
Context
This decision owned the restore-task generation (US2 / former FR-005) — tracer-bullet → refactor-to-comply, spike → clean-rebuild with the prototype marked for deletion, via the seeded /tasks flow.
Decision
US2 (restore-scaffold) was split to the sibling slice TBD-explore-restore when 023's budget went red (the spec's INVEST·Small trigger). This decision, and the §5 alternatives that informed it, move to that slice's plan. 023's graduation now produces spec + plan; the restore tasks are the sibling's concern.
Consequences
+ 023 stays within budget and scope (extract + lift/archive). − The restore-task design must be re-decided in TBD-explore-restore; §5 below is retained as the historical reasoning that fed it.

D-007 · Extract reuses the /spec + /plan re-entry interviews

Status
Accepted
Context
FR-003 says interview the gaps "exactly as a cold /spectastic.spec + /spectastic.design would"; both already have re-entry interview modes, and the evidence ledger is a plan artifact (REQ-LIFECYCLE-006).
Decision
The graduate flow seeds the /spec and /plan interviews with the build's demonstrated behaviour + the run record — the run's proven facts becoming verified rows in the plan's §3 evidence ledger — rather than forking new interviews.
Consequences
+ One interview implementation per artifact, consistent decision discipline. − Graduate's markdown must thread the run record into the plan interview as grounding input.

D-008 · Kernel-first TDD + a failure-injection test

Status
Accepted
Context
The deterministic transaction is the risk surface for SC-003; a pure-judgment test-style choice, no external fact (n-a).
Decision
Unit-test graduateTransaction (marker flip, archive plan, path-deepen, classify) like apply.fold.test.ts; add a failure-injection test asserting the post-failure invariant (marker still quarantined, no specs/<id>/); stub-AIProvider test for extract; one CLI integration test.
Consequences
+ The atomicity guarantee is directly tested, not assumed. − The AI extract's quality is only stub-tested — accepted as the Medium risk (§8).

9 · Complexity tracking

Anywhere this plan introduces complexity not strictly required by the spec, justify it here.

The AI leg has two code paths (in-host Claude for the slash command, an injected AIProvider for the CLI). This duplication is accepted: it is the established house pattern for every AI-coupled verb (spec, plan), and the slash path is keyless while the CLI path is the deterministic-dispatch escape hatch (006 FR-009).

FS rollback is best-effort, not transactional. Accepted because the property that actually matters (NFR-001) is "no silent-ship window," which the marker-flip-last ordering guarantees — a crash can at worst leave a partial specs/<id>/ while the id stays quarantined and refusable, and the cleanup-on-failure path keeps retry clean.
