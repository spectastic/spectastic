Specification · 023-explore-graduation

explore --graduate — the back half of the loop

The graduation half of explore: explore --graduate <id> classifies a quarantined build, extracts a real spec from it with the run as verified grounding, restores every relaxed gate, lifts the quarantine, and archives the exploration as discovered-not-guessed history.

022-explore shipped the front half — scaffold a quarantined build and refuse to ship it. This slice ships the back half: graduation. As an opt-in mode of the same verb, explore --graduate <id> runs three steps — classify (spike or tracer-bullet, recorded immutably), extract (read the build into a Draft spec + plan, seed the run's proven facts as verified grounding in the plan, interview what the build never answered), and restore (turn every relaxed gate back on; the path-appropriate rebuild/refactor task scaffolding is the sibling slice TBD-explore-restore) — then lifts the quarantine and archives the exploration. The deterministic legs are atomic; only the extract is AI-coupled. This is what makes 022's anti-ship guard safe — nothing is forbidden, because everything can graduate.

1 · Context

022-explore made half a promise: build to learn in a quarantined tree the core verbs and validate refuse to advance. It deferred the bridge back. Today a quarantined exploration has two exits — delete or graduate — and graduate doesn't exist, so every build-to-learn that worked is stranded.

The brief (explore-considerations.html §4) settles the shape: classify → extract → restore. The Pragmatic-Programmer taxonomy is the hinge — a spike is throwaway (keep the learning, rebuild clean); a tracer-bullet is a usable skeleton (keep the code, back-fill the spec, harden in place). The explorer classifies on the artifact, not a rule. The build's demonstrated behaviour is then read into a spec + plan, the facts it proved enter the plan's evidence ledger as verified, and every gate relaxed during explore comes back on. Stakeholders: explorers (whose working build must become a real spec without re-derivation) and reviewers (who must trust graduation is the only bridge and can't be gamed).

2 · User scenarios & testing

Each story MUST be independently testable. Both are P1 — discovery (US1 extract) and commit (US3 lift/archive); the restore-task scaffolding split to sibling slice TBD-explore-restore (see the note below). Each verifies alone.

US1 · Extract a spec from the build P1

As an explorer, I want graduation to read my build into a real spec with the run as verified grounding so that the discovery I already proved becomes the spec's evidence, not a fresh guess.

Acceptance: explore --graduate <id> writes a Draft specs/<id>/ bundle (spec.html + plan.html, reusing the id) whose stories, requirements, SC, and plan decisions are drawn from the build's behaviour; the run's proven facts appear as verified rows in the plan's evidence ledger, no re-capture; and the gaps — intent, quantified NFRs, edge cases — are interviewed as a cold /spectastic.spec + /spectastic.plan would.

A former US2 · Restore the gates with a path-appropriate plan (the restore-task generation — refactor-to-comply for a tracer-bullet, clean-rebuild for a spike) was split to the sibling slice TBD-explore-restore when this spec's budget went red (the INVEST·Small trigger). 023 graduates a build into a verified-grounded spec + plan; TBD-explore-restore scaffolds the rebuild.

US3 · Lift, archive, and record immutably P1

As a reviewer, I want graduation to clear the quarantine, archive the exploration, and record the classification where it can't be quietly reversed so that the lifecycle accepts the id while the discovered-not-guessed history stays provable.

Acceptance: on success the marker flips quarantined → graduated (the verbs and validate stop refusing the id); explorations/<id>/ moves to explorations/archive/<id>/, frozen, recording classify=spike|tracer; and the plan's evidence ledger cites that archived source — so reversing the classification means editing a frozen archived artifact.

Edge cases

  • Build never run — the run record is empty; graduation proceeds but seeds no verified facts (grounding stays assumed).
  • Extraction fails partway — nothing is committed: quarantine stays in force, no specs/<id>/ is left, the exploration stays put (NFR-001).
  • --graduate on an id with no quarantined exploration — refused; nothing to graduate.
  • specs/<id>/ already exists — refuse and report; graduation never overwrites a live spec.
  • Reversing a graduation — out of scope (§3); re-enter the resulting spec through the normal lifecycle instead.

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional

Graduation MUST be an opt-in mode of the extended explore verb — explore --graduate <id> — operating on an existing quarantined exploration; it MUST NOT be a new core verb nor a fresh-start command — the back-half partner to explore <intent>, one loop under one verb.

Graduation MUST require an explicit spike | tracer-bullet classification, captured before extraction, and that classification MUST decide the restore path: tracer-bullet keeps the code (refactor-to-comply), spike keeps only the learning (clean rebuild).

Rationale

D-2: the interview classifies, it doesn't assume — the call between "I proved a question" and "I built a usable skeleton" is what the rest branches on.

Graduation MUST extract a Draft bundle at specs/<id>/ — both spec.html and plan.html — reusing the exploration's id, by reading the build's demonstrated screens, flows, and behaviours into user stories, requirements, success criteria, and the plan's design decisions; and MUST interview what the build never answered (intent, quantified NFRs, edge cases) exactly as a cold /spectastic.spec + /spectastic.plan would. It MUST refuse if specs/<id>/ already exists.

Rationale

D-5: the prototype is the bundle's source, not a replacement for the interview. The plan is now part of the extract output because the evidence ledger (FR-004) is a plan artifact.

The run record's proven facts MUST enter the extracted plan's §3 evidence ledger as verified rows, and the <spec-decision>s they support MUST declare grounding="verified" citing the archived exploration (per 000 · REQ-LIFECYCLE-006 — the evidence ledger is a plan artifact, not a spec one), reused from the 022 · FR-008 / 021 verify-shaped record with no re-capture.

Rationale

REQ-LIFECYCLE-006 defines grounding as a /plan concept; no spec carries a grounding-ledger element. The original wording was unbuildable.

Graduation MUST restore the SDD rigor relaxed during explore: the extracted spec + plan bundle is produced under full discipline (requirement IDs, NFRs, SC, INVEST in the spec; the §3 evidence ledger and grounded <spec-decision>s in the plan; full principles compliance), and lifting the quarantine (FR-007) MUST return the id to the gates — so plan enforces estimability and propose runs the adversarial pass. The path-appropriate restore tasks (test-first rebuild/refactor) are scaffolded by the sibling slice TBD-explore-restore.

Rationale

D-3: every relaxed gate comes back on. The evidence ledger lives in the plan (REQ-LIFECYCLE-006); the restore-task generation split to TBD-explore-restore when the budget went red.

On success graduation MUST lift the quarantine — flipping the marker quarantined → graduated — so the core verbs and spectastic validate stop refusing the id (reversing the 022 · FR-006 guard for this id only).

Graduation MUST archive the exploration — moving explorations/<id>/ to explorations/archive/<id>/, preserving the ledger + run record — and the archived marker MUST record classify=spike|tracer and be frozen (immutable, like a changes/archive/ proposal). The extracted spec's grounding ledger MUST cite that archived source, so reversing the classification requires editing a frozen archived artifact — visible in git.

Rationale

Answers the brief's §6 irreversibility question: the archive is the immutable record and the live spec points back at it. Archiving rather than deleting keeps the run prose that justified the verified grounding.

Graduation SHOULD reuse the existing spec / plan / tasks interview machinery and the extended-verb packaging seams rather than forking them — graduation feeds the lifecycle, it does not replace it.

Non-functional

Graduation MUST be all-or-nothing: if any step (extract, restore-scaffold, lift, archive) fails, no change is committed — the quarantine stays in force, no partial specs/<id>/ is left, and the exploration stays put for a clean retry. The deterministic legs (lift, archive, classification record) MUST be reproducible and side-effect-atomic; only the extract leg is AI-coupled.

Rationale

The same fold-before-irreversible-move atomicity the apply kernel uses: do the fallible work and write the spec before the quarantine is lifted and the dir is moved, so a failure never leaves a half-graduated, silently-shippable state.

Graduation is AI-coupled (the extract reads the build into requirements) and SHOULD require ANTHROPIC_API_KEY, like spec / plan and unlike the deterministic apply — the slash-command path uses the in-host session and needs no key.

Out of scope (deferred to other slices)

  • The restore-task generation (former US2 / FR-005) — path-appropriate refactor-to-comply (tracer-bullet) and clean-rebuild (spike, prototype marked for deletion) task scaffolding. Split to a sibling slice when this spec's budget went red (the INVEST·Small trigger).
  • A think-first discovery mode (think-to-learn) — a sibling at the front of the lifecycle, considered separately.
  • A negative-result / "abandoned" terminal state for an exploration that taught something but won't graduate (022 · FR-009 left it out).
  • Re-graduation / un-graduate — reversing a completed graduation. Graduation is one-way (like apply).
  • Adopting Kiro's EARS requirement notation — spectastic's RFC-2119 <spec-rule> form stands.

4 · Data model

This slice reads one exploration (022's tree) and writes one spec dir (the normal bundle). It owns the graduation record; it reuses 022's run record and 000's grounding ledger.

Entities

Graduation
The act and its record: an id (reused from the exploration), a classification, a source (explorations/archive/<id>/), and a target (specs/<id>/). One-way and atomic.
Classification
spike | tracer-bullet. Decides the restore path (FR-002); immutable once graduated, frozen in the archived marker (FR-008).
Extracted bundle
A Draft spec + plan (FR-003) seeded from the build's behaviour; the plan's §3 evidence ledger carries the run's proven facts as verified (a spec has none — REQ-LIFECYCLE-006).

The marker is the single status owner: quarantined (set by 022) → graduated (set here), frozen in explorations/archive/<id>/. The AI-coupled extract runs first and its failure aborts the whole graduation (NFR-001), so the marker only ever flips when a spec actually landed.

5 · Success criteria

Technology-agnostic, measurable outcomes. These are how we know it worked.

100% of successful graduations produce a Draft specs/<id>/ bundle under full rigor (every gate relaxed during explore back in force for the id) and leave the source exploration archived and no longer quarantined — the graduated id goes straight into plan with no quarantine refusal.

Every graduation carries an immutable spike|tracer-bullet classification, and the run record's proven facts appear as verified grounding in the extracted plan's evidence ledger — neither re-captured nor silently reversible (reversal requires editing a frozen archived artifact).

Zero partial graduations: after an injected mid-step failure, the marker is still quarantined and specs/<id>/ does not exist — the exploration is exactly as it was, ready to retry.

The discovered-not-guessed trail is traceable by id alone: for every graduated id, explorations/archive/<id>/ and specs/<id>/ both exist and reference each other.

6 · Assumptions

Graduation operates on an existing quarantined exploration created by 022 · explore; it is not a fresh-start verb and assumes 022's tree, marker, and run record are present.

The exploration id is reused verbatim for specs/<id>/ (shared NNN-kebab scheme), so the history is traceable by id.

The run record is verify-shaped (022 · FR-008); when a build never ran it is empty, and graduation seeds no verified rows into the extracted plan's evidence ledger rather than failing.

Graduation is one-way, like apply / withdraw; to revisit a graduated spec, edit it through the normal lifecycle.

7 · Open questions

None outstanding — every decidable question was anchored in the interview. The brief's §6 graduation questions resolved as: irreversibility = the frozen archived marker + the spec's grounding-ledger back-reference (FR-008); spike-vs-tracer mechanics = two generated restore plans (FR-002, FR-005); run-capture reuse = the verify-shaped record promoted to verified grounding (FR-004). The think-first mode, a negative-result terminal state, and re-graduation are deferred, not open (§3).
