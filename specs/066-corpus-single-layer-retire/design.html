Design · 066-corpus-single-layer-retire

Retire single-layer corpus support

How we will build it.

Status Accepted Spec 066-corpus-single-layer-retire Owner Brian Corbin · @briancorbinxyz Branch 066-corpus-single-layer-retire Created 28 Jul 2026 Read time

Reuse the two-layer registerDocument backbone (065) three ways: re-base adaptCorpus onto it (like convert), add a migratePack that replays existing single-layer documents through it in place (rename to <NNN-slug>.md, re-key to a repo-unique KB-NNNN, drop the pack index), and add a warning-severity validate rule that flags a single-layer pack. Fat-core, thin CLI on both surfaces. Biggest risk: migrate's in-place rewrite — mitigated by making it idempotent and re-runnable (skip already-slug: documents).

4 · Approach

One backbone, three callers. adaptFolder/adaptLlmsTxt stop writing renderDocument(id) + a pack index and instead call registerDocument per file (slug from the filename stem, title/description from the body) — the same re-base 065 did for convert, so AdaptInput gains a marketplace the CLI resolves. A new migratePack(pack) loads the pack, and for every single-layer document (id:, no slug:) replays it through registerDocument — deriving the slug from the current filename stem (keeping an existing NNN- prefix, else allocating the next), renaming the file to <slug>.md, and removing the old id: file and the pack index.md. Already-slug: documents are skipped, so it's idempotent and re-runnable. A new warning-severity rule in the corpus validator flags a pack that still carries single-layer signals.

6 · Decisions

D-001 · Re-base adapt + migrate on the one registerDocument backbone

Status
Accepted
Context
adaptFolder writes the legacy single-layer shape (knowledge/adapt.ts:220-225); the two-layer backbone already exists (registerDocument, 065) and convert proved the re-base.
Decision
Both adapt's new output and migrate's per-document filing call registerDocument. AdaptInput gains a marketplace, resolved by the CLI from corpus.marketplace (pinned, per 065's identity-fragmentation mitigation).
Consequences
+ One tested filing path, three callers. + Consistent output across import/convert/adapt/migrate. − adapt's signature changes (marketplace input); the two adapt CLI sites thread it.

D-002 · migrate is an in-place, idempotent replay; rename to <NNN-slug>.md

Status
Accepted
Context
A single-layer document carries id: (no slug:) at an arbitrary filename; the two-layer convention is references/<NNN-slug>.md (types.ts:65,78).
Decision
migratePack replays each single-layer document through registerDocument — slug derived from the filename stem (keep an existing NNN- prefix, else allocate the next), the file renamed to <slug>.md, the old id: file and the pack index.md removed. Documents already carrying slug: are skipped → idempotent, re-runnable, mixed-pack-safe.
Consequences
+ Idempotent + non-destructive (NFR-001). + A partially-migrated pack finishes cleanly on a re-run. − An in-place rename/delete is more delicate than a fresh write; the skip-if-slug: guard is what makes it safe.

D-003 · Deprecation rule: warning severity, fires on id:-doc OR pack-index

Status
Accepted
Context
The corpus validator scans loaded knowledge/ packs; the repo's own packs are already two-layer (0 id-docs, no index), so a new rule stays green (NFR-002). Warning severity matches the orphan/fragmentation findings.
Decision
A new corpus-single-layer-deprecated finding (warning) fires when a pack has any document with id and no slug, OR a pack-local index.md (pack.index.length > 0), naming corpus migrate as the remedy.
Consequences
+ Opens the deprecation window without a hard break (P-9's "deprecate first"). + Catches both halves of the legacy shape. − A downstream single-layer corpus now sees a warning on every validate until it migrates — the intended nudge.

D-004 · TDD red-first

Status
Accepted
Context
The whole surface is deterministic filesystem I/O over fixture packs — the house test discipline (047/048/065).
Decision
Write each story's tests first (red), then implement. Fixtures: a single-layer pack (id: docs + index.md) and a two-layer pack.
Consequences
+ The two-layer assertions (slug:, registry row, SKILL.md, no index) are pinned before the code. − None material.

8 · Risks & mitigations

RiskLikelihoodImpactMitigation
migrate's in-place rename/delete corrupts a pack if interrupted mid-run.LMIdempotent + re-runnable: skip already-slug: docs, so a re-run finishes a partial migration. Register-then-remove ordering (write the new file + registry row before deleting the old).
The adapt re-base breaks existing adapt tests / the 057 portability path.MMThe 057 raw input is at examples/knowledge/ (ingester input, not adapt output); adapt's own tests are rewritten TDD-first to expect two-layer. Same move 065 made for convert without downstream breakage.
Re-keying breaks an id-based pack-scan citation to a migrated doc.LLAccepted (spec §6 assumption): single-layer docs resolve only via the deprecated pack-scan; the doc is re-cited by its registry coordinate. No registry citation existed to break.
The deprecation warning false-positives.LLNFR-002 + D-003: scoped to loaded knowledge/ packs, fires only on id-without-slug or a real pack-index; the repo's own packs are already two-layer (verified).

9 · Complexity tracking

The only non-trivial mechanic is migrate's in-place rewrite. It is justified by FR-002 (the whole point is converting an existing pack) and kept safe by the idempotent skip-if-slug: guard (D-002) — a re-run is always safe, so a partial run is recoverable.

Deriving a document's slug from its filename stem is faithful for adapt-produced packs (already NNN-name.md) and reasonable for hand-authored ones; a genuinely un-sluggable filename falls back to a slugified default, the same rule convert uses.
