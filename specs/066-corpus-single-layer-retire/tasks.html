1 · Execution strategy

Story IDs follow the spec's numbering (T-1xx = US1, T-2xx = US2, T-3xx = US3) regardless of build order. Priorities are US1 = P1, US2 = P1, US3 = P2 — the recommended order below runs both P1 stories before the P2 deprecation warning.

Setup → Foundational → US1 (adapt → two-layer, P1) → US2 (migrate an existing pack, P1) → US3 (deprecation warning, P2) → Polish. US1 and US2 both re-use the 065 backbone but touch distinct files (adapt.ts vs. the new migrate.ts), so once Foundational lands they can also run side by side.

Setup → Foundational → US1 only → ship. After US1, no verb produces single-layer any more — a viable MVP on its own (spec §2). Add US2 (migrate existing packs) and US3 (the warning) as fast-follows.

After Foundational, one contributor on US1 (adapt.ts + its two CLI sites) and one on US2 (migrate.ts + its two CLI sites) — the files don't overlap. US3 is a single small edit to validate.ts, best folded in by whoever finishes first.

2 · Phase 1 — Setup

Add single-layer / two-layer fixture-pack builders — a shared test helper that writes a pre-062 single-layer pack (id: documents + a pack-local index.md, no registry) and a two-layer pack, reused by the migrate and validate tests. packages/corpus/test/fixtures/single-layer-pack.ts
Scaffold the migrate module — the migratePack/MigrateInput/MigrateResult signatures, no logic yet. packages/corpus/src/knowledge/migrate.ts

3 · Phase 2 — Foundational

The one signal both US2 (which documents to migrate) and US3 (which packs to flag) depend on — extracted once so the migrate replay and the deprecation rule agree on what "single-layer" means.

Add the shared single-layer predicate — singleLayerDocuments(pack) (documents with id set and slug absent) and isSingleLayerPack(pack) (any such document or a pack-local index.md, i.e. pack.index.length > 0), exported for both callers. packages/corpus/src/knowledge/migrate.ts

Grounded in plan D-003 — single-layer ⇔ doc.id && !doc.slug OR a pack-local index. One predicate, so migratePack and the validate rule can never disagree on the boundary.

5 · Phase 3b — US2 · migrate an existing single-layer pack P1

Tests (write & fail first)

Write failing test: migrate converts a single-layer pack in place — after migratePack, every document carries slug: (no id:), the root registry holds one KB-NNNN row per document, a SKILL.md exists, and no pack-local index.md remains. packages/corpus/test/knowledge.migrate.test.ts
Write failing test: migrate allocates a fresh repo-unique id — a pack-local id: KB-001 is never reused as the repo id; the document's registry KB-NNNN is freshly allocated and repo-unique, while its slug stays stable. packages/corpus/test/knowledge.migrate.test.ts
Write failing test: migrate is idempotent and mixed-pack-safe — a second run is a no-op, a run on an already-two-layer pack changes nothing, and a mixed pack (some id:, some slug:) converts only the single-layer documents. packages/corpus/test/knowledge.migrate.test.ts

Implementation

Implement migratePack's per-document replay — load the pack, and for each singleLayerDocuments entry re-file it through registerDocument (slug from the filename stem, keeping an existing NNN- prefix else allocating the next), renaming to <slug>.md; skip already-slug: documents. packages/corpus/src/knowledge/migrate.ts
Remove the old id: file and the pack index.md — register-then-remove ordering (write the new <slug>.md + registry row before deleting the old id: file), then drop the pack-local index.md once every document is migrated. packages/corpus/src/knowledge/migrate.ts
Export migratePack from the corpus barrel — migratePack, its input/result types, and the shared single-layer predicate. packages/corpus/src/knowledge/index.ts
Register migrate on the standalone binary — a migrate <pack> command resolving corpus.marketplace/corpus.root and dispatching to migratePack. packages/corpus/src/cli/curate.ts
Mirror migrate on the main CLI's corpus group — the same corpus migrate <pack> subcommand, same resolution, same dispatch. packages/cli/src/commands/corpus.ts

Closes FR-002, FR-003, SC-001, and migrate's leg of NFR-001 / SC-003.
