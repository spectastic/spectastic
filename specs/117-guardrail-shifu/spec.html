Teaching follow-up (shifu)

After a verdict, ask one Socratic question drawn from the decision's own reason — never a fix — so the developer reasons toward the sanctioned path themselves. Deterministic, off the enforcement path.

1 · Context

The 115 verdict already teaches in the reference sense — it names the decision, its reason, and the offending file:line, so a reviewer who never read the ADR can act. Rubric item 10 asks whether a Socratic follow-up can deepen that: "the rule says driven adapters never call into the core; why does this job need the repository?" — a question that makes the developer reason toward the sanctioned path rather than being handed a fix. The brief imagined an LLM skill; a templated question composed from the verdict's own fields achieves the same intent deterministically, so this slice builds it that way.

Its user is the developer who just hit a verdict. It is strictly advisory and strictly after the verdict — it must never change the deterministic result (P-8) — which is exactly why a deterministic composition, not a model, is the right tool.

2 · User scenarios & testing

A failure prompts reasoning. A verdict flags a direct write to positions outside the adapter. spectastic verdict --teach follows it with: "Decision 002/D-007 exists so that every position change emits PositionChanged — this change has src/recon/Job.java writing positions directly. What makes that necessary here rather than going through the use case?" One question, no fix.

Teaching never gates. Adding --teach changes only what is printed; the exit code and the persisted verdict are identical. A clean verdict yields no questions.

3 · Requirements

A pure shifuQuestions(verdict) MUST return one Socratic question per violation, composed from that violation's decision reason and its source→target. Each MUST be phrased as a question (ending in "?") and MUST NOT contain an imperative fix or a directive to change code. spectastic verdict MUST surface the questions only under an opt-in --teach flag, printed after the deterministic verdict and clearly marked as an advisory follow-up. The teaching follow-up MUST be off the enforcement path: --teach MUST NOT change the verdict, the persisted artifact, or the exit code — it only adds output. A violation missing a source→target SHOULD still yield a well-formed question from the decision reason alone, rather than an empty or malformed one. shifuQuestions MUST be pure and deterministic — the same verdict yields byte-identical questions — with at most 0 model clients and 0 network modules on its path. It is a templated composition, not a model call.
  • An LLM-phrased variant — richer wording via a model, strictly post-verdict. Deferred; the deterministic question meets the intent and stays P-8-clean.
  • The grading-fixture harness — locking the seven guardrail behaviours as regression fixtures is the proving example's job (Phase 4), not a separate harness.

4 · Data model

Verdict
115's persisted verdict — the input; each violation carries decision-id, reason, and source→target.
Socratic question
A single interrogative sentence composed from a violation's reason + source→target; it prompts, it never prescribes.
