Design · 040-run-budget

Run budget

How we will build it.

Status Accepted Spec 040-run-budget Owner Brian Corbin · @briancorbinxyz Branch 040-run-budget Created 09 Jul 2026 Read time

A new packages/core/src/run/budget.ts: a BudgetTracker (spend accumulates from output length; phase() = normal/degrade/halt at the 80%/100% bands), degradeEffort (one band down the 034 ladder, floor-clamped), and a budgeted(ai, tracker) wrapper that records every response. 037's runPipeline gains an optional ctx.budget hook: halt-escalate at the ceiling, pass a degraded effort to the Decider at 80%. Additive — no budget ⇒ unchanged. Biggest risk: the estimate ≠ real tokens — accepted, exact provider usage is deferred.

4 · Approach

run/budget.ts holds BudgetTracker (accumulate estimated tokens, derive phase()), estimateTokens, degradeEffort, and budgeted(ai, tracker) (an AIProvider wrapper that records each chat/subagent/ask output's estimated tokens). 037's runPipeline gains an optional ctx.budget: at the top of each step's loop it halts-and-escalates when phase()==='halt', and answers the step's decisions with a degraded DeciderConfig when phase()==='degrade'. The CLI run adds --budget, constructs the tracker, wraps the provider, and passes both. No budget ⇒ phase() is always normal and nothing changes.

6 · Decisions

D-001 · Spend is estimated from output length; phase from fixed bands

Status
Accepted
Context
The AIProvider returns only text (claude.ts:71,131) — no usage to read.
Decision
estimateTokens(text) = ceil(len/4); phase() = halt ≥ 100%, degrade ≥ 80%, else normal (80% = the REQ-FORMAT-004 amber band). Exact usage deferred.
Consequences
+ deterministic + no provider change; − an estimate, not exact tokens (accepted risk).

D-002 · Additive runPipeline hook — optional ctx.budget

Status
Accepted
Context
037's runPipeline answers decisions via answerDecisions(verb, cfg, ai) in a loop (pipeline.ts).
Decision
Add optional ctx.budget; the loop halts-escalates at halt and passes a degraded DeciderConfig at degrade. Absent ⇒ unchanged (FR-004) — the 037 tests still pass untouched.
Consequences
+ one integration point; − runPipeline now knows about the budget (small, guarded).

D-003 · A budgeted(ai) wrapper records spend transparently

Status
Accepted
Context
AI calls happen inside the steps (plan chat, answerDecisions subagent), not in the driver.
Decision
budgeted(ai, tracker) proxies the provider, recording each response's estimated tokens; the CLI wraps the real provider so the tracker accumulates as steps run.
Consequences
+ the driver stays clean (just reads phase()); − one proxy object.

8 · Risks & mitigations

RiskLikelihoodImpactMitigation
Estimate diverges from real token spendMLAccepted + documented (assumption); a real usage field is the deferred follow-up. The estimate still bounds a runaway run.
The hook regresses an un-budgeted 037 runLHGuarded on ctx.budget?; the parity test (SC-003) + the untouched 037 driver tests prove no-budget behaviour is unchanged.

9 · Complexity tracking

No complexity beyond the tracker + one guarded loop check.

Degradation lowers effort by exactly one band per the ladder; a run that needs to shed more spend degrades again as it crosses further into the band on subsequent decisions (monotone, since spend only grows).
