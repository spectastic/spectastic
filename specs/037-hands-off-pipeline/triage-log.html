Cards

pnpm typecheck fails: run.ts passes an unresolved effort: 'auto' to resolveDecider

Implementation code

Debugging a tsc --noEmit failure at run.ts:58, root cause was an implementation drift — the run command hands its raw DeciderFileConfig (whose effort may be the literal 'auto') straight into resolveDecider, which expects an already-resolved EffortLevel; fixed by resolving 'auto' through 034's resolveEffort before the call; regeneration passes (the spec and plan already say to resolve effort — only the code skipped it).

Expected
pnpm typecheck passes across schema / cli / vscode (exit 0).
Actual
TS2379 at packages/cli/src/commands/run.ts:58 under exactOptionalPropertyTypes: "Type '\"auto\"' is not assignable to type 'EffortLevel'" — exit 2. The tsup build (no strict tsc) tolerated it, so it slipped the build but not the type gate.
Diagnosis
Spec 034-effort-auto made the config-file effort a superset (RequestedEffort = EffortLevel | 'auto') that must be narrowed via resolveEffort before use; run.ts passes loadDeciderConfig(cwd) directly to resolveDecider (core EffortLevel, no 'auto') without that narrowing step. Pure code drift — 037's spec/plan and 034's contract are correct.
Fix
packages/cli/src/commands/run.ts — narrow the project config's effort through resolveEffort (034) into a concrete EffortLevel before handing the Partial<DeciderConfig> to resolveDecider; mirror the same for the --effort override (currently cast as never, which also hides the mismatch).
const project = cfgMod.loadDeciderConfig(cwd); const decider = resolveDecider(project, { …override… }, 'agent'); const project = cfgMod.loadDeciderConfig(cwd); // narrow effort: 'auto' → a concrete EffortLevel (034) before resolveDecider const base: Partial<DeciderConfig> = { ...(project.role ? { role: project.role } : {}), ...(project.effort ? { effort: resolveEffort(project.effort, signal, project.floor) } : {}), }; const decider = resolveDecider(base, { …override… }, 'agent');
Deep dive — none required

No cross-spec contract change (034's RequestedEffort→EffortLevel narrowing is the intended path, not a disagreement), no principles invariant, no deferred scope, no hotfix sequence. Worth a quick grep for other resolveDecider / resolveEffort call sites that pass a raw DeciderFileConfig, in case the same drift exists elsewhere. Separately, the tsup build not running a strict tsc is why this reached the type gate rather than the build — a CI-ordering note, not part of this fix.
