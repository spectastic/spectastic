Hands-off pipeline

Submit an approved spec, walk away: an orchestrator drives plan → tasks → implement → verify, answering every decision through the configured Decider — enforced in code, not prose.

W-1 runs the lifecycle unattended. A human approves a spec; the orchestrator chains plan → tasks → implement → verify, runs validate between steps, and answers every decision through the configured Decider (human / agent / panel). The load-bearing guarantee is P-8: the answerer is chosen by orchestrator code — the decider threaded as config on the CLI (implement via 038, generation decisions via 039), convened by the script on the Workflow surface — never asserted in markdown. Irreversible calls escalate to a human between phases. Assembly over the landed 036/038/039 seams, not invention.

1 · Context

Driving a feature from approved spec to verified implementation is still a human clicking through plan → tasks → implement → verify and answering every decision-phase question by hand. The W-1 handover settled the one design question that blocked automating that chain — who answers the decisions with no human — and the answer, the Decider (033–036), is built and landed. What remains is the orchestration. This spec is for the operator who wants to submit a spec and walk away, and the maintainer who needs that walk-away to be honest: every autonomous decision made by the configured role, recorded, with irreversible calls handed back to a person.

2 · User scenarios & testing

Each story MUST be independently testable: US1 alone is a viable MVP.

US1 · Submit a spec, walk away P1

As an operator, I want to run spectastic run <spec-id> on an approved spec so that the pipeline drives plan→tasks→implement→verify to a verified feature without my input.

Acceptance: on a fixture spec with decider=agent, the run completes all four verbs in order, validate is clean between every step, and no human interaction occurs outside escalation gates.

US2 · The unattended interview is faithful P1

As a maintainer, I want the run to answer each verb's own decision-phase questions through the Decider so that an unattended run makes the same bounded decisions a human path would.

Acceptance: for each verb the orchestrator poses that verb's existing decision-phase taxonomy (smallest-demoable, priorities, test-style, op-type, layer…) to the decider — not an open-ended generated set — and the chosen answers drive the artifact.

US3 · The human never fully leaves P1

As an operator, I want irreversible decisions handed back to me so that a walk-away run can't take a high-stakes call on its own.

Acceptance: a decision that trips the 033 FR-008 escalation guardrail pauses the run between phases, raises a real AskUserQuestion gate, and resumes the next phase on my answer; --checkpoints=minimal|each (default minimal) sets how many planned gates bracket the run.

US4 · The same run, headless on the Claude surface P1

As a Claude-surface user, I want a Workflow script to drive the same chain so that the pipeline runs where I already work, with the same answerer semantics.

Acceptance: the Workflow home convenes the decider per decision (one agent() for agent, a voting fan-out for panel) and produces the same decisions the CLI home would for the same spec + config.

Edge cases

  • The spec is not approved (still Draft / has open blockers): the run refuses up front, like plan's estimability gate — it does not silently proceed.
  • decider=human on an unattended run: the run cannot answer autonomously, so it refuses (a human decider defeats the purpose) rather than escalating every decision.
  • A verb step fails with a non-validate error (e.g. an AI/provider error): the run escalates once rather than retry-looping.
  • A step fails mid-chain: an idempotent re-run resumes on the Draft in-place path (FR-009) — no rollback state to reconcile.

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional

The orchestrator MUST drive plan → tasks → implement → verify in order on an approved (non-blocked) spec, run spectastic validate after each step, and halt-and-escalate on a validate error rather than proceeding — the validate gate is the P-7 evaluator that keeps a bad artifact from propagating.

On the autonomous path the orchestrator MUST answer every decision the run reaches through the configured Decider (resolved by the 033 precedence: flag > project config > default), and MUST NOT prompt a person except at an escalation gate (FR-006).

The orchestrator MUST be the enforcer of the answerer: the decider is threaded as config (CLI) or convened (Workflow) by orchestrator code, never selected by command markdown. No command markdown is relied upon to route a decision to the decider.

Rationale

The load-bearing P-8 requirement. A markdown "if decider=agent, decide it yourself" is advisory and fails silently (T-009); code that chooses the provider is a guarantee. This is why "make the slash-command interviews use decideChoice" is explicitly a non-goal.

The CLI home (spectastic run <spec-id>) MUST thread the resolved DeciderConfig through each step rather than injecting an ask() override: generation-verb decisions are answered via answerDecisions (039); the implement step is performed by the coding-agent runtime (038 drainTasks), which codes and verify-gates each task; and the code-reachable checkpoints (propose's decide, the slicer's confirmRice, triage's escalateLayer) answer through their existing Decider seam.

Rationale

Grounding found the kernel AIProvider is text-only and no verb calls ask() — an injected ask() would be inert. The decider reaches the verbs' decisions as config (the 038/039 seams), which is what actually makes them answerable.

For each generation verb the orchestrator MUST answer that verb's bounded decision-phase questions via answerDecisions(verb, cfg, ai) over the DECISION_TAXONOMY registry (039) and thread the chosen answers into that verb's generation; it MUST NOT generate an open-ended question set at run time. Context-dependent decisions (smallest-demoable framings, per-story priorities) are not in the registry and remain the adaptive interview (deferred).

An irreversible / high-stakes decision (per 033 FR-008) MUST escalate to a human between phases: the orchestrator returns, the main loop raises a real AskUserQuestion gate, and the next phase launches on the answer.

--checkpoints=minimal|each (default minimal) MUST control planned human-gate granularity: minimal = one gate before implement; each = a gate after each generative verb. Irreversible escalations (FR-006) fire regardless of this flag.

The Workflow-script home MUST drive the same chain headless, convening the decider per decision (one agent() for agent; a voting fan-out for panel) with the same role semantics as the CLI home.

Each verb MUST be safe to re-run unattended on the Draft in-place path (P-6): a failed step is recovered by re-running the verb, gated by validate. The orchestrator MUST NOT require a separate run-state / rollback machine — the artifacts are the state.

Non-functional

Every decision the run takes MUST be attributable: its decider role, effort, and grounds are recorded on the touched artifact (leaning on 033 FR-009 / 036), so a walked-away human can reconstruct the run from the artifacts alone.

The escalation gate MUST be a hard stop: the run cannot complete an escalated decision's phase without a recorded human answer — no autonomous fall-through on timeout or error.

Out of scope (deferred to other slices)

  • A per-run cost ceiling with graceful degradation (--budget; degrade decider depth at 80%, halt + escalate at 100%) — peeled to keep this slice estimable; landed as the sibling 040-run-budget.
  • The slice step at the head of the chain — this run starts from an approved spec; driving slice → … is a follow-up.
  • A separate run-level decision-log artifact — the per-artifact grounds (NFR-001) are the audit trail by decision.
  • Open-ended, model-generated interview questions beyond each verb's decision-phase taxonomy (FR-005).
  • Asserting the answerer in slash-command markdown — the guarantee is that the orchestrator injects/convenes it (FR-003).

4 · Data model

The run owns almost no new state — the artifacts are the state (FR-009).

Entities

Run
{ specId, home: 'cli' | 'workflow', decider, effort, checkpoints: 'minimal' | 'each', budget } — the resolved configuration that drives the verb sequence.
Threaded DeciderConfig (CLI)
The resolved { role, effort } the run passes into each step — consumed by answerDecisions (039) for generation, drainTasks (038) for implement, and the existing decideChoice/decide checkpoints. The orchestrator chose the config; the seams answer by role (FR-004).
Escalation
An irreversible decision surfaced between phases — carries the question set and the phase to resume, consumed by the main-loop AskUserQuestion gate (FR-006).

Invariant: on the autonomous path, a decision is answered by exactly one of — the injected/convened decider, or a human escalation gate. There is no third, markdown-driven path (FR-003).

5 · Success criteria

Technology-agnostic, measurable outcomes.

On an approved fixture spec with decider=agent, spectastic run completes plan→tasks→implement→verify with zero human interactions outside escalation gates, and validate is clean between every step.

No autonomous decision is answered by command markdown: swapping the decider config changes the recorded role of every decision the run takes — observable proof the injected/convened decider is the answerer (FR-003).

A decision that trips the 033 FR-008 escalation guardrail pauses the run between phases and resumes the next phase on the human answer — observable on a fixture that triggers the guardrail.

The Workflow home and the CLI home produce the same decisions (same roles answering) for the same spec + config — observable by running both on a fixture and comparing recorded verdicts.

6 · Assumptions

The verbs' decisions are now reachable in code — the reachability this spec once assumed was discharged by the pre-work: implement codes via 038 drainTasks, and the generation verbs' bounded decisions live in 039 DECISION_TAXONOMY. Threading the 039 answers into plan/tasks generation is this slice's work (FR-005).

decideChoice (036) + answerDecisions (039) + drainTasks (038) are the sufficient seams — the run is assembly over them, needing no new decision primitive.

7 · Open questions

None outstanding — every decision was anchored across three interview batches. The one residual unknown — whether any verb has a decision point outside the decider-answerable surface — is an assumption for the plan's grounding pass to verify against real source, not an open decision.
