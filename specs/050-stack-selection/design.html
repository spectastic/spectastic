Design · 050-stack-selection

Stack selection at the plan stage

How we will build it.

Status Accepted Spec 050-stack-selection Owner Brian Corbin · @briancorbinxyz Branch 050-stack-selection Created 22 Jul 2026 Read time

Build the feature across three surfaces, split by the P-8 line: the guarantee — a matrix-winner-integrity schema rule cloning slo-well-formed — lives in the kernel; the MADR augmentation is additive template + CSS on <spec-decision>; the stack-selection interview is advisory guidance in the plan command markdown. Biggest risk is that the interview is a nudge the model can skip (T-009) — mitigated by putting the only hard guarantee (crown-follows-score) in the kernel, where a backward-compat spike already proved 0 of 43 existing matrices would newly fail.

4 · Approach

Build guarantee-first, in three surfaces. (1) The kernel guarantee: a new matrix-winner-integrity per-file rule that flags a <spec-matrix> whose data-winner row's Total is strictly below another row's, skipping matrices whose scores aren't all numeric — authored test-first. (2) The static record: additive template + CSS giving <spec-decision> an optional MADR Considered-Options list (per-option pros/cons) and decision drivers, plus an optional target= on <spec-matrix>. (3) The advisory nudge: the plan command gains a self-skipping stack-selection pass that reads detection + standing docs + the frameworks stance, presents undecided picks with a context-seeded recommendation, and auto-scaffolds the decision card (FR-011). Sequencing guarantee-first means slice 1 (rule + record) ships and validates independently if the interview markdown lags.

6 · Decisions

D-001 · Split the feature along the P-8 line — guarantee in the kernel, nudge in markdown

Status
Accepted
Context
The interview is LLM-driven and cannot be guaranteed to run (§3, T-009 / P-8); the only enforceable requirement is the honest record.
Decision
The crown-follows-score guarantee is a kernel schema rule (error severity); the MADR scaffolding is static template/CSS; the interview is advisory command markdown. Three surfaces, one line.
Consequences
+ The durable value survives even if the model skips the nudge. + Matches the fat-core/thin-CLI convention. − The interview's UX quality is unverifiable by CI (accepted — it's a nudge).

D-002 · matrix-winner-integrity — a per-file rule cloning slo-well-formed

Status
Accepted
Context
slo-well-formed.ts:34-101 is a drop-in template; the backward-compat spike (§3) showed 0 of 43 existing matrices fail a ties-allowed rule.
Decision
Flag a matrix whose data-winner Total is strictly less than any other row's; skip matrices whose scores aren't all numeric (unfilled templates). Severity error. Register in rules/index.ts.
Consequences
+ Ties at the top stay legal (3 existing plans rely on it), so SC-004 holds. + A crowned loser blocks the gate — the bias the spec kills. − A back-filled matrix that still tops the score isn't caught (out of scope; the rule checks integrity, not honesty of scoring).

D-003 · MADR augmentation is additive markup — Nygard cards stay valid

Status
Accepted
Context
No schema rule governs <spec-decision> content beyond id-scoping (§3), so its shape is free-form and 49 existing cards are Nygard.
Decision
Add an optional Considered-Options list + decision drivers as template/CSS on the existing <dl>; add an optional <spec-matrix target="D-NNN"> with a resolves-to-a-decision check mirroring slo-target-required. No breaking shape rule.
Consequences
+ Zero migration of the 49 existing cards. + The new fields appear only where added. − "Considered Options present" is not itself enforced (it's a should, surfaced by the interview auto-scaffold, not a hard rule).

D-004 · The frameworks-axis stance lives in the interview markdown, not core

Status
Accepted
Context
The stance is advisory tie-break guidance the LLM applies; there is no reusable deterministic unit (§5 matrix; spectastic-profiles.json axis is documentary).
Decision
The plan command reads the profile's frameworks value and applies the documented lean (minimal → stdlib/no-dep; conventional → mainstream; staff-level → mature). No core module.
Consequences
+ Keeps the fat-core boundary honest — no kernel unit for advisory guidance. + Simplest surface. − Not unit-testable (accepted — it's a nudge, per D-001).

D-005 · Opt-out via a spectastic.json key, read in the interview

Status
Accepted
Context
spectastic.json is already the config surface (enforce/config.ts reads enforce.waivers); §3.
Decision
A plan.stackInterview: false key disables the pass (auto-on by default). The interview checks it before running.
Consequences
+ One documented, discoverable switch on the existing config file. + Absent key → the safe default (on). − Enforced only by the interview reading it (consistent with D-001).

9 · Complexity tracking

No principle exception. One deliberate coupling worth naming:

The tight interview→record integration (FR-011: a pick auto-scaffolds its MADR card) adds a step beyond a bare interview. It is justified by the spec's explicit "both concerns" scope — the honest record becomes a byproduct of the interview rather than separate manual work — and stays advisory, so it adds no kernel complexity.
