Corpus adapter

Most teams already hold their knowledge in some shape. Meet them where it is — and never fabricate the provenance you can't derive.

First-class treatment (citable, edition-pinned, gated) is a property of the convention, not of any particular pile of files — so the honest answer to "I already have a knowledge base" is a tier, not a door. This spec builds the adapt tier: a deterministic Node generator that emits provenance frontmatter and a curated index from an existing corpus shape (a markdown folder, an llms.txt), turning a user's own knowledge base first-class in one pass. It owns no PDF converter — document conversion stays the user's step — and it never invents provenance it cannot derive: an unknown license or origin is an explicit TODO marker, never a fabricated value. Conversion is lossy and its losses are silent, so the adapter surfaces that caveat and prompts a spot-check.

1 · Context

Adopting the convention wholesale (051) is the most work and the most guarantee. But most teams with specialist knowledge already hold it in some shape — a folder of markdown, an llms.txt index — and asking them to re-author provenance by hand is friction that keeps a good corpus out of the convention. The considerations doc frames this as a tier: adopt (move it in, hand-authored), adapt (run a generator that emits the frontmatter and index from an existing shape), or bridge live via MCP. This spec is the adapt rung.

The sharp edge is honesty. Conversion and adaptation are lossy, and a citation makes a wrong fact more credible, not less. So the adapter has one inviolable rule: it emits what it can derive and marks what it can't as an explicit TODO — it never manufactures a license, an origin, or an edition it did not read. A fabricated provenance field is worse than a missing one.

2 · User scenarios & testing

Each story MUST be independently testable.

US1 · An existing markdown folder becomes citable P1

As a team with a markdown knowledge folder, I want an adapter that emits frontmatter and a curated index from it so that my corpus becomes citable without hand-writing provenance for every file.

Acceptance: pointing the adapter at a folder of N markdown files yields N documents carrying KB-NNN frontmatter and an N-row index that spectastic validate accepts.

US2 · An llms.txt as the index source P2

As a user with an llms.txt, I want the adapter to read it as the index source so that the curated map I already maintain seeds the corpus index.

Acceptance: the adapter reads an llms.txt and produces a corpus index whose rows correspond to its entries.

US3 · Nothing is fabricated P3

As a cautious adopter, I want the adapter to mark provenance it cannot derive as TODO and to warn that conversion is lossy so that I know exactly what to spot-check rather than trusting a confident but hollow field.

Acceptance: a source file with no discernible license/origin yields license: TODO / origin: TODO (never a guessed value), and the adapter surfaces a spot-check caveat.

Edge cases

  • Re-running the adapter on an already-adapted corpus — no duplicate IDs, no duplicate index rows (NFR-001).
  • A source folder mixing already-adapted and raw files — adapted files are left intact; only raw files gain frontmatter.
  • A PDF in the source folder — out of scope; the adapter consumes markdown, and conversion is documented, never shipped (FR-004).

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional

The adapter MUST emit provenance frontmatter (KB-NNN IDs plus the 051 fields) and a curated index from an existing corpus shape — a folder of markdown, or an llms.txt.

The adapter MUST NOT invent provenance it cannot derive — an unknown license, origin, origin-url, or edition MUST be emitted as an explicit TODO marker, never a fabricated value. A content hash MUST be computed where the source is present.

Rationale

Adaptation is lossy, and a citation makes a wrong fact more credible. A fabricated provenance field manufactures false confidence; an explicit TODO tells the user exactly what to verify.

The adapter SHOULD surface the silent-loss caveat on completion, prompting a spot-check of the emitted documents against their sources.

The adapter MUST be deterministic Node (part of the kernel) and MUST NOT own a PDF converter; document conversion (Docling / MarkItDown / Marker) stays the user's step, documented but never depended on.

Rationale

Keeps the kernel free of an external Python runtime and a version matrix. The tool consumes whatever markdown lands in the corpus; the adapter shapes markdown into the convention, it does not produce markdown from PDFs.

Non-functional

The adapter MUST be idempotent — re-running it on an already-adapted corpus MUST NOT duplicate KB-NNN IDs or index rows, nor overwrite hand-corrected provenance with a fresh TODO.

Out of scope (deferred to other slices)

  • The target corpus shape the adapter emits into (layout, IDs, index, frontmatter fields).
  • Adjudicating whether an emitted license permits redistribution — the adapter records the license; the licensing rule surfaces a restrictive one.
  • A shipped PDF converter — a documented recommendation (Docling / MarkItDown / Marker), never a spectastic dependency.

4 · Data model

The entities this feature owns or substantially changes.

Entities

Adapter input
An existing corpus shape: a folder of markdown files, or an llms.txt index. Read-only source.
Emitted frontmatter
The 051 provenance block written onto each source document, with derivable fields populated and non-derivable fields set to TODO.
TODO marker
An explicit placeholder for a provenance field the adapter could not derive — the honest alternative to a guess. Machine-visible so a later validate / review can flag it.

Invariant: the adapter is additive and idempotent — it never destroys a hand-authored value. A field once corrected by a human is left untouched on re-run.

5 · Success criteria

Technology-agnostic, measurable outcomes.

Adapting a folder of N markdown files yields N KB-NNN documents and an N-row index that spectastic validate accepts.

A source file with no discernible license or origin produces TODO markers for those fields — never a fabricated value.

Re-running the adapter on its own output produces no duplicate IDs or index rows and preserves any hand-corrected provenance.

6 · Assumptions

Existing corpora arrive as markdown (or an llms.txt pointing at markdown); documents still in PDF are converted by the user before adaptation, per the documented recipe.

A content hash is computable deterministically from a source document's bytes, so provenance integrity does not depend on a field the adapter would otherwise have to guess.
