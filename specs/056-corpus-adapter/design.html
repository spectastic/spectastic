Design · 056-corpus-adapter

Corpus adapter

A deterministic Node generator that shapes an existing corpus into 051's form — populating what it can derive, marking what it can't as an explicit TODO, and never destroying a hand-authored value on re-run.

Status Accepted Spec 056-corpus-adapter Owner Brian Corbin · @briancorbinxyz Branch main Created 25 Jul 2026 Read time

Add a fat-core module knowledge/adapt.ts that turns an existing corpus shape into 051's form, and a thin CLI command spectastic corpus adapt <path> — the first subcommand group. The core reuses 051's parseCorpusDocument for idempotency (a file that already has frontmatter + a KB-NNN id is left untouched), assigns new ids sequentially from the pack's existing max in sorted-filename order, computes a sha256: content hash from source bytes, and emits every underivable provenance field as a literal TODO — never a guess. Input mode is chosen by what you point at: a directory adapts every .md; an llms.txt seeds the index. Biggest risk: silently fabricating provenance; mitigated by making TODO the only fallback and testing it as a MUST.

4 · Approach

One new core module, one thin CLI command. knowledge/adapt.ts exposes a pure-ish adaptCorpus(input, fs) that: (1) routes on the input kind — a directory adapts every .md under it; an llms.txt file seeds the index from its entries and adapts the files it links; (2) for each source doc, parses any existing frontmatter via 051's parseCorpusDocument and skips it when it already carries a valid KB-NNN (idempotency); (3) for each raw doc, derives what it can — a sha256: hash of the bytes, an edition/origin only where the source or llms.txt genuinely supplies it — and writes every other provenance field as a literal TODO; (4) allocates new ids sequentially from the pack's existing max in sorted-filename order; and (5) merges the index by id (never a duplicate row). The command spectastic corpus adapt <path> [--pack <name>] resolves the pack (default: the source folder's basename), calls core, prints a count summary, and ends with the silent-loss caveat + a spot-check prompt (FR-003).

5 · Alternatives considered

OptionHonesty (no-fabricate)DeterminismReuseTotal
Own the full PDF→markdown→corpus pipeline (bundle Docling/MarkItDown)3216
Generator that best-guesses missing provenance from filename/heuristics1449
Deterministic Node generator: derive what's present, TODO the rest, idempotent via 051's parser55515

Owning conversion drags a Python runtime + a version matrix into the kernel — barred by FR-004. Best-guessing provenance is precisely the failure FR-002 forbids: a fabricated field makes a wrong fact more credible. Deriving what's present and marking the rest TODO is the only option that stays honest, and it reuses 051's parser wholesale.

6 · Decisions

D-001 · Fat-core knowledge/adapt.ts + a thin corpus adapt CLI command

Status
Accepted
Context
FR-004 requires deterministic kernel code; applyGitignore (gitignore/apply.ts:70) is the established read-source-write-derived shape, testable without the binary.
Decision
Add adaptCorpus(input, fs) to @spectastic/core/knowledge; register a thin registerCorpus CLI that delegates. The CLI is the first subcommand group (corpus adapt) — commander 12.1 supports it (D-005).
Consequences
+ Pure derivation is unit-testable in-process. + A corpus namespace gives the 051–059 family a home. − Introduces the CLI's first subcommand group — a small new pattern, contained to one registrar.

D-002 · Input mode selected by what the target points at

Status
Accepted
Context
FR-001 accepts "a folder of markdown, or an llms.txt"; US1's acceptance is folder-shaped, US2's is llms.txt-shaped. fs.stat distinguishes a directory from a file.
Decision
A directory → folder mode (every .md gets frontmatter; index built from them). An llms.txt file → index-seed mode (its entries become index rows; the linked .md files get frontmatter). No flag chooses the mode; the target's kind does.
Consequences
+ Each story's acceptance maps to one mode; zero ambiguity. − An llms.txt pointing outside its own folder needs a base-path rule (resolve links relative to the llms.txt's dir) — a documented edge, not a new mode.

D-003 · Sequential KB-NNN allocation from the pack's existing max

Status
Accepted
Context
NFR-001 forbids duplicate ids on re-run or a second adapt. loadCorpus/parseCorpusDocument already surface every existing id; KB_ID_RE pins the shape.
Decision
Scan the target pack for the highest existing KB-NNN; allocate max+1, max+2… to new (raw) files in sorted-filename order. Already-adapted files keep their id.
Consequences
+ Never collides an existing id; deterministic given a fixed source set. + Human-readable, sequential. − Allocation depends on the current pack contents (a deleted-then-re-added file may get a higher number) — acceptable; ids are stable-forward, never reused.

D-004 · Never fabricate: derive what's present, TODO the rest, hash the bytes

Status
Accepted
Context
FR-002 forbids inventing license/origin/origin-url/edition and requires a content hash where the source is present. The dogfood corpus already ships content-hash: TODO and sha256: hashes elsewhere.
Decision
Populate a field only from a value genuinely read (frontmatter already present, or an llms.txt entry); otherwise emit the literal string TODO. Always compute content-hash: sha256:<hex> from the source bytes via Node crypto. converter records the tool the user named or TODO.
Consequences
+ A wrong fact never gains false credibility; the TODO is machine-visible to validate/review. − Freshly-adapted corpora are TODO-heavy until a human fills them — by design (honesty over convenience); surfaced by the FR-003 caveat.

D-005 · Idempotency + non-destruction via 051's parser

Status
Accepted
Context
NFR-001 requires re-runs to add no duplicate ids/rows and to never overwrite a hand-corrected value with a fresh TODO. parseCorpusDocument reports hasFrontmatter, id, and the present provenance.
Decision
A file with hasFrontmatter && id is skipped whole. The index merges by id (existing row wins its non-empty cells). A provenance field already set to a non-TODO value is never rewritten to TODO.
Consequences
+ Safe to re-run repeatedly; a human's edits survive. − "Already adapted" is judged by a valid id, so a half-adapted file (frontmatter, no id) is re-derived — the correct behaviour, not a bug.

D-006 · TDD, tests written red-first

Status
Accepted
Context
The adapter is deterministic core: a temp source dir in, assert emitted frontmatter/index out. Every SC is cheaply assertable first (N→N + validate; underivable→TODO; re-run→no dups + preserved edits).
Decision
Write the failing unit tests before the generator; a folded spectastic validate over the emitted corpus proves SC-001's "validate accepts" leg.
Consequences
+ Two MUSTs, a MUST-NOT and the idempotency NFR get red-first coverage. − None material for a pure transform.

8 · Risks & mitigations

RiskLikelihoodImpactMitigation
The adapter silently fabricates a plausible-looking provenance value, making a wrong fact more credibleLHThe only fallback for an underivable field is the literal TODO (D-004); a dedicated test asserts a no-license/no-origin source yields TODO, never a guess (SC-002, a MUST).
A re-run overwrites a human's hand-corrected provenance with a fresh TODO, or duplicates idsLMIdempotency judged by 051's parser: valid-id files skipped whole, index merged by id, non-TODO values never rewritten (D-005); an idempotency test re-runs on the adapter's own output.

9 · Complexity tracking

Anywhere this plan introduces complexity not strictly required by the spec, justify it here.
