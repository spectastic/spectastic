Cards

Empty registry array skips the pack-scan fallback in resolveCitation

Implementation code

Debugging a corpus citation that resolved to null even though its document is present in a pack, root cause was implementation drift — resolveCitation's if (registry) guard treats loadRegistry()'s empty-array return (what it yields when no root knowledge/index.md exists) as a loaded registry; fixed by guarding on registry.length > 0; regeneration passes — a faithful implementation of the documented "no registry → pack scan" contract would not conflate an empty registry with a present one.

Expected
resolveCitation(packs, citation, []), with the cited document present in a pack and no root registry on disk, resolves it via the full pack scan — the documented back-compat path (FR-003).
Actual
Returns null. The empty array is truthy, so the registry-authoritative branch runs; matchRegistry finds nothing (no rows) and only the superseded pack lookup runs — never matchCurrent — so a bare or current-edition citation never resolves.
Diagnosis
if (registry) at packages/corpus/src/knowledge/resolve.ts:87 conflates an empty registry array with a loaded one; 062 FR-006's registry authority applies only "with a registry loaded," and a no-rows registry should fall through to FR-003's pack-scan resolution.
Fix
packages/corpus/src/knowledge/resolve.ts — guard the registry-authoritative branch on registry.length > 0 so an empty registry is treated as "no registry" (equivalently, callers pass undefined for an empty registry).
Fixed
packages/corpus/src/knowledge/resolve.ts:110 now guards if (registry && registry.length > 0), so an empty registry array falls through to the pack scan instead of silently skipping it.
if (registry) { if (registry && registry.length > 0) {
Deep dive — impact across consumers (no cross-spec contract disagreement, no principle, no hotfix)

All specs agree on the intended behaviour (registry authoritative when loaded; pack scan otherwise) — this is a code defect, not a contract clash, so it is not a cross-spec gap. But the impact is broader than the one function: the 053 grounding gate's scanCorpusGrounding passes loadRegistry(cwd) straight through, so for any project with corpus packs but no root knowledge/index.md yet (a pre-migration project, or one that ran corpus adapt but never corpus import) valid citations resolve to null and surface as false corpus-provenance errors in shipped code today. The 064 get read-path shipped a local workaround (passing undefined for an empty registry); fixed at source — the guard now reads registry.length > 0, the get workaround is removed, and a regression test in knowledge.resolve-registry-only.test.ts pins the empty-array-is-no-registry behaviour. No spec change was required — the fix passes the regeneration test at the implementation layer.
