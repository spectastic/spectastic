Design · 052-corpus-citation-contract

Corpus citation contract

How we will build it.

Status Accepted Spec 052-corpus-citation-contract Owner Brian Corbin · @briancorbinxyz Branch 052-corpus-citation-contract Created 25 Jul 2026 Read time

Three small additions plus a text-only propose. A citation grammar (KB-NNN@edition) lands in @spectastic/schema as a shared ./citation subpath — following the slo-shared/./slo precedent exactly, because a schema rule needs it and schema is upstream of core. A corpus-citation-form HTML schema rule warns on a bare or malformed citation inside a <spec-decision>. Core's corpus loader gains a references/superseded/ walk into a separate supersededEditions collection (kept out of documents[] so 051's duplicate-id check never false-fires), and a resolveCitation() that resolves a pinned citation to the current or a retained prior edition. The one contract-lock-in risk is that 053–055 read this grammar and model, so the minimal shape is frozen now. The verified green label already renders from unchanged 051-era CSS — no rendering code ships.

4 · Approach

(1) The grammar — parseCorpusCitation(raw): CorpusCitation | null in a new @spectastic/schema/citation subpath (cloning slo-shared): recognises KB-NNN@edition, returns { id, edition } for a pinned citation and { id, edition: null } for a bare one, null for a non-citation. Placed in schema because both the schema rule and core's resolver consume it, and schema is upstream. (2) The form rule — corpus-citation-form, a per-file HTML rule in packages/schema/src/rules/: scans each <spec-decision>'s text for KB-\d{3,} references and warns on a bare (no @edition) or malformed one (FR-002's SHOULD-warn; SC-001's well-formed check). (3) The resolver + superseded loading — the corpus loader gains a references/superseded/ walk that parses prior editions into a new supersededEditions collection (never documents[]); resolveCitation(packs, citation) returns the current document when the edition matches, else a retained superseded edition, else null (FR-003, SC-002).

(4) The widening + verb binding — FR-001 is a /spectastic.propose → /spectastic.apply against 000 adding "a corpus source (KB-NNN@edition)" to REQ-LIFECYCLE-006's enumerated sources; FR-004's verb half edits commands/spectastic.design.md with the "MAY cite" binding and FR-005's domain-facts-only scope. No pack carries the binding (SC-003) — 051's scaffold already omits it; a test pins that.

5 · Alternatives considered

The one genuinely weighed choice: where the citation grammar and the form-scan live. Higher is better; the chosen row is marked.

OptionCorrect layerReuse (rule + core)Precedent fitTotal
Folded CLI scan in core (like 051's corpus-well-formed)2338
Grammar inlined in the schema rule only4127
HTML schema rule + shared ./citation grammar subpath — chosen55515

Citations live in <spec-decision> HTML, not the markdown corpus — so the HTML-bound schema registry is the correct layer, not a folded scan (the mechanism 051 needed for markdown). Inlining the grammar in the rule fails because core's resolver needs it too and schema is upstream. The shared ./citation subpath puts the grammar where both consumers reach it — the slo-shared pattern, verbatim.

6 · Decisions

D-001 · Citation grammar in a shared @spectastic/schema/citation subpath

Status
Accepted
Context
The corpus-citation-form rule (schema) and resolveCitation (core) both need the grammar. packages/schema/package.json has no core dependency — schema is upstream, so the grammar can't live in core. packages/schema/src/slo-shared.ts + the "./slo" export is the exact precedent (shared by a rule and a core scan).
Decision
Add packages/schema/src/citation-shared.ts (parseCorpusCitation) with a ./citation export subpath; the rule imports it directly, core imports it (core → schema is allowed).
Consequences
+ One grammar, both consumers, no cycle. + Follows an established, tested pattern. − One more schema subpath to maintain.

D-002 · corpus-citation-form as an HTML per-file schema rule

Status
Accepted
Context
A citation appears in a <spec-decision>'s Context — HTML, not the markdown corpus. The schema rule registry (packages/schema/src/rules/*) is exactly the HTML-bound path (each rule takes a ParsedDocument; cf. slo-well-formed.ts's textOf).
Decision
Add corpus-citation-form (per-file, warning severity): scan each <spec-decision>'s text for KB-\d{3,} references; warn on a bare or malformed one via the shared grammar. Register in rules/index.ts.
Consequences
+ Right registry for HTML content — no folded-scan misuse (the 051 scar, inverted). + No corpus needed to run (pure grammar check). − A KB-shaped string outside a real citation could warn; scoped to <spec-decision> + warning-only keeps a false positive cheap (§8 R4).

D-003 · Superseded editions: full text under references/superseded/, a separate collection, resolved in core

Status
Accepted
Context
051's loader (index.ts loadDocuments) is non-recursive, and corpus-well-formed (validate.ts duplicateIdFindings) flags two documents[] sharing a KB-NNN. A current + prior edition legitimately share an id.
Decision
Retain a prior edition's full text at references/superseded/<file>.md (its own edition in frontmatter). The loader walks that subdir into a new supersededEditions collection on the model — never documents[]. resolveCitation(packs, {id, edition}) returns the current doc, else a matching superseded edition, else null.
Consequences
+ A pinned citation resolves to the real prior text (SC-002). + 051's duplicate-id check is untouched and never false-fires. − An additive field on the frozen 051 model — expected (051's own R1 named 052–059 as its consumers); frozen minimal here (§8 R1).

D-004 · FR-001 widens 000 via propose/apply; FR-004's verb binding edits the plan verb

Status
Accepted
Context
REQ-LIFECYCLE-006 lives in 000, which is Accepted — P-6 forbids an inline edit. The citation-binding instructions live in commands/spectastic.design.md.
Decision
Realise FR-001 as a /spectastic.propose → /spectastic.apply against 000 (MODIFY REQ-LIFECYCLE-006 to enumerate a corpus source), the same path the 004 tree-count correction used in the 051 drain. FR-004's verb half edits plan.md (+ sync to .claude/) with the "MAY cite KB-NNN@edition" binding and FR-005's domain-facts-only scope.
Consequences
+ P-6-clean; the widening carries its own proposal audit trail. − Two apply cycles (000's, then 052's own) — the honest cost of touching an Accepted sibling.

D-005 · vitest, tests-first; no Playwright

Status
Accepted
Context
052 ships a grammar, a rule, a loader extension, a resolver, a verb-text edit, and a propose — no new interactive artifact. The grounded label is unchanged CSS. A test-style preference; no external fact (n-a).
Decision
Red-first vitest for the grammar, the rule, the superseded walk, and resolveCitation (incl. the superseded-resolves case = SC-002). One optional manual browser confirm of a fixture plan's green label; not a suite (the CSS is 051-era, unchanged).
Consequences
+ Fast feedback on the contract 053–055 depend on. − No browser evidence, correctly — there is no new runtime to exercise.

9 · Complexity tracking

Where this plan introduces complexity or deviates from a standing grain, the rationale.

A new schema ./citation subpath. Justified by a genuine two-consumer need (the HTML rule and core's resolver) and the upstream-schema constraint — not speculative surface. It clones slo-shared/./slo exactly, so it adds a known shape, not a new pattern.

The 051 corpus model gains a field. 051's own plan (R1) named 052–059 as the consumers that would extend its frozen contract; supersededEditions is that additive extension, kept minimal so 053–055 inherit a small, stable shape rather than a broad one.
