Specification · 052-corpus-citation-contract

Corpus citation contract

Cite an ID at an edition — so a domain fact becomes verified, and stays honest about which text it read.

Status Accepted Spec ID 052-corpus-citation-contract Owner Brian Corbin · @briancorbinxyz Reviewers — Created 25 Jul 2026 Principlesv1.8.0 Smallest demoableA plan decision cites KB-0001@2024-05-28 and renders verified (green). Read time

The corpus exists (051); this spec lets a decision cite it. It widens REQ-LIFECYCLE-006 so a design-bearing decision may name a corpus source as its verified source, defines the citation form KB-NNNN@edition — the project-assigned, opaque id (051 FR-002) resolved against the project's root registry, pinned to the exact edition the claim was grounded against — and the supersede-by-append rule that keeps a superseded edition reachable so a pinned citation never dangles. Crucially, the "cite this in a <spec-decision grounding>" binding lives in the harness (core + verbs), never in a domain pack, so a pack stays a clean, publishable unit. Grounding stays scoped to domain facts — a local product choice (a latency target) must not be forced to manufacture a citation.

1 · Context

REQ-LIFECYCLE-006 requires /spectastic.design to ground every design-bearing fact against real source, but the only sources it names are in-repo — the consuming code, a dependency signature, a platform constraint. A domain fact has nowhere to point, so it can only be assumed. With a corpus now in the repo (051), a domain fact has somewhere to point — but only if the grounding contract is widened to accept it, and only if the citation names which edition it read.

A citation is only as durable as the thing it points at, and things move. Scholarship and law have fought link rot for decades: a document gets superseded, or the corpus gets reorganised. The discipline that answers both is a persistent identifier plus an edition pin plus an archived copy plus supersede-by-append — the same convergence scholarship reached, mapped onto the corpus. This spec is that contract.

2 · User scenarios & testing

Each story MUST be independently testable.

US1 · A domain fact becomes verified P1

As a plan author, I want to cite a corpus source ID from a decision so that a domain fact becomes verified against something a reviewer can open, instead of permanently assumed.

Acceptance: a <spec-decision grounding="verified"> that cites KB-0001@2024-05-28 renders the quiet green grounded state, and the citation is well-formed.

US2 · The citation names which text P2

As a reviewer, I want the citation to name the edition it was grounded against so that when the document is later re-ingested at a newer edition, the historical decision still says, unambiguously, which version it read.

Acceptance: a citation of the form KB-NNNN@edition records the pinned edition; a bare KB-NNNN with no edition warns.

US3 · The binding stays out of the pack P3

As a domain-pack author, I want the "cite this in a <spec-decision grounding>" instructions to live in the harness so that my pack carries zero spectastic knowledge and stays a clean, publishable unit.

Acceptance: no citation-binding instruction appears in any corpus pack; the binding is emitted by core / the verbs.

Edge cases

  • A decision cites a corpus ID for a local choice (a latency target) — discouraged; grounding is for domain facts, not a ritual every requirement performs (FR-005).
  • A document re-ingested at a newer edition while an old decision still cites the prior one — the prior edition must remain reachable (FR-003).
  • An existing in-repo grounding source (code, lockfile) — unchanged and still valid; the widening is additive (NFR-001).

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional

REQ-LIFECYCLE-006's grounding MUST be widened so a design-bearing decision MAY cite a corpus source ID as its verified source.

Rationale

Closes the loop the considerations doc names: today a domain fact can only be assumed because every citable source is in-repo. The widening is realised as a proposal against 000-spectastic at apply time, since it modifies that spec's requirement text.

A corpus citation MUST take the form KB-NNNN@edition — the project-assigned, opaque KB-NNNN (051 FR-002) pinned to the edition the claim was grounded against. The citation MUST resolve against the project's root knowledge/index.md registry (051 FR-009), where the KB-NNNN is repo-unique — so resolution is deterministic, ending the array-order ambiguity a per-pack KB-NNN produced when two packs shared an id. The @edition MUST pin the document edition (the referenced document's provenance edition, FR-003), MUST NOT be the source marketplace's plugin version — the two are different axes (a plugin release need not change a document's edition, and an edition can change without one). A bare KB-NNNN without an @edition SHOULD warn. The id grammar (KB-\d{3,}) is unchanged; KB-NNNN (four digits) is the baseline.

Rationale

The scholarly "as of" access date, made machine-checkable — and now unambiguous: the pin resolves against the one repo-unique registry rather than whichever pack loaded first. Keeping @edition the document edition (not the plugin version) is the brief's edition-vs-version distinction: a version bump that leaves a document's text untouched must not appear to change what a decision read.

Re-ingesting a document at a newer edition MUST supersede by append — the prior edition, or at minimum its content hash and provenance, MUST remain reachable so an edition-pinned citation always resolves.

Rationale

Deleting the old edition while a decision still cites it manufactures a dangling reference. Keeping it (e.g. under references/superseded/) means a pinned citation always resolves to the text it actually named.

The citation-binding instructions — how and when to cite a corpus source in a <spec-decision grounding> — MUST live in core and the verbs, and MUST NOT appear in a domain pack.

Rationale

The moment a finance-settlement pack embeds "cite this in a <spec-decision grounding>" it stops being a clean, publishable domain skill. The binding belongs one level up, in the harness, so the pack is equally useful in a spectastic repo and in a plain Claude Code project. (The portable pack shape is 057.)

Grounding SHOULD remain scoped to domain facts — a local product decision (a latency target, a UX choice) MUST NOT be required to manufacture a corpus citation.

Rationale

A corpus asked to justify everything justifies nothing. A performance number is a local product decision, not a domain fact; forcing a citation there turns grounding into a ritual and hollows out the verified signal.

A tool that renders or validates a corpus citation SHOULD surface the reference's human label — its source marketplace, plugin, and slug (or its title) from the root-registry row — beside the opaque KB-NNNN@edition token, so a citation reads at its site without a mutable name in the id. The label MUST be derived at render / validate time from the registry, never stored in the token (the persistent-identifier rule: no semantic meaning in the id, so a rename cannot rot a citation). Where the registry is absent or has no matching row — a plain-agent context with no spectastic present, or a project whose corpus has not been imported yet — the label derivation is a no-op and the token renders opaque, which is acceptable: in a plain-agent context there are no spectastic citations to render (the binding is harness-side, FR-004), and before an import there is no row to draw a label from. The label lands ahead of the ingester that fills the registry (TBD-corpus-root-index-ingester) deliberately, as the contract for how a resolved citation reads — exactly as 051's registry convention landed ahead of its ingester.

Rationale

Resolves the tension a stable id creates: an opaque token is rename-proof but unreadable, and a readable token (a baked-in name) rots. Deriving the label from the registry at render time gets both — the citation is stable in the artifact and legible to the reader. should, not must: resolution (FR-002) is what correctness needs; the label is a readability affordance, and one only a spectastic repo with a registry present can offer.

Non-functional

The widened contract MUST be backward-compatible — existing in-repo grounding sources (consuming code, lockfile signatures, quantified platform constraints) remain valid and require no migration.

Out of scope (deferred to other slices)

  • The validate rules that a cited ID resolves (error) and that a pinned edition is current (warning).
  • Placing the corpus index in front of the model so it can cite in the first place.
  • The spectastic-agnostic pack shape that FR-004's split protects.

4 · Data model

The entities this feature owns or substantially changes.

Entities

Corpus citation
A reference from a decision/requirement to a corpus source. Fields: KB-NNNN (the project-assigned, opaque id, resolved against the root knowledge/index.md registry — 051 FR-009), edition (the pin, the referenced document's own, never the marketplace plugin version). Grammar: KB-NNNN@edition.
Edition
A dated version of a corpus document (e.g. 2024-05-28). The current edition is named in the index (051 FR-004).
Superseded edition
A prior edition retained by append (never overwritten) so an older pinned citation still resolves.

Invariant: an edition pin is immutable once written into a decision; the document may gain newer editions, but the pinned citation must always resolve to the exact text it named. Supersession is append-only.

5 · Success criteria

Technology-agnostic, measurable outcomes.

A plan decision citing a corpus reference by its project-assigned KB-NNNN@edition renders the verified (green) grounded state, the citation resolves against the root knowledge/index.md registry to exactly one document, and the edition-pinned form is confirmed well-formed.

After a document is re-ingested at a newer edition, a decision citing the prior edition still resolves to a retained copy — no dangling reference is produced.

No corpus pack in the repo contains any citation-binding instruction; the binding is emitted only by core / the verbs.

6 · Assumptions

Editions are identifiable by a stable marker (a date or version string) that both the frontmatter and a citation can name; documents without a natural edition can use the ingest date.

The existing <spec-decision grounding> machinery renders verified / assumed unchanged the moment a citation has somewhere to point — no new rendering component is needed.
