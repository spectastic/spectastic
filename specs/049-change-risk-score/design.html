Design · 049-change-risk-score

Change-risk score

How we will build it.

Status Accepted Spec 049-change-risk-score Owner Brian Corbin · @briancorbinxyz Branch 049-change-risk-score Created 18 Jul 2026 Read time

A pure @spectastic/core/change-risk module scans a unified-diff string for five red flags, scores them into a bounded 0–100 number with green/amber/red bands, and a thin spectastic change-risk CLI plus a git adapter feeds it the diff — mirroring the enforce/* fat-core/thin-CLI shape end-to-end. The biggest risk is false positives from the entropy/base64 detector (minified JS, base64 images, lockfile hashes); mitigated by a conservative threshold, the advisory-by-default posture, and tunable weights.

4 · Approach

A linear pure pipeline. A thin git adapter (execFile) resolves the diff — the uncommitted working-tree+staged diff by default, or a --range — and hands its text plus --numstat to a pure scan. The scan runs five independent detectors (binary blob, build-script/CI/packaging edit, install hook, entropy/base64 payload, new dependency) over the diff, each emitting RedFlagFindings with a tier. A scorer folds the findings into a 0–100 number and a band (thresholds from spectastic.json, with defaults). The CLI renders the report and resolves the exit code — 0 by default, non-zero only when an opt-in failAt is met.

The core stays a pure function of a diff string (no git, no clock, no network) so it is deterministic and unit-testable on fixture diffs; git and process I/O live in the adapter and the CLI edge — the same isolation worktree.ts keeps. Nothing here is a new artifact type, so P-4/P-11's HTML concerns don't apply.

6 · Decisions

D-001 · Pure-core scan over a diff string, thin git adapter + CLI at the edge

Status
Accepted
Context
The fat-core/thin-CLI convention and the enforce/* precedent (packages/cli/src/commands/enforce.ts:23); git-in-core is already sanctioned (coding/worktree.ts:32).
Decision
Core scan(diffText, numstat) is a pure function → findings → score. A getDiff() adapter (execFile('git', …)) and registerChangeRisk hold all I/O.
Consequences
+ Deterministic, unit-testable on fixture diffs; no new dependency. + One seam (adapter) isolates git. − A diff-string contract the adapter must feed correctly (covered by the CLI integration test).

D-002 · Core module layout change-risk/{types,diff,scan,score,config}

Status
Accepted
Context
A core module is a tsup entry + an exports subpath (tsup.config.ts:47, package.json exports["./enforce/*"]).
Decision
Add src/change-risk/{types,diff,scan,score,config}.ts, five tsup entries, and ./change-risk/* export subpaths — the enforce/* cluster's parallel.
Consequences
+ Tree-shakeable per-module imports; consistent with every other verb. − Five small files rather than one — the house style, not overhead.

D-003 · changeRisk typed section in spectastic.json, fail-safe loader

Status
Accepted
Context
loadWaivers (enforce/config.ts:119) is the fail-safe typed-section precedent; NFR-004 requires secure-by-default.
Decision
A changeRisk section with bands (amber/red thresholds) + failAt. A loader that clones loadWaivers: absent/malformed → defaults + advisory, never a throw, never silently off.
Consequences
+ Reuses a proven, tested shape; secure-by-default for free. − Defaults live in code (green<25/amber25–60/red>60), documented in the CLI help.

D-004 · Score model — per-finding saturating points, tunable

Status
Accepted
Context
Pure judgment — the spec deferred the weighting arithmetic to the plan and framed the numbers as tunable, not calibrated (FR-004, spec §6 assumption). No external source to cite; sanity-checked against the spec's bands.
Decision
Points per finding — high 40, medium 15, low 5 — summed and capped at 100. Repeated categories accumulate (breadth registers) but saturate. Maps onto the default bands: one high → amber, two → red, a lone new-dep → green.
Consequences
+ Explainable and monotone; easy to reason about a diff's number. − The constants are a v1 default, not validated; over-ridable via config, and the whole surface is advisory (opt-in gate). Recorded as a §9 assumption.

D-005 · Detection signals — numstat for binary/file-list, patch body for content

Status
Accepted
Context
Spike over a binary/manifest/hook fixture (§3): git diff --numstat flags binary as - -; the --no-color patch carries added + lines for manifest deps and scripts hooks.
Decision
Use --numstat for the binary flag + changed-file list; parse the unified patch's added lines for build-script paths, install hooks, dep manifests, and entropy/base64. Detectors are independent, path- and content-pattern based (NFR-002).
Consequences
+ Binary detection is exact (no heuristic); content detectors run on a stable format. − Entropy/base64 is the one heuristic detector — false-positive-prone (see §8).

D-006 · CI job advisory by default; fetch-depth: 0 for the range diff

Status
Accepted
Context
FR-009 (should-tier) reuses the 046 job shape (ci.yml:74); actions/checkout@v4 defaults to a shallow clone, so a --range merge-base needs fetch-depth: 0 (assumed — standard Actions behavior).
Decision
A change-risk CI job runs the built CLI over --range <base>..HEAD with fetch-depth: 0; exit 0 (advisory) unless failAt is set.
Consequences
+ Surfaces the score on every PR without failing the build. − The fetch-depth assumption is unverified here; a task validates the job actually resolves the base. Should-tier, so it warns not blocks.

D-007 · TDD red-first, fixture-diff suite

Status
Accepted
Context
The repo norm (047/048 plan D-005); a pure scan is ideal for it.
Decision
Write each detector's failing test first against a checked-in fixture diff; the CLI integration test drives the built binary over a real git range. SC-001..004 are the acceptance backstops.
Consequences
+ Behavior pinned before code; determinism (NFR-001) directly asserted by re-running a fixture. − Fixtures must cover the false-positive cases too (legit build edit, base64 image).

8 · Risks & mitigations

RiskLikelihoodImpactMitigation
Entropy/base64 detector false-positives (minified JS, base64 images, lockfile hashes)MMConservative length/charset threshold; advisory-only; low-noise weight; fixtures pin known-legit blobs as non-findings (D-007).
CI shallow clone lacks the merge-base for --rangeMMfetch-depth: 0 in the job; the scan errors clearly on an invalid range (spec edge case); a task asserts the job resolves the base (D-006).
Score constants mis-calibratedMLAdvisory + opt-in gate + config-tunable; recorded as a §9 assumption, not a claim of truth.
New-dependency detector varies across ecosystems (npm/pip/cargo/go)LLLow weight + saturating cap; manifest-path allowlist grown per ecosystem, defaulting to no-finding when unsure.

9 · Complexity tracking

Two deliberate choices beyond the literal spec.

The diff-string / git-adapter seam (D-001) is one extra boundary the spec doesn't mandate. It is justified by NFR-001 determinism and unit-testability — the core must be testable without a git repo — and mirrors worktree.ts's git isolation.

The score constants (high 40 / med 15 / low 5, cap 100) are a judgment default, not calibrated truth (D-004). They are config-tunable and the whole surface is advisory, so a wrong number costs a re-tune, never a false block.
