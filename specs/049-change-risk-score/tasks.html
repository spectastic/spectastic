1 · Execution strategy

Setup → Foundational → US1 only, then ship. US1 alone is the spec's smallest demoable: spectastic change-risk on an uncommitted diff prints findings, a score, and a band. US2 (--range + CI) and US3 (the opt-in gate) iterate after US1 is verified.

Setup → Foundational → US1 → US2 → US3 → Polish. Each story closes its conformance before the next opens. Recommended here — US2 and US3 both extend the same CLI command US1 builds, so building them in order avoids merge friction on change-risk.ts.

One team on the five scan detectors (US1 tests + scan.ts), one on the git adapter + config loader (Foundational), one on the CLI edge (US1/US2/US3 change-risk.ts). Coordinate at the scan()/score() signatures (plan §7), not Slack.
