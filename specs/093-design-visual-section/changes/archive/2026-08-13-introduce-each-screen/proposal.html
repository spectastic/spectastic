Introduce each screen

A design declares a path to screens and says nothing about them. A reader learns that screens exist, not what they are.

Introduce each screen

Applied

1 · Intent

A design declaring a visual surface names a path. Nothing requires it to say how many screens there are, what any of them is, or which story each serves. A reader arrives at the section and learns that screens exist somewhere.

This went unnoticed for a reason worth naming: the materialised view partly compensates, listing screen ids and their states in a table. A table of identifiers is not an introduction — it tells a reader what things are called after they already know what the things are. The generated half looked like coverage and hid the authored gap.

The neighbouring section already has this right. A <spec-contract> carries authored reasoning — boundaries, error shape, what a consumer may rely on — beside its declared path, and the template says in as many words that it is not a copy of the schema. The visual section takes the same shape and asks for nothing equivalent per screen.

2 · Scope

In scope

  • A design that declares a surface introduces each screen it addresses.
  • A check, because the screens are enumerable from the declared path.

Out of scope

  • Prescribing what the line says. A screen's description is authored prose and a template for it would produce filler. defer-to=never.
  • Requiring a description of every state. Eleven states with a mandatory line each is how a section becomes unreadable, and the states already carry their own prose where they are declared. defer-to=never.

3 · Approach

Required and checked, rather than recommended. The distinction is the whole point: the sibling gap this was found alongside — that nothing anywhere asks for a render — happened precisely because the expectation lived in command markdown, which the meta-spec and P-8 both exclude as a place a guarantee may live. A prompt that can be skipped, and was, is what produced the artifact that prompted this.

It is checkable without judgment. The declared screens path resolves, the screens in it are enumerable, and each carries an id. So "every declared screen is introduced" is a set comparison rather than an assessment of prose quality — the check can tell whether a screen was mentioned and deliberately cannot tell whether the mention was any good.

Landing after the screen-coordinate change makes the citation exact rather than by name. The requirement is written so it holds either way, so the two do not have to be sequenced to be correct — only to be at their best.

4 · Deltas

A design declaring a visual surface MUST introduce each screen that surface addresses, referring to the screen rather than only to the file that declares it, and a declared screen left unintroduced MUST be reported.

Rationale

The declaration names a path, and a path tells a reader that screens exist. What each one is, and which story it serves, is the thing a reader came for. The adjacent contract declaration already requires authored reasoning beside its path and says explicitly that it is not a copy of the schema; the visual declaration asks for no equivalent.

Required and checked rather than recommended, because the gap this was found beside — nothing anywhere asking for a render — exists exactly because the expectation lived only in command markdown, which P-8 excludes as a place a guarantee may live.

Checkable without judging prose: the screens are enumerable from the declared path and each carries an id, so this compares two sets. It can tell whether a screen was mentioned and deliberately cannot tell whether the mention was any good — which is the right limit for a machine here.

5 · Risk register

Self-run rather than delegated. Recorded rather than glossed.

A required line that cannot be judged becomes a line nobody means

The check can only see that a screen was named. Nothing stops the introduction being the screen's own id restated, which satisfies the requirement completely and helps nobody — and a mandatory field with a zero-effort satisfying answer trains people to give it. The already-required toggle field is the estate's own evidence: it reads as the literal string none in 50 of 61 verify views.

Mitigated. Two things narrow it. The obligation is scoped to screens a design addresses, so a project with one screen owes one line rather than a form to fill. And the requirement asks for an introduction rather than a description, which is a lower and more honest bar. The residue is real and is the reason the requirement stops at reporting an omission rather than assessing what was written.

It reaches into a file the design does not own

Enumerating the screens means reading the declared path, so this is cross-file work in a section whose other checks are per-file. A design that is correct today starts failing when somebody adds a screen to the sidecar without touching the design.

Accepted. That is the intended behaviour, not a side effect: a new screen the design has never mentioned is exactly the drift worth reporting. The cost is that the finding appears against the design when the change was made elsewhere, which is the same shape the existing drift check already has.

Narrow enough to have been folded into a neighbour

One added requirement. It could have ridden along with the screen-coordinate change, which it references.

Accepted. They target different specs — the coordinate belongs to the vocabulary, the introduction belongs to the design section — so folding them would put a delta in a spec that does not own it.

6 · Tasks

  • Enumerate declared screens from the declared path in the visual kernel scan.
  • Report a declared screen the design never mentions; say which screen and which design.
  • Add the per-screen introduction to templates/design.html and to the design command's visual questions.
  • Tests: silent when every screen is introduced; reports the one that is not; silent for a design declaring no surface; unaffected by a screen appearing only in the generated view.

7 · Open questions

None outstanding. Every decision was anchored in the interview.
