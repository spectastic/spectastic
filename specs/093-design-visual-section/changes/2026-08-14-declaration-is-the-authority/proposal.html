The declaration is the authority

Approved

1 · Intent

An independent pass found that FR-014 quietly reverses the rule the neighbouring convention was written to establish.

094 §4, verbatim: "Neither directory is a registry. Nothing enumerates their contents, and a file present but undeclared is invisible to every check here — … the reason the declaration rather than the filesystem is the authority." FR-014's obligation is to introduce each screen the surface addresses, and its check derives that set by enumerating the declared path. Where that path is a directory — the normal case — the declared set and the enumerated set are different sets: one is what the author claimed, the other is whatever is on disk.

It breaks the budget too. 094 NFR-001 permits "at most 1 filesystem call per declaration, and at most 0 directory walks". Enumerating needs a walk and then a parse of every file found, so a project pays a cost linear in files where the NFR promises linear in declarations.

The originating register raised the cross-file reach and accepted it as intended. The half it never asked was which set is authoritative — and accepting a drift check silently assumes the enumerated set is the addressed set.

2 · Scope

In scope

  • Deriving the obligation from what the design declares rather than from what is on disk.
  • Naming the severity, which the requirement omitted while both its siblings state one.

Out of scope

  • Where the check lives. This spec's own out-of-scope defers the screen family and their loud gaps to 095 by name, and reconciling that boundary is its own change. defer-to=TBD-screen-check-placement.
  • What a design does when the author genuinely does not yet know its screens — an assumption this spec records and this change makes load-bearing. defer-to=TBD-unknown-screen-set.

3 · Approach

Turn the check around. Instead of asking "which screens exist on disk, and were they all introduced", ask "which screens does this design introduce, and does each one resolve". The obligation stays exactly as strong for the case that motivated it — a design that names a path and describes nothing still fails — and the authority moves back to the declaration, where 094 put it.

The reversal also dissolves a hazard the original carried into its implementation. 099 materialises a table of screen identifiers inside the declaring element, so a scan looking for identifiers in the design would have had to carve an exclusion zone around content the tool generates into the very element it is scanning. That is the shape this estate has already paid for: verify-view-stale once counted a gap row's own anchor as evidence of the link it was reporting missing. Reading what the design declares rather than searching its text for tokens sidesteps it entirely.

Severity was simply missing. Both siblings say a violation "MUST be an error"; this one said only "MUST be reported", leaving the choice to whoever wrote the rule — and the difference is whether a pre-commit gate blocks on missing prose.

4 · Deltas

What changes: the obligation is derived from the declaration rather than from a directory walk, and the finding's severity is stated.

A design declaring a visual surface MUST introduce each screen it declares that surface addresses, referring to the screen rather than only to the file that declares it, and an introduced screen that does not resolve MUST be reported as an error.

Rationale

A declared path tells a reader that screens exist. What each one is, and which story it serves, is what a reader came for — the adjacent contract declaration already requires authored reasoning beside its path and says it is not a copy of the schema.

The obligation reads the declaration, never the directory. 094 §4 establishes that neither sidecar directory is a registry and that the declaration rather than the filesystem is the authority; the first version of this requirement enumerated the path instead, which reversed that silently and broke 094 NFR-001's zero-directory-walks budget. Turning the check around keeps the obligation identical for the case that motivated it — a design naming a path and describing nothing still fails — while the authority stays where the convention put it.

It also removes a hazard the enumerating version carried: the generated view materialises screen identifiers inside the declaring element, so a text scan would have needed an exclusion zone around content the tool writes into what it is scanning — the shape that produced a false positive in verify-view-stale once already.

Error severity, stated. Both siblings state one; this said only "reported", which left a pre-commit gate's behaviour to whoever wrote the rule.

5 · Risk register

The findings this corrects came from an independent critic; no second independent pass was run on the correction. Self-authored.

The reversal trades one blind spot for another

Reading the declaration means a screen file that exists and is never mentioned is invisible — which is precisely the drift the enumerating version would have caught, and the original register accepted the cross-file reach specifically because catching it was "the intended behaviour". That capability is given up here.

Accepted. 094 already decided this for the whole convention: an undeclared file is invisible to every check, deliberately, because the declaration is the authority. A check that reports an undeclared screen would be reasonable and belongs in 094 as a change to that posture, argued there — not smuggled in through a requirement about introductions.

An assumption this spec records is still load-bearing and still unaccepted elsewhere

§6 assumes authors know at design time which screens a feature touches, with an open question as the stated escape. A must-tier introduction obligation makes that assumption carry weight, and an open question does not satisfy a requirement. The corpus rule is explicit that a must-tier decision resting on an assumed fact needs an accepted risk naming who accepted it.

Accepted, here, by name. Which is the point: the first version left this unrecorded entirely. The narrower question — what a design does when the author genuinely does not know — is deferred as a named slug rather than answered badly under time pressure.

The boundary with 095 is still contradictory

This spec's out-of-scope defers the screen element family and their loud gaps to 095 by name — "this spec declares that screens exist and where; it does not describe one" — while FR-014 obliges a design to describe one and raises a gap when it does not. A reader of the out-of-scope block is told the opposite of what the requirement says.

Accepted and deferred. Reconciling it means deciding whether the introduction is a description, which is a real question rather than a wording fix, and answering it inside a correction would be the same over-reach being corrected. Named as a slug so it is findable.

6 · Tasks

  • Derive the introduced set from the design's declaration; no directory walk, preserving 094 NFR-001.
  • Report an introduced screen that does not resolve, as an error, naming the screen and the design.
  • Tests: silent when each introduced screen resolves; errors when one does not; silent for a design declaring no surface; asserts no directory walk occurs, since that is the NFR the first version broke.
  • Add the per-screen introduction to templates/design.html and the design command's visual questions — the nudge, explicitly not the guarantee.

7 · Open questions

None outstanding. Two genuine questions are deferred as named slugs rather than left open here.
