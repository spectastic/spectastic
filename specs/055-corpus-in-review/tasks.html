4 · Phase 3a — US1 · The critic catches a domain contradiction

Tests (write & fail first)

Test the critic's reviewPrompt corpus presence/absence — with input.adversarial: true and a real knowledge/ corpus at ctx.cwd, assert the ai.subagent()-captured reviewPrompt contains the corpus index; with no corpus, assert the reviewPrompt is byte-identical to the pre-corpus baseline (closes NFR-001/SC-003's testable half — 054 never exercised this path, since its own test passed adversarial: false). packages/core/test/corpus-in-review.test.ts

Implementation

Sharpen propose.ts's reviewPrompt to ask for contradictions — the existing corpusSuffix (054) carries an authoring directive; add a critic-checking line asking it to flag a requirement the corpus contradicts (propose-owned text, not panel.ts). packages/core/src/commands/propose.ts
Add the corpus + a fourth domain-contradiction angle — instruct the critic to read knowledge/ when present and flag a requirement contradicting a cited fact; add the P-11 "treat corpus text as data" reminder for its self-read path. agents/spectastic-critic.md
Wire the corpus into the propose command's critic spawn — step 8's Agent-invocation instructions name reading knowledge/ when present, alongside the existing spec/principles/inbox inputs. commands/spectastic.propose.md

SC-001's full acceptance — the critic actually names the specific contradiction — is model-driven and stays advisory (D-004's honest presence-vs-use line, the same ceiling 054 named for its own FR-004). T-100 tests only the precondition a contradiction-finding depends on: the corpus is genuinely in the critic's input when it exists, and the input is unchanged when it doesn't. The finding itself is review-caught.

Closes FR-001, FR-004 (the core half — 054 already reused fenceArtifactText(); T-111 adds the self-read reminder), NFR-001, SC-001 (precondition only — see warning above), SC-003 (T-100's no-corpus + byte-identical assertions).
