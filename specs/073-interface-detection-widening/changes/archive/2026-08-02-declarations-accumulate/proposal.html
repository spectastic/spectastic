Declarations accumulate, they do not shadow

One CLI-only feature can currently disclaim an API the project genuinely publishes — and the floor reads that as covered.

declaredInterfaceState walks specs/ newest-first and returns inside the first design carrying any <spec-contract>. Every earlier declaration is invisible, so a project has exactly one visible declaration set no matter how many designs assert one. That is not merely stale — it is a false pass on a floor: a project that declared path="openapi.yaml" in spec 005 and whose newest design is a CLI feature declaring shape="none" reads as declares no interface, and contractFirstCovered returns true on that basis. FR-003 says a declaration establishes "that a contract is owed and that one is not" in both directions; newest-wins lets one declaration silently void another, which is the direction FR-003 did not anticipate. This makes declarations compose: the project declares the union, and disclaims only when no design declares anything. A new FR-008 keeps the union honest at both ends of the lifecycle: an unresolved path from a Draft spec's design reports at advisory severity rather than gapping work in progress, a design belonging to a Superseded or Deprecated spec contributes nothing at all — so superseding a spec remains a working way to retire the contract it declared — and every finding names the spec that declared it.

Declarations accumulate, they do not shadow

Applied

1 · Intent

073 FR-003 made a design's declaration outrank inference, and it was right to: dependency presence cannot tell a publisher from a consumer, nor an owned contract from a vendored one. The implementation reads that declaration from the design artifact, and to get a single project-level answer it resolves the obvious way — newest spec directory wins, deterministic over zero-padded ids rather than mtime, so the verdict never depends on the clock.

For the boolean FR-003 needed, newest-wins is defensible. For anything that accumulates it is fatal, and it turns out to be unsafe even for the boolean. Because declaresNoInterface is computed only from the winning design, a per-feature declaration is silently promoted to a project-wide disclaimer:

specs/005-payments-api/design.html   <spec-contract shape="request-response" path="openapi.yaml">
specs/079-cli-flag/design.html       <spec-contract shape="none">

declaredInterfaceState(cwd)  →  { declaredPaths: [], declaresNoInterface: true }
contractFirstCovered(cwd)    →  true          // nothing owed. The API is invisible.

A shape="none" on a CLI-flag feature is an honest statement that this feature exposes no interface. Nothing in the artifact claims it speaks for the project, and reading it that way inverts what the author wrote. The floor then certifies a project that publishes an HTTP API as having no contract obligation — a false pass, on the category whose entire purpose is to catch exactly that.

This is also the substrate defect the placement survey found: a design corpus that shadows cannot accumulate a project map, and a map is built by union. But the fix stands on its own — the false pass exists today, in the shipped floor, whether or not anything is ever built on top of it.

2 · Scope

In scope

  • Composition semantics for declarations across designs: the project declares the union of declared paths, and disclaims an interface only when no design declares one.
  • A severity distinction for unresolved declared paths by the declaring spec's state, so the union cannot newly gap a project whose in-flight design names a contract not yet written.
  • Provenance on the finding — which spec's design declared the path — without which the severity distinction is not actionable by a reader.
  • Excluding designs belonging to Superseded or Deprecated specs from contributing at all, so superseding a spec remains a working way to retire the contract it declared.

Out of scope

  • FR-003's precedence order. Declaration still outranks inference, in both directions; only the composition of multiple declarations is being settled.
  • Any change to path detection, the event-driven signal set, or the advisory landing of FR-004. Inference is untouched.
  • Contract naming. Whether two designs declaring the same basename are the same contract is a separate concern, deferred as TBD-contract-key-stability.

3 · Approach

Replace the early return with an accumulation across every design, and compute the disclaimer from the whole set rather than from one member. A project's declaredPaths becomes the union; declaresNoInterface becomes true only when at least one design was read and none declared a path or a non-none shape. The precedence chain in contractFirstCovered is unchanged — declaration, then inference, then fail-safe — because only what the first step sees is changing.

The union makes one new failure possible: an in-flight design naming a contract path that has not been written yet would gap the project the moment the design is authored, which would make the floor punish work in progress. FR-008 resolves it along the seam P-6 already draws — a Draft spec is loose, a ratified one is locked — so an unresolved path from a Draft design reports at advisory severity rather than as a gap. That requires the state to carry which spec each path came from, which is a shape change to ContractDeclarationState and the reason FR-008 is a separate requirement rather than a clause.

Reading a spec's status is a new dependency for this module, and it must not become a parser dependency: detect.ts is the filesystem-facing detector and deliberately reads <spec-contract> attributes by regex rather than parsing, so a malformed design degrades to "declares nothing" instead of throwing. Status reads the same way, and an unreadable or absent status is treated as Draft — the conservative direction, since it can only downgrade a hard gap to advisory, never invent one.

4 · Deltas

Two deltas. FR-003's existing sentence is preserved verbatim and extended; FR-008 is new.

What changes: adds the composition clause. The precedence sentence is unchanged — what is new is that multiple designs compose rather than one winning.

Where a design declares an interface or a contract path, that declaration MUST take precedence over inference from dependencies or the filesystem — in both directions, establishing that a contract is owed and that one is not. Declarations MUST compose across every contributing design in the project (FR-008) rather than resolving to any single one: the project declares the union of the contract paths those designs declare, and MUST be treated as declaring no interface only when at least one contributing design was read and none declares one.

Rationale

Inference cannot distinguish publishing from consuming, nor a published contract from a vendored one. Only a declaration carries intent, and both false directions have been observed. The composition clause closes a case the original wording did not anticipate: a <spec-contract shape="none"> states that one feature exposes no interface, and resolving the project to a single design promotes that to a project-wide disclaimer — voiding an earlier declaration that a contract is owed, which is precisely the direction this requirement exists to protect. Union is the only composition under which a declaration cannot be silently cancelled by a later, unrelated one.

A design belonging to a spec in a Superseded or Deprecated state MUST NOT contribute a declaration. Among contributing designs, an unresolved declared contract path MUST gap the floor only where the declaring design belongs to a spec in a ratified state; where it belongs to a Draft spec the unresolved path MUST be reported at advisory severity instead. Every report of an unresolved declared path MUST identify the spec whose design declared it. A spec whose state cannot be read MUST be treated as Draft.

Rationale

Composing declarations across designs (FR-003) makes an in-flight design able to gap the project the moment it is authored, since a design routinely names the contract path a spec is about to create. Gapping a floor for work correctly in progress would make the honest act of declaring intent the thing that breaks the build — the surest way to train authors out of declaring. P-6 already draws this seam: a Draft is loose, a ratified artifact is locked, so a Draft declaration is an intention rather than posture. Advisory rather than silent because the signal is still worth surfacing. The terminal states sit at the other end of the same seam — superseding a spec is the act of retiring what it declared, so a Superseded or Deprecated design binding the project would make a contract impossible to retire through the lifecycle's own mechanism. The provenance clause is what makes the distinction usable — a reader told a path does not resolve cannot act without knowing which spec asked for it — and the unreadable-status fallback is deliberately the conservative direction, able only to downgrade a hard gap, never to invent one.

5 · Risk register

The proposal modifies a must-tier requirement, so the adversarial pass applies. Three findings.

Union semantics newly gap a project whose old design declared a contract path that has since legitimately moved or been retired. Under newest-wins the stale declaration was invisible; under union it fails the floor, and the project did nothing wrong.

"the project declares the union of the contract paths its designs declare"

The sharpest finding, and it is a real behavioural regression rather than a hypothetical. 073's own NFR-002 guards against exactly this shape — "at most 0 currently-covered projects may become gaps" — but scopes itself to path detection, so it does not literally cover declaration composition; the spirit plainly applies. Two things bound it. A retired contract should be retired from the design that declares it, and the resulting finding names that design (FR-008), so the remedy is local and obvious rather than a hunt. And the alternative — keeping a stale declaration invisible — is what produces the false pass this change exists to fix, so some projects becoming visibly non-compliant is the intended effect, not a side effect. Accepted knowingly; a migration note belongs in the implementing task.

Superseded and Deprecated specs' designs keep contributing declarations under union, so a contract retired by superseding its spec still binds the project. FR-008 as first drafted split only Draft from ratified and left the terminal states on the hard side.

"only where the declaring design belongs to a spec in a ratified state"

Upheld, and fixed in this proposal rather than deferred. The finding is right on the merits: superseding a spec is the lifecycle's act of retiring what it declared, so leaving those designs binding would make a contract impossible to retire through the mechanism built for exactly that — a worse defect than the one being fixed, and one this change would have introduced. FR-008 now excludes Superseded and Deprecated designs from contributing at all, alongside the Draft severity split, and the scope section carries it as an in-scope goal rather than an exclusion. The author confirmed the widening deliberately, since it decides more than the anchoring question asked; deferring would have shipped a known-wrong terminal-state policy in the interim.

Reading spec status pulls a new input into detect.ts, whose NFR-001 budget is under 500 ms and at most 0 network calls. Walking every spec directory to read both a design and a status is strictly more filesystem work than returning at the first match.

"Declarations MUST compose across every design in the project"

Real but small, and measurable rather than arguable. Newest-wins already walks the directory list and stops early only when a design carries a declaration — on the corpus that motivated this change most designs carry none, so the existing path frequently walks the whole set anyway. The added work is one extra small read per design that does declare, which is the rare case. NFR-001's budget stands unchanged and the implementing task measures against it rather than assuming; if it does not hold, the fallback is to read status only for designs that declare an unresolved path, which is strictly fewer reads than the naive form.
