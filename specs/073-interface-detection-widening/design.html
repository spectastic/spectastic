Design · 073-interface-detection-widening

Interface detection widening

How we will build it.

Status Accepted Spec 073-interface-detection-widening Owner Brian Corbin · @briancorbinxyz Branch main Created 01 Aug 2026 Read time

Three widenings to detect.ts and one to the seeded principle's copy. Broker dependencies join INTERFACE_SIGNALS; contract discovery grows a named-convention path list beyond today's root-plus-four shallow scan; and a design's own declaration is made to outrank both, in both directions — which is the only thing that can tell a publisher from a consumer, since the same kafkajs entry appears in each. The event-driven signals land advisory-only behind a severity split, so a real service that publishes gets warned without any existing project's verdict changing.

5 · Approach

Mostly data. INTERFACE_SIGNALS gains broker and managed-bus entries across the six ecosystems it already covers, each tagged so the event-driven ones can be treated as advisory. CONTRACT_DIRS is replaced by a named-convention path set that includes the ecosystem layouts today's scan misses — src/main/proto for Gradle and Maven, openapi/, protos/, graphql/, and the nested proto/<module>/v1 shape buf and Go projects use — expressed as explicit named segments with a bounded depth, never a recursive walk.

The precedence rule is the part that carries real weight. Before inferring anything, detection asks 070's reader what the design actually declared. A declaration that names a contract makes that contract owed even if the filesystem has nothing; a declaration of shape="none" establishes that none is owed even if a broker dependency is present. This is the only mechanism that can separate a publisher from a consumer, and it simultaneously fixes the mirror false-positive the companion survey found — a crate vendoring an upstream spec to generate a client currently reads as covered when it is a pure consumer. Finally the seeded principle's copy is corrected to name every format the detector already accepts.

6 · Alternatives considered

The load-bearing choice is how a widened contract search finds files without becoming slow or false-positive. Scored 1–5.

OptionFinds real layoutsBounded costFalse-positive riskTotal
Recursive walk for any contract-shaped file5117
Keep root-plus-four; require projects to move files15511
A named-convention path set, bounded depth — chosen44412

The recursive walk is the tempting one and the survey rejected it by name: it finds everything, including a vendored upstream spec in node_modules or a fixture directory, and its cost is unbounded on a large monorepo. The status quo scores well on safety and fails the requirement — FR-002 is explicit that detection follows the ecosystem's own layout rather than making a project rearrange itself to be detectable.

7 · Decisions

D-001 · Broker signals are added as data, per ecosystem, by deliberate export name

Status
Accepted
Context
detect.ts:459-511 shows the existing table matches a manifest substring per ecosystem. The observability category set a precedent worth copying: match the deliberate dependency (an exporter), never a transitive core library, because the latter false-positives.
Decision
Add broker and managed-bus client entries — Kafka, AMQP/RabbitMQ, NATS, Pulsar, SQS/SNS, EventBridge, Service Bus, Pub/Sub, Redis streams — across the six ecosystems, matching the client library a service deliberately depends on.
Consequences
+ Pure data; no control-flow change and trivially reviewable. + Extends to a new broker by one line. − A service reaching a broker through a framework abstraction is still missed; kept as a recorded ceiling per FR-007 rather than chased into false failures.

D-002 · Contract discovery widens by named convention with bounded depth

Status
Accepted
Context
detect.ts:426,441-453 — four directories, one level, non-recursive. Real layouts it misses are enumerable: Gradle/Maven src/main/proto/**, nested buf proto/<module>/v1/, Go api/proto/v1/, plus openapi/, protos/ and graphql/. FR-002 forbids unbounded recursion.
Decision
Replace the flat four-directory list with a named path set carrying explicit segments and a small fixed maximum depth. No recursive walk, and no directory not named in the set is ever entered.
Consequences
+ Finds the layouts ecosystems actually use, so a project is never asked to rearrange itself. + Cost stays bounded and predictable, protecting NFR-001. − The set needs occasional extension as conventions shift; that is a one-line data change, not a redesign.

D-003 · Event-driven signals land advisory-only, via the existing per-category mechanism

Status
Accepted
Context
FR-004 requires advisory-first. policy.ts:36,124 shows STRUCTURALLY_UNDETECTABLE is already an injectable per-category map consumed by evaluateEnforcement, extended twice before (coverage/Go, observability/Swift+C++).
Decision
Reuse that mechanism rather than inventing a severity system: a project whose interface is recognised only through an event-driven signal reports the contract-first gap at advisory strength and does not hard-fail. Promotion to the hard floor is a later, deliberate act.
Consequences
+ No new concept; the third user of a proven extension point. + A real event producer gets told, immediately, without breaking anyone's build. − Two strengths for one category means the report must say which applies; that is FR-004's intent, not a wart.

D-004 · A declaration outranks inference, in both directions

Status
Accepted
Context
Signals are substring tests against a manifest (detect.ts:459-511), so the same kafkajs entry appears in a publisher and a subscriber — producing and consuming are indistinguishable by inference. The design artifact is the only place that knows, and 070's reader makes it readable.
Decision
Consult readContractDeclarations() first. A declared contract establishes one is owed regardless of the filesystem; a declared shape="none" establishes none is owed regardless of dependencies. Inference runs only where the design is silent.
Consequences
+ Separates publisher from consumer, which no filesystem-only method can. + Fixes the mirror false-positive where a vendored upstream spec marks a pure API consumer covered. + Rewards declaring. − A project with no design gets inference only, exactly as today, so the benefit accrues to projects using the lifecycle.

D-005 · Amending 042 is the first task, not a side effect

Status
Accepted
Context
042's FR-014 records the narrow signal set and shallow scan as accepted ceilings. Widening them contradicts a past-Draft spec, which P-6 requires route through propose/apply rather than an inline edit.
Decision
A change proposal against 042 MODIFY-ing FR-014 is task one; the detection work follows it. The spec's own changelog notes this ordering.
Consequences
+ The estate never holds a spec asserting a ceiling the code has already crossed. + The amendment is the audit trail for why the ceiling moved. − One extra propose/apply cycle before code; correct rather than costly, and it is the reason this slice cannot be drained purely in parallel with its siblings.

10 · Complexity tracking

Advisory-first is not a P-9 softening. The distinction matters enough to state: P-9 forbids weakening a gate that currently catches something. These signals catch nothing today — a broker-only service is presently marked covered, not warned. Landing them advisory-first therefore moves a project from silence to a warning, never from a failure to a warning. No project that fails today starts passing. Promotion to the hard floor is named in the spec's own out-of-scope list as a later deliberate act, which is the honest sequencing rather than a permanent softening.

The producer/consumer distinction is only solved for projects that declare. D-004 fixes it where a design exists. A project with a broker dependency and no spectastic design still cannot be classified, and gets the advisory. That residual is exactly FR-007's recorded ceiling, and widening inference to close it would reintroduce the false failures this design is built to avoid.

The path set encodes conventions that will drift. Ecosystem layouts change, and a named set is a snapshot. This is accepted over a recursive walk because a stale entry costs a missed detection (a recorded ceiling) while an unbounded walk costs false positives and unbounded time on every run.
