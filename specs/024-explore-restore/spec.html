1 · Context

023 ships graduation's front half: classify a quarantined build, extract a Draft spec + plan with verified grounding, lift the quarantine, archive the exploration. Its budget went red, so it split the restore-task generation to this sibling — the last step of the explore loop (intent → build loosely → graduate → restore rigor).

"Restore" is path-appropriate (Pragmatic-Programmer, brief D-2): a tracer-bullet kept its code (refactor-to-comply), a spike kept only the learning (clean rebuild + retire the prototype). The classification was frozen at graduation; restore honours it, never re-asks. The judgment on where this lives — a mode of the existing /spectastic.tasks (reuse the lifecycle, don't fork it), made explicit so it can never silently emit the wrong shape — was settled by an adversarial judge over the brief's reuse principle.

2 · User scenarios & testing

Each story MUST be independently testable. Both are P1 — the two real restore modes.

US1 · Refactor a tracer-bullet to comply P1

As an explorer, I want restore to generate the tasks that bring my kept build up to the graduated spec so that a usable skeleton hardens in place under full rigor, nothing thrown away.

Acceptance: for a tracer-bullet, /spectastic.tasks <id> --restore writes a tasks.html of refactor-to-comply work — failing tests first for each requirement, then the changes to bring the kept build to the spec + the gates relaxed during explore (requirement IDs, INVEST, full principles, estimability + grounding) — each task naming a concrete file. The build is kept.

US2 · Rebuild a spike clean P1

As an explorer, I want restore to generate a clean-rebuild plan against the new spec so that a throwaway spike becomes a proper build, with the prototype retired honestly.

Acceptance: for a spike, restore writes a normal test-first tasks.html against the spec, plus an explicit task to delete explorations/archive/<id>/. The prototype is marked for deletion (a reviewable task the explorer runs), never auto-deleted.

Edge cases

  • Plain /spectastic.tasks <id> on a graduated id (no flag) — the archived classify marker is detected and an announced prompt offers restore vs a normal breakdown; it never silently emits the restore shape.
  • --restore on a non-graduated id (no archived marker) — refused; there is no classification to honour.
  • A graduated id whose specs/<id>/tasks.html already exists — refuse or confirm overwrite; never silently clobber a hand-edited tracker.

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional

Restore-task generation MUST be a mode of the existing /spectastic.tasks verb, not a new verb. /spectastic.tasks <id> --restore forces it; absent the flag, a graduated marker (explorations/archive/<id>/quarantine.json carrying classify) MUST trigger an announced prompt (restore vs a normal breakdown) before generating — and MUST NOT branch silently.

Rationale

Graduation feeds the existing verbs (don't fork the lifecycle); the explicit flag + announced prompt close the one hazard of overloading /tasks — a silently wrong-shaped breakdown. Adjudicated by an adversarial judge over the brief's reuse principle.

For a tracer-bullet, restore MUST generate a refactor-to-comply task list: test-first tasks per requirement, then tasks bringing the kept build up to the extracted spec and the gates relaxed during explore (requirement IDs, INVEST, full principles compliance, the estimability + grounding gates). Each task names a concrete file or directory.

For a spike, restore MUST generate a clean-rebuild test-first task flow against the new spec, and MUST include a task to delete the archived prototype (explorations/archive/<id>/) — marked for the explorer to run, never auto-deleted.

The classification MUST be read from the frozen archived marker (per 023 · FR-008), not re-chosen — restore honours graduation's immutable spike|tracer-bullet call.

The generated tasks.html MUST carry a visible banner naming its classification and the source archive, so a reader sees why the tasks are restore-shaped (the anti-silent-wrong-shape guarantee made legible).

Restore SHOULD reuse the existing /spectastic.tasks test-first machinery — each path opens with failing test tasks before implementation — rather than fork a parallel generator.

Non-functional

Restore is AI-coupled (it reads the extracted spec + plan to derive the tasks) and SHOULD require ANTHROPIC_API_KEY like /spectastic.tasks — the slash-command path uses the in-host session and needs no key.

Out of scope (deferred to other slices)

  • Restoring the non-task gates — the bundle's full rigor and the quarantine-lift returning the id to the gates (023 · FR-006). This slice generates the restore tasks only.
  • Re-classification or re-graduation — the classify is frozen at graduation (023 · FR-008); restore reads it, never re-decides.
  • A think-first discovery mode — a sibling at the front of the lifecycle, considered separately.

4 · Data model

This slice reads a graduated bundle + the archived classification and writes one tasks.html. It owns no new persistent entity.

Entities

Classification
spike | tracer-bullet, read from explorations/archive/<id>/quarantine.json (frozen at graduation). Decides the restore path.
Restore task set
The generated specs/<id>/tasks.html — a refactor-to-comply list (tracer) or a clean-rebuild flow with a prototype-deletion task (spike). Test-first; banner-labelled with the classification + source.

5 · Success criteria

Technology-agnostic, measurable outcomes.

100% of graduated bundles get a path-appropriate restore tasks.html — tracer → refactor-to-comply, spike → clean-rebuild — and the wrong shape is never emitted silently: the --restore flag or the announced prompt always gates the restore branch.

Every restore tasks.html names its classification and source archive (the banner) and opens each path with failing test tasks — the test-first gate, relaxed during explore, is back on.

The spike path always includes a prototype-deletion task, and no graduated build is auto-deleted — the explorer runs the deletion deliberately.

The classification is immutable (023 · FR-008); restore reads it rather than re-running the spike/tracer interview.
