Design · 024-explore-restore

explore restore — refactor or rebuild a graduated build to spec

How we will build it.

Status Accepted Spec 024-explore-restore Owner Brian Corbin · @briancorbinxyz Branch main Created 27 Jun 2026 Read time

Add a --restore mode to the existing tasks verb: it reads the frozen classify from the graduated exploration's archived marker and seeds the one AI-coupled tasksCommand kernel with a path-appropriate prompt — refactor-to-comply (tracer) or clean-rebuild (spike) — emitting a banner-labelled tasks.html. No new verb, no forked generator. The biggest risk is the AI quality of the refactor-to-comply path (reading a kept build); mitigated by a stub-AIProvider test that pins the prompt-seeding + banner, with author review before any box is ticked.

4 · Approach

The restore mode is a thin classification-aware front on the existing tasks generator. The CLI gains --restore beside --force; a new core helper reads the frozen classify from explorations/archive/<id>/quarantine.json (sibling to the live read gateOnQuarantine already does); and tasksCommand grows an optional restore input that swaps in a path-appropriate prompt — refactor-to-comply for a tracer-bullet (read the kept build, bring it to spec + the restored gates), clean-rebuild for a spike (test-first against the spec, plus an emitted prototype-deletion task). The output carries a banner naming the classification + source archive.

Triggering is explicit, never silent (the judge's condition on SC-001): --restore forces it on every path; absent the flag, a detected archived marker triggers an announced prompt on a TTY (the confirmStdin pattern), and a refuse-with-hint when piped/CI — where no prompt can run.

5 · Alternatives considered

Settled by an adversarial judge over the brief's "graduation feeds the existing verbs, don't fork" principle. Criteria scored /5: Reuse (does it extend the lifecycle vs fork it), Surface (verb/command-count discipline), Safety (can it emit the wrong shape silently).

6 · Decisions

D-001 · Restore is a mode of the tasks verb, not a new verb

Status
Accepted
Context
The generator is one AI-coupled kernel (tasks.ts:24-29) with an existing CLI option surface (tasks.ts:12-16). The brief commands reuse over fork; the judge scored A 14 vs B 10 (§5).
Decision
Add --restore to the tasks CLI verb and a restore input to tasksCommand. No new verb; the 8-verb surface holds (FR-001).
Consequences
+ Reuses the test-first machinery; + simple post-graduate mental model (run /tasks). − Adds graduation-specific branching to a core derivation verb, gated by D-002.

D-002 · Explicit trigger — flag, then TTY prompt, then refuse

Status
Accepted
Context
SC-001 forbids the wrong shape silently. The CLI can prompt on a TTY and degrade when piped — confirmStdin at implement.ts:117-127 returns false when !isTTY; @clack/prompts@0.9.0 is available.
Decision
--restore forces restore; absent it, a detected archived marker triggers an announced prompt on a TTY and a refuse-with-hint when piped/CI (FR-001, SC-001).
Consequences
+ No silent branch on any path; + reuses a proven TTY pattern. − The non-TTY refusal means a CI caller must pass the flag (acceptable — CI should be explicit).

D-003 · Read the frozen classify from the archived marker

Status
Accepted
Context
Graduate freezes classify in explorations/archive/<id>/quarantine.json (graduate.ts:104-108). The tasks CLI already reads the live marker via gateOnQuarantine (tasks.ts:34) — a different lifecycle state.
Decision
A new core helper reads the archived marker's classify; restore honours it, never re-asks (FR-004). A non-graduated id (no archived marker) refuses.
Consequences
+ The classification stays the single immutable call from graduation. − Two quarantine reads now exist (live for the gate, archive for restore) — §9 justifies the split.

D-004 · Seed tasksCommand by classification, don't fork it

Status
Accepted
Context
Generation is one ctx.ai.chat call (tasks.ts:159); a restore prompt is the same path with a path-appropriate preamble.
Decision
tracer-bullet → a refactor-to-comply prompt (read the kept build, close the gap to spec + restored gates); spike → a clean-rebuild prompt against the spec (FR-002, FR-003, FR-006).
Consequences
+ One generator, two prompts — the no-fork win. − Prompt quality is the dominant risk (§8), strongest on the refactor-to-comply path.

D-005 · A classification banner on the emitted tracker

Status
Accepted
Context
Pure output-shape judgment (no external fact) — the legible half of the anti-silent-wrong-shape guarantee.
Decision
The generated tasks.html opens with a banner naming the classification + source archive (FR-005), so a reader sees why the tasks are restore-shaped.
Consequences
+ A reviewer never wonders why the tracker looks unusual. − One more element in the template (trivial).

D-006 · Kernel-first + stub-AIProvider test style

Status
Accepted
Context
Test-style preference (the canonical n-a case). Mirrors the 023 graduate test pattern that caught a real prompt-regex bug.
Decision
Unit-test the deterministic legs (read archived classify, banner, refuse-without-flag, the spike deletion task) + a stub-AI test that the prompt is seeded by classification; CLI integration smoke per path.
Consequences
+ Pins SC-001/SC-002/SC-003 deterministically. − AI quality stays human-reviewed, not asserted (it can't be).

D-007 · The spike prototype is deleted by a task, never auto-removed

Status
Accepted
Context
The build lives at explorations/archive/<id>/ (frozen by graduate, graduate.ts). Destroying it silently would be unreviewable.
Decision
The clean-rebuild set emits a concrete delete-explorations/archive/<id>/ task the explorer runs (FR-003, SC-003).
Consequences
+ Non-destructive, reviewable. − The archive lingers until the explorer ticks the task (acceptable — it's quarantine-clean already).

9 · Complexity tracking

Anywhere this plan introduces complexity not strictly required by the spec, justify it here.

Two quarantine-marker reads now coexist: gateOnQuarantine reads the live explorations/<id>/ marker (the anti-ship gate), and restore reads the archived explorations/archive/<id>/ marker (the frozen classify). They are different lifecycle states of the same id, not duplication — a live marker means "still quarantined, refuse"; an archived one means "graduated, here is the immutable classification." Keeping them as separate small reads is simpler than one overloaded helper that branches on location.
