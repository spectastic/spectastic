15 tasks across four phases (no US3). Setup → Foundational → US1 (tracer · refactor-to-comply) → US2 (spike · clean-rebuild) → Polish. The foundation carries most of the weight — the restore plumbing (input shape, archived-classify read, banner, CLI trigger) is shared by both stories; each story is then the one path-appropriate prompt. Tasks marked [P] run in parallel. Story tests MUST be written and failing before implementation.

1 · Execution strategy

Setup → Foundational → US1 → US2 → Polish. The shared restore plumbing lands in Foundational; each story then adds its single prompt and closes its conformance before the next opens. Best fit — the two stories share almost all their machinery.

Foundational + US1 (tracer) end-to-end, ship, then US2 (spike). Viable because the tracer path is the harder one — proving it first de-risks the prompt approach.

Overkill here — after Foundational, the two prompt tasks (T-110, T-210) touch the same tasks.ts dispatch and are cheap; one engineer drains both.
