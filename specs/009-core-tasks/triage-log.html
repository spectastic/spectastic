Cards

Refuse-if-exists doesn't distinguish Draft from past-Draft destinations

Spec upstream

Cascade of 008/T-001: spectastic tasks's refuse-if-exists ceremony fires identically against a Draft tasks.html (no consumer commitments) and an Accepted one (locked contract). Same shape as the principles defect; fixed by the same FR pattern.

Expected
Re-running spectastic tasks <spec-id> against a Draft tasks.html edits in place (preserves task IDs; appends a one-line <spec-changelog> entry). Past-Draft destinations require --force or routing through /spectastic.propose.
Actual
CLI subcommand (packages/cli/src/commands/tasks.ts line 29–34) blanket-refuses if the file exists; only path through is --force (overwrite, treated as supersession) regardless of the destination's <spec-status>.
Diagnosis
009's spec doesn't differentiate Draft from past-Draft destinations. Per REQ-LIFECYCLE-004, Draft is the only state with no consumer commitments — in-place edit is the natural authoring loop. The cascade originated in 008/T-001; both bugs are the same shape.
Fix
Open /spectastic.propose against specs/009-core-tasks/spec.html: ADD an FR scoping refuse-if-exists to past-Draft destinations (mirrors the 008 FR-004 modification). Hotfix the CLI in the same PR — read the destination's <spec-status> attribute before deciding to refuse / overwrite / edit-in-place.
Closed by
P-6 ratification + 2026-06-16-p6-cascade-tasks (ADDED FR-012) + CLI hotfix at packages/cli/src/commands/tasks.ts via shared gateOnDestinationState helper (packages/cli/src/state-gate.ts).
Deep dive — cross-spec cascade

One of three cascade cards from 008/T-001. The version-policy half of 008's defect does NOT cascade to tasks (the tasks.html template carries no <b>Version</b> field). Only the Draft-aware refuse-if-exists half applies. The optional P-6 principle candidate flagged in 008's deep-dive would generalise this across all artifact-generating verbs; if elevated, the per-verb amendments collapse into one principles-driven cascade.
