Core tasks verb — task breakdown

Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 009-core-tasks Design design Branch main (squashed-snapshot pattern) Created 16 Jun 2026 Read time

19 tasks across five phases. Setup (4) → Foundational (3) → US1 kernel + CLI end-to-end (8) → US2 markdown MAY-Bash note (1) → Polish + release (5). Tasks marked [P] can run in parallel — different files, no in-flight dependency. Tests for a story MUST be written and failing before its implementation tasks start. Single PR per D-007; v0.1.0-pre.11 ships at the end of Phase 4.

1 · Execution strategy

Drive US1 end-to-end (schema helper, kernel function, CLI subcommand, tests green, bench green). That alone makes the slice shippable. US2 (markdown note) is a one-line documentation change; tag it off when convenient. Polish ships the version bump + tag + publish. Pick this one for solo work.

Setup → Foundational → US1 → US2 → Polish, each phase closing its conformance before the next opens. Slightly more ceremony than MVP-first; cleaner if multiple contributors are involved.

Not applicable — 19 tasks, single contributor expected. Listed for template completeness.

4 · Phase 3a — US1 · Maintainer runs the CLI subcommand P1

The smallest demoable: spectastic tasks <spec-id> end-to-end through the kernel, with deterministic IDs + phase structure and light AI for prose. Closes the architectural slice US3 implies too — the same kernel function the CLI calls is what a downstream MCP surface would import.

Tests (write & fail first)

Write packages/core/test/tasks.test.ts with stub ctx.fs + stub ctx.ai against the real specs/002-validate-cli/ spec + plan fixtures. Assert: five-phase output (per FR-005); deterministic phase IDs + task-ID ranges per D-002 + D-003; every FR/NFR/SC referenced by ≥1 task per FR-008 (covering D-005); uncovered-requirement path emits a <spec-warning>; malformed-chat-response path falls back to placeholder prose per D-004. Import via '@spectastic/core/commands/tasks' subpath. Tests fail initially because T-110/T-111 haven't landed. packages/core/test/tasks.test.ts

Implementation

Create packages/core/src/commands/tasks-phases.ts — pure function mapping the spec's FR/NFR/SC IDs and user stories to the six fixed phase slots (setup / foundation / us1..us3 / polish) per D-002, plus per-phase deterministic ID counter (start 1, 10, 100, 200, 300, 900) per D-003. No ctx, no LLM, no IO. packages/core/src/commands/tasks-phases.ts
Create packages/core/src/commands/tasks.ts implementing tasksCommand(input: TasksInput, ctx: KernelContext): Promise<TasksResult> per D-001: reads spec + plan via ctx.fs.readFile, parses with @spectastic/schema, calls extractSpecMetadata, runs the phase heuristic, invokes ctx.ai.chat() once per non-empty phase for task descriptions per D-004, emits a <spec-note> per US closing its FR/SC set per D-005, returns the structured TasksResult with rendered HTML. Docblock links to commands/spectastic.tasks.md per FR-011. Renderer logic lives in a sibling tasks-render.ts imported here. packages/core/src/commands/tasks.ts
Create packages/cli/src/commands/tasks.ts — spectastic tasks <spec-id> subcommand per FR-003. Resolves specs/<spec-id>/spec.html + design.html, builds ClaudeProvider + KernelContext, calls tasksCommand, writes specs/<spec-id>/tasks.html via ctx.fs.writeFile, prints the after-write report (path, total task count, parallel count). Friendly stderr + exit code 2 on missing spec/plan per the edge-case discipline in §2 of the spec. packages/cli/src/commands/tasks.ts
Write packages/cli/test/tasks.integration.test.ts — happy path against the real 002-validate-cli spec + plan with a stub provider. Asserts: file written; phase IDs + task-ID ranges match per SC-002; exit code 0; report message includes counts. Plus the missing-plan failure mode (exit code 2, helpful stderr). packages/cli/test/tasks.integration.test.ts
Run pnpm -r build end-to-end. Confirm core + schema + cli build cleanly; the new ./commands/tasks subpath emits its own bundle; CLI's typecheck consumes core's emitted .d.ts. packages/{core,cli,schema}/dist/
Run pnpm test and confirm: (a) T-011 schema unit tests pass; (b) T-100 kernel unit tests pass; (c) T-113 CLI integration test passes; (d) all existing tests stay green per SC-004. (test run)
Run pnpm bench and confirm all scenarios within budget per SC-003. init-help-cold-start p50 stays within ±20% of today's baseline — the lazy-loading regression guard per NFR-001 proving the new subpath export did not leak into the init code path. (bench run)
SC-001 manual smoke: run node packages/cli/dist/index.js tasks 002-validate-cli; diff phase IDs + phase ordering + task-ID ranges against today's specs/002-validate-cli/tasks.html. Structural compare (not wording) per the D-004 + risk-table carve-out. (manual smoke; structural comparison)
