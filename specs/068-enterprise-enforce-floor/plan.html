Enterprise enforce floor (dogfood)

How we will build it.

Status Accepted Spec 068-enterprise-enforce-floor Owner Brian Corbin · @briancorbinxyz Branch 068-enterprise-enforce-floor Created 29 Jul 2026 Read time

Mostly config + CI, with two small additive code changes and one cross-spec amendment. The nine-category floor is satisfied by: Biome (one biome.json covers formatter and linter), a vitest v8 + patch-coverage CI step (diff-aware, since vitest thresholds are project-level), a real Semgrep config (security — already a recognised signal), a one-row detector edit to see .github/dependabot.yml (supply-chain), an observability waiver, and the enterprise marker. The spike-forced piece: 047's quantified-NFR gate gains a config-declared convention floor so the marker doesn't redden 59 historical specs. Biggest risk: the Biome lint backlog is unmeasured — sized as the first task, then fixed to green.

Language(s)
TypeScript, ESM; Node ≥ 20; pnpm@9.15.0 monorepo (4 published packages + vscode).

Biome (formatter + linter, one config), @vitest/coverage-v8 (new devDep) + a patch-coverage step, Semgrep (CI action, not a dep), a dependency-audit gate. Vitest 2.1.9 (pinned).

n/a — config + CI wiring plus two additive code changes (a detector signal row in @spectastic/core, a convention floor in @spectastic/core's quantified-NFR gate) and one cross-spec amendment (047 text via propose).
Storage
Filesystem — config files, the .spectastic/profile.json marker, and a spectastic.json floor + waiver entry. No new store.
Testing
Vitest, TDD red-first for the two code changes (D-005); the config gates verified by running them green.
Coverage
Diff-aware: ≥ 80% of changed lines, and a change never lowers coverage of what it touches (FR-003) — never a universal project %. Scope: the four core packages.
Perf targets
The full required CI suite ≤ ~10 min on the standard runner (NFR-003); Biome is sub-second, coverage the main add.
Constraints
Deterministic gates (NFR-001); CI must stay green after landing (NFR-002); detector + floor changes strictly additive/non-breaking downstream.

4 · Approach

Add the config the detector already looks for, wire each as a blocking CI gate, make two additive code changes, and flip the marker — in that order, so the repo is green before it self-certifies. Biome lands first (biome.json + the backlog fix to green), then coverage (v8 + a patch-coverage CI step + a minimal thresholds block), then Semgrep (a real ruleset) and the one-row detector edit for Dependabot plus a dependency-audit gate. The 047 quantified-NFR gate gains a config-declared convention floor (read from spectastic.json) so the historical corpus is exempt; its 047 spec text is amended via propose. Only once enforce and a full-corpus validate both pass do we write .spectastic/profile.json = enterprise and the observability waiver. Finally, reconcile principles.html against the enterprise catalog via the principles verb.

6 · Decisions

D-001 · Biome for formatter + linter

Status
Accepted
Decision drivers
one config satisfies both enforce signals · speed + single devDep · the enterprise frameworks: staff-level axis · SonarJS-parity tradeoff
Considered options
  • Biome (chosen) — + one biome.json covers formatter and linter (detect.ts:45,49); + Rust-fast, one devDep. − not full SonarJS parity.
  • ESLint + Prettier + eslint-plugin-sonarjs — + exact SonarQube discipline the code follows; + mature. − two tools/configs/devDeps, slower.
  • oxlint + Prettier — + fastest. − least mature, partial rules, two tools.
Context
detect.ts:45,49 — biome.json is the recognised signal for both categories. The code was written under SonarLint (CLAUDE.md cites S1515), so tool choice sets what "green" means (FR-002).
Decision
Biome, one config, both categories; codebase brought to green under its recommended + a tuned ruleset.
Consequences
+ Minimal config/deps, fast CI, one detector-covered file for two categories. − Loses exact SonarJS parity; a one-time backlog fix reconciles the rule delta (§8 R1).

D-002 · Diff-aware coverage via a patch-coverage CI step, not project thresholds

Status
Accepted
Context
Vitest thresholds are project/glob-level, not per-changed-line; the spec forbids a universal project % (FR-003). @vitest/coverage-v8 is not yet installed.
Decision
Generate lcov via @vitest/coverage-v8; a CI patch-coverage step computes coverage of the PR's changed lines and fails below 80%. A minimal thresholds block is present only to satisfy the detector's coverage signal, not as the gate.
Consequences
+ True changed-line 80% + never-lower, self-hosted, no external service. + The detector sees coverage configured. − Two coverage concepts (detector signal vs the real gate) documented to avoid confusion.

D-003 · The 047 convention floor is config-declared, not data-derived

Status
Accepted
Context
verify-view-missing.ts:54-65 derives its floor from an artifact signal; the quantified-NFR gate has no clean equivalent (specs 048–067 without <spec-slo> would misbehave). The gate lives at validate.ts:434.
Decision
The quantified-NFR gate reads an explicit floor (a spec number) from spectastic.json; specs below it are exempt, at/above are gated. Auditable, mirrors the waiver's recorded-and-justified ethos; moving it is a config edit.
Consequences
+ Honest, legible, no magic constant; + unblocks self-certification without a corpus rewrite. − A new small config shape (a floor field) the rule reads; the 047 spec text is amended to describe it (D-006).

D-004 · Recognise Dependabot as a supply-chain signal — one additive detector row

Status
Accepted
Context
signalMatches uses join(cwd, sig.file) (detect.ts:274), so a .github/-prefixed signal file works with no engine change. The detector only ever adds coverage.

Consequences

9 · Complexity tracking

The only structural subtlety is that "coverage" resolves two ways — a thresholds block the detector reads (so enforce sees the category covered) and a separate patch-coverage CI step that is the real diff-aware gate (D-002). This is justified by FR-003's explicit "no universal project %" against vitest's project-level thresholds, and documented so a reader doesn't mistake the detector signal for the gate. Everything else clones an in-repo precedent (the detector table, the verify-view-missing floor, the existing CI job shape, the waiver mechanism).

Reconciling principles.html against the enterprise catalog (FR-008) yields a handful of genuinely-missing, scope-applicable additions (formal accessibility conformance is the likely one — the repo already runs axe-core) and several recorded-not-applicable notes (SLOs, structured observability for a CLI) — not a wholesale rewrite. The audit is bounded; the amendment goes through the principles verb.
