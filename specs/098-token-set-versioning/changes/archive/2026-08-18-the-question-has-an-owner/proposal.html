The question has an owner

This spec still says a question lives elsewhere, and elsewhere now answers it.

Status Applied Change ID 2026-08-18-the-question-has-an-owner Spec 098-token-set-versioning Author Brian Corbin · @briancorbinxyz Created 18 Aug 2026 Targets 1 content delta Read time

098's out-of-scope block defers “importing a token set from a design tool, and what its version means on arrival”. 105 FR-016 now answers exactly that, so the deferral points at a question that has been settled. One content delta, and the second half of a fix that was dropped once.

The question has an owner

Applied

1 · Intent

This is the half that was missing. 105/T-011 put it plainly — “Either 098 grows a writer and 105 calls it, or 105 owns the write and 098's out-of-scope is amended to say so. Not both, and not neither” — and the amendment that followed did the first half only. T-013's own diagnosis records the omission.

105 owns the write, as of the proposal applied alongside this one. So 098 saying the question lives elsewhere is now false in a way a reader acts on: someone looking for what an arriving version means is sent away from the spec that answers it.

2 · Scope

In scope

  • Pointing the out-of-scope entry at the requirement that now owns the question.
  • Growing a writer here. That was the other branch of T-011's fork and it was not taken: this spec ships a reader and a refusal, and 105 states the properties its write must satisfy.
  • Checking that an arriving version agrees with its declared change class. Neither spec owns this, deliberately — deciding it is an ordering, which NFR-001 forbids at must tier.

3 · Approach

A content delta rather than a requirement change: the out-of-scope block is prose about what this spec does not cover, and what it does not cover has not changed — only where the reader should be sent. Applying this touches no requirement body.

The two proposals are applied in one session on purpose. A cross-spec obligation split across sessions is how the first half landed alone, and the card that recorded it is the reason this one exists.

4 · Deltas

One content delta. The target names a section rather than a requirement, so it carries a <spec-diff> and no <spec-requirement>.

What changes: the entry stops deferring a settled question and names its owner. The boundary itself is unchanged — importing a token set is still not this spec's work.

Importing a token set from a design tool, and what its version means on arrival. Importing a token set from a design tool. What its version means on arrival is answered by 105 FR-016 — the confirmer supplies it, and this spec's NFR-002 refuses an absent or unreadable one. Whether a supplied version agrees with its declared class is deliberately unowned (TBD-version-class-agreement), because deciding it is an ordering NFR-001 forbids.

The added sentence is what stops the next reader repeating the loop: it says who answers, what this spec still contributes, and which part nobody has taken.

5 · Risk register

The adversarial heuristic does not fire: one content delta, no requirement touched, no removal, one topic prefix. Recorded rather than skipped silently.
