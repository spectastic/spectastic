22 tasks across four phases. Setup → Foundational → User stories (US1·US2·US3) → Polish. Tasks marked [P] can run in parallel. Tests for a story MUST be written and failing before its implementation tasks start.

1 · Execution strategy

Setup → Foundational → US1 → US2 → US3 → Polish. US1 is the version and its forward-only binding; US2 is the guard; US3 is deprecation, which is mostly a matter of using the token format's channel rather than inventing one.

US1 alone makes bumping affordable, which is the point of the whole spec. The guard matters once more than one person is amending.

Not applicable. One artifact, two rules, one guard.

4 · Phase 3a — US1 · A bump does not reopen finished work

Tests (write & fail first)

Write the shape rule's tests red — a missing version errors, a missing binding errors, a change class outside the three tiers errors, and a policy stated nowhere in the artifact errors. packages/schema/test/token-set-shape.test.ts
Write the forward-only binding test red — a screen stamped with an earlier version stays conformant to that version after a later one lands, and the version it was built against is recoverable. packages/schema/test/token-set-shape.test.ts

Implementation

Implement the token-set shape rule — reading the parsed document it is handed rather than re-parsing. packages/schema/src/rules/token-set-shape.ts
Require the bump policy in the artifact — as the element's own prose, because a policy living elsewhere is one nobody reads at the moment of bumping. packages/schema/src/rules/token-set-shape.ts
Accept the binding stamp on a screen — recorded per screen, since two screens in one feature may be accepted months apart under different versions. packages/schema/src/rules/token-set-shape.ts
Style the token-set and release cards — with the change class rendered as the producer's claim, cloning the wording an existing element already uses. assets/spec.css

6 · Phase 3c — US3 · A rename does not break a consumer overnight
