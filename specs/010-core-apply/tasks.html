Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 010-core-apply Design design Branch main (squashed-snapshot pattern) Created 16 Jun 2026 Read time

21 tasks across five phases. Setup (3) → Foundational (3) → US1 apply mode end-to-end (8) → US2 withdraw coverage (1) → US3 slash-command doc note (1) → Polish + release (5). Tasks marked [P] can run in parallel — different files, no in-flight dependency. Tests for a story MUST be written and failing before its implementation tasks start. Single PR per D-008; v0.1.0-pre.12 ships at the end of Phase 4.

1 · Execution strategy

Drive US1 (apply mode) end-to-end: kernel function + CLI subcommand + tests green + bench green + byte-identity smoke. That alone makes the slice shippable for the common case. US2 (withdraw coverage) is a discrete test file against an implementation already in place via the discriminated union; US3 is a one-line markdown update. Polish ships the version bump + tag + publish. Pick this one for solo work.

Setup → Foundational → US1 → US2 → US3 → Polish, each phase closing its conformance before the next opens. Slightly more ceremony than MVP-first; cleaner if multiple contributors are involved.

Not applicable — 21 tasks, single contributor expected. Listed for template completeness.

3 · Phase 2 — Foundational

Shared types + IO interface broadening that the kernel function depends on. T-010 first; T-011 + T-012 follow.

Extend packages/core/src/types.ts with ApplyInput, WithdrawInput (discriminated union on literal mode per D-004), ApplyResult (including crossSpecWarnings: string[] per D-006), DeltaApplication entry shape, and typed errors RiskGateError + DeltaTargetError. packages/core/src/types.ts

Add optional ctx.now(): () => Date to KernelContext per D-007; default to () => new Date() when caller omits it. Lets tests inject fixed dates for deterministic changelog entries. packages/core/src/types.ts

The smallest demoable: extract apply end-to-end with byte-identical output against the archived corpus.

Import via '@spectastic/core/commands/apply' subpath. Tests fail initially because T-111 hasn't landed. packages/core/test/apply.test.ts

Implementation

Create packages/core/src/helpers/html-edit.ts with pure functions per delta op (added / modified / removed / renamed) plus status-flip and changelog-append helpers — targeted string replacement on stable anchors per D-001. No parse5; no AST round-trip. packages/core/src/helpers/html-edit.ts
Create packages/core/src/commands/apply.ts implementing applyCommand(input: ApplyInput | WithdrawInput, ctx: KernelContext): Promise<ApplyResult>: parse discriminated-union input (D-004); run risk-status gate (D-005); apply each delta deterministically via helpers from T-110 (D-001); rename the folder via ctx.fs.rename last (D-002, D-003); append changelog entries with timestamp from ctx.now (D-007); rewrite intra-spec RENAME cross-refs; surface cross-spec drift as warnings (D-006). Docblock links to commands/spectastic.apply.md per FR-014. packages/core/src/commands/apply.ts
Create packages/cli/src/commands/apply.ts exposing spectastic apply <slug> and spectastic apply --withdraw <slug> --reason="…" subcommands via commander. Constructs KernelContext, translates flags into the discriminated-union input, calls applyCommand from @spectastic/core/commands/apply, formats ApplyResult + warnings to stdout, maps typed errors to exit codes. packages/cli/src/commands/apply.ts
Write packages/cli/test/apply.integration.test.ts end-to-end against real archive/ fixtures in a temp dir: both apply and withdraw invocations, exit-code mapping, stdout formatting, risk-gate refusal path. packages/cli/test/apply.integration.test.ts
Run pnpm -r build end-to-end. Confirm all packages build cleanly; types resolve across workspace edges; CLI's typecheck consumes @spectastic/core's emitted .d.ts for the new subpath. packages/{core,cli,schema}/dist/
Run pnpm test and confirm: (a) T-100 kernel unit tests pass; (b) T-113 CLI integration tests pass; (c) all pre-existing tests stay green. (test run)
Run pnpm bench and confirm all scenarios within budget. init-help-cold-start p50 stays within ±20% of its 52 ms CI baseline (the lazy-loading regression guard per NFR-001) — proves the apply subpath isn't eager-loaded onto init. (bench run)
SC-001 byte-identity smoke: for every proposal under specs/000-spectastic/changes/archive/, snapshot the pre-apply live spec, run applyCommand against the snapshot, and diff against the current archived state. MUST be byte-identical per SC-001. (manual smoke; output comparison)
