Cards

The author summary is written into the changelog unescaped, so a < in it corrupts the spec

Implementation code

Debugging four validate errors that appeared immediately after a clean apply, root cause was --summary being interpolated into the changelog <span> verbatim, so element names in the summary text became real elements in the artifact; fixed by escaping the summary before it is written; regeneration passes — nothing upstream says the summary is HTML, and escaping untrusted text before interpolation is ordinary practice a session would apply.

Expected
An apply that reports success leaves the spec valid. The summary is prose the author wrote at a shell prompt, so it is data to display, not markup to honour.
Actual
A summary describing a change to <spec-contract> and <spec-visual> put those tags into spec.html as live elements. Four errors followed at once — an unclosed <spec-decision>, two declarations missing required shape=, and a visual-section-gated finding reporting that a spec with no user interface was carrying a Visual surface section. The apply itself reported success.
Diagnosis
The kernel builds the changelog entry by string interpolation and escapes the slug and the date but not the summary, which is the one field carrying free prose. The failure is loud rather than silent, which is the saving grace — validate caught it on the next run — but the artifact was already written and committed by the same invocation, so the corruption reaches the repository before anything reports it. Any summary describing element-level work hits this, which is most summaries in a project whose artifacts are made of custom elements.
Fix
packages/core/src/commands/apply.ts — escape the summary before interpolating it, using the same helper the rest of the codebase uses for text that lands in an artifact. A test with a summary containing < pins it; the escaping must not reach the slug or the anchor, which are structural.
Deep dive — the same field is written by a second surface

No cross-spec contract; no principles amendment. Worth checking alongside the fix: the withdraw path and the principles-apply path write changelog entries through the same shape, and the proposal generator writes author-supplied prose into artifacts elsewhere. Whether they share the defect is unmeasured here — asserting it without looking would be the error the card next door was filed for.
