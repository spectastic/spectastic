Record the quantified-NFR convention floor

Applied

1 · Intent

068-enterprise-enforce-floor's own plan spike (grounding table, §3) ran quantifiedNfrFindings against this repo's full spec corpus and found 104 unquantified NFR-* requirements across 59 specs — including 068 itself, whose own NFR-003 ("~10 min") prose doesn't satisfy the checker's measurable-target pattern. FR-004 as written has no floor: it gates every spec once a verified/enterprise profile marker exists anywhere in the project, tier-only. Writing that marker (068's own US2 goal) would retroactively turn every one of those 59 pre-existing specs red for a convention none of them were authored against — the exact failure mode verify-view-missing already solved once, for a different rule, the same way: exempt what predates the convention, gate what comes after.

This proposal makes 047's own text describe the mechanism 068 needs to build: FR-004 is amended to name an optional config-declared floor. The code implementing it (a ctx.floor parameter quantifiedNfrFindings reads, and a spectastic.json validate.quantifiedNfrFloor reader in the CLI) ships in 068's own drain, sequenced separately per plan D-006 — this proposal is the required text amendment for 047's Accepted spec, not the implementation.

2 · Scope

In scope

  • Amend FR-004 to describe the optional, config-declared convention floor: a spec whose leading directory number is below the configured floor is exempt from the gate; a spec at or above it, or a project with no floor configured, is unaffected.
  • Name the precedent explicitly (mirrors verify-view-missing's own floor) so a future reader of 047 understands why the shape looks the way it does, without needing to cross-reference 068.

Out of scope

  • The floor's actual value (069) and its implementation (packages/core/src/commands/validate.ts, packages/cli/src/commands/validate.ts) — that's 068's own drain, sequenced after this text amendment per plan D-006. Deferred to 068-enterprise-enforce-floor.
  • Making the floor data-derived the way verify-view-missing's is (from the lowest spec already carrying the signal artifact) — 068's plan D-003 found no clean equivalent signal for quantified-NFR the way verify.html exists for verify-view-missing, so config-declared is the deliberate, recorded choice, not an oversight.

3 · Approach

A single corrective MODIFY on FR-004, no ADD/REMOVE. The existing normative body (resolve the profile, gate at verified/enterprise, inline-or-linked acceptance, fail-safe below verified or with no marker) is preserved verbatim; one clause is appended describing the floor as an optional refinement of the same rule, not a new rule. This keeps 047's single-requirement shape for the quantified-NFR gate intact — the floor is a qualifier on when FR-004 fires, not a second mechanism.

4 · Deltas

One <spec-delta> per requirement touched. target= links to the live spec. op= is one of added | modified | removed | renamed; a missing or invalid op renders visibly broken.

What changes: one clause is appended naming the optional config-declared convention floor and its verify-view-missing precedent. The existing tier-gating and inline-or-linked acceptance clauses are unchanged.

A profile-gated quantified-NFR rule SHOULD resolve the project's profile from .spectastic/profile.json and, at the verified/enterprise tiers, flag at error severity any NFR-* requirement that is neither inline-quantified (a number+unit, percentile, or threshold in its prose or its slo= attribute) nor refined by a linked <spec-slo>. Below verified, or with no profile marker, it MUST be a no-op (fail safe in the advisory direction, mirroring the enforce-waiver scan). The rule MAY additionally resolve an optional config-declared convention floor — a spec number recorded in spectastic.json — and exempt any spec whose leading directory number is below it, mirroring verify-view-missing's own precedent of exempting the specs that predate a convention. A spec at or above the floor, or a project with no floor configured, is gated exactly as before.

Rationale

Tier-gating needs the profile, which the schema engine never sees — so this is a folded CLI scan (like enforce-waiver-well-formed), not a schema PerFileRule. The inline-OR-linked acceptance keeps the heuristic from false-failing a legitimately SLO-linked or thresholded NFR. The floor exists because a project adopting this gate after already carrying an unquantified historical corpus — exactly this repo's own case — would otherwise see every historical spec turn red on the day the profile marker is written; verify-view-missing solved the identical shape of problem for a different rule, so the floor follows its precedent rather than inventing a new one. It is config-declared rather than data-derived: unlike verify-view-missing, which derives its floor from the lowest spec already carrying a verify.html, there is no equivalent signal artifact for quantified-NFR to derive a floor from.
