047's own canonical <spec-slo> example fails slo-well-formed, and the golden-signal vocabulary rejects terms 047 uses as objectives

Spec upstream

Debugging why landing a valid <spec-slo> took three validate round-trips, root cause was a spec-level divergence: 047's documented authoring surface contradicts the contract it defines. The canonical example in §3 puts objective in <dt>/<dd> content, but plan D-003 makes it an attribute — so copying the example errors "missing required objective=". Separately, §2 edge case names an "availability objective" while signal= accepts only the Four Golden Signals, so signal="availability" is rejected. Fixed by reconciling 047's example + signal guidance with the validator; regeneration fails — another author copying the spec's own example reproduces it.

Expected
047's canonical example is copy-paste valid, and the signal vocabulary matches the objective terms the spec itself uses; a first-time author lands a valid <spec-slo> in one pass.
Actual
Three validate round-trips: the canonical example errors on slo-well-formed ("missing required objective=" — it shows <dt>Objective</dt><dd>99%</dd> instead of objective="99%"), and signal="availability" is rejected as not a Four Golden Signals value.
Diagnosis
The spec's illustrative material diverges from the contract the spec defines: slo-well-formed (FR-002) correctly enforces D-003's "scalars-as-attributes, SLI-as-content" shape and the four-golden-signals signal= enum, but the §3 example uses the <dt>/<dd> shape and §2 references an "availability objective" that reads as a signal. Excellent error messages keep it friction, not a blocker.
Fix
/spectastic.propose on 047-slo-nfr-artifact: (a) correct the §3 canonical example to the attribute shape (objective="99%"; SLI as content) so it validates; (b) reconcile the signal vocabulary — clarify in the FR-002 material and the §4 data-model note that availability/throughput are objective concepts mapping onto errors/traffic, not signal= values, or decide to widen the enum (a contract change). Owned by FR-001/FR-002. The validator (packages/schema/src/rules/slo-well-formed.ts, packages/schema/src/slo-shared.ts) is correct and stays put.
Deep dive — none required

No cross-spec contract conflict (048 consumes <spec-slo> and the golden-signal exports correctly — it does not disagree on the contract), no principles invariant violated (the attribute shape was chosen to honour P-4: scalars render via CSS attr() with no JS fallback), no deferred scope exposed, no hotfix-before-amendment needed. Accuracy note: the report cited throughput as appearing in 047's material; it does not (only availability does, at §2) — throughput is folded into the fix as the other intuitive-but-rejected term to address.
