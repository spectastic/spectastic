047's own canonical <spec-slo> example fails slo-well-formed, and the golden-signal vocabulary rejects terms 047 uses as objectives

Spec upstream

The canonical example in §3 puts objective in <dt>/<dd> content, but plan D-003 makes it an attribute — so copying the example errors "missing required objective=". Separately, §2 edge case names an "availability objective" while signal= accepts only the Four Golden Signals, so signal="availability" is rejected. Fixed by reconciling 047's example + signal guidance with the validator; regeneration fails — another author copying the spec's own example reproduces it.

Excellent error messages keep it friction, not a blocker.

A bare percentage never counts as quantified — isQuantifiedTarget's % unit is unreachable

Implementation code

Debugging why an NFR reading "100% of its content" was rejected as unquantified while authoring a new spec, root cause was a trailing \b after an alternation whose members include % in NUMBER_UNIT_RE — a word boundary can never hold between % and a following space, so the % unit matches nothing in practice; fixed by anchoring the unit alternation so non-word units don't demand a word boundary; regeneration passes — FR-004 and the heuristic's own stated intent are correct, the regex is not.

Expected
Per the heuristic's contract — "a number followed by a recognised unit (ms, s, min, %, rps, …)" — an NFR reading "at least 99% availability", "100% of requests", or "error budget 0.1%" counts as quantified.
Actual
isQuantifiedTarget returns false for "100%", "99% uptime", "100% of its content" and "error budget 0.1%". It returns true only when a different branch rescues the text — a comparison (>= 99%) or a threshold word (at least 99%) — so the failure is masked in most real prose and surfaces only when a percentage stands alone.
Diagnosis
NUMBER_UNIT_RE ends (ms|s|…|%|rps|…)\b. \b asserts a word/non-word transition; % is a non-word character, so after matching % the boundary holds only if the next character is a word character — which it never is in ordinary prose (a space, a full stop, or end of input). The % alternative is therefore effectively dead. Word-character units (ms, rps) are unaffected, which is why this survived the original tests.
Fix
packages/schema/src/slo-shared.ts — split the unit alternation so non-word units (%) are not followed by \b, e.g. match word units with \b and % without it. Add regression cases for a bare percentage in all four positions (mid-sentence, sentence-final, end-of-input, decimal).
Resolved
Fixed 31 Jul 2026. WORD_UNITS extracted and the trailing \b scoped to it, leaving % unanchored. New packages/schema/test/slo-shared.test.ts (15 cases) written red-first: 5 percentage cases failed, 10 passed; all 15 green after the fix. Full suite 1,361 passed. The change is strictly more permissive, so it can only reduce findings — confirmed by 0 quantified-nfr-required findings across the estate before and after. The two NFRs written around the bug while authoring 069 and 072 ("at most 0 of its authored elements…") were reverted to the natural "100% of its authored content…", which is what proved the fix end to end through the real CLI path.
/\d+(\.\d+)?\s*(ms|s|…|%|rps|…)\b/i /\d+(\.\d+)?\s*((ms|s|…|rps|…)\b|%)/i
Deep dive — a false negative on the exact axis the heuristic was tuned to avoid

No cross-spec contract, no principles invariant, no hotfix. What makes this worth more than a one-line patch is the direction of the error. The heuristic's own comment states the calibration: "Deliberately liberal (D-004): false negatives (a real target the regex misses) are worse than false positives, since this gates a hard error at verified/enterprise." A dead % branch is precisely that false negative, on the single most common unit an NFR uses.

Blast radius is narrow but real. The scan is profile-gated, so only verified and enterprise projects see it — but this repo self-certified enterprise in 068, so it applies here, and it fires as an error. The practical effect is an author being told a quantified NFR is unquantified and rewording around the tool rather than fixing anything. Found exactly that way, while authoring 069.

Scope note — surfaced, not promoted. The same file's THRESHOLD_WORD_RE uses a .{0,24}? window that will miss longer phrasings, and PERCENTILE_RE accepts p999 as a percentile. Both are judgment calls about liberality rather than defects, and neither is folded into this card.
