Corpus grounding gates

A citation can't rot into a dead reference, and a stale edition can't hide — two validate rules, at the severity each honestly earns.

Status Accepted Spec ID 053-corpus-grounding-gates Owner Brian Corbin · @briancorbinxyz Reviewers — Created 25 Jul 2026 Principlesv1.8.0 Smallest demoablespectastic validate errors on a citation to a non-existent KB-id and warns on a superseded edition. Read time

Two validate rules make the citation contract (052) enforceable. corpus-provenance is an error: a cited KB-NNN that resolves to no committed document is a dead reference — deterministic, fail-closed, the same footing as verify-view-stale and P-3 (IDs are contracts). corpus-staleness is a warning: a decision whose pinned edition is no longer current surfaces loudly, the way an assumed decision already does, but doesn't block a build — the world may have moved with no one having re-ingested. Both integrity gates fire whenever a corpus and a citation both exist, at any profile tier; the softer expectation that domain claims be grounded ladders with the existing grounding profile axis. With no corpus or no citation, neither rule fires.

1 · Context

A citation is only worth its integrity. Scholarship and law lost badly to link rot — ~70% of academic-journal URLs and roughly half of US Supreme Court citation links now dead. A committed corpus dodges the worst of it, but two failure modes remain that a machine can catch: a citation that points at nothing (the document was never ingested, or the ID was mistyped), and a citation whose edition has been superseded. The citation contract (052) defines the grammar; this spec is the enforcement that stops the grammar from lying.

The severity split is the load-bearing design decision. The considerations doc argues grounding stays a warning because "is this a domain claim?" is undecidable — a hard gate would false-fail whole specs on a missed claim. But a written citation resolving to a real file is fully deterministic: it either exists or it doesn't. So the two rules part company — the referential-integrity check fails closed (error); the editorial-staleness check surfaces loudly but advisory (warning).

2 · User scenarios & testing

Each story MUST be independently testable.

US1 · A citation can't rot into a dead reference P1

As a reviewer, I want validate to error when a cited KB-NNN resolves to no committed document so that a citation can never silently point at nothing.

Acceptance: a spec citing KB-999 with no such document produces a corpus-provenance finding at error severity and a non-zero exit.

US2 · Stale grounding surfaces like assumed P2

As a reviewer, I want validate to warn when a cited edition has been superseded so that stale grounding is loud the way an assumed decision is, rather than rotting in silence.

Acceptance: a decision citing KB-001@2017-09-05 when the current edition is @2024-05-28 produces a corpus-staleness finding at warning severity and a zero exit.

US3 · The nag ladders with rigor P3

As a light-tier user, I want the expectation that domain claims be grounded to ladder with my grounding profile so that I get the integrity gates but am not nagged for citations above my chosen rigor.

Acceptance: a light-tier project with a corpus still gets the error gate on a dangling citation, but does not receive the advisory "this domain claim could be grounded" nudge reserved for higher grounding tiers.

Edge cases

  • No corpus present, but a spec contains a KB-NNN-shaped string — neither rule fires; without a corpus there is nothing to resolve against (FR-003).
  • A corpus present but a spec with no citations — neither rule fires; there is nothing to check.
  • A superseded edition retained on disk (per 052 FR-003) — corpus-provenance passes (it resolves), corpus-staleness warns (it's superseded).
  • A regulation superseded upstream with no one having re-ingested it — greps as clean; the staleness rule cannot notice (FR-005, a recorded ceiling).

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional

A corpus-provenance validate rule MUST fire at error severity when a cited KB-NNN resolves to no committed corpus document.

Rationale

A dead reference is deterministically detectable — the file exists or it doesn't — so it can honestly fail closed, exactly as verify-view-stale and the data-delta-shape rules do. This is P-3 (IDs are contracts) applied to the corpus.

A corpus-staleness validate rule MUST fire at warning severity when a decision's pinned edition is not the current edition of the document it cites.

Rationale

A superseded-but-still-resolving edition should surface as loudly as an assumed decision, but must not block a build: the world may have moved with no one yet having re-ingested, and blocking a build on that is too aggressive.

Both rules MUST fire only when a corpus is present and a citation is written; a project with no corpus, or a spec with no citation, MUST see neither finding.

Rationale

The graceful-absence guarantee (051 NFR-001) extends to the gates: they are inert until there is both something to cite and something to resolve against.

The integrity gates (FR-001, FR-002) MUST be tier-independent — they fire at any profile whenever applicable. The advisory expectation that a domain claim be grounded SHOULD ladder with the existing grounding profile axis (light → decisions-cite → +risks → full-ledger).

Rationale

Referential integrity is not a matter of rigor — a dangling citation is wrong at every tier. But how much grounding is expected is exactly what the grounding axis exists to ladder, so the nudge (not the gate) rides that axis.

The corpus-staleness rule MUST detect supersession only from committed corpus editions; it cannot notice that the world changed upstream. This ceiling MUST be recorded, not hidden.

Rationale

Staleness is editorial at root. The rule tells a machine a citation's edition was superseded once someone re-ingests the newer edition — nothing here notices the change itself. Recording the limit keeps the tool honest about what it does and doesn't guarantee.

Non-functional

The gates MUST be deterministic — the same corpus and the same spec produce the same findings, with no clock dependence beyond the staleness rule reading the corpus's own recorded editions.

Out of scope (deferred to other slices)

  • The citation grammar and supersede-by-append rule these gates check.
  • The corpus-license rule (a restrictive license surfaces) — a sibling validate rule with its own spec.
  • Whether the model grounds at all — undecidable, kept advisory, never a gate.

4 · Data model

The entities this feature owns.

Entities

Provenance finding
A corpus-provenance validate result. Fields: the citing artifact + location, the unresolved KB-NNN, severity error.
Staleness finding
A corpus-staleness validate result. Fields: the citing artifact + location, the pinned edition, the current edition, severity warning.

Both findings resolve a citation against the corpus index + document editions (051 FR-004, 052 data model). The rules read those; they never write.

5 · Success criteria

Technology-agnostic, measurable outcomes.

spectastic validate exits non-zero on a spec citing a KB-NNN with no corresponding committed document.

spectastic validate emits a warning (zero exit) on a decision citing a superseded edition; the same project with a dangling citation still gets the error.

A project with no corpus, or a spec with no citation, produces neither a corpus-provenance nor a corpus-staleness finding.

6 · Assumptions

The corpus index and document frontmatter reliably name the current edition of each document, so "is this pin current?" is answerable from committed data alone (per 051 FR-004 / 052 FR-002).

The grounding profile axis is readable at validate time (as the profile-gated quantified-NFR scan already reads tier), so FR-004's laddered expectation can be tier-aware.

7 · Open questions

None outstanding — the severity split (provenance error, staleness warning) and the always-on-gate / laddered-expectation division were anchored in the interview.
