Design · 053-corpus-grounding-gates

Corpus grounding gates

How we will build it.

Status Accepted Spec 053-corpus-grounding-gates Owner Brian Corbin · @briancorbinxyz Branch 053-corpus-grounding-gates Created 25 Jul 2026 Read time

Two validate rules, one traversal. A single folded CLI scan parses each spec/plan's <spec-decision> citations and resolves them against the committed corpus via 052's resolveCitation; its return maps straight to severity — null → corpus-provenance (error, a dead reference), superseded → corpus-staleness (warning, a retained-but-stale edition), current → clean. It clones the exact folded-scan pattern of quantifiedNfrFindings + scanCorpusWellFormed, so there is no new infrastructure and no new dependency. The one honestly-unbuilt piece is FR-004's advisory grounding nudge: detecting an ungrounded domain claim is undecidable (the spec's own out-of-scope), so the integrity gates ship tier-independent and the nudge is recorded as a ceiling — 053 never reads the profile.

2 · Technical context

Language(s)
TypeScript ^5.7, Node >=20 (the existing monorepo).
Frameworks
None new. No new dependency — reuses 052's resolveCitation, the schema parser, and the citation grammar.
Architecture
One folded CLI scan backed by a core finding-function that resolves HTML citations against the corpus — the quantifiedNfrFindings / scanCorpusWellFormed pattern. See D-001.
Storage
Filesystem — reads the committed corpus (one loadCorpus per validate run); writes nothing.
Testing
vitest, tests-first, plus a spawned-CLI integration test (D-005). No Playwright.
Coverage
Not in scope — the meta-repo carries no profile marker, so no coverage floor.
Perf targets
Not a quantified NFR. O(decisions × citations) with one corpus load per run; a no-op when no corpus is present.
Constraints
Deterministic (NFR-001) — no clock; staleness reads only committed editions. Graceful absence (FR-003) — no corpus / no citation → no finding. FR-004(b)'s per-claim nudge is undecidable → not built, recorded (D-004).

Toolchain / enforcement: n/a — the meta-repo has no .spectastic/profile.json. This plan adds to the existing repo gate (vitest + spectastic validate pre-commit).

4 · Approach

One core finding-function, one CLI wrapper. (1) The finding-function — corpusGroundingFindings(docs, packs) in @spectastic/core/knowledge/gates.ts: for each doc, parse the HTML, findAll('spec-decision'), and for each decision extract its KB citation tokens (findCitationTokens, the shared helper), parseCorpusCitation each, and resolveCitation against the loaded corpus. The return picks the finding: null → a corpus-provenance error (FR-001); {kind:'superseded'} → a corpus-staleness warning (FR-002); {kind:'current'} → clean. One traversal emits both rule-ids — the same shape corpus-well-formed uses to emit several check types from one function. (2) The CLI wrapper — scanCorpusGrounding(files, cwd) folded into registerValidate() alongside the other scans: loadCorpus(cwd) once, no-op on an empty corpus (FR-003), build docs from the validated files, call the finding-function.

(3) The shared extraction — findCitationTokens(text) lands in @spectastic/schema/citation and replaces 052's inline TOKEN_RE, so the form rule (052) and these gates (053) agree byte-for-byte on what a citation token is (NFR-001 determinism, and no drift). Not built: FR-004's advisory grounding nudge — detecting an ungrounded domain claim is undecidable, so the integrity gates ship tier-independent and the nudge is a recorded ceiling (D-004), never a faked gate (P-8).

5 · Alternatives considered

The weighed choice: how the two rules are structured. Higher is better; the chosen row is marked.

OptionSingle traversalCorrect layer (needs corpus)Reuses resolveCitationTotal
Two HTML schema rules in the registry3126
Two separate finding-functions / two scans25512
One finding-function emitting both rule-ids, one scan — chosen55515

A schema rule can't reach the corpus filesystem (the registry operates on parsed HTML alone) — the wrong layer, exactly the inversion of 052's case where the form check needed no corpus. Two separate functions would traverse each decision twice for no gain. One function that resolves each citation once and picks the rule-id from the outcome is both the correct layer and the cheapest.

6 · Decisions

D-001 · One folded CLI scan backed by a core finding-function

Status
Accepted
Context
The gates resolve HTML <spec-decision> citations against the markdown corpus — a cross-boundary check that needs loadCorpus (filesystem), which a schema rule can't do. quantifiedNfrFindings (packages/core/src/commands/validate.ts) + scanCorpusWellFormed (051) are the exact precedent.
Decision
Add corpusGroundingFindings(docs, packs) in packages/core/src/knowledge/gates.ts (re-exported from the barrel), and scanCorpusGrounding(files, cwd) folded into registerValidate() — one loadCorpus per run, no-op on an empty corpus.
Consequences
+ Reuses a proven pattern; no new engine, no new dep. + One traversal, both rules. − One more scanX in an already-large validate.ts — the accepted cost the family pays (051, 058 add siblings).

D-002 · resolveCitation's return is the severity mapping

Status
Accepted
Context
resolveCitation (052, packages/core/src/knowledge/resolve.ts) already returns null / {kind:'current'} / {kind:'superseded'} — precisely the three outcomes the two gates distinguish.
Decision
null → corpus-provenance (error, FR-001); superseded → corpus-staleness (warning, FR-002); current → clean. A pinned edition resolving to neither current nor a retained prior returns null → error (interview-anchored: a dead reference, not stale).
Consequences
+ The mapping is a pure function over an already-tested return; every branch is unit-testable. + The provenance error is the named closer for the gap the 000 widening recorded (052's Finding 2). − Staleness only sees editions committed under references/superseded/ (FR-005 ceiling).

D-003 · Single-source the citation-token extraction in @spectastic/schema/citation

Status
Accepted
Context
052's corpus-citation-form rule extracts KB tokens with an inline TOKEN_RE. 053's scan must extract the same tokens; duplicating the regex invites drift (a token 052 flags but 053 doesn't resolve, or vice versa).
Decision
Factor findCitationTokens(text): string[] into packages/schema/src/citation-shared.ts (the ./citation module); the 052 rule and 053's scan both call it. A small additive refactor to the 052 rule (replace its inline regex), covered by 052's unchanged tests.
Consequences
+ One definition of "a citation token", shared by the form check and the resolve gates (NFR-001 determinism). − Touches a just-Accepted 052 file — but only its private extraction, behaviour-preserving, guarded by 052's tests.

D-004 · FR-004's grounding nudge is not built — recorded as an undecidable ceiling

Status
Accepted
Context
FR-004 asks the advisory "this domain claim could be grounded" nudge to ladder with the grounding axis. But detecting an ungrounded domain claim is undecidable — the spec's own §3 out-of-scope defers "whether the model grounds at all … never a gate" to 054, and FR-005 warns many assumed decisions are legit local choices.
Decision
Build FR-004's tier-independence clause (the integrity gates fire at any profile) — satisfied by construction, since 053 reads no marker. Record the laddered nudge as not-built (undecidable), the same honest ceiling FR-005 and the considerations doc keep. Interview-anchored.
Consequences
+ No profile dependency; simpler, deterministic. + P-8-honest — no faked gate presented as a guarantee. − FR-004 (a SHOULD) ships half-met by design; the ceiling is recorded in §9, not hidden.

D-005 · vitest, tests-first; no Playwright

Status
Accepted
Context
053 ships two finding-functions + a CLI scan — no interactive artifact. A test-style preference; no external fact (n-a).
Decision
Red-first vitest for corpusGroundingFindings (every branch: null/current/superseded/bad-edition/bare + no-corpus), plus a spawned-CLI integration test (like 052's validate-corpus) asserting exit 1 on a dangling cite and exit 0 + a warning on a superseded one.
Consequences
+ Fast feedback on the severity mapping, the correctness core. − No browser evidence, correctly — no runtime to exercise.

9 · Complexity tracking

Where this plan introduces complexity or deviates from a standing grain, the rationale.

FR-004's grounding nudge is recorded, not built. Detecting an ungrounded domain claim to nudge on is undecidable — the same limit the spec's out-of-scope defers to 054 and FR-005 names. 053 ships the integrity gates tier-independent (FR-004's MUST clause) and records the laddered nudge as a ceiling rather than faking a gate (P-8). Honest half-met SHOULD, not hidden.

Touching a just-Accepted 052 file. D-003 moves 052's inline token regex into the shared citation-shared module. It is behaviour-preserving (052's tests are the guard) and additive — the alternative, duplicating the regex, is the drift risk R2 names. Not a requirement change, so no proposal against 052 is needed.
