14 tasks across four phases (no separate Setup — see §2). Foundational → User stories (US1 · US2 · US3) → Polish. Tasks marked [P] can run in parallel — different files, no dependency. Tests for a story MUST be written and failing before its implementation tasks start. US3 is test-only by design (D-004): FR-004's tier independence is a consequence of the gates never reading a profile marker, not a separate feature — there is nothing to implement beyond what US1/US2 already build.

1 · Execution strategy

Implement US1 end-to-end — the provenance-error branch alone makes SC-001 real (a dangling citation fails the build). Ship, then extend to US2 (staleness) and confirm US3's tier-independence property once both branches exist.

Foundational → US1 → US2 → US3 → Polish. Each story closes its conformance before the next opens. Recommended here — US1 and US2 are two branches of the same function (plan D-001/D-002), so building them in sequence keeps the single traversal coherent.

US1 and US2 are two branches of one function (corpusGroundingFindings) — splitting them across teams risks merge conflicts on the same file more than it saves time. One team straight through Foundational → US1 → US2 is the honest shape; US3's verification can run in parallel once both branches land.

2 · Phase 1 — Setup

No separate repo wiring is needed. gates.ts joins the existing ./knowledge barrel (051 D-001 — only index.ts is a bundled entry, so a new internal file needs no tsup change), and citation-shared.ts already has its export subpath (052 T-001). Foundational work starts directly below.

3 · Phase 2 — Foundational

The shared citation-token extractor (plan D-003) — both the existing 052 form rule and the new gates function must agree on what a citation token is, so this lands first.

Write failing tests for findCitationTokens — extends the existing grammar test file with cases for multiple tokens in one string, a bare and a pinned token together, and no tokens at all. packages/schema/test/citation-shared.test.ts
Implement findCitationTokens — extracts every KB-\d{3,}(?:@…)? token from a string, trimming trailing sentence punctuation (plan D-003). packages/schema/src/citation-shared.ts
Refactor corpus-citation-form to use findCitationTokens — replaces its inline TOKEN_RE; behaviour-preserving, guarded by the existing (unchanged) fixture pair and unit tests. packages/schema/src/rules/corpus-citation-form.ts

4 · Phase 3a — US1 · A citation can't rot into a dead reference

Tests (write & fail first)

Write failing tests for the provenance-error branch — a citation to a KB-NNN with no committed document, and a pinned citation to a fabricated/typo'd edition (plan D-002: resolves to neither current nor superseded → error, not a warning); plus the graceful-absence cases (no corpus, and a corpus with no citation) producing no finding at all (FR-003, SC-003). packages/core/test/knowledge.gates.test.ts
Write a failing integration test for the CLI scan — a fixture project citing a dangling KB-NNN exits non-zero and names corpus-provenance; a project with no knowledge/ directory exits zero with no such finding. packages/cli/test/validate-corpus-gates.test.ts

Implementation

Implement corpusGroundingFindings — parses each doc's <spec-decision> citations, resolves each via resolveCitation, and emits a corpus-provenance error when the result is null (plan D-001/D-002). A no-op when the corpus is empty. packages/core/src/knowledge/gates.ts
Re-export corpusGroundingFindings from the ./knowledge barrel. packages/core/src/knowledge/index.ts
Wire scanCorpusGrounding into validate — folded into registerValidate() alongside the other non-HTML-adjacent scans; loads the corpus once and no-ops when it's empty. packages/cli/src/commands/validate.ts

Closes FR-001, FR-003, NFR-001 (no clock reads — the same corpus and spec always resolve the same way), SC-001, SC-003.

5 · Phase 3b — US2 · Stale grounding surfaces like assumed

Tests (write & fail first)

Write failing tests for the staleness-warning branch — a citation pinned to an edition retained under references/superseded/ (not the current edition) produces a warning, not an error. packages/core/test/knowledge.gates.test.ts
Write a failing integration test for the staleness case — a fixture project citing a superseded edition exits zero but the output names corpus-staleness; the same project also citing a dangling id still exits non-zero. packages/cli/test/validate-corpus-gates.test.ts

Implementation

Extend corpusGroundingFindings for the superseded case — emits a corpus-staleness warning when resolveCitation returns a superseded match; a current match stays clean. packages/core/src/knowledge/gates.ts

Closes FR-002, SC-002.

6 · Phase 3c — US3 · The nag ladders with rigor

Test-only (plan D-004): FR-004's tier-independence is proven by the gates never reading a profile marker at all — there is no separate nudge feature to implement, so there is no implementation section for this story.

Confirm the integrity gates are tier-independent — the same dangling/superseded fixtures produce identical findings regardless of a .spectastic/profile.json marker (light through enterprise) or its absence, proving FR-004's MUST clause holds by construction rather than by reading a profile. packages/core/test/knowledge.gates.test.ts

Closes FR-004 (the tier-independence half; the laddered advisory nudge is recorded, not built — plan D-004) and FR-005 (the staleness-can't-notice-upstream-change ceiling — already recorded in the spec's own rationale, verified here to still hold).
