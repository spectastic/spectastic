Design · 101-component-interaction-states

What a component does

How we will build it.

Status Draft Spec 101-component-interaction-states Owner Brian Corbin · @briancorbinxyz Branch spec/visual-slice-095-098 Created 13 Aug 2026 Read time

A component gains states and transitions, and a completeness check that reports the expected states it neither declares nor declines. The expected set is data rather than a requirement, because it is a judgment about interface convention that will age — the same lesson a sibling learned when a requirement naming a fixed count had to be reworded. Two exemptions fail safe on the antecedent so a divider and a consumed library component are not asked to decline nine states one at a time.

6 · Approach

Two nested elements on the component that already exists — a state, and a transition between two of its states — plus a hand-enumerated table of the states a component of a given kind is expected to account for. The check walks a component's declared and declined states against that table and reports the difference.

The load-bearing choice is that the expected set is data. A requirement that named the states would have to be amended every time the judgment moved, and this family has already paid for that once: a sibling's requirement fixed how many categories lacked an accessibility analogue, a triage card found the transcription wrong in both directions, and the requirement had to be rewritten mid-proposal to stop asserting a count. The same mistake is available here and is avoided the same way.

Both exemptions fail safe on the antecedent rather than demanding individual declines. A component that declares itself non-interactive is exempt entirely, and a consumed component — one 097 already lets a project declare it does not own — is exempt because its states belong to whoever wrote it.

7 · Alternatives considered

Where the expected set of interaction states lives. Scored 1–5 on how cheaply it can change when the judgment moves, whether a reader can find it, and whether it can be checked.

OptionCheap to changeFindableCheckableTotal
Named in the requirement15511

Per-project configuration ties on the raw total and loses on the thing that matters: it makes the floor negotiable, so a project that finds the check noisy can empty the list rather than declining a state. The whole value of the mechanism is that a blank becomes a question.

8 · Decisions

D-001 · The expected set is data, and no requirement names it

Status
Accepted
Context
A sibling's requirement asserted how many annotation categories lacked an accessibility analogue; 095/T-001 found that transcription wrong in both directions, and the requirement was rewritten mid-proposal to stop naming a count.
Decision
A hand-enumerated table in the schema package. FR-002 requires that it be data and says nothing about its contents.
Consequences
+ A judgment about interface convention ages in one line rather than through a proposal. + The check stays enforceable, unlike a per-project list a project could empty. − The list is still a judgment somebody made, and being wrong is now invisible in the artifact rather than visible in a requirement.

D-002 · Two exemptions, both failing safe on the antecedent

Status
Accepted
Context
097 FR-006 already makes a component declare its origin as authored, vendored or consumed, so the consumed antecedent exists without a new attribute. The contract-first enforcement category set the precedent of exempting rather than warning when the antecedent does not hold.
Decision
A non-interactive component and a consumed one are exempt from the completeness check entirely, rather than being expected to decline each state.
Consequences
+ A divider does not carry nine declines saying one thing. + A project consuming a component library does not document somebody else's decisions. − A component can be wrongly declared non-interactive, and that failure is silent — the least visible kind, which is the standing cost of every declaration-outranks-detection rule in this family.

D-003 · A decline carries a reason, exactly as a declined context does

Status
Accepted
Context
variant-grid-shape already reports a declined context with no reason, on the reasoning that a decline without one is indistinguishable from a shrug.
Decision
The same rule, the same shape, applied to a state. The reason is element content rather than an attribute, so it cannot be an empty string that satisfies a presence check.
Consequences
+ A reader meets one pattern twice rather than two patterns. + Content-not-attribute closes the empty-string hole the grid already closed. − Declining nine states on a genuinely unusual component is verbose, which is what D-002's exemptions exist to bound.

10 · Risks & mitigations

RiskLikelihoodImpactMitigation
The expected set is wrong — the one assumed fact hereMLIt is data, so being wrong costs one line. That is the mitigation, and it is why D-001 refused to put the list in a requirement.
A project declares components non-interactive to silence the checkMMVisible in the artifact rather than hidden, but nothing prevents it. The standing cost of declaration-outranks-detection, recorded rather than solved.
A decline renders indistinguishably from a declarationLHThe whole mechanism dies if this happens. The browser pass asserts they render differently, in both themes.
Nine declines on an unusual component read as noiseMLBounded by the two exemptions. If it still bites, the answer is a wider exemption rather than a shorter list.

11 · Complexity tracking

A third state for every expected state, rather than a boolean. Declared, declined, or unaccounted-for is more than the two a checkbox would give. The third is the entire point: a blank has to be a question rather than a silence, which is the same reason a declined context in the grid is not simply an absent one.

12 · Open questions

None outstanding. The decision that could have gone either way — whether a component's states belong on the component or on each screen that uses it — is settled by the scope 097 already built: a control used by ten screens has one focus ring, and recording it ten times is the duplication component scope exists to remove.
