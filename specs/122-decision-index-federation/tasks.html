Decision index federation

Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Draft Spec 122-decision-index-federation Design design Branch main Created 19 Sep 2026 Read time

35 tasks across five phases. Setup → Foundational → User stories (US1 · US3 · US2 · US4, in priority order) → Polish. Tasks marked [P] can run in parallel — different files, no dependency. Tests for a story MUST be written and failing before its implementation tasks start.

1 · Execution strategy

Foundational, then US1 (an owner can publish and keep it honest) — the smallest demoable slice on its own. US3 proves enforcement with a hand-placed vendored copy before US2's real fetch exists; US2 replaces the hand-placement; US4 and Polish close the spec.

Setup → Foundational → US1 → US3 → US2 → US4 → Polish, in priority order. Each story closes its conformance before the next opens.

US1 and US3 depend only on Foundational and can run concurrently — US3's tests use a hand-placed vendored file, not US2's sync. US2 replaces that hand-placement with a real fetch once both land; US4 depends on all three.
