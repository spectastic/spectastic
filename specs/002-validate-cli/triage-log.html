validate --help description leaks the internal FR ID

Implementation code

Debugging the appearance of FR-002 in validate --help output, root cause was an implementation drift — the Commander .description(...) string echoes the FR ID from the file's source comment into user-facing copy; fixed by trimming the description to plain prose; regeneration passes — nothing in the spec or plan tells the implementer to cite FR IDs in user output.

Expected
validate --help shows a plain-English description of the subcommand. Internal anchors (FR-…, NFR-…, REQ-…) belong in source comments and specs, not user-visible copy.
Actual
validate --help renders "Validate one or more spec-html files. Exits 0/1/2 per FR-002." — the trailing per FR-002 exposes an internal traceability ID to end users.
Diagnosis
packages/cli/src/commands/validate.ts:20 calls Commander's .description() with a string that ends in per FR-002. The same file's docstring at line 9 reads "Implements FR-001, FR-002, FR-014"; the LLM author appears to have carried the FR ID from the comment into the user-facing description. Spec FR-002 (exit-code contract) is correct as written; the leak is purely in the description string.
Fix
packages/cli/src/commands/validate.ts:20 — replace the description with prose that names the exit semantics directly, no FR ID. Suggested: "Validate one or more spec-html files. Exits 0 on clean, 1 on findings, 2 on usage errors."
