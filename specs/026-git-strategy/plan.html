Implementation plan · 026-git-strategy

Git strategy — the opt-in git layer

How we will build it.

Status Accepted Spec 026-git-strategy Owner Brian Corbin · @briancorbinxyz Branch 026-git-strategy Created 2026-06-29 Read time

Build the git layer as a CLI-side module (packages/cli/src/git/) that each register<Verb> action calls after it writes its artifact: read spectastic.json for git.auto, and when on, run validateCommand in-process, optionally create the NNN-slug branch, then commit via git shelled out through node:child_process. The one real unknown — origin-aware id allocation — is should-tier with a local-scan fallback and the shipped 025 CI gate behind it.

4 · Approach

Add one CLI-side module, packages/cli/src/git/, exposing a single orchestrator commitForVerb(verb, ctx) that every register<Verb> action calls at its tail — after the existing gate passes and the file is written. The module is layered: a tiny config reader (spectastic.json → {auto}, defaulting off), pure derive functions (verb→commit subject, verb→branch name) that are trivially unit-testable, an allocate helper that extends explore's resolveNextId with an origin-aware path, and a thin run wrapper around git via execFile. The orchestrator's flow: if git.auto=off (or --no-commit), return immediately — do nothing; otherwise run validateCommand and abort loudly on any finding; then, under branch+commit and for a new spec slice, create NNN-slug; then stage the verb's reported paths and commit <verb>(NNN): <subject>.

The small-work exception (FR-005) and the per-drain rule for implement (FR-007) are encoded in the static verb→git map, so the calling action passes only its verb + paths and the map decides branch-or-not and one-commit-or-many. Staging is scoped to the paths the verb reports (never git add -A), so a commit can't sweep unrelated working-tree changes — important for apply, whose commit must capture the changes/ → archive/ move precisely.

5 · Alternatives considered

The most-deliberated choice was the home for the new git.auto config (no config surface exists today). Scored after an adversarial pass between a root file and a hidden directory.

Growth room is the hidden dir's only edge — and it's largely illusory here: G-001 rejected a tracked id registry (the main future-state candidate) as a merge-conflict hotspot, and the rest of the init --tools payload lands in conventional homes (.github/workflows/, .claude/), not under a spectastic namespace. So a hidden dir would wrap a single file. If real state ever needs a home, migrating then is clean and signposted.

6 · Decisions

D-001 · The layer lives CLI-side as a module the verb actions call

Status
Accepted
Context
Core kernels are pure (packages/core/src/commands/spec.ts returns {html, specId}); all fs writes + process.exit live in the CLI register<Verb> action (packages/cli/src/index.ts). Git is effectful and cwd-bound.
Decision
Add packages/cli/src/git/ exposing commitForVerb(); each verb action calls it at its tail. Pure derivation separated from the effectful run wrapper so the former is unit-tested in isolation.
Consequences
+ Keeps core pure and reusable; + one wiring point per verb. − Two code paths (manual git + automated) to keep coherent; − every register<Verb> gains a small tail + a --commit/--no-commit option.

D-002 · Config home = spectastic.json at project root

Status
Accepted
Context
No config mechanism exists (grep over packages/*/src), so the spec's "config already exists" assumption is false — this slice must introduce one. Root already holds hand-edited config (commands.json, tsconfig.base.json) and visible artifacts (principles.html).
Decision
Read a root spectastic.json with a git section ({ "git": { "auto": "off" } }); absent file or key → defaults (auto=off). Beat the hidden-dir alternative on an adversarial pass (§5).
Consequences
+ Discoverable, hand-editable, on-ethos; + the deferred init --tools installer just writes this file. − A second config home (a .spectastic/ dir) would be a migration if real state ever lands; accepted as YAGNI.

D-003 · Invoke git via node:child_process.execFile, no new dependency

Status
Accepted
Context
The CLI tree has only commander as a runtime dep (packages/cli/package.json:51); the git operations needed are few (status, checkout -b, add, commit, fetch, symbolic-ref).
Decision
Shell out with execFile('git', args, {cwd, timeout}). The timeout option bounds the remote fetch and triggers the local-scan fallback (FR-006/NFR-001). Reject adding simple-git — it wraps the same binary for a lean tree's cost.
Consequences
+ Zero new deps; + native timeout for the fetch bound. − We own argument-quoting and exit-code handling (small, well-trodden); − cross-platform porcelain must stay portable (R4).

D-004 · Origin-aware id allocation, passed into the kernel; offline → local scan

Status
Accepted
Context
The kernel accepts input.specId (spec.ts:29) and otherwise stubs 000-<slug>; explore's resolveNextId (explore.ts:85) already scans local specs/. The spike confirmed default-branch detection.
Decision
Under branch+commit for a new slice, allocate NNN from local specs/ ∪ git ls-tree origin/<default> specs/ after a time-boxed git fetch; on no-remote/timeout, fall back to the local scan. Pass the result as input.specId, and name the branch from it. (should-tier: FR-006.)
Consequences
+ Makes the common case collision-safe (the branch is the reservation); + reuses an existing allocator. − Origin scan adds a network step (bounded, with fallback); − the 025 spec-id-unique gate remains the net for the residual race, by design.

D-005 · The commit gate runs validateCommand in-process, after the existing gates

Status
Accepted
Context
validateCommand is exported and callable in-process (validate.ts:26); the P-6 + quarantine gates already run earlier in the action (state-gate.ts). A quarantined build fails validate by design.
Decision
commitForVerb calls validateCommand after the action's existing gate has passed and the file is written; any finding → no commit, loud message, non-zero. No commit ever precedes a clean validate (FR-001/FR-008).
Consequences
+ One in-process call, no subprocess; + the quarantine guard is inherited for free. − The validate cost counts against the ≤ 1 s p95 budget (SC-004) — measured by the integration test.

D-006 · A static verb→git map; stage only the verb's paths; implement commits per drain

Status
Accepted
Context
The verb→git shape is deterministic (brief §4): verb = type, spec id = scope, slice = branch. The small-work exception (FR-005) and per-drain rule (FR-007) are fixed policy, and each action already knows its written/moved paths.
Decision
Encode a static map: which verbs branch (spec new-slice only), which stay on the current branch (just-do/triage/hotfix), and the commit cardinality (implement = one per drain). Stage the action-reported paths only — never git add -A — so apply's archive move is captured exactly.
Consequences
+ The calling action passes only verb + paths; policy is one table to review. − The map must be kept in step with the verb surface (eight verbs; no new verb here).

9 · Complexity tracking

This plan introduces one capability the spec did not foresee, justified here.

A config reader, not assumed-existing. The spec assumed a config mechanism existed; grounding found none. This slice therefore adds a minimal root-spectastic.json reader (D-002) — the smallest thing that satisfies FR-004 (git.auto configurable, default off). We deliberately do not build a general config system: only a git section with defaults, leaving room for the init --tools sibling to own the writer half.
