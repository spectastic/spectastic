FR-002 demands a (NNN) scope on every auto-commit, but some verbs have no spec id. Allow the unscoped <verb>: <subject> form when there's no scope to carry.

Unscoped commit subjects for spec-less verbs

Applied

1 · Intent

Building the verb→git wiring (026 tasks T-113) surfaced a contradiction in the spec. FR-002 says an auto-commit's subject must follow <verb>(NNN): <subject> — universally. But three verbs run without a spec id: a triage list-intake appends to the project-root inbox.html; principles authors the root principles.html; and an implement drain of an inbox just-do card ticks a card that belongs to no spec. None of them has an NNN to place in the parens.

The git-strategy brief this spec is built on already shows the answer in its §4 verb→git table: triage: <summary> — unscoped, no parens. Conventional Commits itself makes the scope optional. So the fix is not to invent a scope for these verbs, nor to bar them from committing, but to let FR-002 say what the brief already does: scope when you have one, omit it cleanly when you don't.

2 · Scope

In scope

  • Amend FR-002 to allow the unscoped <verb>: <subject> form when a verb has no spec id.
  • State the rule generally — any verb operating without a spec id — so it covers triage list-intake, principles, and an inbox-card implement drain in one stroke.
  • Amend FR-007 in lockstep so the inbox-card implement drain it governs uses the same unscoped form — keeping the two MUST requirements consistent.

Out of scope

  • Changing the scoped form itself — <verb>(NNN): stays exactly as shipped for spec-bearing verbs (the T-100 integration test already pins it).
  • Attribution trailers and the init --tools installer — separate sibling slices, untouched.

3 · Approach

One MODIFY delta on FR-002. The post-state keeps the scoped sentence verbatim, gated on "when a spec id is in play", and adds a second sentence for the spec-less case. Implementation is a small extension of the already-built pure derivation: commitSubject emits <verb>: <subject> when the scope resolves empty, and the existing scopeOf already returns the bare verb path for ids with no numeric prefix — so the spec-less verbs pass an empty/absent spec id and get the unscoped form. The change is additive to behaviour: every existing test (notably the T-100 spec(001): assertion) stays green.

This amendment is the prerequisite the T-113 pause identified: with FR-002 resolved, the remaining verbs (plan/tasks/propose/apply scoped; triage/principles/inbox-implement unscoped) can all be wired against one unambiguous grammar.

4 · Deltas

Two <spec-delta>s. FR-002 sets the grammar; FR-007 is amended in lockstep so the implement inbox-card case (which the general rule pulls in) doesn't end up with two conflicting MUST subjects — the contradiction the adversarial pass caught (§5).

What changes: the single universal <verb>(NNN): rule splits into two — scoped when a spec id is in play, unscoped <verb>: when it isn't. Priority and the scoped form are unchanged.

An auto-commit's subject MUST follow <verb>(NNN): <subject> (Conventional Commits) whenever a spec id is in play — verb as type, the artifact's spec id as scope. When a verb runs without a spec id — triage list-intake, principles, or an implement run draining an inbox just-do card — the subject MUST instead follow the unscoped <verb>: <subject> form. The Conventional Commits scope is omitted, never faked with a placeholder.

Rationale

Some verbs own no spec id, so a mandatory (NNN) is unsatisfiable for them; the git-strategy brief §4 already writes triage: <summary> unscoped, and Conventional Commits treats the scope as optional. Stating the rule generally ("no spec id → unscoped") also covers the inbox-card implement case — which means FR-007 must move in step (next delta).

What changes: FR-007's commit subject splits the same way as FR-002 — scoped implement(NNN): when the drain advances a spec's tasks, unscoped implement: when it drains an id-less inbox just-do card. The one-commit-per-drain rule is unchanged.

With the git layer on, /spectastic.implement MUST emit exactly one commit per drain invocation, not one per ticked task. When the drain advances a spec's tasks.html, the subject is the scoped implement(NNN): <summary>; when it drains an inbox just-do card — which has no spec id — the subject is the unscoped implement: <summary>, consistent with FR-002.

Rationale

An inbox just-do card belongs to no spec, so the same no-spec-id-means-unscoped rule FR-002 sets must apply here too; without this delta the two MUST requirements would disagree on the inbox-card commit (the adversarial finding in §5).

5 · Risk register

FR-002 is a must-tier requirement, so the adversarial pass fired. One <spec-risk> per finding; status= stays identified until the author dispositions it. /spectastic.apply refuses while any risk is identified.

Folding the inbox-card implement drain into the unscoped form collides with FR-007, which mandates implement(NNN): <summary> — so the same commit would be governed by two conflicting MUST rules, the opposite of the "unambiguous grammar" this change promises.

Delta op="modified" target="FR-002" — "or an implement run draining an inbox just-do card … the unscoped <verb>: <subject> form."

Mitigated by the second delta on FR-007: both requirements now route the id-less inbox-card drain to the unscoped form, and keep (NNN) where a spec id exists. The two rules agree rather than conflict — confirmed on accepting the 2-delta version.

As first drafted (FR-002 only), the change silently overrode FR-007's implement(NNN): subject for the inbox case without listing FR-007 as a delta — shipping a spec internally inconsistent across two must-tier requirements.

Live spec FR-007 — "MUST emit exactly one implement(NNN): <summary> commit per drain invocation."

Addressed — FR-007 is now the second MODIFY delta in §4, amended to use the unscoped form for the id-less inbox-card drain. The proposal targets two requirements and is internally consistent post-apply.

The general "any verb with no spec id" scope is broad enough to pull in the inbox-card implement drain — the case owned by FR-007 / FR-005 — rather than narrowing to the two genuinely id-less verbs (triage list-intake, principles); that breadth is what created the FR-007 collision.

§2 In scope — "State the rule generally — any verb operating without a spec id … inbox-card implement drain in one stroke."

The breadth is intentional (an inbox-card drain genuinely has no spec id and needs a defined grammar), and the collision it surfaced is resolved by amending FR-007 in the same proposal rather than deferring. A narrower one-delta version — triage + principles only, leaving inbox-card implement to a later change — remains available if the author prefers the smaller surface.
