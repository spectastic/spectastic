21 tasks across four phases (one user story — the whole feature is US1). Setup → Foundational → US1 → Polish. Tasks marked [P] can run in parallel — different files, no dependency. Each module's tests are written and failing before its implementation, and the US1 integration tests gate the whole story against the success criteria.

1 · Execution strategy

The natural fit here — solo work, one story, with the lone discovery risk (origin-aware allocation) isolated to allocate.ts. Build the foundational modules, land commitForVerb wired into spec first (proves SC-001 end-to-end), then fan the wiring out to the other verbs.

Setup → Foundational → US1 → Polish, closing each module's unit tests before the orchestrator, and the US1 integration suite before Polish.

Overkill for one story. If staffed, split the foundational modules (config / derive / run) across people after Setup — they're independent files — then converge on the orchestrator.
