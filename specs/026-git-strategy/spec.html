Git strategy — the opt-in git layer

The lifecycle already projects onto git — verb is the commit type, spec id is the scope, the slice is the branch. This slice makes that projection automatic: a config switch, default off, that lets each verb derive its own branch and commit from the artifact it just wrote.

1 · Context

spectastic's artifacts are the source of truth; git has always been a side effect a human performs by hand. Yet the history already follows a grammar nobody designed — spec(NNN):, plan(NNN):, implement(NNN): T-xxx (verb as type, spec id as scope) — and branches like 018-explain matched their spec dirs. The git-strategy brief formalizes that projection into several slices; this is the core automation slice (G-002 + G-003).

The foundation already landed: 025-id-uniqueness shipped the spec-id-unique CI gate (G-001) that keeps the readable NNN ids safe when two branches race. What's missing is the part that lets a developer stop thinking about branches and commits: a layer that, switched on, derives each verb's git shape from the artifact it just wrote. The users are spectastic adopters who want their git history to be the lifecycle record without hand-typing it.

2 · User scenarios & testing

The slice carries a single story; trailers and the installer are sibling slices (§3, out of scope).

US1 · Verbs commit themselves P1

As a spectastic user, I want to turn on the git layer and have each verb create the right branch and commit for me so that my git history is the legible record of the lifecycle without me typing a single git command.

Acceptance: With git.auto=branch+commit, running spec on a new feature creates branch NNN-slug off the default branch and commits the artifact as spec(NNN): <title>. With commit it lands on the current branch, no branch. With off (the default) nothing git happens. --commit/--no-commit overrides per invocation.

Edge cases

  • No remote / offline. Branch allocation fetches origin/<default>; with no remote or a timed-out fetch, it falls back to a local scan of specs/.
  • Validate fails. The artifact doesn't pass spectastic validate — no commit, and the failure is surfaced loudly.
  • Quarantined exploration. A quarantined build fails validate by design, so the layer cannot commit it to a shippable branch.
  • Small revert-safe work. just-do, triage-list intake, and one-file hotfixes stay on the current branch even under branch+commit.

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional

When git.auto is commit or branch+commit, after a verb writes its artifact and clears the existing P-6 state-gate, spectastic MUST run spectastic validate and commit only if it passes; on failure it MUST produce no commit and surface the failure loudly.

Rationale

A commit is the reward for a clean verb, not a way past its refusal. The gate runs after the state-gate, never around it (brief §7).

An auto-commit's subject MUST follow <verb>(NNN): <subject> (Conventional Commits) whenever a spec id is in play — verb as type, the artifact's spec id as scope. When a verb runs without a spec id — triage list-intake, principles, or an implement run draining an inbox just-do card — the subject MUST instead follow the unscoped <verb>: <subject> form. The Conventional Commits scope is omitted, never faked with a placeholder.

Rationale

Some verbs own no spec id, so a mandatory (NNN) is unsatisfiable for them; the git-strategy brief §4 already writes triage: <summary> unscoped, and Conventional Commits treats the scope as optional. Stating the rule generally ("no spec id → unscoped") also covers the inbox-card implement case — which means FR-007 must move in step (next delta).

Under git.auto=branch+commit, when spec opens a new slice spectastic MUST create and switch to a branch named NNN-slug off the default branch before committing.

git.auto MUST default to off, and with off no verb MUST perform any git action. Every verb MUST accept --commit/--no-commit to override the configured behavior per invocation.

Rationale

The house enforcement stance (C-005): opt-in, default off, documented loudly. A developer running their own git flow is never surprised.

just-do work, triage-list intake, and one-file revert-safe hotfixes MUST stay on the current branch — no branch creation — even under branch+commit, reusing the existing just-do boundary; they MAY still receive a commit.

Rationale

Reuse the line the triage layer already draws ("one file, no contract change, revert-safe"); don't invent a second boundary (brief §7).

When opening a new-slice branch under branch+commit, spectastic SHOULD allocate NNN by fetching and scanning origin/<default>; if no remote exists or the fetch exceeds its timeout, it MUST fall back to a local scan of specs/.

Rationale

The branch is the reservation (G-001a); the 025 spec-id-unique gate stays the cross-branch safety net when the rare race still slips through.

With the git layer on, /spectastic.implement MUST emit exactly one commit per drain invocation, not one per ticked task. When the drain advances a spec's tasks.html, the subject is the scoped implement(NNN): <summary>; when it drains an inbox just-do card — which has no spec id — the subject is the unscoped implement: <summary>, consistent with FR-002.

Rationale

An inbox just-do card belongs to no spec, so the same no-spec-id-means-unscoped rule FR-002 sets must apply here too; without this delta the two MUST requirements would disagree on the inbox-card commit (the adversarial finding in §5).

The git layer MUST honor the explore quarantine: a quarantined exploration that fails validate MUST NOT be committable to a shippable branch by this layer. The layer reads that signal, never weakens it.

Non-functional

The git layer's own work (staging, commit) MUST add ≤ 1 s at p95 to a verb's runtime, measured excluding network. A remote fetch MUST be bounded by its own timeout that falls back to local allocation (FR-006).

The layer MUST NOT introduce squash-on-merge as a default and MUST NOT rewrite or squash existing default-branch history; full per-commit history is the legible record and is preserved.

Out of scope (deferred to other slices)

  • Attribution trailers (G-004) — git.trailers and the Author/Acked-by/Refs mapping from <spec-meta> — a sibling slice, after the lifecycle reviewer-capture amendment.
  • The spectastic init --tools installer (brief's ④) — config, hook, CI workflow, commit template, monorepo-vs-project detection — a sibling slice; until it ships, git.auto is set by hand.
  • The house-level REQ-GIT-* contract (the grammar as a meta-spec rule, brief's ②) — a separate /spectastic.propose against the meta-spec.
  • Splitting under the branch model (G-005) — contiguous N-id reservation, the parent Superseded flip, the merge sequence, --stacked — owned by the W-2 slicer / /spectastic.split.

4 · Data model

This slice owns one new configuration key and introduces no new artifact type.

Entities

Git config (git.auto)
One key in the project config: git.auto ∈ {off (default), commit, branch+commit}. The plan owns where it lives. (git.trailers arrives with the trailers sibling.)
Verb→git derivation
The deterministic map from a just-written artifact to its git shape: the verb is the commit type, the artifact's spec id is the scope, the slice id is the branch. Nothing for the developer to decide — it falls out of the artifact.

The layer is strictly a projection: it reads artifacts and config and writes git, never mutating an artifact. It composes after the P-6 state-gate and the explore quarantine — reading those signals, never relaxing them.

5 · Success criteria

Technology-agnostic, measurable outcomes. These are how we know it worked.

With git.auto=branch+commit, running spec on a new feature produces branch NNN-slug and a commit whose subject is exactly spec(NNN): <title> — with zero manual git commands.

With git.auto=off (the default), no verb performs any git operation; a repository's existing git state is byte-for-byte unchanged by running a verb.

A verb whose artifact fails spectastic validate produces no commit, and the validation failure is surfaced to the user.

The git layer adds ≤ 1 s at p95 to a verb's runtime, measured excluding network round-trips.

6 · Assumptions

The project already has a config mechanism the git.auto key can live in; this slice adds a key, it does not invent the config system.

The 025 spec-id-unique CI gate remains the cross-branch safety net, so the reservation (FR-006) only needs to make collisions rare, not impossible.

Until the init --tools sibling ships, a user enables the layer by setting git.auto by hand — acceptable for an opt-in, documented value.
