Design · 018-explain

explain — the grounded coach

How we will build it.

Status Draft Spec 018-explain Owner Brian Corbin · @briancorbinxyz Branch 018-explain Created 19 Jun 2026 Read time

Ship the coach as a single markdown command file (commands/spectastic.explain.md) that drives the in-session agent to ground its explanation in real repo source via its own file tools — no CLI subcommand, kernel, or AIProvider call, because the coach writes no artifact (FR-001). The only code is a bundler change: a commands.json tier manifest so init installs the eight core verbs by default and explain only via init --with explain. Biggest risk: procedural grounding leans on the agent actually reading source — guarded by a mandatory read-then-refuse step and a manual smoke, with the heavier verification layer deferred to the course.

Storage

Testing

Perf targets

Reuse the existing command-file shape (FR-010); keep the eight hero verbs the default surface; add no persistent state; the packaging seam must exist before this first extended verb ships (FR-009).

3 · Approach

Two work streams, almost independent. The coach is one markdown file under commands/ following the same front-matter + Procedure + Output-style shape as the other verbs. Its procedure drives the in-session agent: parse <target> and --proficiency from $ARGUMENTS; resolve the target against real source with the agent's own Read/Grep tools; if it doesn't resolve, report the miss and stop; otherwise explain, citing only references confirmed to exist, at a depth set by the band. Grounding is achieved by the agent literally reading the source — the same way /spectastic.spec grounded itself by reading the handover — so no retrieval or verification code is built in this slice.

The packaging seam is the only code. A new commands.json at the repo root lists verbs by tier; the prebuild step copies it into _bundled/; init reads it to filter the bundle inventory so the eight core verbs install by default and extended verbs install only when named via a new repeatable --with <verb> flag. The filter slots in between resolveBundle() and buildPlan(); everything downstream (conflict prompts, writes, summary) is untouched.

5 · Decisions

D-001 · The coach is a markdown command file only — no CLI/kernel/AIProvider

Status
Accepted
Context
The six AI verbs carry a CLI subcommand + @spectastic/core kernel + AIProvider because they generate artifact files deterministically and stub-test them in CI. The coach generates no artifact (FR-001) and is ephemeral, in-chat.
Decision
Ship commands/spectastic.explain.md only. The in-session agent grounds via its own Read/Grep tools and parses <target> + --proficiency from $ARGUMENTS. No packages/cli or packages/core command module.
Consequences
+ Smallest possible surface; matches the ephemeral nature exactly. + No new retrieval/verify infra. − No vitest unit test for the coaching itself (verified by manual smoke, R3). − Diverges from the six-verb CLI pattern (logged in §8).

D-002 · commands.json tier manifest; init --with installs extended verbs opt-in

Status
Accepted
Context
FR-009/D-011 require the installer to distinguish core from extended and keep explain out of the default install. Today no verb registry exists — the core set is duplicated across four places (the commands/ dir, cli/src/index.ts, core tsup.config.ts, core package.json exports).
Decision
Add repo-root commands.json: { "core": […8 verbs], "extended": ["explain"] }. prebuild.mjs copies it into _bundled/. A new init/manifest.ts reads it; init filters the bundle inventory so extended command files are written only when their verb is named by a repeatable --with <verb> flag. Unknown/unlisted command files default to core (fail-safe: a verb installs unless explicitly marked extended).
Consequences
+ One real registry; retires the four-place duplication. + Forward-compatible as more extended verbs land. − Manifest can drift from the file set (mitigated by the default-to-core rule + R2 test). − The filter is a new branch in the init path (covered by the integration test).

D-003 · Procedural grounding + refuse-and-report; verification code deferred to the course

Status
Accepted
Context
FR-003/SC-001 demand zero hallucinated references; FR-004 demands refuse-and-report. No grounding/verification utility exists, and D-001 leaves no code layer to run one.
Decision
Grounding is procedural: the command mandates the agent read the real target first, cite only references it has confirmed exist, and stop with a reported miss if the target doesn't resolve. No post-processing verifier in v1. The retrieval/verify layer (handover D-010) is reserved for explain --course.
Consequences
+ Proportionate to an ephemeral, low-stakes coach. + Nothing to build. − The guarantee rests on the agent's tool-use discipline, not an algorithm (R3); the procedure makes the read-then-explain order non-optional and the smoke checks both the grounded and refusal paths.

D-004 · --proficiency parsed in-prose, default wheels, no persisted state

Status
Accepted
Context
FR-006 (D-012 seam) fixes the flag vocabulary in v1 so personalization arrives additively; NFR-002 defers storage.
Decision
The procedure parses --proficiency=wheels|completion|independent from $ARGUMENTS, defaults to wheels when absent, rejects any other value against the fixed vocabulary, and tunes explanation depth (FR-007). No state is read or written.
Consequences
+ CLI contract is stable from v1; later "default from stored band" is purely additive. − Until storage lands, the band is set by hand each call.

The coach's "zero hallucinated references" guarantee (SC-001) is enforced by procedure and the agent's tool-use, not by code, in this slice. Accept this before implementation: it is proportionate for an ephemeral coach, and the algorithmic verifier lands with explain --course.

8 · Complexity tracking

Two deviations from the established pattern, each required-or-justified.

Markdown-only diverges from the six-verb CLI-backed pattern (D-001). Justified: those verbs exist in TypeScript because they emit artifact files that must be generated deterministically and stub-tested in CI. The coach emits no artifact (FR-001), so a kernel + AIProvider + retrieval/verify layer would be complexity the spec explicitly defers to the course — not complexity this slice needs.

commands.json is a new config file (D-002). Justified: FR-009/D-011 require the installer to distinguish core from extended before the first extended verb ships, and no such registry exists today. The manifest is the minimal mechanism that satisfies that and retires the existing four-place duplication of the core set.

9 · Open questions

None block implementation. The two decisions the spec deferred to this plan are resolved above: extended-verb packaging is D-002 (commands.json + init --with); the grounding approach is D-003 (procedural + refuse-and-report). Storage of the proficiency band and the algorithmic verifier remain owned by the deferred explain --course sibling, not this slice.
