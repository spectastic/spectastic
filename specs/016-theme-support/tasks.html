Themes

Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 016-theme-support Design design Branch 016-theme-support Created 18 Jun 2026 Read time

40 tasks. The original 25 (Setup → Foundational → US1·US2·US3 → Polish) shipped the theme/mode mechanism; a re-scope (T-002) adds Phase 3d — 15 tasks for vivid visual parity with the reference (checklist measured via the Chrome connector), sliced shape → layout. Tasks marked [P] can run in parallel — different files, no dependency. Tests for a story MUST be written and failing before its implementation tasks start. The three stories are layered rather than fully independent: they share assets/spec.css and assets/spec.js, so within a file the order holds.

1 · Execution strategy

Setup → Foundational → US1 → US2 → US3 → Polish. Each story closes its conformance before the next opens. Recommended — solo work on a shared-asset refactor where the stories layer on one token foundation.

Foundational + US1 end-to-end (calm/vivid switch in the default light mode), ship, then add US2 (dark) and US3 (no-flash). Viable: US1 alone is a usable theme switcher.

After Foundational, the test files and the US3 retrofit split cleanly; the spec.css/spec.js implementation seams do not. Coordinate at the token contract (plan D-001), not Slack.
