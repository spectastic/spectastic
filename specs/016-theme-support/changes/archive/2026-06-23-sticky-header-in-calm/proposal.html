Sticky header in calm too

Applied

1 · Intent

The sticky, backdrop-blurred top header — brand/back-link, artifact path, theme dropdown, sun/moon mode toggle — is the most convenient chrome spectastic has: always-visible navigation, orientation, and control. FR-009 gave it to spectastic-vivid only and explicitly kept it off calm to honour P-5 (calm density / "no visual chrome that doesn't carry meaning").

That deferral conflated two things: the header's position + function (always-visible nav, orientation, controls — universally useful) and vivid's aesthetic (blur, density). Re-weighed, the function carries meaning under P-5, so calm should have it — but in calm's own register, not vivid's. Calm gains the same elements and sticky position in a minimal, calm-native treatment (flat warm-cream, thin rule, no blur), keeping the calm and vivid identities distinct.

2 · Scope

In scope

  • MODIFY FR-009: the sticky header is presented by every artifact in both themes, with the theme + mode controls in the header — not the footer. Vivid keeps its dense blurred bar; calm renders a minimal, calm-native treatment (flat warm-cream, thin rule, no blur/density).
  • Remove calm's footer theme/mode switcher (controls now live in the header).
  • Consequential prose: US1 acceptance (§2) and the plan's header note, which currently say "footer for calm / calm has no header."

Out of scope

  • An identical-to-vivid calm header — rejected in favour of a lighter, calm-native treatment that preserves the calm/vivid distinction (the value is the header's position + controls, not vivid's blur).
  • Reference-parity for calm's header against the original design — SC-006 measures vivid; calm's header is identical, so no separate parity target. (Calm's header contrast is not hand-waved: NFR-003 now applies to the header in both themes, and a §6 task verifies it for calm's lighter #f6f5f1 backdrop.)

3 · Approach

The header is already built by the shared switcher logic (no per-document markup, NFR-005) and is currently gated behind [data-theme="spectastic-vivid"] in assets/spec.css + assets/spec.js. The change: the header renders in both themes, but calm gets its own minimal styling — flat --c-bg surface (no backdrop-filter), a thin --c-border-soft rule, restrained height — while vivid keeps its blurred, dense bar. Calm's footer-switcher branch is dropped so the controls live only in the header. No new markup: per-theme styling on an existing feature.

P-5 is re-weighed, not violated. P-5 forbids "chrome that doesn't carry meaning"; the header carries navigation + orientation + control, so it clears that bar — and calm's minimal treatment adds no decorative density. The original FR-009 rationale judged the whole header vivid-identity decoration; we separate its function (universal) from vivid's aesthetic (vivid-only).

4 · Deltas

One <spec-delta> — MODIFY FR-009. The post-state is rendered inline as it will appear when archived.

What changes: the header is no longer vivid-only — every artifact presents it in both themes (calm in a minimal, calm-native treatment; vivid keeps its blurred bar), and the theme/mode controls move to the header in both (calm's footer switcher is removed). The P-5 rationale is re-weighed.

Every artifact MUST present a sticky top header carrying, left to right: a brand/back-link (the spectastic mark, linking to the project landing index.html); the artifact's path/name; the theme dropdown; and a light/dark mode control shown as a sun/moon icon. The theme dropdown and mode control MUST live in this header — not the footer — in both themes. Each theme renders the header in its own register: spectastic-vivid presents the dense, backdrop-blurred, reference-faithful bar; spectastic-calm presents a minimal, calm-native treatment — flat warm-cream surface, a thin bottom rule, restrained height — carrying the same elements without vivid's blur or density (per P-5). The header is built by the existing switcher logic, so it needs no per-document markup (NFR-005); in each theme it MUST hold WCAG AA contrast over its backdrop (NFR-003), reflect the booted theme/mode with no flash (NFR-001), and — with JavaScript disabled — render no header at all (it is JS-built) while the artifact falls back to the default calm theme, fully readable (NFR-002).

Rationale

Un-deferred vivid-only on the 2026-06-19 re-entry to resolve the P-5 (calm density) tension. Re-weighed (T-009): the value is the header's positioning — always-visible navigation (brand/back-link → index.html), orientation (the path), and control (theme + mode), so they are never "go fish" in the footer — not vivid's aesthetic. Calm therefore gains the same elements and sticky position in a minimal, calm-native treatment (no blur or density), which honours P-5's "no chrome that doesn't carry meaning" while keeping the distinct calm and vivid identities. The footer switcher is removed in both themes.

5 · Risk register

Adversarial pass per REQ-CHANGE-004 (triggered: FR-009 is priority="must"). Statuses stay identified until the author commits them — apply refuses while any remain identified.

Rendering calm's header identical to vivid (backdrop-blur + density) imports vivid's aesthetic into calm and erodes the calm/vivid distinction the whole spec is built on — in 30 days the regret is "calm no longer looks calm, so why two themes?"

The original draft's FR-009 "render the identical header" + §3 "we accept the identical treatment" (both revised by this mitigation). The blurred bar is the most vivid-coded chrome (SC-006 lists it under "Header (vivid only)").

Mitigated: flipped to a lighter, calm-native header. Calm keeps its minimal register — flat warm-cream surface, thin rule, no blur or density — so the calm/vivid distinction holds; calm gains only the header's position + controls (nav / orientation / control), which carry meaning under P-5. The header's blur + density stay vivid-only.

With the header JS-built and calm's footer switcher removed, a no-JS calm reader would have no header and no switcher — no theme/mode affordance at all.

FR-009 no-JS clause + §2 Scope "Remove calm's footer theme/mode switcher."

Theme/mode switching is already JS-gated (NFR-002 / P-4 progressive enhancement) — the footer switcher never functioned without JS, so removing it loses no no-JS capability; the artifact still renders fully readable in calm + light. Incorporated: the FR-009 no-JS clause now says no header is built (it is JS-rendered), removing the apparent self-contradiction.

"Covered transitively by SC-006" is an untested assumption — calm's lighter #f6f5f1 background gives a different contrast situation over the blurred backdrop than vivid, so calm's header may fail NFR-003 where vivid passes.

§Scope out-of-scope item "Reference-parity for calm's header … covered transitively"; SC-006 measures vivid only.

Incorporated: NFR-003 (WCAG AA over the blurred backdrop) now applies to the header in both themes in the new FR-009, so calm's contrast is required — not assumed. Added a §6 task to verify calm's header contrast against its own background, and corrected the out-of-scope item.
