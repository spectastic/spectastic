Boundary map detection

Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 081-boundary-map-detection Design design Branch main Created 02 Aug 2026 Read time

16 tasks across five phases. A task is [P] only where no sibling in its phase touches the same file. Tests for a story MUST be written and failing before its implementation tasks start.

1 · Execution strategy

The fit. The normalised shape lands first because both readers target it, then one reader per format, then the dispatch that decides between a map, no map, and unmapped-by-form.

Either reader alone is shippable. Viable — but shipping one first is exactly what lets the shape become whatever that format emits, which D-001 takes both formats to avoid.

The two readers are genuinely independent once the shape exists, so this is the one slice here where parallel work would fit. Not applicable for a single author.

2 · Phase 1 — Setup

Add the boundary modules to the build — tsup entries and export subpaths, so 082 can import the map without the CLI. packages/core/tsup.config.ts

3 · Phase 2 — Foundational

The shape both readers target, and the three-state result.

Define the map and the three-state result — a map, no map, and unmapped-by-form carrying its reason; the third is the one a reader most needs distinguished. packages/core/src/units/boundary.ts

4 · Phase 3a — US1 · Read the rings a project already declares

Tests (write & fail first)

Test the Nx ESLint form — tags from project.json, constraints from an ESLint config under onlyDependOnLibsWithTags. packages/core/test/units.boundary.test.ts
Test the Nx conformance form — the same map from nx.json under onlyDependOnProjectsWithTags, and tags from a package.json sub-key (D-001). packages/core/test/units.boundary.test.ts
Test the import-linter form — an ordered layers contract expanding losslessly into permitted pairs (D-002). packages/core/test/units.boundary.test.ts
Test a map with units and no constraints — legal, and distinct from having no map at all. packages/core/test/units.boundary.test.ts

Implementation

Implement the Nx reader — both constraint locations and both tag locations, treating a partial read as no map. packages/core/src/units/adapters/boundary-nx.ts
Implement the import-linter reader — the narrow INI subset, parentheses stripped from optional layers (D-003). packages/core/src/units/adapters/boundary-import-linter.ts
Implement the format dispatch — first positive map wins; a positive map is never merged with forbidden edges (FR-004). packages/core/src/units/adapters/boundary.ts

Closes FR-001, FR-004 and SC-001.

5 · Phase 3b — US2 · Be told when the declaration cannot answer the question

Tests (write & fail first)

Test the unmapped-by-form case on this repository — one forbidden-edge config and no positive map, reported with its reason rather than half-derived (FR-002, SC-002). packages/core/test/units.boundary.test.ts
Test that no boundary config yields no map — distinct from unmapped-by-form, which means the project declared something unusable. packages/core/test/units.boundary.test.ts
Test that malformed config degrades — no map, no throw (FR-006, SC-004). packages/core/test/units.boundary.test.ts

Implementation

Detect the negative forms and report the reason — dependency-cruiser and ArchUnit recognised well enough to say why they cannot answer, never to derive a partial order. packages/core/src/units/adapters/boundary.ts

Closes FR-002, FR-005, FR-006, SC-002 and SC-004.
