A screen is a kind

Applied

1 · Intent

FR-013 has been written twice and been wrong twice, and both failures share one cause: the mechanism was asserted from a spec that describes it, without opening the code to see which half shipped.

The first attempt described …/spec/<spec-id>/screen/<name>. The kind segment is the first recognised literal in the path, so that parses as kind spec with the name <spec-id>/screen/<name> — a spec coordinate wearing a screen's clothes. The second used 067's anchor fragment, which names something inside spec.html; a screen is declared in a sidecar, so the coordinate composed, parsed, and dereferenced to nothing. Nothing in the codebase resolves an anchor at all.

Opening project-shared.ts settles it and corrects the diagnosis that was offered for the first failure. It was called a nested form no kind uses — but name is documented as "everything after the kind, joined by /", and the corpus kind already ships a two-segment name, plugin/slug. The composer interpolates name verbatim. So a multi-segment name is neither new nor a problem; making screen a segment inside a spec's name was.

A screen becomes a fifth kind with a two-segment name — the corpus precedent applied exactly. It denotes the screen rather than a fragment of a document the screen is not in.

2 · Scope

In scope

  • A screen resource kind, named <spec-id>/<screen-id>.
  • Both halves of 076 FR-007, the first strengthened to required: a declared coordinate name, and a collision reported as an error.
  • A minting surface — spectastic id is spec-only by construction, so the requirement ships with something able to satisfy it.
  • Amending 078, whose enumeration names three kinds against five shipped.

Out of scope

  • A consumer. Nothing is obliged to use this yet, and shipping a consumer as a task with no delta is one of the defects being corrected. defer-to=099-visual-embedded-view
  • Resolving a coordinate to an open document. Nothing resolves any coordinate today — that is a gap across every kind, not this one. defer-to=TBD-coordinate-resolution

4 · Deltas

What changes: the mechanism is a resource kind rather than a fragment or a nested spec name, and the collision rule arrives with its escape hatch.

A declared screen MUST be addressable by a resource coordinate of its own kind, qualified by the spec that owns it; a screen MUST declare the name it is addressed by, and two screens within one spec resolving to the same name MUST be reported as an error.

Rationale

A screen is the thing a design conversation is most often about and was the one thing it could not name, while a contract has had a coordinate since 076.

A kind, not a fragment. An anchor names something inside the document its coordinate denotes — a requirement or a task inside spec.html — and a screen is declared in a sidecar, so an anchor coordinate composes, parses, and points at nothing. A kind denotes the screen itself. The name spans two segments, the owning spec and the screen, which is the shape the corpus kind already ships as plugin/slug: name is everything after the kind, and the composer interpolates it verbatim.

The declared name is 076 FR-007's first half, taken this time rather than dropped — and strengthened past its tier, deliberately. 076 is should-tier and its own follow-up found that should-tier plus no prompt produced filenames-as-keys for every contract in the estate. Requiring it here means one identity is authoritative for addressing, a collision cannot silently arise, and the rename screen-shape warns against is never the remedy. The cost is an attribute on every screen, which the authoring prompt supplies. The first draft of this correction wrote MAY while claiming to inherit both halves; under the committed conformance vocabulary an author who never declares one would then be fully conforming, leaving the rename that screen-shape warns against as the unremarked default. Without it the only cure for a collision is renaming a screen — and FR-001 requires that identifier to be stable precisely because annotations, traces and reviews reference it. A requirement whose sole remedy breaks its neighbour is not a remedy.

5 · Risk register

Run by an independent spectastic-critic against the draft, before apply — which is where the skill puts it and where the previous two attempts did not. Every finding is left at identified with no by=; the dispositions are the author's to commit.

The load-bearing grounding row is overstated, and the spec that owns the grammar is unmentioned

§3 asserted "widening takes two edits" as verified. The cited comment says the two declarations move together; it never says they suffice, and the estate proves they do not — when unit was added the round-trip matrix behind 078 FR-008's "for every kind" was left covering three, and 078 FR-005 still reads "spec, contract and corpus". Two must-tier obligations are already one kind stale; this adds a second. §1 also called screen "a fourth kind" when the union it claims to have opened holds four already.

Mitigated. Verified independently: ResourceKind is 'spec' | 'contract' | 'corpus' | 'unit', the matrix matches unit zero times, and 078 FR-005 enumerates three. The row is re-marked assumed, the count corrected, and a warning added that amending 078 is part of this change. Whether this proposal should carry deltas on 078 rather than a task is the open call.

Update, 14 Aug — every fact above has since changed, and the disposition still holds. Recorded rather than rewritten, because the response is a record of what was checked and when. Since it was written, 078's own amendment landed and was implemented: the two declarations are collapsed into one RESOURCE_KINDS, the matrix now matches unit across all four combinations, and FR-005 enumerates nothing. The open call is answered by that, not by this proposal — deltas on 078 were the wrong instrument (the apply kernel folds same-spec deltas only), and the sibling propose was the right one. What remains for screen is one edit to the declaration plus its fixtures, and 078 FR-014 now fails if the fixtures are missed rather than letting the omission through, which is the hazard this finding was actually about. Filed as 095/T-005.

A second identifier whose stability nothing owns, and a justification that contradicts the clause beside it

§3 says "the spec id is what disambiguates". It does not: two files under one spec's directory can each declare converter and produce the same name — which is exactly why the delta then needs a collision error. So a screen carries an id that annotations and traces reference and a coordinate name external references pin, with different uniqueness scopes, and only the first is checked by anything that ships.

Mitigated. The sentence is wrong as written and should say the spec id qualifies rather than disambiguates. Whether one screen may carry two identities at all is the real question, and it may be an argument for the declared name being required rather than recommended.

Neither a composer nor a consumer, and it orphans the card it was sequenced behind

Scope defers the consumer to 099 and defers nothing to mint the coordinate. The only minting surface is spectastic id, which is spec-only by construction — it throws unless specs/<spec-id> exists and calls specResourceUri with the kind hardcoded, and the CLI registers no --kind. Meanwhile T-003's fix says the 099 propose is sequenced after this settles what a screen coordinate is; applying this closes T-002 and T-004 and leaves T-003 with nothing scheduled. Which is T-002's original charge restated: a MUST nothing can determine conformance against.

Mitigated. Accurate. Either this change grows the minting surface, or FR-013 should not be must-tier until something can produce a coordinate.

"Both halves" re-tiered one of them, against the committed conformance vocabulary

KB-0001@2026-07-25 commits "SHOULD — a strong recommendation; a reason to deviate must exist" against "MAY — genuinely optional; either choice is conforming." 076 FR-007 is should-tier; the draft shipped MAY while §Scope claimed both halves and §3 called the declared name the escape hatch. Optional escape hatch, unremarked rename default — and 076's own follow-up found that even at should-tier nothing prompts for the attribute, so every contract key is a filename in practice.

Mitigated. Corrected to SHOULD in the delta above. The deeper finding stands unanswered: should-tier plus no prompt produced filenames-as-keys for contracts, and nothing here prevents the same outcome.
