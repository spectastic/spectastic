22 tasks across four phases. Setup → Foundational → User stories (US1·US2) → Polish. Tasks marked [P] can run in parallel — different files, no dependency. Tests for a story MUST be written and failing before its implementation tasks start.

1 · Execution strategy

Setup → Foundational → US1 → US2 → Polish. US1 lands screens and states; US2 lands annotations on top of them. A screen with no annotations is already useful, which is what makes the split honest rather than administrative.

US1 alone ships the thing the survey was written about: the states nobody drew, made visible. Annotations are the half that turns a drawing into an assertion.

Not applicable. One vocabulary, one stylesheet, one shared constants module.
