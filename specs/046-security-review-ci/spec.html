Read time

045 shipped the two boundary gates (the no-executable-content validate rule and a strict template CSP), proven by isolated positive/negative fixture pairs and one browser spike. That proves the rule works on a toy input — it doesn't prove it holds against a realistic combined payload, and nothing stops a security regression from merging: today's CI dogfood runs with || true (advisory) and never fails the build. This spec is the adversarial-testing sibling. It adds (1) a single hostile spec-family artifact carrying the full injection battery, (2) a red-team test that asserts every categorical vector is blocked and every hidden-channel vector is honestly marked not-yet-blocked (the FR-004 gap 045 deferred), (3) a corpus-clean assertion, and (4) a dedicated security-review CI job that fails hard on any finding. The dual-LLM ceiling and the AI-verb fence red-team stay out of scope — the fence itself isn't built yet.

1 · Context

045 ratified the enforcement half of P-11: a no-executable-content validate rule (author-time) and a strict CSP (open-time). Its coverage is proven by per-vector positive/negative fixture pairs — each vector in isolation. Spectastic's own threat model (recommendation 7) and the project's standing verification discipline both say the same thing: a rule that passes on a toy input is not verified against a real adversary. A hostile spec combines vectors, buries instructions in channels a human never sees, and only has to find one that slips through.

Two concrete gaps remain after 045. First, there is no red-team — no single realistic hostile artifact the layer is tested against end to end. Second, the gate has no teeth in CI: the dogfood step runs spectastic validate … || true and only uploads SARIF, so a <script> merged into a shipped artifact would not fail the build. This spec closes both, and is honest about what the categorical rule does not yet catch (the hidden-channel vectors 045 deferred to its FR-004 heuristic rule).

2 · User scenarios & testing

US1 · A security regression fails CI P1

As a maintainer, I want executable content in any shipped artifact to fail a dedicated CI job so a regression can't merge — not merely be logged to SARIF.

Acceptance: a security-review job runs on every push and PR; if any artifact in the scanned corpus carries a no-executable-content error, the job exits non-zero and the build is red. A clean corpus passes.

US2 · The layer is red-teamed with a real payload P1

As a reviewer, I want one hostile artifact carrying the full injection battery, and a test asserting the categorical vectors are all caught, so coverage is proven against a realistic attack, not just isolated fixtures.

Acceptance: a checked-in adversarial artifact carries an inline script, a non-sanctioned external script, an on*= handler, a javascript: URI, a data: URI, and an <iframe>; the red-team test asserts validate raises a no-executable-content error for each.

US3 · Coverage is legible, not overclaimed P2

As a reviewer, I want the hidden-channel vectors the categorical rule does not yet catch to be asserted as a documented gap, so no one mistakes "the red-team passes" for "every channel is closed".

Acceptance: the same hostile artifact carries an imperative HTML comment, a display:none instruction block, an aria-hidden block, and zero-width Unicode; the red-team test asserts these produce no finding today and marks each as the deferred 045 FR-004 gap.

Edge cases

  • Courses stay exempt. The red-team asserts a course-titled artifact with an inline gate script is not flagged — the sanctioned-interactive carve-out from 045 must survive.
  • Advisory vs hard. The existing structural dogfood stays advisory (SARIF, || true); only the new security gate fails the build. A structural WIP finding must not turn the security job red, and vice versa.
  • docs/** is unscanned. The corpus glob excludes docs/** (as today). A hostile docs page would not be caught by the corpus gate — a recorded ceiling, deferred, not silently closed.

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional

The repository MUST carry a single checked-in adversarial injection fixture — one hostile spec-family artifact combining, in one document, every categorical injection vector the no-executable-content rule governs (an inline <script>, a non-sanctioned external <script src>, an on*= handler, a javascript: URI, a data: URI, and an <iframe>) and a representative set of hidden-channel vectors (an imperative HTML comment, a display:none instruction block, an aria-hidden block, and zero-width Unicode smuggling).

Rationale

One realistic combined payload, not isolated pairs. It doubles as the living record of what the layer is tested against, and what it does not yet catch.

A red-team test MUST run validate over the fixture and assert that every categorical vector produces a no-executable-content error finding. It MUST also assert that every hidden-channel vector produces no finding today, each marked as the deferred 045 FR-004 gap, and that a course-titled variant carrying an inline gate script is not flagged (the sanctioned-interactive carve-out holds).

Rationale

Structural "it renders / the rule exists" checks are insufficient — the standing discipline. Asserting the gap explicitly keeps coverage legible: "the red-team passes" never reads as "every channel is closed".

A corpus-clean assertion MUST run validate over the shipped spec-family corpus (the same glob the CI dogfood scans — specs/**, examples/*, and the root artifacts) and assert zero no-executable-content findings, so a security regression in a real artifact is caught, not just a synthetic one. The adversarial fixture MUST be excluded from this glob (it is hostile by design).

A dedicated security-review job in the CI workflow MUST run the red-team (FR-002) and corpus-clean (FR-003) gates and MUST fail the build (non-zero exit) on any finding. The pre-existing structural dogfood MUST remain advisory (SARIF upload, non-blocking) — the two gates MUST NOT conflate, so a structural finding never fails the security job and a security finding is never merely logged.

Rationale

A distinct, required status check is the guarantee half (P-8): the gate lives in CI, not in prose. Keeping it separate from the advisory dogfood is what gives "security fails hard" a clean meaning.

Non-functional

The red-team and corpus-clean gates MUST be deterministic and offline — a static fixture and pure validate calls, no network and no LLM. Re-running on the same commit MUST yield the same result.

Out of scope (deferred)

  • Extending the security corpus scan to docs/**. Docs are artifacts too and pass the rule clean today, but bringing them into the gate is a separate decision — the exclusion is a recorded ceiling here, not a silent gap.
  • The hidden-instruction heuristic rule that would actually catch the hidden-channel vectors (045 FR-004). This spec only documents the gap; closing it is 045's later slice.
  • A red-team of the AI-verb fence/sanitize step (045 FR-003) — the fence is not built yet, so there is nothing to red-team.
  • Exfiltration / lethal-trifecta tool-layer tests (allowlisted egress, no-auto-render). These need the fence and a tool-boundary first; a far-future ceiling.

4 · Data model

This feature owns no persistent entities. It adds one static hostile HTML fixture, two test assertions (a pure function over validate's output), and one CI job definition.

Categorical vector
An injection channel the no-executable-content rule flags categorically today: <script> (non-sanctioned), on*=, javascript:/data: URI, <iframe>. Asserted blocked.
Hidden-channel vector
An invisible-to-a-human channel a model still reads: HTML comment, display:none/aria-hidden text, zero-width Unicode. Asserted not-yet-blocked (the 045 FR-004 gap).

5 · Success criteria

Adding a <script> (or any categorical vector) to a shipped artifact makes the security-review CI job fail (non-zero exit); with the corpus clean, the job passes. Demonstrable by a local dry-run of the gate over a temporarily-dirtied artifact.

The red-team test documents both the blocked categorical vectors and the not-yet-blocked hidden-channel vectors, so a reader can see exactly what the layer stops and what it defers — coverage is legible, never overclaimed.

6 · Assumptions

spectastic validate exposes the no-executable-content rule id and error severity in its output (it does — 045 FR-001), so the red-team can assert per-vector rather than on a bare pass/fail.

The shipped corpus is clean of executable content at authoring time (045 verified this), so FR-003 lands green with zero migration.

7 · Open questions

None outstanding — fixture scope (both categorical + hidden-channel, gaps marked), CI shape (a job in the existing workflow), gating hardness (security fails hard, dogfood stays advisory), and corpus glob (docs excluded, recorded) were all anchored in the interview.
