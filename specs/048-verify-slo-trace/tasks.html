17 tasks across five phases. Setup → Foundational (the shared ObservablesRow reader + the CapturedRun.observables field, both loci every story reads) → US1 (the §Observables trace + the widened stale-rule guard, since SC-001 requires both) → US2 (the run-grounded capture) → US3 (the signal cross-check) → Polish. Tasks marked [P] touch a distinct file with no in-flight dependency. Per story, tests are written and failing before implementation starts (plan D-005).

1 · Execution strategy

Setup → Foundational → US1 → US2 → US3 → Polish. US2's capture rendering and US3's cross-check both read the ObservablesRow shape US1 renders against, and the cross-check specifically needs the capture US2 adds — a real dependency chain, matching the plan's Low risk-tolerance call (every locus extends shipped code, so sequencing tight keeps the copy-verify loop short).

Ship US1 alone (the derived trace + quantified gaps, no run-grounding) and stop. US2/US3 (the capture + the cross-check) land as a second pass once the trace shape has seen review.

Not recommended — US3's cross-check is a direct extension of US2's capture-rendering code in the same function (renderVerifyHtml's §3), and both read the Foundational ObservablesRow shape US1 renders.

2 · Phase 1 — Setup

Extend the existing verify-view-stale fixture pair with NFR/SLO content — the registry harness allows exactly one positive/negative bundle per rule; add an <spec-slo target="NFR-001"> to both spec.htmls, drifted (unlinked) in the positive bundle and consistent (linked) in the negative, so the one pair exercises the observables-drift leg alongside the existing SC/task-drift leg. packages/schema/fixtures/verify-view-stale/{positive,negative}/specs/999-*/spec.html + verify.html

3 · Phase 2 — Foundational

The two shared loci every story reads or writes: the reader's NFR/SLO derivation, and the capture's type shape.

Add ObservablesRow + extend readBundle — collect every <spec-slo> grouped by its target NFR and every NFR-* requirement into BundleModel.observables; classify each row as traced (has an SLO), loud gap (quantified via isQuantifiedTarget, no SLO), or n/a (D-001, D-003). packages/core/src/commands/verify.ts
Add CapturedRun.observables — a structured field: endpoint, signals (golden-signal ids observed), slosCite, and the existing verified flag's scope extended to cover it (D-002). packages/core/src/types.ts

4 · Phase 3a — US1 · An NFR gets a proof leg

Tests (write & fail first)

Author readBundle/render observables tests — an NFR with a linked <spec-slo> traces (objective/window/SLI/signal shown); a quantified NFR with no SLO is a loud gap; a non-quantified NFR is a quiet n/a. packages/core/test/verify.observables.test.ts
Author the widened verify-view-stale fixtures + test — positive: a bundle whose <spec-slo> target set no longer matches what verify.html links; negative: matching sets, and a bundle with no SLOs at all (NFR-002, no false positive). packages/schema/fixtures/verify-view-stale/*.html + packages/schema/test/verify-view-stale.test.ts
Author the §Observables Playwright spec — asserts the section renders, gap rows are visually distinct, and the table doesn't overflow its container; written against the not-yet-existing render so it fails first (SC-001). tests/verify.observables.spec.ts

Implementation

Render §3 Observables — renderObservables mirroring renderTrace's table shape, consuming T-010's rows; quantified-aware gap styling reusing TRACE_GAP (FR-001). packages/core/src/commands/verify.ts
Widen verify-view-stale — derive the expected NFR-id set from the bundle's <spec-slo target>s, compare to the ids §Observables links, and emit an observablesDriftFinding (error) on mismatch, mirroring driftFinding; an empty set → no finding (FR-004). packages/schema/src/rules/verify-view-stale.ts

Closes FR-001, FR-004, SC-001.

5 · Phase 3b — US2 · The instrumentation is grounded in a real run

Tests (write & fail first)

Extend the observables tests for the capture — an observables capture fills the instrumentation column; absent renders loudly "not recorded"; verified:false renders "suggested"; a links-only regeneration preserves an existing capture. packages/core/test/verify.observables.test.ts

Implementation

Render the instrumentation column from the capture — the endpoint + observed signals, with the not-recorded/suggested affordances cloned from renderRunBlock (FR-002). packages/core/src/commands/verify.ts
Preserve the capture on links-only regen — a new OBSERVABLES_RE extract/re-inject, mirroring RUNBLOCK_RE (NFR-001). packages/core/src/commands/verify.ts
Extend the CLI's captured-run cast — readCapturedRun's inline type gains observables so it passes through from stdin JSON untouched. packages/cli/src/commands/verify.ts

Closes FR-002; contributes to SC-002 (fully closed by US3).

6 · Phase 3c — US3 · A claimed signal that isn't emitted is caught

Tests (write & fail first)

Extend the observables tests for the signal cross-check — a verified capture missing a signal the SLO declares is a loud gap; the same missing signal on a suggested or absent capture produces no gap (D-003). packages/core/test/verify.observables.test.ts

Implementation

Implement the verified-only signal cross-check — for each SLO with signal=, compare against the capture's observed-signals set only when verified !== false; a declared-but-unobserved signal renders a loud gap (FR-003). packages/core/src/commands/verify.ts

Closes FR-003, SC-002.

Browser-verify SC-001/SC-002 on a fixture bundle — confirm the trace, gaps, and cross-check render correctly in both themes with zero console errors. (verification run)
