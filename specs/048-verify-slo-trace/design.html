Verify-page observables trace

Four edits, every one extending shipped code: the verify generator, one CapturedRun field, the stale rule, and 047's slo heuristic.

Status Accepted Spec 048-verify-slo-trace Owner Brian Corbin · @briancorbinxyz Branch verify-slo-trace Created 12 Jul 2026 Read time

The verify generator (021) already reads a spec+tasks bundle into a BundleModel and renders an SC trace + a run-grounded Run/Demo block. This adds a parallel §Observables trace: extend the reader to collect <spec-slo> (grouped by target NFR) + all NFRs, add a structured observables CapturedRun field (plain-JSON passthrough), render §3 with quantified-aware gaps and a verified-only signal cross-check, and widen verify-view-stale to guard the new NFR/SLO links. All grounding verified; no spikes; Low risk.

4 · Approach

The generator already has the exact shape to copy. Reader: readBundle gains an observables pass — collect every <spec-slo> grouped by its target NFR, and every NFR-* requirement; each NFR becomes an ObservablesRow (its SLOs, or a gap classified by isQuantifiedTarget). Field: CapturedRun gains a structured observables object (endpoint · observed golden signals · cited ids · verified flag), a plain-JSON passthrough the CLI already forwards. Render: a §3 Observables table mirrors renderTrace, with the instrumentation column from the capture (loud "not recorded" / "suggested" reusing the Run/Demo affordances) and a verified-only signal cross-check. A new OBSERVABLES_RE preserves the capture on links-only regen. Guard: verify-view-stale gains an observablesDriftFinding mirroring driftFinding.

6 · Decisions

D-001 · §Observables trace extends the generator, mirroring the SC trace

Status
Accepted
Context
verify.ts already reads a bundle into BundleModel and renders renderTrace; the NFR trace is the same shape over <spec-slo> instead of test tasks.
Decision
readBundle gains an ObservablesRow[] (NFRs × their SLOs / gap class); renderVerifyHtml gains a §3 table mirroring renderTrace. By-reference, links + the SLO's own declared values.
Consequences
+ One cohesive generator; identical determinism story. + Reuses textOf/findAll/TRACE_GAP. − BundleModel grows one array.

D-002 · A structured observables CapturedRun field, passthrough + preserved

Status
Accepted
Context
readCapturedRun (cli/verify.ts:53) is JSON.parse + a cast — a new field needs no parser work; RUNBLOCK_RE (verify.ts:359) is the links-only preservation pattern.
Decision
Add observables?: { endpoint?, signals?: string[], slosCite?: string[], verified? } to CapturedRun; render it in the instrumentation column with the existing not-recorded/suggested affordances; preserve it on links-only regen via a new OBSERVABLES_RE.
Consequences
+ No new parsing/validation; forward-compatible (passthrough). + Same P-7 honesty as Run/Demo. − Two preserve-regexes to keep in step.

D-003 · Gap + cross-check logic reuses 047's slo helpers; cross-check is verified-only

Status
Accepted
Context
@spectastic/schema/slo exports isQuantifiedTarget + isGoldenSignal/GOLDEN_SIGNALS (slo-shared.ts:12-38).
Decision
A SLO-less NFR that isQuantifiedTarget → loud gap; else quiet n/a (FR-001). The declared-vs-observed signal cross-check (FR-003) fires only when the capture is verified (run) — a suggested capture's missing signal means "not checked", not "not emitted".
Consequences
+ No new heuristic; the gap gate matches 047's quantified rule. + Verified-only avoids a false "unobserved" gap. − One extra branch on the verified flag.

D-004 · verify-view-stale widens with an observablesDriftFinding

Status
Accepted
Context
driftFinding (verify-view-stale.ts:167) compares expected SC/task id sets vs linkedIds(verify) — the exact pattern to mirror.
Decision
Derive the expected NFR-id set (NFRs referenced by <spec-slo target>) from the bundle; compare it to the NFR ids verify.html's §Observables links; a mismatch is an error via a new observablesDriftFinding. An empty set (no SLOs) → no finding, so existing bundles are untouched.
Consequences
+ The derived view stays honest, same as the SC trace. + Zero effect on SLO-less specs (empty set). − One more id-set derivation in the rule.

D-005 · Structural vitest + a light browser check

Status
Accepted
Context
The generator renders HTML and the stale rule is a schema rule; the §Observables table is static (no interaction), but positioned content should not overflow (CLAUDE.md discipline).
Decision
Fixture-bundle vitest for readBundle/render (rows, gaps, cross-check) + a schema fixture pair for the widened rule; a light Playwright render/containment check reusing the 021 verify harness.
Consequences
+ Proves the derivation logic and the render. − One browser spec to maintain.

9 · Complexity tracking

The verified-only gate on the signal cross-check (D-003) is one extra branch beyond a naive "flag any present capture" — justified: a suggested capture's missing signal is "not checked", and flagging it would be a false P-7 gap. Confirmed in the interview.
