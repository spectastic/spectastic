Verify-page observables trace

Today verify.html proves success criteria and ignores NFRs. This gives a reliability NFR a proof leg — SLO to SLI to the instrumentation that actually emitted it.

Read time

The observability chain's last rung. 047 gave an NFR a first-class <spec-slo>, but verify.html still traces only SC-NNN — a reliability target has no proof leg. This adds a §Observables trace: each NFR → its <spec-slo> (objective · window · SLI · signal) → the instrumentation that emitted it. Grounded, like the Run/Demo block, in a real run — a structured observables capture (one per-project endpoint + the golden signals observed) — and the trace cross-checks each SLO's declared signal= against what was seen: a claimed but unobserved signal is a loud gap. Gaps are quantified-aware (047's heuristic): an SLO-less NFR that looks like a reliability target is a loud gap; a non-quantified NFR a quiet n/a. verify-view-stale widens to guard the new links. 1 · Context

The chain is NFR → SLO → SLI → instrumentation. 047 built the SLO rung (<spec-slo target="NFR-NNN"> — SLI, objective, window, budgeting, golden signal). But verify.html — spectastic's P-7 proof view — derives a trace only for SC-NNN (success criterion → acceptance → test task). An NFR appears in no trace, so a quantified reliability target still has no proof leg: nothing shows that the promised SLO is backed by instrumentation that actually emits its signal.

This is the fourth and final move of the observability-slo research — the other three (the principle, the enforce category, the <spec-slo> artifact) have shipped. It closes the loop by giving the NFR the same proof leg the SC already has.

2 · User scenarios & testing

US1 · An NFR gets a proof leg P1

As a reviewer, I want each NFR traced to its SLO and the instrumentation that emits it, so a reliability promise is proven, not asserted.

Acceptance: verify.html gains a §Observables section; an NFR with a linked <spec-slo> shows its objective · window · SLI · signal, plus the captured instrumentation; a quantified NFR (047's heuristic) with no SLO is a loud gap; a non-quantified NFR is a quiet n/a.

US2 · The instrumentation is grounded in a real run P1

As an implementer, I want to record the real /metrics check so the trace shows evidence, not intent.

Acceptance: a structured observables capture (one per-project endpoint + the golden signals observed, citing the SLO/NFR ids) fills the instrumentation column; absent, it renders loudly not recorded; unexecuted, it renders suggested (P-7), never as verified.

US3 · A claimed signal that isn't emitted is caught P2

As a reviewer, I want an SLO whose declared signal the run didn't observe flagged, so "present ≠ wired" can't hide.

Acceptance: for each SLO, its signal= is cross-checked against the observed-signals set; a declared-but-unobserved signal renders a loud gap in the trace.

Edge cases

  • No SLOs at all. A spec with no <spec-slo> renders verify.html as before — the §Observables section states "no SLOs declared", never a broken table (NFR-002).
  • Multiple SLOs per NFR. Each linked <spec-slo> is its own row under the NFR; each cross-checks its own signal.
  • No capture. The trace still derives from the bundle; only the instrumentation column is "not recorded" — the NFR → SLO → SLI legs are present.

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional

verify.html MUST gain a §Observables trace derived by reference from the bundle: one row per NFR, showing — for an NFR with a linked <spec-slo> — its objective, window, SLI, and signal (read from the <spec-slo>), plus the instrumentation column (FR-002). Gaps MUST be quantified-aware: an NFR with no linked <spec-slo> that is quantified (the @spectastic/schema/slo isQuantifiedTarget heuristic — it looks like a reliability target) renders a loud gap; a non-quantified NFR renders a quiet n/a.

Rationale

The NFR analog of the SC → acceptance → test trace, extending P-7. Not every NFR is a reliability target, so — unlike the SC trace, where every SC is a loud gap without a test — the gap is gated on 047's quantified heuristic to avoid false alarms on security/determinism NFRs.

A structured observables field MUST be added to the captured-run model: one per-project capture of the metrics endpoint and the golden signals observed (a subset of latency / traffic / errors / saturation), plus the SLO/NFR ids it cites. It fills the instrumentation column; when absent it MUST render loudly as not recorded (never a silent blank), and when marked unexecuted it MUST render as suggested — not yet run, mirroring the Run/Demo block's P-7 honesty.

For each <spec-slo> carrying a signal=, the trace MUST cross-check that signal against the captured observed-signals set; a signal the SLO declares but the run did not observe MUST render a loud gap — the proof that the SLO's claimed observability is actually emitted. When no capture exists, the cross-check is skipped (the instrumentation column already reads "not recorded").

The verify-view-stale rule MUST widen to guard the new links: it derives the expected NFR/SLO id set the bundle declares and compares it to what verify.html's §Observables trace links, flagging drift at error severity — the same drift-guard the SC/test-task trace already gets, so a changed <spec-slo> set without regeneration is caught.

Non-functional

Regeneration MUST stay deterministic and byte-identical on an unchanged bundle (no timestamps, stable order), and the captured observables block MUST be preserved on a links-only regeneration — mirroring the Run/Demo block's FR-006 behaviour. No new runtime dependency.

A spec with no <spec-slo> SHOULD render verify.html exactly as today apart from a "no SLOs declared" §Observables note — no broken table, no regression to the existing SC trace.

Out of scope (deferred)

  • verify itself probing a live /metrics endpoint — the capture is recorded by whoever runs the check (like tests/demo), a real-run input, not something the deterministic generator fetches.
  • Gating on observability coverage — that is the shipped observability enforce category's job; this view proves, it does not gate.
  • Per-SLO / multi-service captures (different SLOs hitting different endpoints) — the per-project capture covers the common single-service spec.

4 · Data model

Extends two existing models; owns no persistent entity.

Observables trace row
An NFR id, its linked <spec-slo>(s) with objective/window/SLI/signal, and a status: traced, loud gap (quantified, no SLO, or a declared-but-unobserved signal), or n/a (non-quantified, no SLO).
Captured observables
Per-project: the metrics endpoint, the observed golden-signal set, the cited SLO/NFR ids, and the executed/suggested flag. A field on the captured-run model beside tests/demo.
Golden signal
The Four Golden Signals enum (latency / traffic / errors / saturation), reused from 047's @spectastic/schema/slo.

5 · Success criteria

For a bundle whose NFR has a linked <spec-slo>, verify.html renders a §Observables row tracing that NFR → its SLO (objective · window) → SLI → instrumentation; a quantified NFR lacking an SLO renders a loud gap; a non-quantified NFR renders a quiet n/a; and regeneration is byte-identical and guarded by verify-view-stale.

The instrumentation column reflects the real captured run — its endpoint and observed signals — and an SLO whose declared signal= is not in the observed set renders a loud gap; with no capture the column reads loudly not recorded, never silently blank.

6 · Assumptions

The <spec-slo> shape (047) and the isQuantifiedTarget / golden-signal exports (@spectastic/schema/slo) are stable and available to the verify generator — both shipped 12 Jul 2026.

The observability capture is trustworthy input recorded by the runner (the P-7 suggested/verified flag is its honesty control); verify does not itself confirm the endpoint is live.

7 · Open questions

None outstanding — slice scope (all three parts), quantified-aware gap rendering, the structured per-project capture, the declared-vs-observed signal cross-check, and widening verify-view-stale were all anchored in the interview.
