Course teaching payload

A course objective's teaching content is one flat paragraph — the weakest way to learn. Give it the moves the art of teaching turns on: an analogy, two cases held side by side, a worked example, a picture beside the words.

A course objective's whole teaching payload is one flat read string — mechanically, rereading, the lowest-utility study technique. 1 · Context

019-explain-course generates a grounded course: each objective carries a read paragraph and a quiz, and the kernel verifies every cited reference and rejects a blind-guessable quiz before writing. The quiz is retrieval practice done right — but the teaching half, the read, is one flat string. The teaching considerations brief makes the cost concrete: a paragraph-you-read is, mechanically, rereading — the technique the evidence rates lowest — and the moves that carry the most evidence (analogy, two cases side by side, a worked example, a picture beside the words) have nowhere to live.

019 kept its v1 small and deferred the richer payload. This spec is that slice: it widens the teaching content into a structured payload of those moves, keeping 019's grounding guarantee and adding one — an analogy must not mislead. For the learner ramping on a spec via explain --course.

2 · User scenarios & testing

Each story MUST be independently testable: if you implemented only US1, you would still have a viable MVP.

US1 · Learn by comparison P1

As a learner, I want an objective to teach by analogy and by contrasting two aligned cases so that I grasp the deep, transferable structure, not a surface definition.

Acceptance: a generated objective can present an analogy (a mapping from a familiar concept to the target) and a contrast (two cases compared across named dimensions) as distinct rendered elements.

US2 · Show, don't just tell P2

As a learner, I want a worked example and a small illustration where the concept is procedural or structural so that I follow the steps and use the visual channel, not words alone.

Acceptance: an objective can present a workedExample (ordered solved steps) and an illustration (a self-contained inline diagram), both legible with JavaScript disabled.

US3 · Trust what it teaches P1

As a learner, I want every move grounded, an analogy that can't quietly mislead, and my existing courses to keep working so that a richer course is more trustworthy, not less.

Acceptance: the course is written only when every member's refs resolve and no analogy is flagged by the blind check; a prose-only objective (the pre-060 form) still generates unchanged.

Edge cases

  • An objective with only reading prose (the pre-060 flat form) must generate exactly as today.
  • An analogy sound to a human but flagged by the blind check — resolved by 019's regenerate-or-drop loop, never a silent write.
  • A member citing a reference that doesn't exist — the whole item fails existence (as in 019), never a partial course.

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional

A course objective's teaching content MUST support an optional structured teaching payload — reading prose plus zero or more optional teaching members — superseding the single flat string as the only form.

Rationale

The flat read: string is the bottleneck: every move below needs somewhere structured to live.

The payload MUST support an analogy member (a mapping from a familiar concept to the target) and a contrasting-cases member (two aligned cases compared across named dimensions), each rendered as a distinct semantic element.

The payload SHOULD support a worked-example member (an ordered sequence of fully-worked steps) and an illustration member (a self-contained inline SVG with a caption), the illustration reusing the existing architecture-sketch pattern.

Rationale

Worked examples (Sweller) and words-with-pictures (Mayer) are well-evidenced and static — no new rendering technology. Step-fading by band is deferred (019's band-personalization).

Before a course is written, every reference cited by any member MUST be verified to exist against real source, extending 019's existence check (019 FR-003); an unresolved reference fails that item.

An analogy member MUST additionally be posed to a blind check that attempts to flag a misleading or mis-mapped analogy; a flagged analogy fails the item and is regenerated or dropped, mirroring the quiz-guessability pass (019 FR-004).

Rationale

An analogy is the one member with a mapping that can be wrong, and a wrong analogy teaches a wrong structure — worse than none. The check reuses 019's per-item failure + regenerate-or-drop loop.

An objective authored with only reading prose (the pre-060 flat form) MUST continue to generate a valid course with no behavioural change; the payload and every member are optional, and their absence changes nothing.

Non-functional

Every member MUST render legibly with JavaScript disabled and introduce no external asset and no executable content — this slice stays within P-4 and the spec-045 CSP. Interactive widgets are deferred.

Assembly and the existence check MUST be deterministic; the blind analogy check MUST route through the AIProvider factory so the CI stub drives it, exactly as 019's guessability pass does — no live model in CI.

The ≤ 7-objective bound (019 NFR-001) is unchanged, and members SHOULD be used sparingly per objective (coherence), so a course stays completable in one sitting.

Out of scope (deferred to other slices)

  • Fading worked-example steps (and course depth) by --proficiency band — 019's deferred band-personalization.
  • Interactive teaching widgets (predict-reveal, step-through, toggle) and the relaxed-CSP tier they need.
  • The bare in-chat explain coach's teaching moves (prompt-only, no artifact).
  • Auto-generating a quiz from a contrast; interleaving; hands-on Build objectives.
  • Validating an analogy is semantically correct beyond the blind flag — analogical fitness isn't decidable; a passing analogy isn't certified sound (a recorded ceiling).

4 · Data model

The entities this feature owns or substantially changes. Exact field names and tag names are the plan's; these are the shapes.

Entities

Structured read
The widened teaching content of a CourseObjective: prose plus optional analogy, contrast, workedExample, and illustration. A plain string (the pre-060 form) stays valid (FR-006).
Analogy
A familiar source concept, the target, and the mapping between them; carries its refs. The mapping is what the blind check probes (FR-005).
Contrasting cases
Two aligned cases and the named dimensions compared across; carries its refs.
Worked example
An ordered sequence of fully-worked steps; carries its refs.
Illustration
A self-contained inline SVG plus a caption — data, never script (P-11).
Teaching-item failure
Extends 019's per-item failure with a new kind, misleading-analogy, beside the existing missing-ref.

Invariant: the payload only ever adds to 019's contract. Every member is optional; a course with none equals a pre-060 course; no member is written until its refs resolve and (for an analogy) the blind check clears it.

5 · Success criteria

Technology-agnostic, measurable outcomes.

A generated course objective presents an analogy and a pair of contrasting cases as distinct teaching elements a reader sees rendered; an objective authored with only prose still generates a valid course unchanged.

An analogy the blind check judges misleading fails its item (regenerated or dropped); a sound analogy passes — and the course is written only when every member's refs resolve and no analogy is flagged. Exercised end to end with the CI stub.

A worked example renders as an ordered sequence of steps and an illustration renders as a contained inline diagram, both legible with JavaScript disabled.

6 · Assumptions

019's hybrid split holds: the agent drafts the payload from real source; the kernel verifies (existence + the blind analogy check) and assembles. This spec extends that contract, it does not re-open it.

019's v1 "no new custom elements" was a scoping choice, not a permanent invariant; this deferred slice spends it, adding semantic teaching elements styled by spec.css (no build step to view).

A blind check catches a grossly mis-mapped analogy as it catches a guessable quiz — a floor against obvious harm, not a proof of soundness (§3 ceiling).
