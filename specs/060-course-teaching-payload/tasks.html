Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 060-course-teaching-payload Design design Branch main Created 25 Jul 2026 Read time

24 tasks across five phases. Setup → Foundational (the widened type + the course-scoped stylesheet skeleton) → User stories US1·US2·US3, independent of each other once Foundational lands → Polish. Tasks marked [P] touch a distinct file with no in-flight dependency; most course.test.ts tasks stay sequential since they share one file. Tests precede implementation in every story.

1 · Execution strategy

Recommended. Drive US1 end-to-end — analogy + contrast render as distinct elements. Then US3 (existence + the blind analogy-fit check) before US2, since trust matters more than the last two members; US2 (worked example + illustration) closes the set.

Setup → Foundational → US1 → US2 → US3 → Polish. Each story closes its conformance before the next opens.

After Foundational, one person per story — all three depend only on the Foundational types, not on each other. Coordinate at the shared seam: packages/core/src/commands/course.ts.

2 · Phase 1 — Setup

Confirm baseline green before changes — pnpm -w build && pnpm -w test; no new dependency is needed. .

3 · Phase 2 — Foundational

The shared seam every story needs: the widened type shape and the course-scoped stylesheet's skeleton. T-011 is a distinct file, independent of T-010.

Widen the course-objective type — CourseObjective.read becomes string | StructuredRead, the optional structured payload (FR-001); add Analogy, Contrast, WorkedExample, Illustration member interfaces; extend CourseItemFailure.kind with 'misleading-analogy' (D-002, D-003). packages/core/src/types.ts
Create the course-scoped stylesheet skeleton — course-analogy, course-contrast, course-worked-example, course-illustration get a display reset and consume the shared --c-* tokens; no per-member styling yet, and nothing added to spec.css (D-004). assets/course.css
Accept the structured payload and link the stylesheet — validateCourseDraft accepts read as either a plain string or a StructuredRead object (still throwing CourseDraftError naming the offending path on a malformed shape, no member-specific checks yet); assembleCourse links course.css in <head> alongside spec.css (D-002, D-004). packages/core/src/commands/course.ts

4 · Phase 3a — US1 · Learn by comparison P1

Tests (write & fail first)

Test analogy/contrast rendering — assembleCourse emits a <course-analogy> and a <course-contrast> element, each carrying its content, when present in the payload (SC-001). packages/core/test/course.test.ts

Implementation

Implement analogy/contrast validation — the analogy shape (source, target, mapping, refs) and the contrast shape (two cases, named dimensions, refs) in validateCourseDraft. packages/core/src/commands/course.ts
Implement analogy/contrast rendering — renderAnalogy and renderContrast helpers wired into the structured-payload branch of renderObjective, emitting <course-analogy>/<course-contrast> in authored order (FR-002). packages/core/src/commands/course.ts
Style the analogy and contrast elements — a source→target mapping display for course-analogy, a side-by-side two-case layout for course-contrast, off the shared design tokens. assets/course.css

Closes FR-002 — verified by SC-001 (rendering half) via T-100/T-101.

5 · Phase 3b — US2 · Show, don't just tell P2

Tests (write & fail first)

Test worked-example/illustration rendering — assembleCourse emits a <course-worked-example> (ordered steps) and a <course-illustration> (figure + svg + caption) when present (SC-003). packages/core/test/course.test.ts

Implementation

Implement worked-example/illustration rendering — renderWorkedExample (a numbered step list) and renderIllustration (a figure/svg/figcaption, mirroring spec-arch's shape) wired into renderObjective (FR-003). packages/core/src/commands/course.ts
Style the worked-example and illustration elements — a numbered step list for course-worked-example, a centered figure with caption for course-illustration. assets/course.css

Closes FR-003 — verified by SC-003 via T-200/T-201/T-202.

6 · Phase 3c — US3 · Trust what it teaches P1

Tests (write & fail first)

Test existence extends to every member — a ref cited by any teaching member (not only the objective-level refs[]) is flagged when it doesn't resolve (FR-004). packages/core/test/course.test.ts
Test backward compatibility — a flat-string objective (the pre-060 form, no payload) still validates and assembles with no payload-related findings, unchanged from today (FR-006). packages/core/test/course.test.ts
Test the blind analogy-fit check via the stub — a scripted blind-subagent response matching the analogy's mapping flags 'misleading-analogy'; an unsure/non-matching response passes, mirroring 019's guessability test shape (SC-002, NFR-002). packages/core/test/course.test.ts

Implementation

Extend existence verification to every member — verifyExistence collects refs from any present analogy, contrast, worked example, or illustration, alongside the objective-level refs[]. packages/core/src/commands/course.ts
Implement verifyAnalogyFit — one blind AIProvider.subagent call per analogy (task course-analogy-fit), reporting a 'misleading-analogy' CourseItemFailure on a flagged response (FR-005, D-003). packages/core/src/commands/course.ts
Wire the analogy-fit check into courseCommand — alongside verifyExistence and verifyGuessability, so the course is written only when all three pass (SC-002). packages/core/src/commands/course.ts

Closes FR-004, FR-005, FR-006, NFR-002 — verified by SC-001 (backward-compat half) and SC-002 via T-300/T-301/T-302.
