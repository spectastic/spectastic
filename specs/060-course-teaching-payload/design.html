Design · 060-course-teaching-payload

Course teaching payload

Extend the course kernel in place: widen one field into a structured payload, add one blind check, and render the new members from a course-scoped asset set — so the spec design system carries none of it.

Status Accepted Spec 060-course-teaching-payload Owner Brian Corbin · @briancorbinxyz Branch main Created 25 Jul 2026 Read time

Widen CourseObjective.read from a flat string to a union with a structured teaching payload (analogy · contrast · worked example · illustration), extend the kernel's verify pass with a blind analogy-fit check that reuses the guessability plumbing wholesale, and render the members from a new assets/course.css with a course-* vocabulary — never spec.css/spec.js, because a teaching move is not a spec construct. All additive: a flat string still renders unchanged. Biggest risk: the analogy-fit heuristic over- or under-flagging — bounded by regenerate-or-drop and recorded as a ceiling, never a proof of soundness.

4 · Approach

One field, one check, one asset. The field: CourseObjective.read becomes string | StructuredRead, where StructuredRead is reading prose plus optional analogy, contrast, workedExample, and illustration members (D-002). validateCourseDraft accepts either form; renderObjective branches on the type and, for the structured form, emits each present member as its element. A flat string renders exactly as today (FR-006).

The check: a verifyAnalogyFit pass mirrors verifyGuessability — one subagent call per analogy, tagged course-analogy-fit, returning a new misleading-analogy failure kind that flows through the same per-item regenerate-or-drop loop the agent already runs (D-003). Existence verification simply extends to every ref a member cites (FR-004). The asset: the members render from a new assets/course.css carrying a course-* vocabulary — the first member of the extended-verb asset set — so spec.css/spec.js stay untouched (D-004). Illustration is the lightest member (an inline SVG in a figure, near spec-arch's one-liner).

5 · Alternatives considered

The load-bearing choice was where the teaching elements live.

Putting teaching elements in spec.css burdens the lifecycle design system with course-only concerns (and the spec- prefix mislabels a teaching move as a spec construct). Reusing spec-note abuses its semantics and weakens P-2. A course-scoped set costs one new stylesheet but keeps each system owning only its own vocabulary — and it is the extended-verb asset set the teaching considerations brief's interactivity tier will later build on.

6 · Decisions

D-001 · Extend the course kernel in place — no new module or pattern

Status
Accepted
Context
The whole feature is a widening of the existing hybrid course kernel (packages/core/src/commands/course.ts) — validate, verify, assemble already exist and are tested.
Decision
Add the payload types, the analogy check, and the render branches to the existing kernel + types.ts; the CLI passthrough is unchanged (it already pipes ctx.ai and writes result.html).
Consequences
+ Reuses a proven, stub-tested pipeline; no architectural surface. + The agent's regenerate-or-drop loop is untouched. − course.ts grows; kept cohesive by one render helper per member.

D-002 · read: string | StructuredRead — a backward-compatible union

Status
Accepted
Context
CourseObjective.read is a flat string today (types.ts:499); FR-006 requires a pre-060 course to generate unchanged.
Decision
Widen to a union: a plain string, or a StructuredRead of prose + optional analogy / contrast / workedExample / illustration. validateCourseDraft accepts either; renderObjective branches on typeof.
Consequences
+ Zero migration — existing drafts and tests keep passing. + Each member is independently optional. − A union widens the validator; covered by red-first tests for both arms.

D-003 · The blind analogy check reuses the guessability plumbing

Status
Accepted
Context
verifyGuessability (course.ts:260) already poses a blind subagent call per quiz and reports a per-item CourseItemFailure the agent regenerates or drops; the stub drives it in CI (stub.ts:114).
Decision
Add verifyAnalogyFit mirroring it: one subagent call per analogy (task course-analogy-fit), a new 'misleading-analogy' failure kind, same loop. Existence verification extends to every member's refs.
Consequences
+ No new agent contract; CI-deterministic via the stub (NFR-002). + One clear per-item meaning. − Heuristic efficacy is unprovable — recorded as a ceiling (§8), never claimed as soundness.

D-004 · Teaching elements live in a course-scoped asset set, not spec.css/spec.js

Status
Accepted
Decision drivers
A teaching move is not a spec construct · keep each design system owning its own vocabulary · give the extended-verb interactivity tier a home
Considered options
  • New spec-* elements in spec.css — + one asset. − burdens the spec design system (its display:block registry, spec.css:655) with course-only concerns; the prefix mislabels the construct.
  • No new elements — + cheapest. − abuses <spec-note> and plain tables; weak semantics (P-2).
  • Course-scoped course-* in assets/course.css — chosen — + honest semantics, spec system untouched, and the seed of the extended-verb asset set. − one new stylesheet.
Context
Grounded in spec.css:655–668 (the spec-* display registry) and course.ts:355–397 (assets linked via one ASSETS base — a course.css link is a one-line add).
Decision
Add assets/course.css defining course-analogy, course-contrast, course-worked-example, and (light) course-illustration — their own display + styling off the shared design tokens. assembleCourse links it alongside spec.css. No spec.css/spec.js change. A course.js is not needed now (members are static); the set is the home for the D-4 interactivity tier if it lands.
Consequences
+ Course concerns never touch spec validation or the spec design system. + Themes automatically off the tokens. − A second stylesheet to keep token-aligned (no value duplication — it consumes --c-*).

D-005 · TDD red-first, with a Playwright/structural backstop for the render

Status
Accepted
Context
The kernel is deterministic (draft in, findings/HTML out) and mirrors 019's D-006 test style; the render is HTML whose presence is not containment (CLAUDE.md verification discipline).
Decision
Write failing unit tests first — payload validate (both arms), member existence, analogy-fit via the stub, flat-string unchanged — then implement. Add a structural/Playwright backstop asserting each member renders and stays legible with JS off.
Consequences
+ Both MUSTs get red-first coverage; the render is browser-checked, not asserted-present. − A small Playwright spec to maintain — cheap against the containment class of bugs it catches.

8 · Risks & mitigations

RiskLikelihoodImpactMitigation
The analogy-fit check over-flags a sound analogyMLRegenerate-or-drop degrades gracefully (worst case: the analogy is dropped, the objective keeps its prose); the prompt is tuned to flag only gross mis-mappings. Recorded ceiling (spec §3/NFR-001).
The check under-flags a subtly-wrong analogyMMThe ceiling is explicit — a floor against obvious harm, not proof of soundness; SC-002 only claims gross catches; human review remains the backstop.
course.css drifts from spec.css's design tokensLLIt consumes the shared --c-* tokens directly — no value duplication; browser-verified in both themes.

9 · Complexity tracking

The only additions beyond the spec's minimum are the union type and a second stylesheet — both required, not incidental.

The union on read is required by FR-006 (a flat string must still work); the separate course.css is required by D-004 (a teaching move is not a spec concern and must not enter the spec design system). Neither is optional complexity — each is the minimum the constraint admits.
