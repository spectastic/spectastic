Cards

An absent view reports twice, and one of the two messages is untrue

Implementation code

Debugging two errors on a design that had simply never been materialised, root cause was that the drift check does not first ask whether a view exists; fixed by having drift stand down when visual-view-missing owns the case; regeneration passes, because the two requirements are distinct and only their interaction is unhandled.

Expected
A design declaring a surface with no view reports visual-view-missing, once.
Actual
It reports visual-view-missing and visual-view-drift — "The visual view in … no longer matches the screens it projects" — for a view that has never existed. Reproduced deterministically by stripping the view from a valid design and revalidating: 2 errors, both at 1:1.
Diagnosis
The drift check compares a rendering of the declared screens against what the design carries, and an absent view compares unequal like a stale one. It reads as staleness because that is the only outcome the check can express. The two findings are not equal in usefulness: "there is no view" is actionable, "the view no longer matches" sends a reader looking for a view to inspect. Worth noting the sibling contract rule cannot hit this, because an absent contract view is permitted — this spec deliberately diverged there (an unreported absence is indistinguishable from a capability that does not work), and the divergence brought a case the clone had never faced.
Fixed
17 Aug — visualViewDriftFindings returns early when the document declares a surface and carries no <spec-visual-view> at all. Scoped to no view anywhere rather than to any declaration lacking one: where some views exist and one does not, the present ones can genuinely be stale and both findings are then true. Verified in both directions against a real project — a never-materialised design now reports visual-view-missing alone, and a materialised design whose screen then changed reports visual-view-drift alone.

Found during the closure backfill rather than by a failing test, which is the argument for the backfill: the card had sat unmarked and the defect was still live.
Fix
packages/core/src/commands/validate.ts — the drift finding returns early when no view element is present, leaving the case to visual-view-missing. Two findings for one fact is noise, and the noisier of the two is the misleading one.
Deep dive — found by running, not by reading

Surfaced while authoring the first real design in a downstream project. Both errors appeared together at a moment when the honest state was simply "not built yet", which is the state every design passes through — so this fires on the common path rather than an edge.
