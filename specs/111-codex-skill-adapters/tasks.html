Status Draft Spec 111-codex-skill-adapters Design design Branch 111-codex-skill-adapters Created 10 Sep 2026 Read time

24 tasks across five phases. Setup → Foundational → User stories (US1·US2·US3) → Polish. Tasks marked [P] can run in parallel — different files, no dependency. Tests for a story MUST be written and failing before its implementation tasks start. The scaffold refactor (Foundational) is fenced by a byte-snapshot captured first (T-002); the Codex-invocation spike (T-001) leads, since it can't run in CI.

1 · Execution strategy

Recommended for this solo, refactor-risk slice. Setup → Foundational → US1 → US2 → US3 → Polish. Each story closes its conformance before the next opens; the byte-snapshot stays green through the Foundational refactor.

Implement US1 end-to-end (verbs run in Codex). Ship. Iterate to US2 (drift gate) and US3 (degradation note) only after US1 is verified in a real Codex session.

One team per story after Foundational. Coordinate at the shared seam (the AdapterTarget descriptor and the render primitive) via the design, not Slack.

De-risk the Codex skill format — hand-author one verb's SKILL.md, drop it in, and invoke it in a real Codex session; record whether it triggers and produces its artifact before building the translator. Run by a human — Codex cannot run in CI. .agents/skills/spectastic-spec/SKILL.md
Capture the default-scaffold byte-snapshot — golden fixture + a test asserting default spectastic init output matches it, captured before any refactor. This is the NFR-002/SC-003 guard. packages/cli/test/init/default-scaffold.test.ts

4 · Phase 3a — US1 · Run the lifecycle inside Codex

Tests (write & fail first)

Unit-test translateToSkill — assert the kebab name matches its dir, the description carries, the metadata map holds triggers/use-when/sibling-boundary, model is dropped, $ARGUMENTS is rewritten, name ≤ 64 / description ≤ 1024, and re-rendering the same source yields identical bytes. packages/core/test/skills/translate.test.ts
Integration-test init --target codex — assert a .agents/skills/<verb>/SKILL.md exists for each core verb under the project dir, extended verbs appear only with --with, and default (no --target) output still matches the golden snapshot. packages/cli/test/init/target-codex.test.ts

Implementation

Implement translateToSkill(commandMd, verb) — the pure, deterministic render primitive: parse frontmatter, kebab the name, map description + metadata, drop the model tier, rewrite $ARGUMENTS, emit { relPath, content }. packages/core/src/skills/translate.ts
Add the codex AdapterTarget instance — destDir .agents/skills, render = translateToSkill, its own marker. packages/cli/src/commands/init/adapters.ts
Add the --target <claude|codex> option — default claude; route it through the scaffold; help copy carries no internal id (P-10). packages/cli/src/commands/init.ts
Pre-render the Codex tree into the bundle — so buildPlan stays a dumb copier (D-007). packages/cli/scripts/prebuild.mjs
Exercise US1 in a real Codex session — spectastic init --target codex in a fixture, then invoke the spec verb in Codex and confirm a spec.html is produced. Entry point: $spectastic-spec (Codex). Run by a human — the SC-001 meter. $spectastic-spec

Closes FR-001, FR-002, FR-003, FR-004, FR-005, NFR-002, NFR-003; SC-001, SC-003.
