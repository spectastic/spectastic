1 · Context

spectastic's lifecycle verbs run only inside Claude Code. spectastic init installs them as .claude/commands/*.md (and subagents as .claude/agents/*.md) — a project-local, byte-for-byte copy of the source command files. A developer who works in a different agent cannot use the lifecycle at all.

Cross-tool installers were always anticipated and deferred: spec 003 named a --target cursor|aider|claude|copilot|generic family, and spec 031 deferred the same under TBD-cross-tool-installers. What changed is that the target is now a settled standard: OpenAI's Codex — the leading alternative agent CLI — converged with Claude Code and 30-plus other tools on the Agent Skills Open Standard (.agents/skills/<name>/SKILL.md, Dec 2025), which Codex scans from the working directory up to the repo root. Codex's own custom-prompts path is deprecated in its favour.

This spec pulls codex forward and makes it the first alternative host. It targets the host surface only — running the verbs inside a Codex session, where Codex's own model does the work and no API key is needed, exactly as a slash command runs in Claude Code. Using Codex as an LLM backend for headless spectastic <verb> is a separate, deferred surface (§3). Stakeholders: developers who work in Codex, and maintainers who must keep the adapters honest against their source.

Agent Skills is one format across 30+ tools, so the same output likely reaches Gemini CLI, Cursor, and Kiro too — but this slice demos Codex.

2 · User scenarios & testing

Each story MUST be independently testable: if you implemented only US1, you would still have a viable MVP.

US1 · Run the lifecycle inside Codex P1

As a developer working in Codex, I want to invoke spectastic's verbs as Codex skills so that I can spec, design, and implement without leaving my agent or holding an Anthropic key.

Acceptance: after spectastic init --target codex, each core verb exists at .agents/skills/<verb>/SKILL.md; invoking $spectastic-spec <request> in Codex produces a spec.html.

US2 · Codex adapters cannot ship stale P1

As a spectastic maintainer, I want a managed Codex adapter that drifts from its source command to block the commit so that a Codex user never pulls an out-of-date verb.

Acceptance: editing a source command without regenerating trips the drift check at error severity and the pre-commit gate blocks; regenerating clears it. A hand-managed .agents/skills/ tree is untouched.

US3 · Honest degradation for subagent passes P2

As a Codex user, I want the verbs that rely on Claude subagents to say so so that I am not misled into thinking a fan-out ran.

Acceptance: the generated Codex skill for propose, implement, and triage notes that its adversarial / parallel / list-intake sub-pass runs inline under Codex; no subagent files are emitted into the Codex target.

Edge cases

  • Both hosts in one project: .claude/ and .agents/skills/ coexist without collision.
  • A dotted verb name (spectastic.spec) maps to a standard-legal skill name (spectastic-spec) matching its parent directory.
  • Codex not installed: init --target codex still writes the files (generation needs no Codex binary); only invocation needs Codex.
  • The decision-phase interview: Codex has no structured question tool, so AskUserQuestion steps degrade to plain chat questions (see §6).

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional — the scaffold

spectastic init --target codex MUST emit each in-scope verb as one .agents/skills/<verb>/SKILL.md in the target project — the core lifecycle verbs by default, extended verbs (explain, explore) opt-in via --with, mirroring the Claude scaffold. The default target (no --target) MUST stay claude, the cross-tool axis specs 003 and 031 anticipated.

Each generated SKILL.md MUST carry valid Agent-Skills frontmatter — a name (lowercase-hyphen, matching its parent directory, ≤ 64 chars) and a description (≤ 1024 chars, sourced from the command's router description) — with the command's instruction body as the skill body.

Because the standard defines no argument mechanism, the generator MUST translate the command's $ARGUMENTS token so the body reads the user's request from the invoking message — no positional token survives into the emitted skill.

The generator SHOULD preserve the command's triggers, use-when, and sibling-boundary metadata in the skill's metadata map; the description remains the authoritative trigger surface. The Claude-only model tier MAY be dropped — Codex has no verb-tier concept.

Codex adapters MUST be written project-local, under the target project's working directory (.agents/skills/), never a global user directory.

Functional — the guarantee layer

The guarantee-layer install for the Codex target MUST stamp a managed-adapter marker and (re)generate the skill adapters deterministically and idempotently.

A drift check MUST flag, at error severity, any marker-managed Codex adapter that diverges byte-for-byte from its source command or is missing — and MUST NOT judge an .agents/skills/ tree the project manages by hand (no marker).

The pre-commit gate MUST block a commit that would ship a drifted managed Codex adapter; regenerating the adapter MUST clear the block.

The Codex install SHOULD be reversible — an uninstall path removes the marker and the generated adapters.

Functional — fidelity

The Codex target MUST NOT contain subagent definitions — the standard defines no nested-agent concept — so verbs that fan out to subagents under Claude Code (propose's adversarial pass, implement's parallel/escalation path, triage list-intake) run inline under Codex.

Each such verb's generated skill SHOULD state that its sub-pass runs inline/single-turn under Codex, so a Codex user is not led to believe a fan-out ran.

The default spectastic init (the claude target) MUST also emit the portable Agent Skills adapters — one .agents/skills/<verb>/SKILL.md per in-scope verb — alongside the .claude/commands adapters, so a Claude project carries both invocation surfaces. Neither surface is removed, and the same verb-scope rules apply (core by default, extended via --with). A Claude-target skill MUST NOT carry the Codex-specific inline-degradation note: FR-011 scopes that note to the Codex host, so the shared render must be host-appropriate and a skill installed for Claude Code (which does have subagents) must not tell its reader the fan-out ran inline.

Rationale

Claude Code is documented as an Agent Skills host, and the same rendered output already runs unmodified in Codex and Antigravity. Making it the default carries the portable surface everywhere at near-zero cost — the render already exists. The one real cost the adversarial pass surfaced: the note that is correct for Codex is false for Claude, so the render must become host-aware (see Approach + Tasks).

Under spectastic init --tools, the Claude managed install SHOULD stamp a managed marker and drift-guard the .agents/skills tree as well as .claude/commands, so a managed Claude project's skills cannot ship stale either — the same "can't ship stale" guarantee (FR-007/FR-008) applied to the second surface.

Rationale

An unguarded second surface would silently drift from source the moment a command changed. should, not must: the unmanaged scaffold (FR-012) is the core ask; the managed guarantee is the natural completion, but a plain init without --tools is still valid.

Non-functional

Adapter generation MUST be deterministic — the same source command yields byte-identical output (≤ 0 differing bytes across repeated regenerations), with no clock or network input — so the byte-for-byte drift check (FR-007) is well-defined.

Beyond the deliberate addition of the .agents/skills tree (FR-012), adding portable skills MUST NOT change the default spectastic init output: a Claude project's .claude/commands, .claude/agents, assets, templates, and generated .gitignore/spectastic.json stay byte-identical (≤ 0 changed non-skills files), and the run introduces ≤ 0 new validate findings.

Generated names and descriptions SHOULD obey the standard's limits (name ≤ 64 lowercase-hyphen matching its directory; description ≤ 1024 chars) so Codex loads every skill without error.

Out of scope (deferred to other slices)

  • Codex as an LLM backend for headless spectastic <verb> — a CodexCliProvider shelling to codex exec, selected by --provider openai (or credential presence, ambiguity erroring), with --model <openai-id> pass-through. A different surface from this host installer.
  • Faithful subagents on Codex (an agents/openai.yaml mapping of critic / classifier / impl-task). The standard defines no nested-agent concept; carrying them is unproven research.
  • The same .agents/skills/ output for the other Agent-Skills hosts (Gemini CLI, Cursor, Kiro, +28). The format is portable; this slice demos Codex.
  • Unifying the Claude adapters onto the portable Agent-Skills format (retiring .claude/commands for .agents/skills).
  • The deprecated Codex custom-prompts format (~/.codex/prompts/, /prompts:name) — considered and rejected as deprecated and Codex-only.

4 · Data model

The feature owns one derived artifact and the state that scopes its gate.

Entities

Skill adapter
The derived .agents/skills/<verb>/SKILL.md for one verb. Its name equals both its parent directory and the kebab-cased verb; its body is a faithful translation of the source command with no $ARGUMENTS token; it regenerates byte-identically. When marker-managed it is never hand-edited.
Target
The host an adapter set is emitted for — claude (default) or codex. A project may carry adapters for more than one target at once without collision (.claude/ vs .agents/skills/).
Managed marker
The per-target flag that scopes the drift gate: present iff spectastic generated and owns that target's adapters. Absent → the gate does not judge the tree.

An adapter is managed (marker present, drift-gated) or unmanaged (hand-authored, ignored). Transitions: none → managed (install/regen) → drifted (source edited) → managed (regen) → none (uninstall). Drifted is the only state the pre-commit gate blocks on.

5 · Success criteria

A developer with no Anthropic credential gets each core verb's artifact from within a Codex session — the whole lifecycle usable in Codex, a host it could not reach before. Core verbs producing their artifact ≥ 6 of 8 (target 8 of 8), from no established baseline (0 verbs are runnable in Codex today).

Meter

A reviewer invokes each $spectastic-<verb> against a fixture in a real Codex session, once per release — recording which produced its artifact, and confirming the skill triggers on its description, ships no subagent files, and (for propose/implement/triage) states its inline degradation.

Falsified by

A core verb that Codex fails to recognise, or that produces no artifact when invoked.

A maintainer who edits a source command without regenerating is stopped before a stale managed adapter — for either host target — reaches the repo, so a user never pulls an out-of-date verb. Drifted managed-adapter commits blocked ≥ 99% (target 100%), from no established baseline.

Observed at

The pre-commit run and spectastic validate over a deliberately-drifted managed adapter — a Codex skill and (per FR-013) a Claude-target skill — as CI fixtures.

Falsified by

A committed managed adapter, of either target, whose bytes differ from its rendered source.

An existing user's default spectastic init leaves everything but the new skills tree undisturbed — the .claude/commands, .claude/agents, assets, templates, and generated files stay byte-identical. Changed non-skills files ≤ 0 (target 0), from the pre-feature scaffold as baseline.

Observed at

A fixture comparing default-init output — the non-skills files byte-for-byte and a validate sweep — before and after the feature.

Falsified by

Any difference in a non-skills file's bytes or the non-skills file set, or a new finding on a Claude project.

A developer who opens a default-scaffolded spectastic project in any Agent Skills host finds the verbs available as portable skills — the .agents/skills tree ships in the plain spectastic init output, no flag required. Core verbs present as skills ≥ 8 of 8 (target 8), from 0 today (skills shipped only under --target codex).

Observed at

Listing .agents/skills/ after a plain spectastic init in a fixture, asserting one SKILL.md per core verb.

Falsified by

A default scaffold missing the .agents/skills tree, or missing a core verb's SKILL.md.

A maintainer who uninstalls the Codex target is left with none of spectastic's managed Codex files in the project — a clean reversal. Residual managed files ≤ 0 (target 0), from no established baseline.

Observed at

Running the uninstall path on a fixture that had the Codex target installed, then listing the tree for the marker and adapters.

Falsified by

Any spectastic-managed Codex adapter or marker remaining after the uninstall.

6 · Assumptions

Codex reads the Agent Skills Open Standard from .agents/skills/ as documented, and the format is stable enough to target. If the standard shifts, the adapter shape follows it.

A Codex session provides the shell, file, and interactive capabilities the verbs assume — but no structured question tool, so the decision-phase interview degrades to plain chat questions rather than the AskUserQuestion surface it uses in Claude Code.

7 · Open questions

None outstanding — every decision (target format, selection flag, guarantee-layer scope, subagent fidelity) was anchored in the interview. The metadata carrier and exact flag composition are design choices, not open spec questions.
