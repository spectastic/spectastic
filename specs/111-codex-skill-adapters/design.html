Design · 111-codex-skill-adapters

Codex skill adapters

How we will build it.

Status Draft Spec 111-codex-skill-adapters Owner Brian Corbin (@briancorbinxyz) Branch 111-codex-skill-adapters Created 10 Sep 2026 Read time

One source (commands/*.md) renders to two targets through an AdapterTarget descriptor: Claude verbatim, Codex translated to Agent-Skills SKILL.md. A single render(source) ≠ on-disk drift check covers both, folded into validate so the existing pre-commit hook gates Codex for free. Biggest risk: threading the target through the working Claude scaffold — fenced by a byte-identical default-scaffold snapshot.

3 · Data model & contracts

The spec's conceptual entities (Data model) land physically as files on disk and one in-memory descriptor. No wire interface is exposed — this is a file-writing CLI installer.

Conceptual entityPhysical shapeNotes
Skill adapterA directory .agents/skills/<kebab-verb>/ holding one SKILL.md — YAML frontmatter (name, description, metadata) + the translated command body.Output of translateToSkill; never hand-edited when managed.
TargetAn in-memory AdapterTarget descriptor { id, destDir, render, marker }, selected by the --target flag (default claude).D-002. Claude and Codex are two instances.
Managed markerA .spectastic-managed file inside the target's dest dir (per target).Scopes the drift gate; absent → the gate ignores the tree.

This feature exposes no request/response, RPC, GraphQL, or event interface — it writes adapter files into the project. It follows the house pattern for internal CLI features (every <spec-contract> across the estate is shape="none"). The Agent Skills format the output conforms to is an external standard this design targets, not a contract this project owns.

5 · Approach

Keep one source of truth and add one seam. The existing commands/*.md files stay the only authored source; the Claude adapter remains a verbatim copy. We introduce an AdapterTarget descriptor — { id, destDir(cwd), render(sourceMd, verb) → {relPath, content}, marker } — and make claude and codex two instances of it. Claude's render is the identity (byte copy); Codex's is a pure translateToSkill in @spectastic/core that emits .agents/skills/<kebab-verb>/SKILL.md with a mapped frontmatter and a body whose $ARGUMENTS token is rewritten to read the invoking message.

The seam unifies drift: for either target, drift is exactly render(source) ≠ what's on disk — which for Claude collapses to the current source==adapter check, and for Codex compares the freshly-translated skill against the file. We fold a scanSkillsDrift into validate beside scanCommandsDrift, so the pre-commit hook gates Codex with no hook change. --target <claude|codex> (default claude) threads through inventoryAt/buildPlan/adapters.ts; prebuild pre-renders the Codex tree into the bundle so buildPlan stays a dumb copier. The one real cost — touching the working Claude scaffold — is fenced by a byte-identical snapshot of the default scaffold output.

7 · Decisions

D-001 · Single source of truth — render, don't fork

Status
Accepted
Context
Adapters already derive from commands/*.md (adapters.ts:21,47). A second hand-authored source would drift by hand and duplicate the router description.
Decision
Keep commands/*.md the only source; Codex is a deterministic translation of it, Claude the verbatim copy.
Consequences
+ One source, no sync burden; the drift check stays meaningful. − Every Codex change must go through the translator, never edited in place.

D-002 · An AdapterTarget descriptor threaded through the scaffold

Status
Accepted
Decision drivers
single-source fidelity · reuse · drift unification · Claude-path safety
Considered options
  • Separate codex/ source tree — + no translator. − two sources drift by hand.
  • Dedicated generator, Path A untouched — + safest. − duplicates orchestration, two drift checks.
  • AdapterTarget abstraction — chosen — + one path, unified drift. − refactors working scaffold code.
Context
The scaffold walks fixed dirs (bundle.ts:71-76, plan.ts:56-60). A { id, destDir, render, marker } descriptor makes Claude and Codex two instances.
Decision
Thread a target through inventoryAt/buildPlan/adapters.ts; both targets are descriptors, render is per-target.
Consequences
+ DRY, one drift path, extensible to the next tool. − Touches tested code → NFR-002 becomes an invariant to prove (see Risks).

D-003 · --target <claude|codex>, default claude, unmanaged by default

Status
Accepted
Context
No --target today (init.ts:206-231); 003/031 anticipated the axis. Default init writes an unmanaged scaffold; --tools manages.
Decision
Add --target (default claude). init --target codex writes an unmanaged skill scaffold; --target codex --tools adds marker + drift + hook — symmetric with Claude. Composes with --with/-only/--uninstall.
Consequences
+ Familiar mental model; existing invocations unchanged (default stays claude). − Two behaviours per target to test.

D-004 · Unified drift = render(source) ≠ on-disk, folded into validate

Status
Accepted
Context
The current check compares raw source==adapter (core/validate.ts:44) — invalid for a translated target. scanCommandsDrift folds into validate and no-ops when unmanaged (cli/validate.ts:110,790); the hook just runs validate (hook.ts:57).
Decision
Generalise drift to render(source) ≠ on-disk for both targets (Claude's render is identity, so its check is unchanged in behaviour); fold a scanSkillsDrift beside scanCommandsDrift.
Consequences
+ FR-008/009 come with no hook change; one drift concept. − Determinism (NFR-001) is now load-bearing — a non-deterministic render would false-fire.

D-005 · SKILL.md shape — metadata map carries the extra keys

Status
Accepted
Context
The standard allows only name/description + an optional metadata map; commands carry more (spectastic.spec.md:1-13).
Decision
name = kebab(verb) (spectastic.spec → spectastic-spec, matching its dir); description = the router description (authoritative); triggers/use-when/sibling-boundary → the metadata map; model dropped; $ARGUMENTS rewritten to read the invoking message.
Consequences
+ Nothing authored is silently lost; standard-valid. − Codex ignores the metadata map today (informational only until a consumer reads it).

D-006 · No subagents in the Codex target; degrade with a note

Status
Accepted
Context
Subagents dispatch via Claude's Task tool (propose.md:118); the standard defines no nested-agent concept.
Decision
Emit no subagent files into .agents/skills; the propose/implement/triage skills carry an appended note that their sub-pass runs inline under Codex.
Consequences
+ Honest — a Codex user isn't misled a fan-out ran. − Those passes are single-turn under Codex; fidelity is lower than Claude Code.

D-007 · Prebuild pre-renders the Codex tree; buildPlan stays a copier

Status
Accepted
Context
Path A byte-copies from the prebuilt bundle (prebuild.mjs:27-32, bundle.ts). Rendering inside buildPlan would make the scaffold path smart.
Decision
Prebuild renders .agents/skills into the bundle; buildPlan copies it like any other tree. The drift gate renders at runtime (from source) to compare — same core primitive, deterministic, so the two renderings agree.
Consequences
+ Scaffold stays a dumb copier; render lives in one primitive. − Render runs in two places (prebuild + drift), which the determinism test locks together.

D-008 · Test strategy — red-first unit + CLI integration, no Playwright

Status
Accepted
Context
Deterministic, no-AI file generation; no interactive HTML artifact is produced, so a browser test has nothing to drive.
Decision
vitest units on translateToSkill (name mapping, $ARGUMENTS rewrite, metadata carry, render(render(x))=render(x) determinism) + CLI integration (init --target codex tree; mutate a skill → drift error; uninstall clean; default scaffold byte-snapshot). Written failing-first.
Consequences
+ A translation bug localises precisely; the snapshot guards NFR-002. − The Codex-invocation claim (SC-001) is out of unit reach — it is the release-time spike.

9 · Risks & mitigations

Threading target through buildPlan/inventoryAt/adapters.ts touches the working Claude scaffold. The byte-identical default-scaffold snapshot (SC-003) must be in place and green before the refactor lands — do not merge the abstraction without it.

10 · Complexity tracking

Where this plan adds complexity beyond a minimal Codex-only generator, the justification is here.

The AdapterTarget abstraction is more than a Codex-only path would need. It is justified by single-source fidelity and a single drift concept across both targets (D-002), accepted at Medium risk with the default-scaffold snapshot as the guard.

This design ships adapters, not a guarantee that the verbs behave identically under Codex. Whether the interview happens or the commit runs is advisory in any host (T-009 / P-8); the only guarantee here is that a managed adapter cannot ship stale.
