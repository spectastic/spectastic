Specification · 034-effort-auto

Auto effort

Spend more scrutiny when the change is riskier. Derive the decider's effort level from signals the verb already computes — so the default is adaptive, not fixed.

Status Accepted Spec ID 034-effort-auto Owner Brian Corbin · @briancorbinxyz Reviewers — Created 09 Jul 2026 Principlesv1.3.0 Parent Configurable decider Smallest demoablepropose at default --effort=auto: a removed-op change fires a high-effort panel; a trivial one stays low. Read time

033 shipped an explicit effort dial (low…max) with a fixed medium default. This slice adds --effort=auto — the brief's §9.3 Q2, the piece it names as required before a hands-off pipeline (W-1) can run unattended. auto resolves to a concrete level from per-verb risk signals over a shared floor: each verb supplies its own rule (propose's is its existing must-tier / removed-op / ≥2-prefix heuristic), clamped so auto never drops below a configurable floor. The chosen level and its reason are logged, so an adaptive decision is auditable. auto becomes the default; an explicit level always wins.

1 · Context

033 made effort an explicit knob but left the default fixed at medium — so a trivial typo-fix proposal and a must-tier-removing one get the same scrutiny. The workflow brief (§9.2) argues the default should be auto: derive the level from signals the tool already computes, because "effectiveness varies with the difficulty of the prompt" — allocate effort adaptively, not uniformly.

The signal already exists: propose's adversarial pass auto-fires on must-tier / removed-op / ≥2-prefix (propose.ts). This slice reuses that as the depth signal, not just the fire/skip one, and frames it as a per-verb rule other verbs can supply later.

Who this is for: the maintainer running propose (and, later, an unattended pipeline) who wants heavy scrutiny to appear exactly when the change earns it — without setting a level by hand each time.

2 · User scenarios & testing

Each story is independently testable: implementing only US1 still yields a viable MVP.

US1 · Effort tracks risk P1

As a maintainer, I want auto to pick the effort level from the change's own risk so that a risky change gets a panel and a trivial one doesn't, with no manual knob.

Acceptance: at --effort=auto, a removed-op / must-tier propose resolves to high; a ≥2-prefix change to medium; an otherwise-trivial change to the floor.

US2 · The adaptive choice is auditable P1

As a reviewer, I want the resolved level and its reason recorded so that an automatic decision can be inspected, not just trusted.

Acceptance: the verdict grounds name the level and the signal that chose it (e.g. "effort=high — auto: must-tier touched").

Edge cases

  • Explicit beats auto. --effort=high on a trivial change still runs high — an explicit level always wins over auto.
  • Floor clamps. auto never resolves below the configured floor, even for a no-signal change.
  • Human decider. With --decider=human, effort is moot — no panel to size; auto is a no-op.
  • Unknown verb. A verb with no signal rule falls back to the floor (never errors).

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) per RFC 2119.

Functional

--effort=auto MUST resolve to a concrete level (low…max) before the decider runs, via a per-verb signal→level rule. auto becomes the default effort.

Each verb MUST supply its own signal rule. Propose's MUST reuse its existing heuristic: removed-op or must-tier → high; ≥2 topic prefixes → medium; otherwise the floor.

A configurable floor MUST bound auto from below — the resolved level is never lower than the floor. Default floor low.

An explicit effort level MUST override auto — --effort=high on a trivial change resolves to high.

The resolved level and the signal that chose it MUST be recorded on the verdict grounds (e.g. "effort=high — auto: removed-op"), so an adaptive decision is auditable.

A verb with no registered signal rule SHOULD resolve auto to the floor rather than erroring.

Non-functional

Resolution SHOULD be pure and deterministic — the same change + config resolves to the same level and reason every time.

Out of scope (deferred)

  • Signal rules for verbs other than propose — those arrive as each verb adopts the Decider (035).
  • Scaling fan-out width / loop depth by auto (the full §9.2 primitive table) — this slice resolves the decider's level only.
  • W-1 consuming auto to run unattended — this slice provides the resolver.

4 · Data model

No new persisted entity — auto is a resolution step over 033's config and effort levels.

Entities

Signal rule
A per-verb pure function: (change signals) → an effort level. Registered by verb name; propose's is the reference.
Resolution
The output of auto: the concrete level + a one-line reason (the signal that chose it), floor-clamped, override-beaten.

Precedence within effort: an explicit level > auto's signal-derived level > the floor. This nests inside 033's config precedence (flag > project > default) — auto is what the "default" now is.

5 · Success criteria

At --effort=auto, a removed-op / must-tier propose runs a high (3-voter) panel and a trivial one runs at the floor — observable by counting panellist invocations.

An explicit --effort=high on a trivial change still runs 3 voters — override beats auto.

auto never resolves below the floor — a no-signal change at floor medium runs ≥ 1 voter per the medium level, not low.

The verdict grounds name the resolved level and its signal reason for an auto run.

6 · Assumptions

033's effort levels and the panel sizing they drive are unchanged; auto only chooses which level, then defers to 033's effortToDepth.

Propose's existing signal predicates (removed-op, must-tier, topic-prefix count) are the right depth signals, not just fire/skip signals — reusing them keeps one heuristic, not two.
