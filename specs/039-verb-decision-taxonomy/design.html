Verb decision taxonomy

How we will build it.

Status Accepted Spec 039-verb-decision-taxonomy Owner Brian Corbin · @briancorbinxyz Branch 039-verb-decision-taxonomy Created 09 Jul 2026 Read time

A single packages/core/src/decider/taxonomy.ts: a frozen DECISION_TAXONOMY registry (plan → test-style + risk-tolerance; tasks → execution-strategy, labels mirrored from the command markdown) and an answerDecisions(verb, cfg, ai) that looks up the verb and delegates to the landed decideChoice. No generation kernel is touched. Biggest risk: registry drift from the markdown — mitigated by a parity test asserting the exact labels.

4 · Approach

One new file, packages/core/src/decider/taxonomy.ts, exported from the decider index. It declares a DECISION_TAXONOMY: Readonly<Record<string, Question[]>> with entries for plan and tasks only, each Question mirroring the command markdown's header + option labels + descriptions. answerDecisions(verb, cfg, ai) looks up the verb; if absent it returns {} without calling the Decider; otherwise it returns decideChoice(cfg, DECISION_TAXONOMY[verb], ai). No generation kernel imports this — 037 will.

5 · Alternatives considered

A central registry keeps the lift additive (no kernel touched, NFR-001) and reviewable in one place; embedding a method per kernel couples generation to the Decider prematurely; run-time generation is the deferred context-dependent case, not the bounded one.

6 · Decisions

D-001 · A central frozen registry, mirrored from the command markdown

Status
Accepted
Context
The option copy exists in commands/spectastic.{plan,tasks}.md (read this turn, §3).
Decision
DECISION_TAXONOMY holds one Question[] per liftable verb; labels/descriptions mirror the markdown verbatim. A parity test (SC-003) guards drift.
Consequences
+ one reviewable source; + additive. − two copies of the option copy (markdown + code) — the parity test is the reconciler.

D-002 · answerDecisions delegates wholesale to decideChoice

Status
Accepted
Context
decideChoice (choice.ts:22) already dispatches by role, sizes the panel by effort, and defaults out-of-range labels.
Decision
answerDecisions is a thin lookup + decideChoice call; it re-implements no dispatch (FR-003). Absent verb → {}, no Decider call.
Consequences
+ inherits 036's guardrails + tests; − none of note.
