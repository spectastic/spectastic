Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 078-federated-resource-uri Design design Branch 078-federated-resource-uri Created 01 Aug 2026 Read time

23 tasks across five phases. Setup → Foundational → User stories (US1 · US2 · US3 · US4) → Polish. Tasks marked [P] can run in parallel — different files, no dependency. Tests for a story MUST be written and failing before its implementation tasks start, per D-005.

1 · Execution strategy

Setup → Foundational → US1 → US2 → US3 → US4 → Polish. Each story closes its conformance before the next opens. US3 has no implementation of its own — it proves a property US1 already establishes, so it is cheap to slot in right after US1 lands if that ordering reads more naturally.

Implement US1 end-to-end — a corpus document renders a coordinate, standalone. Ship. US2's parser and US3's dedupe proof follow once a real consumer needs the reverse direction.

One team on the schema grammar (Foundational + US1/US2's project-shared.ts work), one on the corpus package bindings (US1/US2/US4's knowledge/resolve.ts and CLI wiring). They meet at the shared file boundary — coordinate the grammar's shape before starting, since both sides write to it.
