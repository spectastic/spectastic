Visual render capture

Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 106-visual-render Design design Branch spec/visual-render-106 Created 19 Aug 2026 Read time

29 tasks across five phases. Setup → Foundational → User stories → Polish. Tasks marked [P] can run in parallel — different files, no dependency. Tests for a story MUST be written and failing before its implementation tasks start.

Story order is not story number. US1 needs a byte-safe file port to write a real capture, so US2 — the story about that port — is built first. Task IDs still follow story identity (T-1xx is always US1, T-2xx always US2), only the document and build order changes. §8 states the chain explicitly.

1 · Execution strategy

Foundational, then US2 end-to-end (the byte port has to exist before anything else can write a real capture), then US1. Ship there — a single artboard captured correctly is the smallest demoable. US3's accounting and Polish follow.

Setup → Foundational → US2 → US1 → US3 → Polish. Each story closes its requirements before the next opens, in the order the real dependency runs.

Not recommended here. US1 cannot be built, let alone tested end-to-end, before US2's byte path exists — a team starting on US1 in parallel would be blocked immediately. One person, in dependency order, or two people once US2 is done and US1 and US3 can proceed with US3 still waiting on US1's manifest hook.

5 · Phase 3b — US1 · A design becomes a picture

Tests (write & fail first)

Assert the offline refusal — an unreachable egress check refuses with a stated reason and writes 0 capture files, before a page is opened (FR-005, SC-003). packages/core/test/render.egress.test.ts
Assert the template guard — a label still carrying template syntax (e.g. {{ s.id }}) is refused and not captured, even when egress is reachable — the second guard the offline spike showed was needed. packages/core/test/render.egress.test.ts
Assert labels slug to a name, and a collision is reported — no-rate · light → no-rate-light, and two labels slugging alike are reported rather than one silently overwriting the other (FR-006, FR-007, SC-005). packages/core/test/render-naming.test.ts
Assert the write location — a capture lands under the owning spec's visual/renders/, and a destination behind a dot-segment is refused (FR-008). packages/core/test/render.write-location.test.ts
Assert there is nothing to compare against — the render module imports no diff or comparison utility, and its exported function accepts no baseline argument (FR-010). packages/core/test/render.no-comparison.test.ts
Assert one browser process per run — capturing every artboard from one design source launches Chromium once (NFR-001). packages/render/test/single-session.test.ts
Assert only one verb can reach the port — no CLI command other than the render subcommand imports @spectastic/render (NFR-002, FR-004). packages/cli/test/render.port-reach.test.ts

Implementation

Implement the verb's preflight and capture loop — call ctx.render.checkEgress(), refuse with a stated reason if false; otherwise load the source once and iterate its captures (FR-004, FR-005). packages/core/src/visual/render-capture.ts
Implement label slugging and collision detection — one rule for every label, case and separators normalised (FR-006, FR-007). packages/core/src/visual/render-naming.ts
Write each capture through the byte-safe port — under the owning spec's visual/renders/, refusing a dot-segment destination (FR-008). packages/core/src/visual/render-capture.ts
Implement the Playwright adapter — one browser launch per run; capture each [data-screen-label] element at its own bounding box, never the page (FR-003, NFR-001). packages/render/src/index.ts
Wire the adapter into the render subcommand only — add @spectastic/render to the CLI package's dependencies and construct playwrightRenderer() there, and nowhere else (FR-004, NFR-002). packages/cli/src/commands/visual.ts
Exercise the verb against a real export — spectastic visual:render 106-visual-render against a committed fixture, confirming a captured file opens as a viewable image. Entry point for this story's path.

Closes FR-003, FR-004, FR-005, FR-006, FR-007, FR-008, FR-010, NFR-001, NFR-002, SC-003, SC-005.
