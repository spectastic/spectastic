Minimal node crops / overspills its content (fixed height)

Implementation code

Debugging a node whose title + pill + metric spilled past its border in the live canvas, root cause was implementation drift — the node used a fixed height instead of growing to fit; fixed by switching to min-height + a flex content column with title ellipsis; regeneration passes (FR-002/FR-005 never mandated a fixed height).

Expected
The minimal node (FR-002) contains its verb label, title, status pill and metric inside its border.
Actual
With a wrapping title (001-game-ui), the stacked content exceeded the fixed 64 px box and spilled below the border; the attention ring was clipped at the canvas edge.
Diagnosis
updateNode set el.style.height = pos.h (a hard height), so taller content overflowed; the grid also let label+title wrap together.
Fix
packages/vscode/src/webview/node.ts + webview/canvas.css: min-height floor, flex .ncontent column, title nowrap+ellipsis; larger node in webview/layout.ts. Guarded by a Playwright assertion that scrollHeight ≤ clientHeight for every node.
el.style.height = `${pos.h}px`; // fixed → content overspills el.style.minHeight = `${pos.h}px`; // floor → box grows to fit
Deep dive — none required

No cross-spec contract, no invariant, no hotfix sequence. Pure rendering correctness; spec + plan unchanged.

Compact-card popover clipped near panel edges

Implementation code

Debugging a hover card that was cut off, root cause was implementation drift — the card was appended inside the canvas surface, which the scroll container clips with overflow:auto; fixed by rendering it on <body> with position:fixed, viewport clamping, and flip-above; regeneration passes (FR-005 specifies the card, not its stacking context).

Expected
The hover/select compact card (FR-005) is fully visible wherever its node sits.
Actual
For nodes low/right in the panel the card extended past the surface and was clipped by #canvas-root { overflow:auto }.
Diagnosis
The card was a child of .canvas-surface with position:absolute, so it lived inside the clipped, scrollable region.
Fix
packages/vscode/src/webview/card.ts + webview/canvas.css: append to document.body, position:fixed from the node's getBoundingClientRect(), flip above when no room below, clamp within the viewport. Regression test shrinks the panel and asserts the card stays on-screen.
Deep dive — none required

No cross-spec contract, no invariant, no hotfix. Positioning-context fix only.

Plan node falsely flagged needs-attention by a "None outstanding" open-questions placeholder

Cross-spec upstream

Debugging a red needs-attention border on a plan whose only "open question" was the prose "None outstanding — everything resolved in the interview", root cause was a cross-spec format gap: <spec-questions> has no unambiguous "zero" representation, so spec/plan generation writes a freeform placeholder <li> indistinguishable from a real question; fixed by defining a canonical empty representation at the generating side; regeneration fails — any consumer of the artifact reproduces the false count.

Expected
A plan/spec with no open questions does not trigger the canvas needs-attention state (FR-006).
Actual
A plan whose <spec-questions> holds a single "None outstanding…" <li> renders red — the placeholder counts as one open question.
Diagnosis
The <spec-questions> contract has no canonical "zero open questions" form: generation writes a prose "None" <li> that reads identically to a real question, so extractHealth (correctly counting <li>, feeding FR-006) over-counts. The reader is fine; the generated format is ambiguous.
Fix
Define an unambiguous empty form at the generating side — when there are no open questions, /spectastic.spec + /spectastic.plan leave <spec-questions> empty (no <li>), not a "None" placeholder; codify in the meta-spec format + templates/{spec,plan}.html. No 020 code change — extractHealth then reads zero.
Deep dive — cross-spec contract

Shared contract: the <spec-questions> "no open questions" representation. It is consumed by 020 (extractHealth → FR-006) and produced by every authoring verb — so the fix is upstream of 020, not in it. The user's call: "no room for ambiguity" — fix where questions are generated, don't patch the reader.

Cascade (a candidate change-proposal against the meta-spec, not 020): (1) the meta-spec format defines "zero open questions = empty <spec-questions>" (or a resolved marker); (2) commands/spectastic.spec.md + commands/spectastic.plan.md emit the empty form; (3) templates/{spec,plan}.html drop the placeholder <li>; (4) existing specs carrying a "None" <li> migrate to the empty form. extractHealth is unchanged.

Scope note (not promoted): a stricter option — a validate rule rejecting a placeholder/prose-"None" <li> inside <spec-questions> — is surfaced here, not adopted. Filed against 020 because that's where it manifested; the fix lands in the meta-spec/format.
