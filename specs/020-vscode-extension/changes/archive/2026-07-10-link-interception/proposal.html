Add FR-015 — intercept cross-artifact links in the webview

Applied

1 · Intent

020's asset rewrite (rewriteForWebview) sends every relative href through asWebviewUri — including a cross-artifact link like ../001-x/spec.html#SC-002, which becomes a vscode-resource URL that escapes the panel when clicked (the anchor percent-encoded to %23). Triage T-011. 020's navigation contract (FR-003 governs panel identity) was silent on intra-corpus link interception — the same spec-gap family as T-006 (missing verify node) and T-007 (panel identity). This change closes it.

2 · Scope

In scope

  • ADD FR-015 (must): a cross-artifact link clicked in a webview opens the target artifact in the extension + scrolls to the anchor, never escaping to a vscode-resource URL.
  • Append a changelog entry citing T-011.

Out of scope

  • Intercepting genuinely external links (http(s):, mailto:) — those keep VS Code's default open-externally behaviour.

3 · Approach

One additive MUST delta. The host marks relative .html (optionally #anchor) links with data-artifact-link/data-anchor instead of URI-rewriting them, injects a nonce-authorised click interceptor that posts {openLink}, and resolves the target against the source artifact's directory. The anchor is baked into the target panel's <body data-scroll-to> for a race-free on-load scroll (no messaging round-trip). Each panel's handler closes over its own artifact path, so links resolve correctly per panel.

4 · Deltas

What's added: a must-tier requirement for intra-corpus link interception.

A cross-artifact link clicked inside an artifact webview — a relative .html (optionally #anchor) reference to another corpus artifact — MUST open that artifact in the extension and scroll to the anchor, not escape to an external vscode-resource URL. The host MUST NOT rewrite such links through asWebviewUri; it MUST intercept the click and resolve the target against the source artifact's directory.

5 · Risk register

Adversarial pass fires (must-tier requirement touched).

Intercepting all relative .html links could catch a non-corpus or intentionally-external target

Concern. A blanket "intercept every relative .html" could swallow a link to an HTML file that isn't a corpus artifact, or one a user meant to open externally, and a non-existent target would dead-end.

Mitigated. Interception is scoped to same-corpus targets: the host resolves the link against the source dir under localResourceRoots (the workspace), and a missing target surfaces the existing loud error page rather than a silent failure. Absolute schemes (http(s):, mailto:, vscode-) are already excluded from the rewrite and stay externally-openable.

Injecting an inline interceptor script widens the panel's CSP

Concern. The artifact panel's CSP was script-src ${cspSource} (no inline). Adding an inline interceptor could force 'unsafe-inline', weakening the panel's script policy.

Mitigated. The interceptor ships under a per-render nonce ('nonce-…'), not 'unsafe-inline' — a single host-controlled script with no user input executed; the artifact's own spec.js still loads from cspSource. CSP is narrowed to a nonce, not broadened.
