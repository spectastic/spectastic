042's deterministic detection + policy live in the CLI, not the core kernel

Implementation code

Debugging a placement inconsistency surfaced while reviewing 043, root cause was drift from the fat-core / thin-CLI convention — 042's pure detection (SIGNALS, detectTooling, detectEcosystems) and policy diff (evaluateEnforcement) sit in the CLI package though they're deterministic kernel logic; fixed by moving them to @spectastic/core and keeping only the commander registration CLI-thin; regeneration passes — behaviour is correct, the fix is code placement, not an upstream gap.

Expected
Deterministic logic lives in @spectastic/core (every verb's core is there); the CLI is a thin wrapper that registers the command and calls core — and P-8: a guarantee belongs in the kernel.
Actual
packages/cli/src/commands/init/detect.ts (signal table + detectTooling/detectEcosystems) and enforce.ts's pure evaluateEnforcement are CLI-local; three CLI files (init.ts, enforce.ts, gitignore.ts) import detect from there.
Diagnosis
042 shipped correct behaviour but placed its deterministic pieces in the CLI. The convention (fat core / thin CLI) isn't written as a principle or a validate rule, so nothing caught the drift — and 041, 042, and 043's first pass all drifted the same way. Behaviour-neutral; purely organisational (NFR-001 "deterministic core" is met either way, but the kernel isn't its home).
Fix
Move the signal table + detectTooling/detectEcosystems and evaluateEnforcement (+ the shared EnforcementCategory/EnforceGate/Signal types) to packages/core/src/ with tsup entries + package.json exports; repoint the three CLI importers; keep registerEnforce CLI-thin. Mirrors the 043 review fix (0cb5330). No behaviour change; tests move with the code.
Deep dive — the convention isn't written down (surfaced, not promoted)

No cross-spec contract; no hotfix. The recurrence is the real signal: 041, 042, and 043-as-first-authored all put deterministic logic in the CLI, because "fat core / thin CLI" lives only as an unwritten habit — not a principle, not a validate rule, not a lint boundary. The immediate fix is this implementation move for 042. Whether to prevent recurrence — a one-line convention in CLAUDE.md, or an architectural boundary check (e.g. an ESLint rule that CLI command modules may only register + delegate) — is a separate, higher-layer question surfaced here, not silently promoted into this card's scope. 043's own core logic now sits correctly in @spectastic/core/gitignore; this card brings 042 in line.
