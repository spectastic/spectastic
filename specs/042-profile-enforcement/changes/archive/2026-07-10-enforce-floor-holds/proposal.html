Add FR-009 — bump before disabling a gate

Applied

1 · Intent

042 makes a profile's floor a gate (spectastic enforce), but the gate can only report missing categories — it can't see a tool a project disabled. The dogfooding failure (T-014) was exactly that: a pinned Error Prone was switched off instead of bumped. The durable answer is P-9 (constitution) plus the concrete guidance projects actually read. This change ties 042's contract to P-9 so the enforcement guidance a profile ships tells the agent to fix-before-disable.

2 · Scope

In scope

  • ADD FR-009 (should): a hard-gate profile's enforcement guidance carries the P-9 discipline, delivered via 041 profile content.
  • Append a changelog entry citing P-9 + T-014.

Out of scope

  • The actual AGENTS/preset wording — 041 profile content (its own applied change).
  • Detecting a disabled tool in enforce — a disabled config is indistinguishable from an absent one by shallow signal detection; the guidance route is the honest fix.

3 · Approach

One additive SHOULD delta on an Accepted spec. Points at P-9 (the invariant) and 041 (the delivery vehicle for the guidance), keeping 042's own surface — the enforce command — unchanged. Adversarial pass did not auto-fire (single should-tier requirement, single topic prefix); no risks recorded.

4 · Deltas

What's added: a should-tier requirement tying the profiles' enforcement guidance to P-9.

A hard-gate profile's enforcement guidance SHOULD carry the P-9 discipline — a failing gate tool is fixed (version bump / config / known-good pin) before it is disabled, and any weakening is explicit and recorded. Delivered through the verified/enterprise profile content (041), since a disabled tool silently defeats the floor enforce protects.
