Contract-first as the 9th enforcement category

If you expose an interface, a consumer depends on it — so a checked-in contract is the floor. If you don't, there is nothing to contract, and the gate stays silent.

Status Applied Change ID 2026-07-11-contract-first-enforce Spec 042-profile-enforcement Source Considerations: engineering-principles (D-001) · the machine teeth for the contract-first principle + the contracts axis (2026-07-11-contracts-axis); resolves TBD-contract-first-enforce Author Brian Corbin · @briancorbinxyz Created 11 Jul 2026 Targets 1 modified (FR-002) + 1 added (FR-014) + 1 data/content delta (verified/enterprise floor + axis labels) Read time

Contract-first landed as a principle at standard (the lean-four) and as a contracts axis; this adds its machine teeth — a 9th enforce category that detects a checked-in interface contract (OpenAPI/Swagger, Protobuf, GraphQL SDL, JSON Schema, or AsyncAPI). But contract-first is unlike the other eight in one load-bearing way: a contract only matters if the project exposes an interface. A CLI, a batch job, or an internal library has none, and hard-failing it for lacking an API schema is precisely the false failure that manufactures the disable-the-gate reflex P-9 forbids. So the category is interface-gated (new FR-014): it is a gap only when a web/RPC framework is detected and no contract is present; a project with no detected interface is treated as covered — nothing to contract. This makes the gate fail safe on the antecedent, which is why — unlike coverage (Go) and observability (Swift/C++) — it needs no FR-010 undetectable rule: an interface it cannot see is an interface it does not gate. Verified/enterprise floor; manifest edits ride the data/content-delta contract (T-018).

Contract-first as the 9th enforcement category

Applied

1 · Intent

Contract-first is the highest-value principle for agent code — a checked-in schema is a fixed, inspectable target a producer and consumer (human or agent) can both bind to, and it bounds hallucinated interfaces. It landed as a principle at standard and as the contracts profile axis, but a principle is advisory (P-8); the durable guarantee is a machine check. This adds that check as the 9th enforce category, mirroring the coverage (7th) and observability (8th) splits: principle at standard, machine-check at verified/enterprise.

The mirror is not exact, and the difference is the whole design. Coverage applies to every project (all code can be covered); observability applies to every service (all services can emit metrics). A contract applies only to a project that exposes an interface. Add contract-first to the hard floor naïvely and every CLI, batch job, and internal library on verified exits 1 for lacking an OpenAPI document it has no use for — a false failure that contradicts 042's founding "never a false failure" guarantee and invites the very gate-disabling P-9 exists to prevent. This proposal ships the honest version: the category is interface-gated — required only when the project shows it exposes an interface — so it fails safe (a project with no detected interface is exempt), and a real gap (interface present, contract absent) still hard-fails where it should.

2 · Scope

In scope

  • MODIFY FR-002: add contract-first to the detected categories; the signal is a checked-in interface contract (OpenAPI/Swagger · Protobuf · GraphQL SDL · JSON Schema · AsyncAPI), interface-gated per FR-014.
  • ADD FR-014: the interface-gated applicability rule — required only when a public-interface framework is detected; no interface → covered (never a hard failure); the unlisted-framework false-negative recorded as the honest ceiling.
  • ADD contract-first to the verified and enterprise enforce.required floor + refresh both axes.enforcement labels (a data/content delta).
  • Widen detection for the contract signals only from strictly-root to root + a small set of conventional contract directories (api/, proto/, schema/, contracts/). The other eight categories keep strict root-only detection, so NFR-002's shallow-detection invariant is unchanged for them — this is a scoped contract-detection concern, not a global detection-model change.
  • Core machinery (§6): the EnforcementCategory union, the contract SIGNALS, a small interface-framework signal set, the interface-gated resolution in detectTooling, honest compose.ts floor wording, fixtures + tests.

Out of scope

  • Validating the content of the contract (that the OpenAPI is well-formed, that it matches the running routes). Detection proves a contract is checked in, not that it is correct or current — the same "present ≠ wired" ceiling coverage and observability record.
  • A drift check that the checked-in contract matches the implemented interface (a generated-vs-committed diff, à la the commands-drift gate). A larger, separate effort.
  • Requiring contract-first at standard. The principle is at standard; the machine check hardens at verified/enterprise, matching the coverage/observability tier placement and the considerations doc ("machine-check at verified").

3 · Approach

Two of the three integration points are the uniform category machinery: the EnforcementCategory union and ALL_CATEGORIES gain 'contract-first'. The contract SIGNALS match a checked-in contract file — openapi.*/swagger.*, *.proto, a GraphQL SDL (schema.graphql/*.graphqls), asyncapi.*, or a JSON Schema only under a contracts/ directory (a bare *.schema.json is usually config validation, not an interface contract, so it does not certify the floor). Because contract files conventionally live one level down (api/, proto/, schema/, contracts/), detection widens — for the contract signals only, leaving the other eight categories strictly root-only — from root to root + those conventional dirs, a bounded, still-deterministic extension of the shallow rule (NFR-002), scoped as a first-class §2 item and a §6 task.

The third point is what makes contract-first different: interface-gating. A second signal set detects that the project exposes an interface — a web/RPC framework declared as a dependency (express, fastify, @nestjs/*; flask, fastapi, django; spring-web/jakarta.ws.rs; gin, echo; actix-web, axum; a grpc/protobuf toolchain) — matched by dependency name exactly as the observability exporters are. detectTooling then resolves contract-first specially: covered if a contract is present, or if no interface framework is detected (nothing to contract); missing only when an interface is present and no contract is. So the gate fails safe on the antecedent, and — unlike coverage and observability — it needs no FR-010 entry: an interface spectastic cannot detect is one it does not require a contract for.

The honesty line, held wherever contract-first surfaces (FR-002, the compose.ts floor block): a green contract-first proves an interface contract is checked in — not that it is valid, complete, or matches the running routes. Content and drift validation are out of scope (§2). And the fail-safe cuts the other way as a recorded ceiling: a project exposing an interface via a framework not in the signal set is silently exempt (a false-negative), never false-failed — the deliberate trade, on par with observability's "declared ≠ wired".

4 · Deltas

What changes: contract-first joins the enumerated categories, detected from a checked-in contract file and interface-gated per FR-014.

Detection MUST classify present enforcement categories — formatter · linter · type-checker · security · supply-chain · test-runner · coverage · observability · contract-first — from config/manifest signals across Python, JS/TS, Java, Go, Rust, Swift, and C++. For coverage, the signal MUST be a declared threshold or check (e.g. fail_under, a coverageThreshold block, a JaCoCo check rule), not a bare coverage library — because for coverage alone, presence of the tool does not imply a gate. Detection proves a coverage threshold is configured; it MUST NOT be surfaced as proof that a CI diff-gate blocks a coverage drop. For observability, the signal MUST be a metrics registry/exporter/starter dependency matched by its deliberate export name (e.g. micrometer-registry-prometheus, spring-boot-starter-actuator, prometheus/client_golang, @opentelemetry/exporter-prometheus, prometheus_client, the Rust prometheus crate), not a transitively-arriving core library or a tracing-only package (e.g. @opentelemetry/api). Detection proves an observability exporter is a declared dependency ("monitoring is possible"); it MUST NOT be surfaced as proof that the /metrics endpoint is wired or exposed. For contract-first, the signal MUST be a checked-in interface contract — an OpenAPI/Swagger document, a *.proto, a GraphQL SDL, or an AsyncAPI document (a JSON Schema counts only under an explicit contracts/ directory, since a bare *.schema.json is usually a config-validation schema, not an interface contract) — found at the project root or a conventional contract directory — and the category is interface-gated per FR-014. Detection proves a contract is checked in; it MUST NOT be surfaced as proof that the contract is valid, complete, or matches the running interface.

Rationale — thresholds, gaps, ceilings, and interface-gating

An .eslintrc means lint runs, so most categories survive presence-detection; coverage breaks that (threshold-bearing signal; Go flag-only gap → FR-010), and observability has an exporter-manifest convention outside Swift/C++ (FR-010) with a "declared ≠ wired" ceiling. Contract-first breaks it differently: a contract is only owed if an interface is exposed, so the signal is paired with an interface-gate (FR-014) rather than an FR-010 undetectable entry — the gate fails safe on "no interface detected", and its ceiling is that a contract is checked in, not that it is correct.

What's added: the interface-gated applicability rule that keeps contract-first from false-failing a project with no public interface.

The contract-first category MUST be interface-gated: it is a gap only when the project exposes a detectable public interface — an HTTP/RPC framework declared as a dependency (e.g. express/fastify/@nestjs, flask/fastapi/django, spring-web/jakarta.ws.rs, gin/echo, actix-web/axum, or a gRPC/Protobuf toolchain) — and no checked-in contract is present. A project with no detected interface framework MUST be treated as covered for contract-first (there is nothing to contract) — MUST NOT hard-fail — so a CLI, batch job, or internal library is never false-failed for lacking an API schema. This is categorically distinct from FR-010 and does NOT override it: FR-010 warns when a category that does apply cannot be expressed in the project's stack (an applicable-but-undetectable gap); contract-first's applicability is itself conditional — "no interface detected" means the category may not apply at all, not that an applicable category is invisible — so the correct posture is exempt, not warn. Warning on every interface-less project (each CLI, batch job, and library) would be the warn-washing FR-010's demotion is expressly not meant to cause. Because the gate fails safe on the antecedent, it requires no FR-010 undetectable entry; the residual is that an interface exposed via a framework outside the signal set is silently exempt (a false-negative), which SHOULD be recorded as the honest ceiling rather than closed by widening the gate into false failures.

Rationale — fail safe on "does this even expose an interface?"

The other eight categories are unconditionally applicable at their tiers; contract-first is conditional on the project's nature. The choices are: hard-require it everywhere (false-fails interface-less projects — the P-9 reflex), make it advisory (a weaker, non-gating category), or gate it on a detectable antecedent. Interface-gating is the only option that keeps it a real hard gate where a contract is genuinely owed while never false-failing where it isn't. The trade is a false-negative on unlisted frameworks — deliberately preferred over a false-positive, because a false failure trains teams to disable the gate, while a false-negative is a missed nudge the principle (advisory, at standard) still covers.

What's added: contract-first appended to the verified and enterprise enforce.required arrays in spectastic-profiles.json, both axes.enforcement labels refreshed. A data/content delta (target names the manifest, embeds a <spec-diff>, no requirement-body change). Safe under the hard gate because FR-014 makes it interface-gated.

Rationale — why verified + enterprise

Interface stability matters once a second consumer exists — a verified/enterprise concern, matching the coverage/observability placement and the considerations doc's "machine-check at verified". Standard keeps the contract-first principle (advisory); the hard check starts at verified. With interface-gating, a green contract-first at these tiers means either a checked-in contract or a project that exposes no interface — never a false failure.

5 · Risk register

From the adversarial pass (auto-fired: FR-002 is must-tier). Three findings, all mitigated in the review interview; each records the human who committed the transition. The mitigations are folded into the deltas above.

A bare *.schema.json is a ubiquitous config-validation artifact (settings schemas, tsconfig/package schemas), not an interface contract — so it will false-positively green contract-first on an interface-exposing project that has no API contract, exactly where the hard floor was meant to bite.

§4 FR-002 lists "a JSON Schema (*.schema.json)" as a contract signal and §6 widens matching into schema//contracts/ dirs; the first enterprise project with a config.schema.json + an Express API but no OpenAPI exits 0 and ships an ungated interface.

Mitigated. Bare *.schema.json is dropped from the contract signal set (FR-002 + the §6 SIGNALS task). The signals are OpenAPI/Swagger, *.proto, GraphQL SDL, and AsyncAPI — all unambiguously interface contracts — plus a JSON Schema only under an explicit contracts/ path, never a bare root/schema/ match. A config schema can no longer certify the floor.

FR-014's "an interface exposed via an unlisted framework is silently exempt" makes contract-first the only floor category whose undetectability yields green rather than a warning — straining against FR-010's rule that an undetectable required category MUST degrade to a visible warning, never pass silently.

Live FR-010: an undetectable required category "MUST degrade to a warning, never a hard failure"; FR-014 instead treats the no-interface-detected case as covered (green) and only "SHOULD record" the unlisted-framework gap.

Mitigated. FR-014 now states the distinction explicitly and that it does NOT override FR-010: FR-010 warns when a category that does apply can't be expressed in the stack; contract-first's applicability is itself conditional — "no interface detected" means the category may not apply, not that an applicable category is undetectable — so the correct posture is exempt, not warn. Warning on every interface-less project would be the warn-washing FR-010's demotion is not meant to cause. The unlisted-framework false-negative stays the recorded ceiling.

The change quietly alters a cross-cutting invariant: widening detection from strictly-root to root + conventional subdirs (api/, proto/, schema/, contracts/) touches the shallow root-only detection contract (NFR-002) shared by all nine categories, yet it rides inside a "Core machinery" §6 bullet rather than a first-class scope item.

§3 states detection "widens from strictly-root to root + a small set of conventional directories … recorded as a §6 task", but no NFR-002-touching item appears in §2 In scope — unlike the coverage/observability additions, which touched only the uniform category machinery.

Mitigated. The directory-widening is now scoped to contract-first signals only (a first-class §2 in-scope item + the §6 SIGNALS task): the other eight categories keep strict root-only detection, so NFR-002's shallow-detection invariant is unchanged for them. The shared invariant is not touched; only contract detection reaches into api//proto//schema//contracts/.
