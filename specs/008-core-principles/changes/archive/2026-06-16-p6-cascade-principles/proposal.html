FR-004 currently demands the kernel reject any pre-existing principles.html at the resolved path. Per the just-ratified P-6, that gate is too coarse: Draft destinations carry no consumer commitments and should accept in-place edit; only past-Draft destinations need the refuse-with-pointer-to-/propose ceremony. Scope refuse-if-exists to past-Draft (cite P-6)

Applied

1 · Intent

This proposal is one of four mechanical cascades from the just-applied P-6 elevation. The principle codifies the Draft-vs-past-Draft asymmetry; each artifact-generating verb's spec now needs a one-line FR scoping its refuse / overwrite / re-entry behaviour to honour it. The substance was exhausted by the parent's adversarial pass; this proposal contributes only the verb-specific application.

For the principles verb, the gap is in FR-004's blanket refuse-if-exists rule. The fix is to MODIFY FR-004 to scope refusal to past-Draft destinations and explicitly cite P-6. The kernel implementation hotfix (read the destination's <spec-status> before deciding) follows in the same PR per the discipline in 008/T-001's Fix field.

2 · Scope

In scope

  • MODIFY FR-004 to gate refuse-if-exists on destination's <spec-status> per P-6.
  • Hotfix packages/core/src/commands/principles.ts + packages/cli/src/commands/principles.ts to honour the new gate in the same PR.

Out of scope

  • The version-policy half of 008/T-001 (hardcoded v1.0.0 in Draft state). Principles-verb-specific; lands in a separate FR-008 proposal — does not generalise to other verbs (no other verb's template carries a <Version> field). Deferred to TBD-008-version-policy.
  • Re-deriving the principle in the FR body. P-6 is the source of truth; FR-004's MODIFY links to it.

3 · Approach

Single MODIFY on FR-004. The post-state preserves the original intent (v1 is fresh-generation-focused; amendments go through /spectastic.propose) but narrows the refuse trigger to past-Draft destinations. Draft destinations get an in-place edit path (preserve ID, append a one-line <spec-changelog> entry per P-3 + P-6). The --force override stays for past-Draft destinations.

4 · Deltas

What changes: Refuse-if-exists scopes to past-Draft destinations (per P-6); Draft destinations honour in-place edit; --force override stays for past-Draft.

v1 scope MUST be fresh-generation focused. The kernel function MUST gate its behaviour on the destination's <spec-status> per P-6: a Draft destination (or fresh path with no destination) MUST be authored / edited in place (preserve the existing ID; append a one-line <spec-changelog> entry); a past-Draft destination (Accepted, In Review, Superseded, Deprecated, Blocked) MUST be refused with a typed error pointing at /spectastic.propose. A --force override MAY bypass the past-Draft refuse, but invoking it MUST emit a one-line warning that the operation skips the change-management surface.

Rationale

Cascade of 008/T-001: the original FR-004's blanket refuse-if-exists conflated Draft (no consumer commitments) with past-Draft (locked contracts). P-6 ratified the asymmetry as a project principle; this FR honours it by reference. The version-policy half of 008/T-001 (Draft → v0.1.0 vs v1.0.0) is principles-verb-specific and lands as a separate FR-008 proposal.

5 · Risk register

Adversarial pass deliberately opted out (--no-adversarial). The substance of this MODIFY was exhausted by the parent P-6 proposal's adversarial pass; this proposal is the mechanical cascade per P-6's own design intent. The three risks raised against the parent (reversible-state lumping; In Review → Draft path; "without ceremony" license) were all mitigated in P-6's body before apply.
