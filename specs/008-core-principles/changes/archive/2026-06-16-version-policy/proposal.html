Initial-version policy: Draft artifacts carry pre-1.0

Applied

1 · Intent

The original smoke-test defect in 008/T-001 had two distinct upstream gaps. The first — refuse-if-exists conflating Draft and past-Draft — landed cleanly through the P-6 elevation + 2026-06-16-p6-cascade-principles. The second — the kernel hardcoding v1.0.0 while the artifact ships in Draft — does not generalise to other verbs (no other artifact template carries a Version field today) and is therefore scope-local to this spec.

The asymmetry the policy honours is the same one P-6 codified: pre-1.0 means content can shift without ceremony (matches 006 FR-012's pre-1.0 discipline for the @spectastic/* npm packages); v1.0.0+ means consumers have anchored against the contract. A Draft principle deck has no consumers anchored against it — it must not claim v1.0.0.

2 · Scope

In scope

  • ADD FR-008 specifying that principlesCommand emits a pre-1.0 version (default v0.1.0) while the artifact is Draft.
  • Tie the Draft → v1.0.0 graduation to the bundled-flip prompt (Draft → Accepted) per REQ-LIFECYCLE-005.
  • Hotfix packages/core/src/commands/principles.ts: the template literal at line 139 changes from v1.0.0 to v0.1.0.

Out of scope

  • Extending the policy to other verbs. None of spec / plan / tasks generate artifacts with a Version field today; extending the policy is a no-op for them. If a future artifact template gains a Version field, that slice authors its own version-policy FR. defer-to="never" at the project scope; defer-to="TBD-<slice>" when surfaced per future slice.
  • Renumbering or otherwise mutating already-shipped principles.html artifacts that carry v1.0.0+ (the project's own ratified principles.html stays at its current version per P-6's "ratified is locked"). The policy applies to future Draft generations only.
  • A CLI flag for choosing the initial version. The kernel's default is v0.1.0; authors who want a different pre-1.0 starting point can edit the generated artifact directly (Draft is loose per P-6).

3 · Approach

Single ADD on FR-008. The post-state names v0.1.0 as the default initial version, explicitly forbids 1.0.0+ while in Draft, and points at the bundled-flip prompt as the graduation gate. The kernel hotfix is mechanical — a single template-literal edit. The policy carries forward to any future Draft-state principles authoring; the project's own currently-Accepted principles.html (now at v1.1.0) is unaffected.

4 · Deltas

The generated principles.html artifact MUST carry a version below 1.0.0 (default v0.1.0) while its <spec-status> is draft. The kernel MUST NOT emit v1.0.0 (or higher) on a Draft artifact. Graduation to v1.0.0 MUST happen at the Draft → Accepted bundled-flip prompt per REQ-LIFECYCLE-005, not in this verb. Subsequent in-place edits while Draft MAY bump the pre-1.0 version (e.g. v0.1.0 → v0.2.0) but MUST NOT cross the 1.0.0 boundary.

Rationale

Companion to FR-004 (Draft-aware refuse) per P-6. Pre-1.0 versioning matches the project-wide discipline already enforced for the @spectastic/* npm packages (006 FR-012); extending it to generated artifacts is consistent. A Draft artifact with no consumers anchored against it must not claim v1.0.0 — the version field reads as a contract; the contract doesn't exist yet.

5 · Risk register

Adversarial pass deliberately opted out (--no-adversarial). The policy is scope-local (one verb's template), explicitly carried over from a project convention already established for npm packages, and the user-named substance directly mirrors the recommendation in 008/T-001's Fix field.
