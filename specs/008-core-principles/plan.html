Core principles — implementation plan

3 · Approach

Three moves, one PR. One: implement principlesCommand at packages/core/src/commands/principles.ts per 006's signature; reads template via ctx.fs, interviews through ctx.ai.chat(), fills placeholders, returns { html, principlesCount }. Two: add a spectastic principles CLI subcommand that constructs ClaudeProvider + KernelContext, calls the kernel, writes to ./principles.html. Three: add the MAY-Bash note to commands/spectastic.principles.md per FR-006.

The refuses-if-exists check happens kernel-side (FR-004): the function stats the output path through ctx.fs and rejects with a typed PrinciplesExistsError before any AI call. Keeps the contract uniform across surfaces — CLI, future MCP, future VS Code all get the same guard.

4 · Alternatives considered

OptionMaintainabilityDrift riskEffortTotal
Inline template as TS string literal2248
Bundle template at build via tsup asset copy3339

Disk-read keeps one source of truth and avoids the inline-string maintenance tax. Inline drifts whenever the template changes; bundle-at-build adds asset-copy config and complicates downstream consumers. Disk-read is also how the slash command works today — parity for free.

5 · Decisions

D-001 · principlesCommand reads template via ctx.fs, fills placeholders, returns HTML string

Status
Accepted
Context
Near-pure template generation: templates/principles.html already carries every [PLACEHOLDER]; LLM authors the variable parts, kernel fills and emits.
Decision
Signature async function principlesCommand(input: PrinciplesInput, ctx: KernelContext): Promise<PrinciplesResult> per FR-001. Reads template via ctx.fs.readFile, calls ctx.ai.chat() for variable parts, replaces placeholders, returns { html, principlesCount }. Kernel does not write — caller decides output path.
Consequences
+ One source of truth; + downstream surfaces consume rendered HTML without committing to a filesystem. − Missing template surfaces as a typed error per spec edge-case.

D-002 · Refuse-if-exists — kernel rejects when principles.html already exists

Status
Accepted
Context
FR-004 mandates fresh-generation only; amendments stay in /spectastic.propose. CLI-only guard would let future MCP / VS Code consumers silently overwrite.
Decision
Before any AI call, principlesCommand stats the resolved output path (input.outputPath, defaulting to <ctx.cwd>/principles.html) via ctx.fs.stat. If the file exists, throw a typed PrinciplesExistsError. CLI surfaces "principles.html already exists; use /spectastic.propose to amend."
Consequences
+ Uniform contract; + AI cost saved on rejection. − Caller can't ask kernel to overwrite (intentional).

D-003 · PrinciplesInput shape — all fields optional; kernel interviews to fill gaps

Status
Accepted
Context
Spec data-model declares projectName? + principlesCount?. CLI may have argv; future MCP may have nothing. Both surfaces must work without per-caller interview logic.
Decision
PrinciplesInput = { projectName?: string; principlesCount?: number; outputPath?: string }. Kernel checks each; if absent, prompts via ctx.ai.chat(); clamps principlesCount to 3–5 with a warning per spec edge-case. outputPath defaults to join(ctx.cwd, 'principles.html').
Consequences
+ Surfaces with no UI get a fully-interviewed result from one call. − Three optional fields means three kernel branches.

D-004 · Template source — read templates/principles.html from disk; don't inline

Status
Accepted
Context
Three options (matrix above): inline TS string, tsup asset copy, or disk read. Template already lives at templates/principles.html for the slash command.
Decision
Kernel computes join(ctx.cwd, 'templates/principles.html') and reads via ctx.fs.readFile. Missing → typed TemplateNotFoundError. Asset-path adjustment (../assets/ → ./assets/) per slash-command markdown happens kernel-side as a string replace.
Consequences
+ Zero drift between slash and CLI flows. − Kernel binds to repo layout via ctx.cwd; a global-install use case needs a bundled-templates story (deferred).

D-005 · Single-PR migration; ships as v0.1.0-pre.10 after 007 lands

Status
Accepted
Context
008 depends on 007's ClaudeProvider for ctx.ai.chat(). 006 (pre.8) and 007 (pre.9) established the single-PR cadence.
Decision
Land 008 as a single PR after 007 publishes; ships as v0.1.0-pre.10. Bench enforces lazy-loading; CLI integration tests prove structural byte-identity per 007's precedent; SC-001's real-Claude check runs under skipIf.
Consequences
+ Atomic; + reverts cleanly. − Blocked on 007 shipping first.

D-006 · CLI subcommand owns disk write and exit-code translation

Status
Accepted
Context
FR-003 splits responsibilities: kernel owns deterministic core; CLI owns shell-side concerns (argv, prompts, stdout, exit codes).
Decision
CLI's src/commands/principles.ts imports principlesCommand from @spectastic/core/commands/principles, constructs ClaudeProvider + KernelContext, calls kernel, writes html to ./principles.html, exits 0. PrinciplesExistsError → exit 1 + message; usage error → exit 2.
Consequences
+ Matches 006 D-007's thin-shim discipline. − Each surface owns its own IO (intentional).

8 · Complexity tracking

One deliberate addition warrants flagging:

Kernel-side refuses-if-exists guard (D-002). Could live CLI-only, saving a kernel branch. Pushed kernel-side so every future surface (MCP, VS Code) gets the guard for free — a careless MCP server otherwise overwrites a ratified principles document on a misclick. Cost: one ctx.fs.stat call; benefit: "amendments only via propose" enforced at the contract layer.
