Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 029-value-ranked-slicer Plan plan Branch 029-value-ranked-slicer Created 30 Jun 2026 Read time

28 tasks across five phases. Setup → Foundational → User stories (US1 · US2 · US3 · US4) → Polish. [P] tasks touch distinct files with no in-flight dependency. Per D-007: the pure core (corpus, coverage, verdict) is TDD vitest; the agentic orchestration runs against a stub AIProvider; real-LLM quality is a local test:smoke. US1 + US2 are the shippable MVP.

1 · Execution strategy

Setup → Foundational → US1 → US2 → US3 → US4 → Polish. Each story closes its conformance before the next opens. US1 (split proposal) + US2 (coverage proof) are both P1 and together are the shippable MVP; US3 (rival panel) is P2, US4 (auto-offer) P3 — so the order also tracks priority.

Land US1 + US2 end-to-end (a covering, ranked, ordered proposal) and stop there to demo. Add the rival-decomposition panel (US3) and the auto-offer (US4) once the core proves out.

After Foundational, US1 and US2 share seams (slice.ts, render.ts) so they're better sequenced; US3 and US4 can run alongside once US1's rank.ts / spec.ts entry exist. Coordinate at those files via the plan.
