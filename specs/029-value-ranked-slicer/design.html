Design · 029-value-ranked-slicer

The value-ranked slicer

How we will build it.

Status Accepted Spec 029-value-ranked-slicer Owner Brian Corbin · @briancorbinxyz Branch 029-value-ranked-slicer Created 30 Jun 2026 Read time

A new pure-orchestrating core kernel sliceCommand, invoked from the spec verb's split-mode (no new verb). It drafts a decomposition via ctx.ai.chat, estimates + confirms RICE via ctx.ai.ask, builds an in-memory synthetic corpus and calls 028's orderCommand({corpus}) to order the hypothetical children, checks coverage with a pure-TS requirement-ID partition plus a critic subagent, and renders a <spec-split> section appended to a Draft parent. The bias-resistant ranking panel extends propose's single-subagent precedent to N scorers (P2). Biggest risk: the agentic judgment (decomposition + RICE quality) is only smoke-testable — the coverage partition is the hard gate that keeps a bad split from shipping.

4 · Approach

The slicer is one new core kernel, sliceCommand, that the spec verb calls when it is in split-mode (detected on an over-budget parent, or requested). It is mostly orchestration over primitives that already exist: it drafts a decomposition with chat, estimates RICE and confirms it with ask, hands the hypothetical children to 028's orderCommand as an in-memory corpus, and proves coverage with a pure-TS partition backed by a critic subagent. The only genuinely new agentic machinery is the ranking panel (P2) — and that is propose's single-subagent pattern fanned out to N scorers with a median.

The output is a <spec-split> section appended to the parent — additive, Draft-only. Nothing is minted and no branch is cut; the human reviews, and a later slice executes the mint + git fan-out. When no candidate both covers the parent and leaves every child in budget, the kernel returns a "don't split" verdict instead.

6 · Decisions

D-001 · A new sliceCommand kernel, entered from the spec verb's split-mode

Status
Accepted
Context
Kernels are one async fn per verb (packages/core/src/commands/spec.ts:22); FR-001 forbids a new slash command.
Decision
sliceCommand(input, ctx) holds the agentic work; spec gains a split-mode that calls it. No new verb, no new CLI subcommand.
Consequences
+ Isolated, stub-testable, CLI-dispatchable; + 8-verb surface holds. − One more kernel + a branch in the spec verb's wiring.

D-002 · Agentic structure extends propose's subagent precedent

Status
Accepted
Context
propose.ts:60 runs one adversarial subagent — the only subagent user today.
Decision
P1: chat drafts the decomposition; one critic subagent does the semantic coverage pass. P2: the ranking is N independent scorer subagents. All via ctx.ai.subagent/chat.
Consequences
+ Reuses a proven mechanism + the stub provider. − P2 multiplies agent calls (bounded by the effort primitive, §9).

D-003 · R-002 handoff via an in-memory synthetic corpus

Status
Accepted
Context
orderCommand({corpus}) orders a passed-in CorpusEntry[] without touching disk (028).
Decision
Build synthetic spec.html strings — a parent carrying defer-to to each child, children carrying <spec-parent> + estimated <spec-rice> — and call orderCommand({corpus}). The stubs are acyclic by construction.
Consequences
+ Zero disk writes; + reuses R-002's inference + cycle guard verbatim. − Children must be serialised to the exact link shape R-002 reads (covered by a corpus-build unit test).

D-004 · Coverage = pure-TS requirement-ID partition + a critic subagent

Status
Accepted
Context
extractSpecMetadata (extract.ts:57) yields the parent's FR/NFR/SC id lists.
Decision
The hard gate (FR-005) is a pure check: every parent id assigned to exactly one child (total + disjoint). The semantic pass (FR-006, SHOULD) is a critic subagent on top.
Consequences
+ The trust outcome (SC-001) is mechanically verifiable, not LLM-judged; + cheap. − Semantic gaps a partition can't see depend on the SHOULD critic.

D-005 · <spec-split> element; Draft-only in-place append

Status
Accepted
Context
extractSpecStatus (extract.ts:48) reads the parent state; <spec-rice> is the element + validate-rule precedent (this session).
Decision
New <spec-split> element (CSS/JS like <spec-rice>) + a split-well-formed validate rule. Append in place only when status is draft (+ a changelog line); a terminal parent gets a propose-shaped output instead (FR-008).
Consequences
+ P-6 honoured by a hard guard. − A second authoring path (in-place vs propose) to test.

D-006 · Panel aggregation = median of per-child scores

Status
Accepted
Context
NFR-001 wants ≥ 3 independent scorers, bias-resistant. A method choice, no external fact.
Decision
Each scorer rates every child; take the median RICE per child, then order. Robust to a single outlier judge; explainable.
Consequences
+ One biased judge can't decide the order; + keeps RICE magnitude (unlike a rank vote). − P2; until then P1 uses a single scorer + the critic.

D-007 · Layered tests — TDD pure core, stub-AI orchestration, local smoke

Status
Accepted
Context
The stub provider (ai-factory.ts:15, SPECTASTIC_AI_STUB) is the project's AI-in-CI pattern; the agentic quality is non-deterministic.
Decision
vitest TDD on the pure pieces (partition, corpus-build, order handoff, verdict); a stub AIProvider for deterministic orchestration tests; real-LLM judgment quality in local test:smoke.
Consequences
+ CI is deterministic; + the invariants that matter are mechanically tested. − Decomposition/RICE quality is only smoke-gated, not in CI.

D-008 · RICE confirmation via ctx.ai.ask, provisional until confirmed

Status
Accepted
Context
AIProvider.ask<T> (types.ts:115) mirrors AskUserQuestion; works in-host and via stub in CI.
Decision
Agent-estimated RICE is surfaced through ask for confirmation (FR-004); the ranking renders provisional until confirmed.
Consequences
+ Human owns the value inputs; + same path in-host and stubbed. − An extra round-trip before the order is final.

8 · Risks & mitigations

RiskLikelihoodImpactMitigation
R-1 · The agent proposes an unnatural / low-value decompositionMMThe coverage partition is a hard gate (a non-covering split can't ship); the don't-split verdict (FR-007); the human confirms, and minting is a separate slice anyway.
R-2 · RICE estimates are unreliable, skewing the rankingMMProvisional-until-confirmed (FR-004); the human edits before it's final; the dependency order holds regardless of value.
R-3 · Panel cost — N rivals × ≥3 scorers + criticMLEffort-level bound (default ≤ 2 rivals); the panel is P2 — P1 ships with a single scorer + critic.
R-4 · Appended to a non-Draft parent (P-6 violation)LHextractSpecStatus hard guard refuses in-place on terminal state (FR-008); the propose path is the only route there.
R-5 · Synthetic-corpus stubs malformed → cycle/dangling in orderCommandLMStubs are built parent→child only (acyclic by construction); a corpus-build unit test asserts the shape; R-002's cycle error is the backstop.

9 · Complexity tracking

The ranking panel (≥ 3 scorers × ≤ 2 rivals) is real agent cost. Justified by NFR-001's bias-resistance requirement and bounded by the effort-level primitive; it is P2, so P1 ships a single-scorer ranking + the coverage critic and adds the panel later.

A new kernel rather than folding into specCommand. The multi-agent flow is different enough from the single-pass spec interview that isolating it keeps both testable; the cost is one extra file + a wiring branch (D-001).

Two authoring paths for the proposal (Draft in-place vs Accepted-via-propose). The propose path (FR-008, SHOULD) may land after the Draft path; both are tested against the extractSpecStatus guard.
