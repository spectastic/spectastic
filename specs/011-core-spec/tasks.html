4 · Phase 3a — US1 · Maintainer authors a fresh feature spec via CLI P1

The smallest demoable: fresh-mode spectastic spec "<feature>" walks the two-phase interview and writes a populated spec.html to disk.

Tests (write & fail first)

Write packages/core/test/spec.test.ts — unit-first per 006 D-008. Constructs a stub AIProvider with a scripted queue of chat() + ask<T>() answers; calls specCommand(input, ctx) via the '@spectastic/core/commands/spec' subpath. Covers: (a) fresh-mode happy path produces a populated SpecResult; (b) smallest-demoable is the first decision question (FR-006 / D-007); (c) INVEST pass populates six rows and emits a warning on ✗ picks (FR-007 / D-003); (d) empty-queue mid-interview fails loudly with the unconsumed question text (edge case in spec §2); (e) termination via the typed "complete?" ask after the three-iteration minimum, and the 24-iteration ceiling emits a warning (D-005). Tests fail until T-110 lands. packages/core/test/spec.test.ts

Implementation

Create packages/core/src/commands/spec.ts implementing async function specCommand(input: SpecInput, ctx: KernelContext): Promise<SpecResult> per FR-001. The function builds an InterviewSession (D-001) and runs the two-phase loop: each iteration calls ctx.ai.chat() with session state to pick the next InterviewPhase, then dispatches — chat phases append to narrative slots, decision phases call ctx.ai.ask<T>() and record picks. Fresh-mode's first decision iteration is hard-coded as the smallest-demoable ask with three derived options + a follow-up if the answer reaches for "the whole feature" (FR-006 / D-007). User-story extraction uses a structured-prompt JSON parse with one retry (D-006); INVEST pass runs after termination (D-003); the budget gauge recomputes word count after each delta and fires a splitting ask + appends to warnings on crossing 70% (FR-008 / D-004); decidable open questions are anchored via ask<T>() first (FR-009); termination via the typed "complete?" ask past iteration 3 with a 24-iteration ceiling (D-005); returns structured SpecResult with html, specId, requirementsCount, warnings — no filesystem writes (FR-010). Docblock links to commands/spectastic.spec.md as canonical procedure (FR-013). Re-entry path delegates to the reentry.ts helper for the existing-spec snapshot and constrains the engine to ADD / ENHANCE (FR-005 / D-002). No module-level side effects; no eager template or parse5 import per NFR-001. packages/core/src/commands/spec.ts
Create packages/cli/src/commands/spec.ts — spectastic spec "<feature-description>" subcommand per FR-003. Owns shell-side concerns: argument parsing, ID assignment (scan specs/ for highest existing number, increment; collision triggers re-entry confirmation), directory creation, template copy with asset-path rewrite (../assets/ → ../../assets/), and the writeFile for the kernel's returned html. Detects existing specs/<spec-id>/spec.html when the argument matches an existing ID and switches to re-entry mode (FR-005). Imports specCommand via the '@spectastic/core/commands/spec' subpath. packages/cli/src/commands/spec.ts
Write packages/cli/test/spec.integration.test.ts covering the fresh-mode happy path with a stub AIProvider: invoke the subcommand in a temp workspace; assert specs/001-test-feature/spec.html exists; assert asset paths are correctly rewritten to ../../assets/spec.css + ../../assets/spec.js; assert no [PLACEHOLDER] tokens remain; assert exit code 0 per FR-011. packages/cli/test/spec.integration.test.ts
Run pnpm -r build end-to-end. Confirm all three packages build cleanly; the new spec.ts entry emits its own ESM chunk; CLI's typecheck consumes the new @spectastic/core/commands/spec subpath. packages/{core,cli,schema}/dist/
Run pnpm test and confirm: (a) T-100 kernel unit tests pass; (b) T-112 CLI integration tests pass; (c) existing 006 / 007 / 008 / 009 / 010 tests stay green; (d) T-200 re-entry fixture test passes. (test run)
Run pnpm bench and confirm all four bench/baselines.json scenarios within budget per NFR-001 + SC-004. The init-help-cold-start p50 stays within ±20% of today's post-007 baseline (52 ms on CI) — proving the new spec subpath does not eagerly load HTML-generation or template-parsing dependencies onto the init path. (bench run)
SC-001 manual smoke: in a clean temp workspace run node packages/cli/dist/index.js spec "test feature", walk a scripted interview, and confirm specs/001-test-feature/spec.html exists with structurally-valid content (FR IDs present, INVEST linkage intact, conformance index populated). Per the plan's risk note, assert on structural fields — not byte-identical prose — modulo whitespace + dynamic Created date per SC-001.
