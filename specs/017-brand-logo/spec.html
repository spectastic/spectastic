Brand logo

Make the spectastic mark conform to the brand guide — the canonical eight-prong spectrum SVG, in the cap-line wordmark lockup, used everywhere a logo appears.

Read time

Spectastic has a brand guide for its logo — an eight-prong "spectrum" mark — but the codebase doesn't follow it: the only mark we render is a Unicode ✻ in the vivid header (016 · T-007). This spec makes the canonical mark real: one rotated-prong SVG whose eight colours are the eight lifecycle commands, placed after the wordmark and lifted to its cap line, sized in em so it tracks the type. It ships as a reusable lockup adopted by the vivid header, the landing wordmark, and a favicon, with spectrum / mono / dark renderings — so the brand reads identically wherever it appears. The guide is the reference; this spec encodes it as a contract.

1 · Context

There is a canonical spectastic logo guide: the mark is an eight-prong "spectrum" asterisk — one prong path drawn in a 100×100 box and rotated eight times at 45°, its eight fills the eight lifecycle-command colours, placed after the "spectastic" wordmark and aligned to the word's cap line. The guide gives a paste-verbatim SVG, two lockup techniques, clearspace and minimum-size rules, and spectrum / mono / dark colour modes.

The codebase does not follow it. The only logo mark we render is a Unicode ✻ glyph in the vivid header (assets/spec.js) — placed before the wordmark, in a single crimson, not cap-aligned — and there is no canonical SVG, no prong colour tokens, and no favicon. The mismatch was triaged as 016 · T-007 (regen fail — no spec captured the logo). This spec is the missing contract; whoever renders the brand — the chrome, the landing page, a browser tab — is the audience.

2 · User scenarios & testing

Each story MUST be independently testable: if you implemented only US1, you would still have a viable MVP.

US1 · The mark in the wordmark lockup P1

As a reader or author, I want the spectastic wordmark to carry the canonical eight-prong spectrum mark, on-guide so that the brand reads correctly in the chrome instead of a stand-in glyph.

Acceptance: the vivid header shows the canonical SVG mark after "spectastic", cap-line aligned, sized 0.52em; the eight prongs carry the eight lifecycle colours in order; no Unicode asterisk remains; it renders correctly in light and dark.

US2 · Favicon P2

As a visitor, I want the browser tab to show the spectrum mark so that an open artifact is recognisable at a glance.

Acceptance: a favicon.svg reuses the canonical prong path and the prong colours; artifacts reference it; it stays legible at favicon sizes (≥ 16px).

US3 · Landing wordmark & running text P2

As a visitor to the landing page, I want the "Spectastic" wordmark to use the canonical lockup so that the front door is on-brand; and in prose, the mark can sit in a line of text without breaking it.

Acceptance: index.html's wordmark uses the lockup (Technique A); the running-text superscript (Technique B) is available for the mark inside prose; a mono single-ink derivation exists for single-colour contexts.

Edge cases

  • Dark surfaces — the prong palette is the brightened set the active mode swaps in; never a hand-picked dark recolour (mode owns colour, per 016 · FR-002).
  • Below 16px or without colour — the mark falls back to the mono single-ink lockup; the prongs must not merge into a blob.
  • JavaScript off — an inline-SVG lockup still renders (it is markup, not script-built); only the JS-built header chrome is gated by 016 · NFR-002.

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119. The brand guide is the reference; any divergence is a documented decision, not a default.

Functional

The logo mark MUST be the canonical eight-prong spectrum SVG — a single prong path (viewBox 0 0 100 100, overflow:visible) rendered eight times via rotate(n·45° 50 50) — used verbatim from the guide. It MUST NOT be a Unicode glyph, emoji, font character, or a hand-redrawn path.

Rationale

The current header uses a Unicode ✻ — a different shape entirely, with no control over prong count or colour. Rotating one path guarantees the eight prongs are identical and 45° apart.

The eight prongs MUST carry the eight lifecycle-command colours in fixed clockwise order from prong 0 (pointing up): principles #5f023e, spec #960462, plan #e1624f, tasks #e0a23c, implement #3f6a37, propose #04a5bb, apply #00758f, triage #7558b2. The order and colours MUST NOT be shuffled, recoloured, or dropped to fit a palette.

The wordmark lockup (Technique A) MUST place the mark after the "spectastic" wordmark, aligned to the word's cap line (via display:inline-flex; align-items:flex-start, not the baseline or x-height), sized 0.52em of the wordmark.

The vivid header (016 · FR-009) MUST adopt the canonical lockup, replacing the Unicode ✻ glyph — closing T-007.

Colour modes MUST follow the guide: the eight-colour spectrum is the default wherever colour renders; a mono (single-ink) derivation covers single-colour contexts; on dark surfaces the prongs use the brightened palette the active mode swaps in — never a hand-picked dark recolour. Prong fills MUST reference tokens, so one markup renders in every mode.

A favicon.svg SHOULD reuse the canonical prong path and colours; artifacts SHOULD reference it.

The landing page (index.html) wordmark SHOULD use the canonical lockup rather than plain text.

A running-text superscript lockup (Technique B) SHOULD be available for the mark inside prose — placed via <sup> with the guide's vertical-align and relative sizing — for contexts where inline-flex is awkward.

Non-functional

The mark MUST be sized in em (never px) within a lockup so it tracks the type; the standalone icon MUST keep clearspace of one prong-length on all sides and MUST NOT be rendered below 16px, where the prongs merge.

The mark is decorative: it MUST be aria-hidden, with the accessible name carried by the adjacent "spectastic" wordmark text, which MUST meet WCAG 2.1 AA contrast in all theme×mode combinations (consistent with 016 · NFR-003).

The mark SHOULD render with no new typeface or binary asset download — an inline SVG (and an SVG favicon), so it costs nothing beyond markup.

Out of scope (deferred to other slices)

  • Animated or spinning mark, hover motion, or a loading-spinner variant — the mark is static.
  • A full brand book beyond the logo (typography scale, voice, colour usage rules, spacing system) — this spec is the logo only.
  • Print / physical-media logo specifications (CMYK, minimum print sizes, raster exports).

4 · Data model

No persisted data. The "entities" are static brand assets owned by this spec.

Entities

Prong path
One SVG path (M50 50 L43.5 18 Q50 10.5 56.5 18 Z) in a 0 0 100 100 viewBox, rotated eight times at 45° about the centre. The single source of the mark's geometry — the favicon reuses it.
Prong colour tokens
Eight tokens (one per lifecycle command, FR-002 order) with light (spectrum) values and dark (brightened) values the mode swaps in; a mono token for single-ink.
Lockup
The wordmark + mark composition: Technique A (cap-line inline-flex, FR-003) and Technique B (running-text superscript, FR-008).

Invariant: the mark's geometry has exactly one source (the prong path rotated eight times); colour has exactly one source (the prong tokens). Nothing redraws the path or hand-picks a prong colour.

5 · Success criteria

Technology-agnostic, measurable outcomes.

No shipped artifact renders the logo as a Unicode asterisk/emoji or font glyph — every mark is the canonical SVG. Verifiable by a search for asterisk glyphs in the brand position and an assertion of the eight-path SVG structure.

The mark's eight prong fills equal the eight FR-002 hex values in clockwise order — property-by-property, no human judgement.

In the vivid header, the mark follows the wordmark, its top aligns to the wordmark's cap line (not baseline), and its rendered size is 0.52em of the wordmark — verifiable via computed styles / measured geometry.

A favicon.svg exists and uses the prong path; the landing wordmark uses the lockup — both verifiable by inspection.

The mark renders with eight distinct (non-merged) prongs at 16px, and under data-mode="dark" the prongs use the brightened palette — measurable across light and dark.

6 · Assumptions

The brand guide (the local logo-guide reference) is authoritative and stable; its prong path, colour order, and lockup geometry are taken as given (the reference is law).

The eight prong colours overlap spectastic's existing palette (e.g. principles #5f023e = the link crimson, propose #04a5bb = the sea accent); the plan decides whether the --spec-* tokens reuse or alias the existing colour tokens.

7 · Open questions

None blocking — every decision (slice boundary, surfaces in scope, colour modes) was anchored during the interview. The token-aliasing detail (assumption above) is a plan-level choice, not a spec open question.
