Design · 017-brand-logo

Brand logo

How we will build it.

Status Draft Spec 017-brand-logo Owner Brian Corbin · @briancorbinxyz Branch 017-brand-logo Created 19 Jun 2026 Read time

One canonical inline SVG (eight prongs, fills var(--spec-1…8)) is the single source of the mark; a thin spec.js helper builds the header lockup, static surfaces (landing, prose) paste the same SVG, and favicon.svg reuses the path. The --spec-* tokens are independent brand literals (light + dark), decoupled from the UI palette. Biggest risk: the prong path is duplicated across three inline copies — mitigated by a test that asserts they match the guide.

3 · Approach

One inline SVG is the canonical mark — the guide's prong path rotated eight times, each fill a var(--spec-n) token. The --spec-1…8 tokens are defined as independent brand literals in :root with a brightened [data-mode="dark"] set, plus a mono token for single-ink. CSS provides the lockup (.spec-logo: cap-line inline-flex, 0.52em mark) and a mono modifier. The vivid header calls a small spec.js helper that returns the lockup (replacing the ✻ glyph); the landing wordmark and any running-text superscript paste the same inline SVG; favicon.svg is its own file reusing the path.

5 · Decisions

D-001 · Prong colours are independent brand tokens, not aliases of the UI palette

Status
Accepted
Context
FR-002 fixes the eight prong colours by lifecycle command; six already match palette tokens (principles #5f023e = --c-link, propose #04a5bb = --c-accent, …).
Decision
Define --spec-1…8 as their own literals in :root, with a brightened [data-mode="dark"] set and a --spec-mono for single-ink. They do not alias --c-*.
Consequences
+ The brand is decoupled from the UI palette — retuning a link/accent colour for AA never silently shifts a prong (FR-002 holds). + One block is the brand's source of truth. − The six overlapping values appear in two places (palette + brand); a comment cross-links them, and a test pins the prong values (R-3). Not duplication — distinct contracts.

D-002 · Inline SVG everywhere + a JS helper for the header (no custom element)

Status
Accepted
Context
The mark renders in JS-built chrome (the vivid header), in static HTML (landing, prose), and as a favicon. FR-001 wants the verbatim SVG; P-4 wants the static landing to work without JS; theming needs per-prong var(--spec-*) fills.
Decision
The mark is an inline SVG with var(--spec-*) fills. A spec.js helper returns the lockup for the header (which is JS-only anyway); the landing + superscript paste the same inline SVG; favicon.svg is its own file. No <spec-logo> element, no data-URI.
Consequences
+ No-JS-safe landing (P-4); + full per-prong theming incl. the dark swap; + no new downloads (NFR-003). − The prong path is duplicated across the helper, the landing, and favicon.svg (R-1) — accepted because the guide endorses paste-verbatim and a test pins it. A custom element would be DRY-er but breaks no-JS (matrix §4).

templates/      # <link rel="icon" href=…favicon.svg> in the artifact <head>
                #   (so init'd projects ship the favicon reference)

tests/
  brand-logo.spec.ts   # NEW — 8-path SVG, prong colours = lifecycle order,
                       #   cap-line + 0.52em geometry, no-glyph, favicon, dark

Adding a <link rel="icon"> to every existing artifact is a retrofit (like the theme-boot insertion); the first slice wires the template + landing, and the broad retrofit is its own task so the smallest demoable (header lockup) isn't gated on it.

7 · Risks & mitigations

RiskLikelihoodImpactMitigation
The prong path / colours drift across the three inline copies (helper, landing, favicon)MedMedA test asserts each copy's path d + the eight fills match the guide's canonical values (SC-002); the guide is the cited source of truth.
Cap-line alignment is font-metric / browser sensitive (the mark floats off the cap line)LowMedUse the guide's flex technique (align-items:flex-start + small margin-top), not <sup>/font metrics; SC-003 measures the rendered geometry.
The six prong values that duplicate palette colours drift if one side changesLowLowIndependent tokens (D-001) are the brand source of truth; a comment cross-references the palette; the prong-colour test pins them.
The brightened dark prong palette is hard to read / muddy on dark surfacesLowMedDerive the dark set from the existing dark palette where prongs overlap it; SC-005 checks eight distinct prongs render in dark mode.

8 · Complexity tracking

Anywhere this plan introduces complexity not strictly required by the spec, justify it here.

The six prong values that coincide with palette tokens are restated as independent --spec-* literals rather than aliased (D-001). The minor duplication is deliberate — it keeps the brand contract (FR-002) immune to UI-palette retunes — and is the only non-obvious complexity here.

9 · Open questions

None blocking — token strategy (D-001) and delivery mechanism (D-002) are decided. The favicon-link retrofit scope (all artifacts now vs template-only first) is a task-ordering choice, noted in §6, not a design unknown.
