The output layer can't tell an ownership violation from a layering one

Spec upstream

Debugging a non-owner's verdict --explain that misdirects the author, root cause was a spec gap — the output layer (115 Violation, 118 explain, 117 teach) predates 119's ownership semantics and carries no signal that a touch was disallowed for ownership; fixed by a new small spec that records the cause on the violation and renders it; regeneration fails because no current requirement asks the output to distinguish "outside allowed-in" from "not the owner".

Expected
For a non-owner: "nowhere in this service — the store spectastic://…/datastore/positions is owned by briancorbin/position-keeper-guardrails; route the change through that service's API," with the coordinate naming the authority; verdict.json records cause: "ownership". For the owner: unchanged.
Actual
The "Sanctioned path — where this pattern is permitted instead" block prints src/**/persistence/** — exactly where the offending file already sits — and the coordinate is the consumer's projection (spectastic://acme/reconciliation-service/decision/002-downstream-consumers/D-007), the copy, not the authority. The VIOLATION line and artifact are byte-identical to a single-repo path violation.
Diagnosis
verdictFor emits no cause on Violation (types.ts — no field), so explainViolations resolves sanctionedPath from rule.allowedIn/decision.paths (explain.ts:49) and never reads decision.resource or currentProject — 118 cannot know it was an ownership violation, and 117's --teach templates its question from a reason authored for the layering case.
Fix
A new small spec — TBD-ownership-aware-verdict-output. Additive Violation.cause ("path" | "ownership") plus the owner coordinate when ownership, set in verdictFor (115/119) and consumed by explain (118) + teach (117); artifact byte-identical for existing path violations. Item 2 (the cause field) is the data item 1 needs — the explainer must read the cause, never re-derive ownership.
Deep dive — cross-spec contract

The fix grows a shared contract across four specs rather than living in one: 115 owns the Violation shape (the new cause field), 119 sets it in the owner-aware branch, 118 reads it to render the sanctioned-path message + the authority coordinate, and 117's teach question templates from it. The load-bearing constraint (P-14-adjacent): ownership is decided once, in the verdict, and flows outward as data — the explainer is a renderer, not a second site of the owner comparison. Scoped as a new spec rather than a 118 amendment because the Violation contract it touches is 115's, not 118's. No exit code changes; existing path violations are unaffected.

The scope note claims a copied-in decision isn't evaluated — but it was

Implementation code

Debugging a scope note that reads false in a consumer carrying the owner's decision, root cause was implementation wording drift — the note describes the wrong invariant ("owned by this repo" rather than "present in this checkout"); fixed by rewording to what is literally true; regeneration passes — no spec constrains the wording, the fix is code-only.

Expected
"Scope: repo-local — evaluated N decision(s) from this checkout. A decision not present in this checkout is not evaluated."
Actual
"…Decisions owned by other repositories are not evaluated." — false when the owner's D-007 is copied into the consumer: that decision is owned by another repository, and it was evaluated, because it is present in this checkout.
Diagnosis
The TBD-verdict-scope-honesty scope note (packages/cli/src/commands/verdict.ts:80) describes ownership when the true invariant is presence; the artifact's scope: "repo-local" + decisionsEvaluated remain correct (wording only).
Fix
packages/cli/src/commands/verdict.ts — drop the "owned by other repositories" clause; say "not present in this checkout".
Fixed
Shipped as proposed (verdict.ts:80): the note now reads "A decision not present in this checkout is not evaluated." The explanatory comment was corrected to name the true invariant (presence, not owner). Verified live on the position-keeper repo's clean path; the artifact's scope/decisionsEvaluated were already correct and are unchanged.
'Decisions owned by other repositories are not evaluated.'; 'A decision not present in this checkout is not evaluated.';
Deep dive — none required

No cross-spec contract, no invariant, no hotfix. One-line CLI copy; revert-safe.
