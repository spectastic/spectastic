Design · 028-dependency-ordering

Order by dependency-respecting value

How we will build it.

Status Accepted Spec 028-dependency-ordering Owner Brian Corbin · @briancorbinxyz Branch 028-dependency-ordering Created 30 Jun 2026 Read time

Reuse the @spectastic/schema parse5 reader to build a precedence DAG from the corpus — where an edge is a reciprocated defer-to↔<spec-parent> pair (the relation an existing validate rule already enforces), never a bare defer-to — then run Kahn's topological sort with a RICE-priority ready-queue and subtree-value elevation, emitting an ID list and a roadmap.html rendered by the same string-template pattern as verify.html. Biggest risk: reciprocity edges are sparse across today's 28 specs, so v1's order is mostly a flat RICE ranking until the corpus (or W-2's dense child sets) supplies structure — correct behaviour, but it must be communicated, not mistaken for a bug.

4 · Approach

A small deterministic pipeline in @spectastic/core, exposed as a new deterministic CLI verb spectastic order. expandGlobs('specs/*/spec.html') enumerates the corpus; each file is parsed once with the existing parse5 reader. A graph builder collects nodes (specs) and edges — and an edge is admitted only when a <spec-parent specid="P"> on the child reciprocates a defer-to on P (the relation parent-child-reciprocity already validates), directed parent → child. A new extractRice() reads each spec's <spec-rice> block into a value score (R×I×C÷E); specs without one are carried as unranked (FR-006).

Ordering is Kahn's algorithm with a value-priority ready set: of all nodes whose dependencies are already emitted, take the highest elevated score — a node's own RICE plus the summed value of every spec it transitively unblocks (FR-004); residual ties break by spec ID (NFR-001). If any node never becomes ready, the graph has a cycle: collect the residual and hard-error naming it (FR-005). The core returns one Ordering model; two thin renderers project it — a plain ID list for callers (W-2) and renderRoadmapHtml() for humans, the latter also computing the WSJF cross-check (FR-008).

6 · Decisions

D-001 · An edge is a reciprocated defer-to↔spec-parent pair, directed parent→child

Status
Accepted
Context
The spec's §4 first draft treated any defer-to as an edge; the §3 spike showed that makes the live corpus cyclic (007↔008, 012→006). packages/schema/src/rules/parent-child-reciprocity.ts already defines the reciprocal relation.
Decision
Admit an edge P→C iff C carries <spec-parent specid="P"> and P carries defer-to="C". Bare/sibling defer-to is see-also, excluded.
Consequences
+ Acyclic on the real corpus; + zero new authoring; + reuses a ratified invariant. − Edges are sparse today (few parent/child clusters), so most specs order by value alone — see §8 R-1.

D-002 · Reuse the @spectastic/schema parse5 reader; add extractRice()

Status
Accepted
Context
packages/schema/src/parser.ts:13 + extract.ts:57 already parse spec HTML and pull metadata. cheerio in the lockfile is transitive, not a dep.
Decision
Build graph + RICE on the existing parser; add extractRice(doc) beside extractSpecMetadata and export it. No new parsing dependency.
Consequences
+ One parser, one grammar; + RICE reuse for any future consumer. − Couples R-002 to the schema package's traversal helpers (acceptable; they're the public surface).

D-003 · Kahn's topological sort with a RICE-priority ready-queue + summed-subtree elevation

Status
Accepted
Context
No reusable topo/DAG utility exists in-repo (§3); the per-spec LifecycleGraph in vscode is not cross-corpus. FR-004 elevation chosen as sum of transitively-unblocked value.
Decision
Implement Kahn's algorithm in core/src/ordering/topo.ts: ready set ordered by (elevated score desc, spec ID asc); a never-ready residual is the cycle (FR-005).
Consequences
+ O(V+E), deterministic, cycle detection falls out for free; + elevation is one DFS of descendant value. − Summed value double-counts a spec unblocked via two paths; acceptable for a ranking heuristic (§9).

D-004 · A deterministic `spectastic order` verb emitting an ID list + roadmap.html

Status
Accepted
Context
The feature is pure (no LLM). verify is the template for a deterministic verb that renders a self-contained view (cli/src/commands/verify.ts:16, core/.../verify.ts:261); AI is opt-in via createAIProvider() (ai-factory.ts:15).
Decision
registerOrder(program) in cli/src/index.ts; context {cwd, fs} only (no AI key). Core returns { ids, html }; the CLI prints ids and writes html to roadmap.html.
Consequences
+ Runs in CI with no secret; + machine list for W-2 and human view from one call. − Adds a CLI verb (not a slash-command/8-verb concern — this is a CLI subcommand, see §9).

D-005 · <spec-rice> element: authored attributes, JS-computed gauge, validate rule

Status
Accepted
Context
assets/spec.js renders elements by query-then-mutate (the spec-budget block); P-4 requires JS-off readability.
Decision
<spec-rice reach="" impact="" confidence="" effort=""> — values live in attributes; a spec.js block computes the score, a CSS card styles it. A rice-well-formed per-file rule (numeric, effort>0) registers in schema/src/rules/index.ts.
Consequences
+ Degrades to readable attributes; + validation catches malformed blocks early. − One more element in the vocabulary (justified: a new first-class concept per P-2).

D-006 · WSJF cross-check = CoD ÷ JobSize, with DAG leverage folded into CoD

Status
Accepted
Context
FR-008 (SHOULD) wants WSJF, but the RICE block lacks cost-of-delay inputs. Owner direction: derive it from RICE and the DAG.
Decision
JobSize ← Effort; Cost of Delay ← (Reach×Impact×Confidence) × (1 + normalised unblocked-subtree value from D-003). WSJF = CoD ÷ JobSize. The view flags specs whose WSJF rank differs from their RICE rank.
Consequences
+ WSJF genuinely differs from RICE (it rewards leverage), so divergence is a real signal; + no new authoring. − It's a modelling judgment, not a standard SAFe WSJF (§9); SHOULD-tier, advisory only.

D-007 · TDD on the pure core, Playwright on the view

Status
Accepted
Context
P-7 / CLAUDE.md: interactive HTML must be browser-exercised (presence ≠ containment); the algorithm is pure and lends itself to test-first.
Decision
vitest specs written test-first for graph/sort/elevation/cycle/determinism; a Playwright spec drives a generated roadmap.html and asserts the order, the unranked flags, the divergence marks, and on-screen containment.
Consequences
+ Catches the closure-over-var / behaviourally-broken-but-present class of bug CLAUDE.md warns about. − Playwright adds CI time (already in the project).

9 · Complexity tracking

WSJF is a derived approximation, not standard SAFe WSJF (D-006). We fold DAG leverage into Cost of Delay rather than authoring cost-of-delay components, because per-spec WSJF authoring across 28 specs isn't worth it for a SHOULD-tier cross-check. The divergence flag is advisory; it never changes the RICE-primary order.

One new CLI subcommand, not a ninth slash command. spectastic order is a deterministic CLI verb (principles §Scope explicitly permits complementary CLIs); it does not touch the 8-slash-command surface. W-2, the future workflow, will consume this verb's ID-list output.

Elevation DFS dedupes descendants by ID (R-4). A diamond-shaped graph counts each unblocked spec once per ancestor; this is a deliberate simplification of "critical-path value" adequate for ranking, revisitable if W-2 needs exact path accounting.
