Change proposal · 021-verify-view

Add FR-011 — verified vs suggested Run commands

The view that materialises "done means verified" must not itself present unrun commands as verified.

Status Applied Change ID 2026-07-10-verified-suggested Spec 021-verify-view Source triage 021/T-003; principles P-7 Author Brian Corbin · @briancorbinxyz Created 10 Jul 2026 Targets 1 added (FR-011, must) Read time

A dogfooded verify.html suggested a Gradle command it hadn't checked; run for real it NPE'd (no TTY). The derived view that materialises P-7 was itself presenting an unverified command as done. This change adds FR-011: the Run/Demo block distinguishes verified (executed) from suggested (authored, unrun) commands via a verified flag; a verified:false block renders as "suggested — not yet run." A single additive MUST requirement.

Add FR-011 — verified vs suggested Run commands

Applied

1 · Intent

The verify Run/Demo block already loudly marks empty fields (FR-009), but a present-but-unrun command carried the same authority as an executed one. Triage T-003: a verify.html suggested a command it "admittedly hadn't checked"; run for real it failed. This is the concrete P-7 ("presence is not proof") surfacing in the very tool meant to enforce it. The fix gives the block a verified/suggested axis.

2 · Scope

In scope

  • ADD FR-011 (must): a verified flag on the captured run; verified:false renders a suggested marker + a "not yet run" note.
  • Append a changelog entry citing T-003 + P-7.

Out of scope

  • Forcing verify to run the commands itself — verify is a deterministic renderer, not an executor; the honest signal is the flag, set true only by a real capture.

3 · Approach

One additive MUST delta. CapturedRun gains a verified boolean; renderRunBlock stamps data-status="suggested" + a P-7 note when it is false. Default true preserves the existing /implement-capture semantics (those commands did run); the honest downgrade is an explicit verified:false.

4 · Deltas

What's added: a must-tier requirement distinguishing verified from suggested Run commands.

The Run/Demo block MUST distinguish verified commands (actually executed) from suggested ones (authored but not run). A captured run carries a verified flag; when it is false, the block MUST render as suggested (a data-status="suggested" marker + a visible "not yet run — verify before trusting" note), never presenting unexecuted commands with the authority of verified ones (P-7).

5 · Risk register

Adversarial pass fires (must-tier requirement touched).

Default-verified preserves the loophole — an author can still claim verified without running

Concern. With verified defaulting to true, a session that pipes unrun commands and simply omits the flag renders them as verified — the exact T-003 failure. The mechanism exists but the default doesn't force honesty.

Mitigated (accepted residual). The default matches the real /implement capture path, which does run its commands, so flipping the default to require an explicit verified:true would mark every legitimate capture suggested. FR-011 supplies the honest signal; the discipline (set verified:false when unsure) rides on P-7. If misuse recurs, tightening the default is a scoped follow-on — noted, not built.
