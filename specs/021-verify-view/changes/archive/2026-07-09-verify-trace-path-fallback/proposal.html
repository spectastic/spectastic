Change proposal · 021-verify-view

Path-fallback for subsection-less test tasks

Let the trace see a test task in a hand-authored tasks.html that never wrote a <h3>Tests</h3> subsection — without re-opening the fixture-exclusion hole T-001 closed.

Status Applied Spec 021-verify-view Change 2026-07-09-verify-trace-path-fallback Created 09 Jul 2026 Origin Triage 021/T-002 (trace-join half)

Modify FR-003: the Tests subsection stays the primary signal, but when a story phase declares no such subsection, the aggregation falls back to identifying a test task by file path (.test. / .spec.). This makes 034–036 — hand-authored bundles whose test tasks sit flat in the phase-usN section — trace their proof leg instead of rendering an empty, falsely-green trace. The fallback fires only where there is no subsection, so it cannot re-exclude the fixture-driven tasks T-001 restored.

1 · Scope

One modified requirement — FR-003 — mirrored in the two implementations that share its join key: the generator (packages/core/src/commands/verify.ts) and the drift rule (packages/schema/src/rules/verify-view-stale.ts). No other requirement changes; the completeness gate (FR-008) and presence rule (FR-010) are untouched. The change is additive — every bundle that already traced under the subsection convention traces identically.

2 · Approach

collectTestTasks(section) keeps its DOM-bounded subsection scan as the primary path. Only when a phase-usN section contains no <h3>Tests…</h3> heading does it fall back to scanning that section's <spec-task>s and admitting the ones whose <span class="path"> matches a test-file pattern (/\.(test|spec)\./). The pattern and the two-tier logic are defined once and copied byte-for-byte into both call sites, exactly as the existing subsection scan already is — the cross-impl cascade T-001 named. Because the fallback is gated on the absence of a subsection, a phase that does use the convention (where fixture tasks live) never reaches the path test, so the fixtures/ exclusion T-001 fixed cannot recur.

3 · Deltas

The aggregation MUST trace each SC-NNN to its acceptance scenario and to the test task(s) that verify it. The primary signal for a test task is a <spec-task> whose nearest preceding heading is the story's <h3>Tests (write & fail first)</h3> subsection — identified by that structural position and independent of its file path (so fixture-driven test tasks, whose paths live under fixtures/, are recognised; a task under the story's Implementation subsection is not). When a story phase declares no Tests subsection, the aggregation MUST fall back to identifying test tasks by file path — a <spec-task> whose declared path matches a test-file pattern (.test. / .spec.). The path fallback applies only to phases without a Tests subsection, so it cannot re-exclude the fixture tasks the subsection signal recognises. These traces MUST be materialised as static links at generation time, with no cross-file fetching at render time.

Rationale

Single-file HTML cannot fetch siblings (P-1, P-4); generation is the only moment siblings are read. The subsection is the authoring convention's own signal, and stays primary so the path-only heuristic that once excluded fixture-driven tests (triage 021 · T-001) cannot return. But a hand-authored tasks.html that never wrote the subsection (034–036) had no signal at all, so its trace rendered every proof leg empty and — reading as test-less — dodged the FR-008 completeness gate entirely: a hollow trace that passed validate (triage 021/T-002, trace-join half). The path fallback gives those bundles a signal without weakening the one fixtures rely on.

Reason. 034–036 rendered a fully-empty verification trace yet passed validate, because the whole-bundle completeness exemption (expectedTasks.length === 0) treats a bundle with no recognised test task as genuinely test-less. They are not test-less — their tests sit flat in the phase-usN section. P-7: a green trace must mean verified, not un-seen.

4 · Risk register

Fallback re-opens the T-001 fixture-exclusion hole

Concern. The path heuristic (.test. / .spec.) is exactly what T-001 removed for silently dropping fixture-driven tests whose paths sit under fixtures/.

Response. Mitigated by gating: the path test runs only for a phase with no Tests subsection. Every fixture-driven task lives under a subsection (that is how T-001 restored it), so it is matched by the primary scan and never reaches the fallback. The fallback is a floor for the no-signal case, not a replacement for the subsection.

Generator and rule drift apart

Concern. collectTestTasks is implemented twice — in the generator and the drift rule. A fallback added to one and not the other makes validate disagree with the rendered trace.

Response. The same cross-impl cascade T-001 flagged: both copies are edited in the same change with byte-identical logic and pattern constant, and both are covered — the generator by verify.test.ts, the rule by a positive/negative fixture pair — so a future one-sided edit reddens a test.

Rollout: completeness flips on and reddens Accepted bundles

Concern. Once a bundle gains a recognised test task, the FR-008 completeness gate stops being exempt — so any success criterion that no phase closes now becomes a loud finding, potentially reddening validate across 034–036.

Response. Intended, and handled in the same change: 034–036's tasks.html are authored so every SC is closed by a phase-usN note whose phase holds a path-recognised test, and all five verify.html (032–036) are regenerated with their real Run/Demo block. The landing gate is the full suite + spectastic validate clean — a hollow trace can no longer pass.
