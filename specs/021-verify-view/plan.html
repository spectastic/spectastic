Implementation plan · 021-verify-view

Verify view

How we will build it.

Status Accepted Spec 021-verify-view Owner Brian Corbin · @briancorbinxyz Branch main Created 2026-06-24 Read time

Build spectastic verify <spec-id> as a deterministic engine in @spectastic/core (a thin @spectastic/cli wrapper, the course precedent), reusing the @spectastic/schema parser to aggregate the bundle and the test-task citation as the join key (each T-NNN cites the SC-NNN it closes and lives in a phase-usN phase, which names the user story). /implement's slash command feeds the real commands it ran into the engine; a new cross-file validator rule does live ID-set comparison to catch drift. Biggest risk: the SC→user-story join has no direct link today, so it is derived through the citing task — an SC with no test task can't map, which must render as a loud gap, not a silent one.

4 · Approach

Add a deterministic verifyCommand to @spectastic/core and a thin spectastic verify <spec-id> wrapper to @spectastic/cli, mirroring course. The engine reads specs/<id>/spec.html and tasks.html through the @spectastic/schema parser and builds the trace: for each SC-NNN it finds the test tasks that cite it, reads each task's enclosing phase-usN to identify the user story, and emits links to spec.html#SC-NNN, spec.html#USn (acceptance), and tasks.html#T-NNN (proof). The Run/Demo block is the only authored region: on completion, /implement's slash command passes the commands it actually ran (JSON on stdin); the engine writes them into the typed elements and preserves that block on a links-only regeneration. A new cross-file validator rule re-derives the linkable ID set from the bundle and flags any divergence from what verify.html links — the drift signal, made loud.

6 · Decisions

D-001 · Deterministic engine in core, thin CLI wrapper (the course shape)

Status
Accepted
Context
019 already established the pattern at packages/cli/src/commands/course.ts: the CLI wrapper delegates to a pure @spectastic/core engine; the slash command owns any agentic work. Generation here is fully deterministic (no LLM), so it fits even more cleanly.
Decision
verifyCommand lives in @spectastic/core/commands/verify; @spectastic/cli registers a thin verify subcommand. No new lifecycle verb (FR-001).
Consequences
+ Reuses build/test/wiring seams; the engine is stub-free and unit-testable. + Verb surface unchanged. − One more core command + CLI registration to maintain.

D-002 · The test task is the join key for the trace

Status
Accepted
Context
No markup directly links an SC to its user story. But test tasks cite the SC they close (specs/020/tasks.html, T-013 → FR-010) and sit inside id="phase-usN" phases. The task is the only machine-derivable bridge from SC to both its proof and its story.
Decision
For each SC-NNN: collect the T-NNN citing it; the enclosing phase-usN yields the user story n. Emit links to the SC, to spec.html#USn, and to each citing task (FR-002, FR-003).
Consequences
+ Both trace legs derive from one parse, no hand-authored mapping. − An SC with no citing test task can't be joined to a story — handled as a loud gap (see R-1, FR-009).

D-003 · Add stable id="USn" anchors to user-story headings

Status
Accepted
Context
The acceptance leg should land on the readable scenario prose in spec.html, not a tasks phase — but US headings carry no anchor today (verified against 020). D-002 already derives which US; it just needs a target.
Decision
Add id="US1"… to user-story <h3>s in templates/spec.html and in this spec (021). The generator links the acceptance leg to spec.html#USn; when the anchor is absent (older specs), it falls back to #scenarios.
Consequences
+ Acceptance leg lands on the exact story; strengthens SC-001 discoverability. + Anchors are cheap, stable contracts (P-3). − Touches the spec template — a ripple beyond 021's generator, logged in §9. − Pre-anchor specs degrade to the coarse fallback (acceptable; forward-only).

D-004 · Drift = a cross-file rule doing live ID-set comparison

Status
Accepted
Context
The validator already runs cross-file rules over a parsed doc set (types.ts:73, rules/index.ts), with no-broken-defer-to as a working model. Live comparison keeps the links as the single source of truth — no hidden fingerprint.
Decision
Add a CrossFileRule that re-derives the linkable SC/T ID set from the sibling bundle and compares it to the IDs verify.html links; on mismatch it emits a finding naming the divergence and the fix spectastic verify <id> (FR-008). Registered in rules/index.ts.
Consequences
+ No stored state; the finding can name what drifted. + Reuses the rule registry and parser. − The rule only fires when verify.html is in the validated doc set (cross-file scope) — documented as a known boundary.

D-005 · Run block captured by the slash command, merged by the engine

Status
Accepted
Context
SC-003 wants the Run/Tests commands to be the ones that actually ran. /implement already runs a Verify step and knows its commands; implement.ts:43 is the deterministic last-tick seam. The course hybrid (agent supplies data via stdin, engine is deterministic) fits.
Decision
At completion the /implement slash command passes its real commands to spectastic verify (JSON on stdin); the engine writes them into the typed Run/Demo elements and, on any later links-only regeneration, preserves that captured block (FR-005, FR-006).
Consequences
+ Run block is grounded evidence, not prose; engine stays deterministic and testable. − The capture contract (what JSON shape) is a new seam between the slash command and the engine; specified in tasks.

D-006 · verify.html is git-tracked (unlike course.html)

Status
Accepted
Context
019's course.html is git-ignored (ephemeral teaching). verify.html is part of the spec bundle, reviewed in the PR as the "validation" section — it must be committed.
Decision
verify.html is a tracked artifact under specs/<id>/. Idempotent generation (NFR-002) makes a CI rebuild-and-diff meaningful.
Consequences
+ Reviewable, diffable, present at rest. − A regeneration that isn't committed shows as a dirty tree — the intended drift signal.

8 · Risks & mitigations

RiskLikelihoodImpactMitigation
R-1 · An SC with no citing test task can't be joined to a user story.MLRender the acceptance/test legs as a loud "no test task cites this SC" gap (FR-009), never a silent blank; a test asserts the gap rendering.
R-2 · id="USn" ripples to the spec template; pre-anchor specs lack it.MLGenerator falls back to #scenarios when no US anchor (D-003); forward-only, consistent with the spec's scope.
R-3 · Non-idempotent output (timestamps, unstable ordering) breaks the CI diff signal.MMNo timestamps in derived regions; order trace rows by ID; a vitest asserts byte-identical re-generation (NFR-002).
R-4 · Drift rule false-positives when an SC is legitimately untested-yet.LMRule compares the linkable ID set the view claims vs the bundle's; an intentional gap renders as a known gap (R-1 path), not a drift finding.

9 · Complexity tracking

One deviation introduces complexity beyond 021's generator proper.

Editing templates/spec.html (D-003). Adding id="USn" anchors to the shared spec template is a change outside this feature's own files, justified because the acceptance-leg link (SC-001 discoverability) has no good target otherwise, and the anchors are inert, stable contracts (P-3) that cost future specs nothing. The fallback to #scenarios means the change is additive, not breaking, for specs authored before it.

The capture contract (D-005). A small JSON shape passed from the /implement slash command to spectastic verify is new surface between an agent step and a deterministic engine. It is kept minimal (run / toggle / tests / demo strings) and specified in tasks so the two sides can't drift.
