Verify view

Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 021-verify-view Design design Branch main Created 24 Jun 2026 Read time

22 tasks across five phases. Setup → Foundational → User stories (US1·US2·US3) → Polish. Tasks marked [P] can run in parallel — different files, no dependency. Tests for a story MUST be written and failing before its implementation tasks start. The shared engine and parser land in Foundational; US1 adds the Run/Demo block, US2 the SC→proof trace, US3 the drift rule and standalone regeneration.

1 · Execution strategy

Recommended. Setup → Foundational → US1 → US2 → US3 → Polish. Each story closes its conformance before the next opens. US1 (Run/Demo block) is a viable MVP on its own — a generated verify.html that tells a human how to run and see the feature, even before the trace aggregation lands.

Implement US1 end-to-end and stop there if needed: the Run/Demo block alone fixes the dogfooding gap. Add US2's trace and US3's drift rule once US1 is verified in a browser.

After Foundational, US1 (Run block + /implement capture), US2 (trace aggregation), and US3 (validator rule) touch mostly distinct seams. Coordinate at the shared engine file (verify.ts) and the capture JSON contract via the spec, not Slack.
