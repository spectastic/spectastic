Implementation plan · 043-init-project-config

Init project config — ignore files

How we will build it.

Status Draft Spec 043-init-project-config Owner Brian Corbin · @briancorbinxyz Branch main Created 10 Jul 2026 Read time

A shared deterministic core applyGitignore(cwd, {stack?}) composes spectastic's entries into a sentinel-delimited block and set-union-merges it into any existing .gitignore, never touching lines outside the block. init calls it base-only (no stack knowledge); a new spectastic gitignore command adds the detected-stack entries — the deterministic home for the plan-phase append (P-8), the same shape as 042's enforce. Biggest risk: the base must ignore spectastic's ephemera without ignoring the tracked profile marker, and it overlaps 019's nested .spectastic/.gitignore — both reconciled in §6/§8.

4 · Approach

One deterministic core function merges spectastic's entries into a sentinel block; two callers drive it. init writes the base block after scaffolding (no stack yet); a new spectastic gitignore command re-applies base + detected-stack entries, and is what the /spectastic.plan verb invokes so the stack append is kernel-owned, not plan-markdown prose (P-8). Merge is set-union inside the block; every line outside is preserved verbatim, making brownfield safe and re-runs idempotent.

6 · Decisions

D-001 · One merge core, two callers

Status
Accepted
Context
Base (init) and stack (plan) both write the same file; drift-prone if duplicated.
Decision
applyGitignore(cwd, { stack?: boolean }) in core composes entries and merges the sentinel block. init calls it base-only; spectastic gitignore calls it with stack:true.
Consequences
+ One place owns the merge + idempotency. − A new core module + CLI command.

D-002 · Sentinel block, set-union merge

Status
Accepted
Context
FR-002/FR-004/NFR-002: bounded managed region, never clobber, idempotent.
Decision
Markers # >>> spectastic (managed) >>> … # <<< spectastic <<<. Merge = union of (existing block entries ∪ new); everything outside preserved byte-for-byte; absent block appended at EOF. A second run is a no-op.
Consequences
+ Brownfield-safe + idempotent by construction. − Must parse/replace exactly one block region (regex-bounded, tested).

D-003 · Base ignores ephemera, not the marker

Status
Accepted
Context
FR-003: .spectastic/ is mixed — courses ephemeral, the profile marker tracked.
Decision
Base entries are specific: .spectastic/courses/ and exploration ephemera — not .spectastic/ wholesale, so .spectastic/profile.json stays trackable.
Consequences
+ The 041 marker survives. − Base list must be maintained as spectastic adds ephemeral outputs (data, in D-001's entries module).

D-004 · Stack entries via 042 detection + a data map

Status
Accepted
Context
FR-005/FR-006: append the stack's build ignores from the detected ecosystem, as data.
Decision
Add detectEcosystems(cwd) (ecosystems whose 042 signals match) + an ecosystem → ignore entries map (Node → node_modules/,dist/; Python → __pycache__/,.venv/; Rust → target/; …). gitignore --stack unions them into the block.
Consequences
+ Extending a stack is a data edit. − Detection is a heuristic; an unrecognised stack simply adds nothing (safe).

D-005 · spectastic gitignore is the deterministic plan-phase home

Status
Accepted
Context
FR-005 says the plan verb appends stack ignores; P-8 says the guarantee can't be plan prose.
Decision
Ship spectastic gitignore [--stack]; the plan command markdown invokes it. The write is deterministic (kernel/CLI); the markdown is only the nudge to run it — same split as 042's enforce.
Consequences
+ Deterministic, CI-testable, key-free. − One more CLI verb (kept tiny).

D-006 · --no-gitignore opt-out

Status
Accepted
Context
FR-007: some users manage ignores themselves.
Decision
init --no-gitignore skips the base write; the command path is unaffected.
Consequences
+ Escape hatch. − One option flag.

8 · Risks & mitigations

RiskLIMitigation

Not a blocker for US1.

9 · Complexity tracking

The only non-trivial piece is the sentinel-block merge; it's justified as the mechanism that makes brownfield-safe + idempotent true by construction rather than by careful appending. Kept in one pure function.
