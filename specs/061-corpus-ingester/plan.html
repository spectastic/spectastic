Implementation plan · 061-corpus-ingester

Corpus ingester

How we will build it.

Status Accepted Spec 061-corpus-ingester Owner Brian Corbin · @briancorbinxyz Branch 061-corpus-ingester Created 26 Jul 2026 Read time

Build a new fat-core knowledge/ingest.ts that turns any acquisition into a registered KB-NNNN row, reusing 056's conversion internals and 051's registry parsers wholesale; the CLI grows corpus import / interview / source subcommands that delegate to it. The install fetch sits behind a PackFetcher provider seam (real: shell git/claude; stub: a fixture dir) so the whole flow is CI-testable without a network. Biggest risk: the real fetch mechanism (which marketplace verb lands a pack where we can read it) is a spike — mitigated by the --from <path> escape hatch, which keeps the install door shippable on a local checkout while the auto-fetch is proven.

4 · Approach

One deterministic core module, packages/core/src/knowledge/ingest.ts, owns the registration backbone: a repo-wide id allocator that reads loadRegistry for the current max, a mergeRegistryRows that folds new rows into the root knowledge/index.md non-destructively (mirroring adapt.ts's mergeIndexRows), a supersede step that moves a prior document under references/superseded/ and bumps the row's edition, and an orphan pass that flags a vanished (marketplace, plugin, slug) in place. Conversion is not reinvented — ingest calls adapt.ts's deriveProvenance/contentHashOf and reshapes the output to a SKILL.md slug map plus a registry row (the two-layer model), while corpus adapt stays for raw-KB conversion.

The one external effect — fetching a marketplace pack — sits behind a PackFetcher provider in core/providers, selected by a createPackFetcher factory exactly as createAIProvider selects the AI provider: the real impl shells to git/claude, the stub returns a fixture directory, and SPECTASTIC_PACK_STUB (or a --from path) picks the stub. The CLI's corpus.ts grows three thin subcommands that resolve the coordinate, call the fetcher, and delegate to ingest. The install door (US1/US2) is built to depth; the interview and source doors register through the same backbone entry and carry their own origin/status shape, but their acquisition mechanics defer to their sibling TBDs.

6 · Decisions

D-001 · Fat-core ingest module, thin corpus subcommands

Status
Accepted
Context
The standing fat-core/thin-CLI convention; corpus.ts:15 is already a thin registrar delegating to core.
Decision
All deterministic logic in packages/core/src/knowledge/ingest.ts; corpus.ts adds import/interview/source subcommands that parse args, call the fetcher, and delegate.
Consequences
+ Backbone unit-testable without a binary. + One reuse site for adapt + registry parsers. − A new core module + tsup/exports entry (cheap).

D-002 · Install fetch behind a PackFetcher provider + factory

Status
Accepted
Context
NFR-002 requires an injectable fetch seam; packages/cli/src/ai-factory.ts is the proven precedent (injectable detector, factory, env-selected stub).
Decision
A PackFetcher interface in core/providers (real: execFileSync git/claude; stub: a fixture dir), selected by createPackFetcher with a SPECTASTIC_PACK_STUB env override — mirroring createAIProvider verbatim.
Consequences
+ Whole flow CI-testable with no network (SC-004). + The one subprocess boundary is audited in one place (P-12). − One more provider/factory pair to maintain.

D-003 · Reuse adapt's conversion (sync node:fs), reshape the output

Status
Accepted
Context
adapt.ts already converts with the never-fabricate rule + content hash, using sync node:fs; the ingester is its closest sibling.
Decision
Call deriveProvenance/contentHashOf/title-desc from adapt.ts; stay on sync node:fs (not the async FileSystem seam) so the two files share one idiom. Reshape output to a SKILL.md slug map + a registry row; corpus adapt coexists for raw-KB conversion.
Consequences
+ No duplicated conversion, one never-fabricate path. + Tests use a temp dir, adapt's existing pattern. − Two fs idioms across the codebase (adapt/ingest sync, apply kernel async) — accepted; they serve different callers.

D-004 · Repo-wide opaque KB-NNNN allocation, kernel sole-writer

Status
Accepted
Context
adapt.ts's allocateIds is per-pack; FR-001/FR-003 need repo-wide, monotonic, never-reused, sole-writer assignment over loadRegistry.
Decision
A repo-wide allocateRegistryIds reads the current max from loadRegistry and continues from it; mergeRegistryRows folds non-destructively (hand-edited cells win). The ingester is the only writer of the id column; a hand-edited collision is caught by an existing/extended validate scan.
Consequences
+ Deterministic, serialised, single source of truth (P-8). + Reuses the mergeIndexRows shape. − Assignment must read the whole registry each run (trivial at corpus scale).

D-005 · Supersede-by-append; orphan = a registry status column + a warning scan

Status
Accepted
Context
loadSuperseded + 052 FR-003 settle the on-disk convention; FR-007 requires a visible, never-dropped orphan.
Decision
Re-import moves the prior document to references/superseded/<slug>@<edition>.md and bumps the row edition. An orphan gets a new 8th registry status column set to orphaned plus a warning-level validate finding — never a delete (the enforce-waiver posture).
Consequences
+ A pinned citation to a prior edition still resolves; a dropped reference is loud, not silent. − The registry widens 7→8 columns; parseRegistry/renderRegistryTable + the 051 template gain a column.

D-006 · Extend MarketplaceManifest to read (name, version, renames)

Status
Accepted
Context
pack-agnostic.ts:117-141 reads only plugins[].source; the re-import anchor (FR-004/FR-006) needs the marketplace name, plugin version, and renames map.
Decision
Widen the manifest reader (a shared helper both pack-agnostic and ingest use) to surface name, each plugin's version, and the renames map, keeping the malformed-manifest-is-no-crash stance.
Consequences
+ The re-import anchor and plugin-rename migration key off the platform's own coordinate, not a bespoke one. − A second consumer of the manifest reader — keep it a shared function, not a fork.

D-007 · Backbone + install to depth; interview/source seam-only

Status
Accepted
Context
Scope judgment (no external fact): the spec sets install P1, interview P2, source P3, each door's mechanics deferred to its sibling TBD.
Decision
Build the backbone and the install door (US1/US2) to implementation depth. The interview/source subcommands register through the same backbone entry with their origin/status shape, but their acquisition mechanics (running the interview, the allowlist-bounded fetch) are named as later tasks / deferred to TBD-corpus-interview, TBD-corpus-sourcing, TBD-corpus-authority-allowlist.
Consequences
+ Ships the must-have without pulling the allowlist + interview harness in now. − Two doors are stubs until their siblings land — recorded, not hidden.

D-008 · Red-first vitest + a stub-fetcher CLI integration test

Status
Accepted
Context
Test-style preference (no external fact); the house norm and feedback: AI in CI uses stubs.
Decision
Write failing unit tests first for each backbone unit (allocate, merge, supersede move, orphan-flag), then a CLI integration test that drives corpus import end-to-end through the stub fetcher and asserts the written registry. CI runs the stub only.
Consequences
+ Behaviour pinned before code; no network in CI. − The real fetch path is exercised only in the local smoke tier (accepted, matching the AI-provider split).

9 · Complexity tracking

Anywhere this plan introduces complexity not strictly required by the spec, justify it here.

A second filesystem idiom (sync node:fs in adapt/ingest vs the async FileSystem seam in the apply kernel) is accepted deliberately (D-003): the ingester extends adapt and shares its conversion, so one idiom across those two files beats seam-consistency with a kernel it never calls.

The interview and source subcommands ship as registration seams with deferred mechanics (D-007). This is a deliberate slice boundary, not an unfinished feature — each names its sibling TBD, and the shared backbone is what this spec guarantees.
