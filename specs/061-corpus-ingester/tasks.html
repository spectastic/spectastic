Corpus ingester

Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 061-corpus-ingester Design design Branch 061-corpus-ingester Created 26 Jul 2026 Read time

41 tasks across six phases. Setup → Foundational → User stories (US1 install · US2 supersede · US3 interview · US4 source) → Polish. Tasks marked [P] can run in parallel — different files, no dependency. Tests for a story MUST be written and failing before its implementation tasks start. The backbone (allocate/merge/fetcher-seam) is Foundational — every door registers through it, so it ships before any story opens.

1 · Execution strategy

Setup + Foundational, then US1 end-to-end (install → a citation resolves green). Ship. US2's supersede path is the very next iteration — the same registry a fresh install just proved needs to survive a re-import before it's trustworthy. US3/US4 (seam-only) follow once US1/US2 are verified.

Setup → Foundational → US1 → US2 → US3 → US4 → Polish. Each story closes its conformance before the next opens. Recommended here: US1/US2 share one file (ingest.ts) and one mental model (the backbone in action), so drifting them apart risks two half-built re-import paths.

One team on Foundational (backbone + fetcher seam). Once it lands, US1 and the doc-shape half of US3/US4 can proceed in parallel — they share the backbone contract, not each other's files. US2 should follow US1 sequentially (same file, same registry invariants); splitting it out risks two conflicting edits to ingest.ts's supersede logic.

Shared infrastructure no door can ship without — the registration backbone every one of the four stories registers through (plan D-004/D-005). Sequential where order matters (the fetcher stub needs its interface; the allocator needs the widened registry shape).

Red test — repo-wide id allocation and non-destructive merge — allocateRegistryIds is monotonic, never reuses a retired id, and continues from the real registry max (not a per-pack one); mergeRegistryRows preserves a hand-edited cell across a re-run; the same inputs produce byte-identical output on repeated calls (NFR-001). packages/core/test/knowledge.ingest.test.ts

Define the PackFetcher interface — one method resolving a <plugin>@<marketplace> coordinate to a local directory path. No concrete implementation yet — the real fetch mechanism is confirmed in US1's spike (T-100). packages/core/src/providers/pack-fetcher.ts

5 · Phase 3b — US2 · Re-import a newer edition without dangling a citation

Tests (write & fail first)

Red test — supersede-by-append — re-importing a reference at a newer edition keeps its KB-NNNN, bumps the registry row's edition, and retains the prior document under references/superseded/ so an edition-pinned citation to it still resolves (FR-005). packages/core/test/knowledge.ingest.test.ts
Red test — orphan-flagging — a reference present in a prior import but absent from a re-import is marked status=orphaned in its row and is never deleted (FR-007). packages/core/test/knowledge.ingest.test.ts
Red test — plugin-rename migration — a re-import whose marketplace renames map points a former plugin name at its current one resolves to the same KB-NNNN row rather than minting a duplicate (FR-006). packages/core/test/knowledge.ingest.test.ts
Red test — the orphan validate finding — extending corpusRegistryFindings with exactly one warning per orphaned row (FR-007). packages/core/test/knowledge.validate.test.ts
Red CLI test — the orphan warning surfaces end-to-end — spectastic validate reports the orphan finding on a project whose registry carries one, and a hand-edited duplicate KB-NNNN is caught as an error (FR-003, FR-007). packages/cli/test/validate-corpus-orphan.test.ts
Red test — re-import idempotency — re-running corpus import with no underlying change writes nothing and rewrites no hand-corrected field back to TODO (NFR-003). packages/cli/test/corpus-import.test.ts

Implementation

Implement supersede-by-append — on a matching (marketplace, plugin, slug) at a newer edition, move the prior document to references/superseded/<slug>@<edition>.md and bump the registry row's edition, keeping the same KB-NNNN. packages/core/src/knowledge/ingest.ts
Implement orphan detection — a previously-registered (marketplace, plugin, slug) absent from a re-import's fetched set is marked status=orphaned in place. packages/core/src/knowledge/ingest.ts
Implement plugin-rename migration — resolves a renamed plugin via T-022's renames read before the anchor match, so the same reference keeps the same KB-NNNN across a rename. packages/core/src/knowledge/ingest.ts
Extend corpusRegistryFindings for the orphan warning — one warning-severity finding per orphaned row, alongside the existing duplicate-id and missing-field checks. packages/core/src/knowledge/validate.ts
Wire the registry scan into spectastic validate — a scanCorpusRegistry wrapper (matching scanCorpusWellFormed's shape) loads the root registry and folds corpusRegistryFindings in — the one wiring step that surfaces both the sole-writer duplicate-id check (FR-003) and the new orphan warning (FR-007) at the CLI boundary. packages/cli/src/commands/validate.ts

Closes FR-003 (validate-surfacing half), FR-005, FR-006, FR-007, NFR-001, NFR-003, SC-002, SC-003.
