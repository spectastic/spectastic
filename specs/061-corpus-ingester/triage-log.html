FR-008 remote-source ceiling lifted — RealPackFetcher now git-clones an object-sourced plugin

Implementation code

Not a defect — a deliberately-deferred ceiling now built. FR-008 ("the import door MUST drive the install") shipped cache-read-only: an installed or string-sourced plugin resolved, but an object-sourced (remote) plugin threw and named /plugin install as the ceiling (plan D-002 / the T-100 spike, to avoid re-implementing git). That ceiling is now lifted — a remote plugin is git-cloned. Regeneration passes: the change is entirely in code behind the existing seam; the spec/plan are unchanged and still correct.

Expected
An object-sourced plugin in an added marketplace resolves without a manual /plugin install — FR-008's "drive the install" met for the remote case, not just the cached one.
Actual
Before: RealPackFetcher threw PackFetcherError on an object source, naming /plugin install / --from as the only paths.
Diagnosis
A recorded scope ceiling (plan D-002), not a bug: the object-source clone was deferred at 061 to avoid re-implementing a git client. Building it fully satisfies the must-tier FR-008.
Fix
packages/core/src/providers/pack-fetcher.ts — a new GitRunner seam (real impl shells a hardened git; a fake is injected in tests so CI never clones) + parseGitSource for the url/git-subdir/github shapes. Clones shallow, no submodules, hooks disabled, pinned to the manifest sha when present; cached under ~/.claude/plugins/.spectastic-cache/<coordinate>@<rev> and reused. 14 fetcher tests green.
Deep dive — security posture + the residual ceiling

Trust boundary. The clone URL comes from a marketplace the user added via /plugin marketplace add — a trust decision already made — so import clones by default (no extra --allow gate, unlike the arbitrary-web-fetch source door). Integrity comes from pinning to the manifest's immutable sha when present (the supply-chain-integrity-considerations lever), plus a hardened clone that runs no remote code (no hooks, no submodule recursion).

Residual ceiling (recorded, not hidden). An unknown marketplace still errors — its manifest, and thus any URL, isn't on disk until /plugin marketplace add. Cloning a whole marketplace from its known_marketplaces.json source is a further step, not built here. A ref/HEAD (unpinned) source is cached mutably by name; only a sha is immutable-by-key.
