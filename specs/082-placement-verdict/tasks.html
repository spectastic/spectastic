Placement verdict

Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 082-placement-verdict Design design Branch main Created 02 Aug 2026 Read time

19 tasks across five phases. A task is [P] only where no sibling in its phase touches the same file. Tests precede implementation. The headline test is the one the whole slice exists for: a requirement in consumer vocabulary, with a structural edge to the producer, must rank the producer first.

1 · Execution strategy

The fit. Evidence vocabulary → the pure ranking → the two refusals → evidence gathering from 079 and 081 → the optional refinement last, since it is the only part that is not the default path and nothing else depends on it.

US1 alone — a ranked case with named evidence — is the shippable core. The refusals sharpen it, but a ranked shortlist a human reads is already useful.

Not a fit for one author; the ranking is a single small algebra every story touches.

2 · Phase 1 — Setup

Add the placement modules to the build — tsup entries and export subpaths. packages/core/tsup.config.ts

3 · Phase 2 — Foundational

The vocabulary consumers bind to, and the weights that must never look measured.

Define the evidence and verdict types — four named classes, a candidate, and the three terminal outcomes. packages/core/src/units/placement.ts
Define the weights — uncalibrated defaults stated as such in the module itself, overridable from config (NFR-001). packages/core/src/units/placement-weights.ts

4 · Phase 3a — US1 · Get a ranked case, not an assertion

Tests (write & fail first)

Test the producer/consumer case — the headline: a requirement in consumer vocabulary with a structural edge to the producer ranks the producer first (FR-003, SC-001). packages/core/test/units.placement.test.ts
Test that every candidate carries its evidence — typed at the finding level, each with a class and a source (FR-002). packages/core/test/units.placement.test.ts
Test that conflicting evidence is surfaced — structural favouring one candidate and domain another is reported, never silently resolved (FR-008). packages/core/test/units.placement.test.ts
Test determinism — repeated ranking on unchanged input is identical, independent of iteration order (NFR-003, SC-005). packages/core/test/units.placement.test.ts

Implementation

Implement the pure ranking — weighted accumulation over typed evidence, sorted deterministically. packages/core/src/units/placement.ts
Implement the confidence bands — three, with an automatic hedge on low or on a tie at the top (FR-004). packages/core/src/units/placement.ts

Closes FR-001, FR-002, FR-003, FR-004, FR-008, SC-001 and SC-005.

5 · Phase 3b — US2 · Be told when the answer is not known

Tests (write & fail first)

Test the abstention — no candidate reaching the floor returns the refusal with reasons and names at most 0 units (FR-005, SC-002). packages/core/test/units.placement.test.ts
Test the domain-only cap — resemblance alone never reaches the unhedged band, which is the configuration that produces the opening failure (FR-009, SC-004). packages/core/test/units.placement.test.ts

Implementation

Implement both refusals as terminal states — carrying reasons, never reached as a fallback from a failure. packages/core/src/units/placement.ts
Enforce propose-never-mint — the new-unit outcome creates no repository, package or directory, and no placement is auto-applied (FR-006, FR-007, SC-003). packages/core/src/units/placement.ts

Closes FR-005, FR-006, FR-007, FR-009, SC-002, SC-003 and SC-004.

6 · Phase 3c — US3 · Gather the evidence from what already exists

Tests (write & fail first)

Test evidence gathering — structural from 079's edges, declared from 081's map, domain from lexical overlap, prior-art from existing specs. packages/core/test/units.placement.test.ts
Test that lexical overlap discriminates — two candidates differing only in topic score differently, so ranking is signal rather than noise. packages/core/test/units.placement.test.ts

Implementation

Implement evidence gathering behind the port — consuming 079 and 081 rather than re-deriving either. packages/core/src/units/adapters/placement-evidence.ts
Implement lexical scoring — normalised for length, common tokens dropped, no index and no embeddings (D-002). packages/core/src/units/adapters/placement-evidence.ts

7 · Phase 4 — Polish

Record the verdict's mode — deterministic or refined, so a reader can tell a reproducible verdict from one they cannot re-run (D-001). packages/core/src/units/placement.ts
Assert the read path writes nothing — 0 files outside the report, 0 network calls (NFR-002). packages/core/test/units.placement.test.ts

8 · Dependencies

  • T-010 blocks everything — the evidence vocabulary is what consumers bind to, and class names are expensive to change later.
  • T-110 blocks T-111, T-210 and T-211 — bands and refusals extend the ranking rather than replacing it.
  • T-310 depends on 079 and 081, both Accepted and shipped, so nothing here waits on a sibling slice.
  • A task is [P] only where no sibling in its phase touches the same file. Only T-011 qualifies; every test lands in one spec file.
