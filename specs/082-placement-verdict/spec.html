Placement verdict

A ranked case a person can check, and two answers that are allowed to be "no".

Status Accepted Spec ID 082-placement-verdict Owner Brian Corbin · @briancorbinxyz Reviewers — Created 02 Aug 2026 Principlesv1.9.0 Smallest demoableGiven a requirement and a single checkout, a ranked shortlist of candidate units with each candidate's evidence named — or an explicit refusal. Read time

The forward-look this closes proposed routing a requirement to the estate it most resembles. That mechanism produces the failure it exists to prevent: a requirement written in a consumer's vocabulary resembles the consumer most, which is how a fix belonging in a library is built in the application calling it. So resemblance stays — it is the only signal available for a project that declares nothing — but as one weighted evidence class among four, able to be outranked by a structural dependency pointing the other way. The verdict shape is inherited rather than invented: three-band confidence with an automatic hedge, from triage's layer classifier, and a first-class negative outcome carrying reasons, from the slicer. Two refusals are terminal states, not fallbacks — propose a new unit, never create one, and no confident owner, which exists so the engine is never forced to name a plausible-but-wrong one.

1 · Context

An orchestrator given a fresh requirement has to decide where the work belongs. The placement survey established that the obvious mechanism — rank by similarity to each estate — is not merely insufficient but actively wrong, because the requirement genuinely does resemble the unit whose vocabulary it borrowed. Improving the ranker makes that answer more confident, not more correct.

What defeats it is structural evidence, which 079 and 081 now supply. This slice is what consumes them: it gathers evidence of several named kinds per candidate, ranks, and returns a case rather than a decision. The distinction is not decoration. P-14 records that this exact judgment resists mechanisation, so an engine that decided would be overclaiming; one that argues, with its evidence visible, is worth having.

2 · User scenarios & testing

Each story MUST be independently testable: if you implemented only US1, you would still have a viable MVP.

US1 · Get a ranked case, not an assertion P1

As an orchestrator, I want candidate units ranked with each one's evidence named so that a human can check the reasoning rather than trust a number.

Acceptance: a requirement describing a defect in consumer vocabulary, where a structural edge shows the consumer depends on a library for that surface, ranks the library first and shows both pieces of evidence — including the resemblance pointing the other way.

US2 · Be told when the answer is not known P1

As a maintainer, I want "no confident owner" to be an available answer so that the engine never names a plausible-but-wrong unit for want of an alternative.

Acceptance: an estate where no candidate accumulates sufficient evidence returns the refusal with its reasons, and names at most zero units as the placement.

US3 · Hear that nothing fits, without anything being created P2

As a maintainer, I want a proposal that a new unit may be needed so that work is not pushed into whichever existing unit fits least badly — while nothing is created on my behalf.

Acceptance: the new-unit outcome is returned as a proposal with reasons; no repository, package or directory is created, and no file outside the report is written.

Edge cases

  • Exactly one candidate unit exists — still ranked and still subject to the confidence bands, never placed by default.
  • Two candidates tie on total evidence: reported as a tie and hedged, never broken arbitrarily.
  • A project with no edges and no boundary map, so only resemblance is available — permitted, and capped below the confidence needed to place without a hedge.
  • Evidence that conflicts: structural pointing one way and resemblance the other. The tension is surfaced, not resolved silently.

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional

A placement result MUST be a ranked shortlist of candidate units, never a single answer, and each candidate MUST carry its supporting evidence.

Rationale

The information-retrieval literature this resembles has always produced a human-inspected shortlist rather than a decision, and P-14 says why that is right here specifically. A ranked case can be checked; a bare answer can only be believed.

Evidence MUST be typed at the finding level, using the named classes structural, declared, domain and prior-art, rather than aggregated into an untyped score.

Rationale

Clones the shape change-risk already uses, where each finding carries its own category and weight. A reader shown "why" can disagree with a specific piece of evidence; one shown only "how confident" can only disagree with the tool.

Structural evidence MUST be capable of outranking domain resemblance for the same candidate set.

Rationale

This is the survey's central finding made mechanical. A requirement resembles the unit whose vocabulary it borrowed, so a ranking that resemblance can always win reproduces the producer/consumer failure by construction.

Confidence MUST be reported in three bands, and a low band or an invalid candidate MUST produce a hedged result requiring human resolution.

Rationale

Inherits triage's classifier shape, which already routes a "which layer owns this" question with three bands, an automatic hedge, and a consolidated human gate. Reusing a proven escalation is better than a second confidence vocabulary in the same estate.

No confident owner MUST be a first-class terminal outcome carrying reasons — never an error, and never a fallback reached only when something else failed.

Rationale

Forced choice over a ranked list always returns something, and what it returns is the unit whose vocabulary the requirement happened to borrow. Making abstention a real answer is what stops the opening failure re-entering through the back door. The slicer's own negative verdict is the precedent.

Where no existing unit fits, the engine MAY propose that a new unit is needed, and MUST NOT create a repository, package or directory.

Rationale

Propose-never-mint matches the slicer, which drafts provisional ids and creates nothing. Standing up a unit is an organisational commitment about team boundaries; suppressing the conclusion would push work into whichever unit fits least badly, but acting on it would decide something the tool has no standing to decide.

A placement MUST NOT be applied automatically at any confidence: the result is always returned for confirmation.

Conflicting evidence — structural favouring one candidate and domain another — SHOULD be surfaced as such rather than silently resolved by the ranking.

Rationale

The conflict is the most informative thing in the output. A reader told the two signals disagree, and which way each points, is better served than one handed a winner.

Where only domain evidence is available, the result SHOULD NOT reach the confidence band that places without a hedge.

Rationale

Resemblance alone is precisely the configuration that produces the opening failure, so it must never be sufficient on its own.

Non-functional

Evidence weights MUST be declared uncalibrated defaults from the outset and MUST be configurable: at most 0 weights may be fixed beyond override, and at most 0 may be presented as measured rather than chosen.

Rationale

Change-risk states plainly that its constants are a v1 default rather than measured truth. Anything else invites a tuned-looking number being read as evidence in itself.

Producing a verdict MUST write at most 0 files outside its own report and MUST make at most 0 network calls.

The same inputs SHOULD yield the same ranking: at most 0 verdicts may depend on clock, filesystem ordering, or iteration order.

Rationale

A suggestion a reviewer cannot reproduce is a suggestion they cannot argue with, and determinism is the estate's standing expectation of anything that reads artifacts.

Out of scope (deferred to other slices)

  • Ranking across more than one checkout. Single-checkout first; the estate-wide form needs a federated read surface that lives outside this repository.
  • The orchestrator that acts on a verdict — driving a spec into the chosen unit. This slice returns a result and stops.
  • Routing to a team rather than a unit. The estate has no ownership field, so the question cannot yet be asked.
  • Tuning the weights against real outcomes, which needs a corpus of confirmed placements that does not exist.

4 · Data model

Three entities: what is being placed, what supports a candidate, and what comes back.

Entities

Candidate
A unit that might own the work, together with the evidence gathered for it. A candidate is always a unit that already exists; the proposal of a new one is a verdict, not a candidate.
Evidence
One reason a candidate might be right, carrying its class (structural, declared, domain, prior-art), its weight, and its source. Evidence is always attributable — a piece with no source is not evidence.
Verdict
The terminal result: a ranked placement, a proposal that a new unit is needed, or no confident owner. Every form carries reasons; the two refusals are as fully-formed as the placement.

Confidence is a property of the verdict, not of any single piece of evidence, and it is derived rather than authored. That keeps one thing true that matters: a verdict cannot be made more confident by adding evidence of a class that was never able to place on its own (FR-009). Accumulating resemblance does not become structure.

5 · Success criteria

Technology-agnostic, measurable outcomes.

For the producer/consumer case — a requirement in consumer vocabulary, with a structural dependency on the producer — the producer ranks first, and at most 0 such cases place the consumer without surfacing the conflict.

An estate in which no candidate accumulates sufficient evidence returns the refusal, naming at most 0 units as the placement.

Across the full fixture set, verdicts create at most 0 repositories, packages or directories, and at most 0 placements are applied without confirmation.

A project with only domain evidence available reaches the unhedged confidence band at most 0 times.

Re-running placement on unchanged inputs produces at most 0 differing rankings.

6 · Assumptions

A human reviews every verdict. Nothing here is safe to automate, and FR-007 makes that structural rather than advisory.

Candidate units are enumerable from the checkout. Where the estate is larger than the checkout, the verdict is honest about ranking only what it could see rather than silently ranking a subset.

The four evidence classes are sufficient for v1. Adding a class later is additive; consumers bind to class names, so the four must be roughly right now.

7 · Open questions

None outstanding. The evidence vocabulary was anchored in the interview; the three-band confidence, the hedge, and both refusals were settled by the placement survey's decisions and inherit shapes already shipped in triage, the slicer, and change-risk.
