Change proposal · 019-explain-course

The correct answer must not always be first

A quiz whose answer is always in position one is guessable without reading the question.

Status Proposed Change ID 2026-08-12-answer-position Spec 019-explain-course Author Brian Corbin · @briancorbinxyz Created 12 Aug 2026 Targets 1 requirement(s) Read time

Every generated quiz places the correct option first. FR-004 already forbids an item that can be answered with the source hidden — but it checks each item alone, and the tell here is not in any item. It is in the sequence: a learner who notices the pattern once can score full marks without reading another question, which defeats the gate rather than evading it. The fix is a deterministic seeded shuffle, so output stays reproducible.

The correct answer must not always be first

Proposed

1 · Intent

FR-004 requires each quiz item to be unguessable from its own content, and the guessability check poses one item at a time. By construction it cannot see a property that only exists across items — and the correct option is always at index zero.

The requirement is not wrong; it is incomplete. It defends against an item that gives itself away and says nothing about a set that does.

2 · Scope

In scope

  • Extending the guessability rule to cover the position of the correct option across a course.
  • A deterministic shuffle, so the same input still produces byte-identical output.

Out of scope

  • Distractor quality, which is a different guessability problem and a harder one.
  • Item ordering within a course.

3 · Approach

Extend FR-004 rather than adding a sibling, because it is the same property measured over a wider window. The shuffle is seeded from something already stable in the course — its identifier — so a regenerated course is unchanged and the determinism requirement the command already carries is not weakened.

4 · Deltas

What changes: the guessability rule gains a clause about the correct option's position across the course, which a per-item check cannot see.

Each quiz item MUST be generated from retrieved real source and MUST pass a guessability check before shipping: an item the model can answer correctly with the source hidden MUST be rejected and regenerated. An objective whose quiz stays guessable after retries MUST be dropped rather than shipped. Across a course, the position of the correct option MUST NOT be constant, and MUST be determined by a deterministic, seeded shuffle so that regenerating a course produces byte-identical output.

Rationale

A quiz answerable from generic knowledge tests nothing about the repo — and neither does one whose answer is always first. The per-item check cannot catch it, because the tell is a property of the sequence rather than of any item in it. Seeding the shuffle keeps the determinism the course generator already promises.

5 · Risk register

The adversarial pass triggered on a must-tier requirement being modified. One finding, recorded and answered.

A shuffle seeded from the course identifier makes the position predictable to anyone who knows the seed, which is stated in the artifact.

"determined by a deterministic, seeded shuffle"

True, and accepted: the threat is a learner noticing a constant pattern while taking a quiz, not one deriving a permutation from a published seed. Determinism is worth more here than unpredictability, because a course that regenerates differently every run breaks the drift check that makes it reviewable.
