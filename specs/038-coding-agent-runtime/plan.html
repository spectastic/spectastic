Implementation plan · 038-coding-agent-runtime

Coding-agent runtime

How we will build it.

Status Accepted Spec 038-coding-agent-runtime Owner Brian Corbin · @briancorbinxyz Branch 038-coding-agent-runtime Created 09 Jul 2026 Read time

A deterministic drainTasks runtime in core walks the unchecked <spec-task>s, hands each to an injected CodingAgent that works inside a throwaway git worktree, runs the task's verify there, and ticks (reusing the 014 kernel) only on a pass. CI wires a script-replay stub; a thin subprocess adapter over the headless claude CLI is the local-only real agent. Biggest risk: deriving each task's verify command — mitigated by reading it from the task's declared test-file path.

4 · Approach

A new packages/core/src/coding/ module holds the deterministic runtime. drainTasks(input, ctx) scans tasks.html for the first unchecked <spec-task>, builds a TaskWork (id, title, path, bundle context), and hands it to ctx.coding.perform(work). The CodingAgent works inside a git worktree created at HEAD; when it returns, the runtime runs the task's verify (derived from the task's test-file path) in the worktree. On a pass, the runtime accepts the changes and ticks via the existing implementCommand; on a fail/blocked/no-change outcome it removes the worktree (primary tree untouched) and returns an escalation. It then repeats for the next unchecked task until the list drains or one fails. The CLI wires createCodingAgent() (stub vs real, by env) exactly as it wires the AIProvider; the real adapter is a thin subprocess over claude -p.

5 · Alternatives considered

Sandbox optionIsolationRevert costComplexityTotal
Git worktree at HEAD55414
Edit primary tree + git stash/reset on fail2349
Copy repo to a temp dir (no git)44210

The worktree wins: native git isolation, free revert (remove the worktree), and it shares object storage so creation is cheap. Editing the primary tree risks a half-applied change surviving a crash; a bare copy loses git context the agent (and tests) may need.

6 · Decisions

D-001 · The CodingAgent seam mirrors the AIProvider/stub pattern

Status
Accepted
Context
CI must stay offline + deterministic (cli/src/ai-factory.ts:15 shows the established stub-by-env seam).
Decision
Define CodingAgent { perform(work): Promise<TaskOutcome> }; createCodingAgent() returns a script-replay StubCodingAgent when SPECTASTIC_CODING_STUB is set, else the real subprocess adapter.
Consequences
+ CI deterministic; + one swappable boundary. − the real path is untested in CI (accepted: smoke tier).

D-002 · Sandbox = a git worktree created at HEAD

Status
Accepted
Context
The W-1 guardrail requires isolation; the spike (§3) created + removed a worktree cleanly this turn.
Decision
Each drain step creates a detached worktree at HEAD; the agent + verify run there; on pass the diff is accepted into the primary tree, on fail the worktree is removed. Primary tree byte-unchanged on failure (FR-004).
Consequences
+ native isolation + free revert; − requires a git repo (edge case: refuse when absent).

D-003 · Verify-before-tick derives the test command from the task's path

Status
Accepted
Context
A task carries its test-file path in <span class="path"> (the verify trace-join convention, core/src/commands/verify.ts).
Decision
For a test-bearing task the runtime runs vitest run <path> in the worktree as the verify; a task with no test path is treated as blocked (can't verify → can't tick). The tick fires iff the verify passes (NFR-002).
Consequences
+ reuses the existing path convention; − a mis-declared path blocks the task (loud, not silent).

D-004 · Real adapter = subprocess over the headless claude CLI

Status
Accepted
Context
Spike found claude v2.1.153 on PATH; the AIProvider SDK is text-only so a tool-using agent must be external.
Decision
The real adapter runs claude -p <task-prompt> with the worktree as cwd (v1). Smoke-tier only (FR-006); an in-process SDK tool-loop is the documented fallback if the subprocess proves unfit.
Consequences
+ reuses a real, capable agent; − couples the smoke tier to a local claude install (acceptable — local-only).

D-005 · Idempotent resume — no run-state machine

Status
Accepted
Context
The implement kernel already resumes from the first unchecked task (implement.ts); P-6 makes the Draft artifact the state.
Decision
drainTasks re-scans tasks.html each run; a partial drain resumes at the first unchecked task (FR-005). No persisted run state.
Consequences
+ crash-safe + simple; − no cross-run memory of a previously-failing task (re-attempted — acceptable).

9 · Complexity tracking

The worktree lifecycle (create/accept/remove) is the one non-trivial addition beyond the spec's plain statement.

Accepting a worktree's diff into the primary tree is done by applying the worktree's committed/staged changes (or a git merge of the detached commit) — the concrete acceptance mechanism is a tasks-phase detail, bounded by "primary tree ends with exactly the worktree's passing changes." Justified: isolating this in worktree.ts keeps drainTasks a clean gate.
