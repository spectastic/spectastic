3 · Phase 3a — US1 · Drain a task list into tested code

Tests (write & fail first)

Drain + verify-gate test — N tasks: ticks each whose stub outcome passes verify; halts on the first failing task with its box unticked; a "done but verify fails" outcome does NOT tick (SC-001, SC-003). packages/core/test/coding-runtime.test.ts

Implementation

drainTasks runtime — scan first unchecked <spec-task>, build TaskWork, call ctx.coding.perform, run the task-derived verify, tick via implementCommand only on pass; halt + escalate on fail/blocked (D-003, D-005, FR-002, FR-003). packages/core/src/coding/runtime.ts
Verify-command derivation — read the task's <span class="path">; a test-file path → vitest run <path>; no test path → blocked (D-003, NFR-002). packages/core/src/coding/runtime.ts

Closes FR-002, FR-003, FR-005, NFR-002, SC-001, SC-003.

4 · Phase 3b — US2 · A bad run can't corrupt the tree

Tests (write & fail first)

Worktree isolation test — a failing run leaves the primary tree byte-for-byte unchanged; a passing task's changes are accepted only after verify (SC-002). packages/core/test/coding-worktree.test.ts

Implementation

worktree lifecycle — create a detached worktree at HEAD, run the agent + verify there, accept the diff into the primary tree on pass, remove-force on fail; refuse when not a git repo (D-002, FR-004). packages/core/src/coding/worktree.ts

Closes FR-004, SC-002.

5 · Phase 3c — US3 · The real agent behind the seam

Tests (write & fail first)

Implementation

Claude-code subprocess adapter — perform runs claude -p <prompt> with the worktree cwd, maps its result to a TaskOutcome (D-004, FR-006). packages/cli/src/adapters/claude-code.ts

Closes FR-006, SC-004.
