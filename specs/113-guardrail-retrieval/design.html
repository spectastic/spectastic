Design · 113-guardrail-retrieval

Scoped decision retrieval

How we will build it.

Status Accepted Spec 113-guardrail-retrieval Owner Brian Corbin · @briancorbinxyz Branch main Created 13 Sep 2026 Read time

A read-only, AI-free kernel command adrsCommand (mirroring order) reads decisions from design.html files via the fs port, a pure decisionsForPaths glob-matches scope against the query, and a pure buildRetrievalLog renders a deterministic log given an injected clock. Biggest risk: a naive glob matcher; mitigated by a small dependency-free compiler with an explicit ceiling and a matrix of matching tests.

1 · Principles check

All deterministic logic is in @spectastic/core (P-14 — fat core, thin CLI: the CLI just parses --for, resolves the project, and prints). The command carries no AIProvider and no clock of its own — the clock is injected — so it runs in CI with no key and stays deterministic (the enforce/policy precedent). Retrieval is the first half of the guarantee the gates complete (P-8).

2 · Technical context

Kernel
packages/core/src/commands/adrs.ts (adrsCommand + loadDecisions), a new tsup entry + ./commands/adrs export subpath.
Pure helpers
packages/core/src/guardrail/: parse.ts (design.html → decisions), glob.ts (compiler), retrieve.ts (decisionsForPaths), log.ts (buildRetrievalLog/renderRetrievalLog), types.ts.
CLI

3 · Data model & contracts

Types in guardrail/types.ts: GovernanceDecision, RetrievalMatch, RetrievalLog (see spec §4). The log is JSON with stable key order and a trailing newline. The decision coordinate is @spectastic/schema/project's decisionResourceUri (from 112).

5 · Grounding & evidence

The retrieval research pass established: the corpus injects into five authoring verbs but not implement; retrieval is by id/text with no path scoping and no log. So this slice does not extend the corpus read path — it adds a distinct, decision-specific retrieval over the design.html source of truth, leaving the corpus's domain-fact read path untouched. The order kernel is the shape precedent: read-only over the corpus via ctx.fs, deterministic, AI-free.

6 · Approach

  1. Write the glob compiler with a tests-first matrix (**/*/?/literal metachars/normalisation).
  2. Write parseDecisions (tolerant — malformed shape is 112's rule's concern) and decisionsForPaths (accepted + scoped only, sorted).
  3. Write the log builder (injected clock) + the kernel command; wire the CLI; add the no-network test over the transitive import graph.

7 · Alternatives considered

  • Add a glob dependency (picomatch/minimatch). Rejected: the enforcement path must pull nothing (NFR-001); a ~15-line pure compiler covers the scope-glob vocabulary with a documented ceiling.
  • Read decisions from a registry file. Rejected for this slice: the design.html is the authored source of truth; a registry is a later distribution concern (TBD-guardrail-decision-index).

8 · Decisions

packages/core/src/guardrail/** packages/core/src/commands/adrs.ts Retrieval sits on the enforcement path the merge gate calls, so a model or a socket must never reach it; the guarantee is a test, not a convention.

D-001 · No model or network on the retrieval path

Context. The merge gate (Slice 3) will call this same function. Decision. Keep retrieval a pure, fs-only, clock-injected kernel; assert it by walking the transitive import graph. Consequences. The path can be trusted in the deterministic verdict; adding an AI or network import there fails the suite.

 A full glob dependency would pull transitive code onto the enforcement path and is overkill for a scope pattern.

D-002 · A dependency-free glob compiler with a stated ceiling

Context. Scope matching needs **/*/?. Decision. A small pure glob→RegExp compiler; no brace expansion, no negation, no extglob. Consequences. Zero new dependencies; the ceiling is documented in glob.ts and covered by a matrix of tests.

10 · Risks & mitigations

Glob matcher edge cases

Mitigation: a matrix of tests (separators, zero-segment **/, extension anywhere, literal metachars, normalisation).

Model/network on the retrieval path

Mitigation: the transitive-import no-network test (D-001).

11 · Complexity tracking

None beyond the glob compiler, whose ceiling is stated and tested.
