Specification · 113-guardrail-retrieval

Scoped decision retrieval

Given a set of code paths, return the governance decisions that govern them — deterministically, and to a reproducible log the plan-time and merge-time gates can diff.

1 · Context

Phase-1 gap G1 has two halves: no decision surfaces by path, and no gate fails when a plan ignores one. This slice closes the first half — the retrieval — which both gates (Slice 3) and the write-time injection (Slice 4) depend on. The research pass found the corpus's retrieval is by citation-id and text only, with no path-scoped retrieval and no log; this slice adds exactly that, over the decision records Slice 1 defined.

Its users are the agent (at plan time) and CI (at merge time) — both call the identical function, so a plan that retrieved a different governing set than the merge sees is itself detectable by diffing the two logs.

2 · User scenarios & testing

A path surfaces its governing decisions. A developer runs spectastic adrs --for src/app/persistence/Repo.java. The command lists the accepted decisions whose scope globs match that path, in precedence order, and writes a retrieval log.

An unrelated path surfaces nothing. The same command for docs/readme.md lists no decisions and writes an empty-governing log — silently correct, not an error.

The log reconstructs from disk. With a pinned clock, the same query yields a byte-identical log — the record the merge verdict (later) reconstructs from.

3 · Requirements

A plumbing command spectastic adrs --for <paths…> MUST return the ACTIVE (status="accepted") decisions whose <spec-scope> path globs match any of the given paths, in a stable precedence order (by spec id then decision id). It MUST NOT be a lifecycle verb — the eight stay eight. Retrieval MUST read decisions from each specs/<id>/design.html — the source of truth that authored them — via the injected filesystem port, tolerating a spec directory with no design.html. The command MUST write a reproducible retrieval log recording the query paths, each governing decision's coordinate (spectastic://…/decision/…), and the paths it matched, so a verdict can later reconstruct entirely from disk. Scope matching MUST use path globs as the universal floor, supporting ** (across separators), * (within a segment), and ? (one non-separator character), with regex metacharacters in a glob treated literally. A proposed, superseded, or retired decision, and a decision whose scope declares no path, MUST NOT govern any path — only accepted, scoped decisions are returned. The retrieval path MUST carry no model client and no network access — a test MUST assert the retrieval kernel's transitive imports include at most 0 model-client modules and at most 0 network modules. Retrieval and the log MUST be deterministic: the same paths and decisions yield the same governing set and, given an injected clock, a byte-identical log — verified with at most 1 repeated-run diff.
  • The plan-stage and merge-stage gates that consume retrieval — Slice 3.
  • Injecting the governing decisions into the agent before writing — Slice 4.
  • Reading from a decision registry rather than design.html — the registry is a later distribution concern; the design is the source of truth here.

4 · Data model

GovernanceDecision
The machine projection of a <spec-decision> (from 112): id, specId, status, posture, scope paths + modules, supersedes, reason, enforcement.
RetrievalMatch
A governing decision + the query paths its scope matched.
RetrievalLog
{ at, paths[], governing: [{ coordinate, specId, id, matchedPaths[] }] } — the reproducible record.

5 · Success criteria

Given decisions parsed from a design.html, adrs --for a path under an accepted decision's scope lists exactly that decision (and any other matching accepted decision, sorted); a path outside every scope, and a proposed/superseded decision, list nothing.

 With a pinned clock, the retrieval log is byte-identical across at least 2 runs, and its governing entries carry the decision coordinates.

6 · Assumptions

  • Decisions carry the structured scope metadata 112 defined; a bare legacy decision simply never governs (no scope).
  • The project identity resolves via resolveProjectConfig (067), for the decision coordinates in the log.

7 · Open questions
