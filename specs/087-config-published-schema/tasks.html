The published config schema

Status Draft Spec 087-config-published-schema Design design.html Created 03 Aug 2026 Strategy MVP-first — US1 is the finding, which is the half that reaches everyone; the schema and its reference follow. Read time

Twelve tasks. US1 lands the unrecognised-key finding, which needs no schema file and no network; US2 generates, commits and references the schema; US3 guards it against drifting from the registry it derives from.

Phase 1 · US1 — be told about a typo

First because it is the half that works with no editor, no network and no schema file — and because it is the silence the whole survey opened on.

Write the scan's tests — an unrecognised section, an unrecognised key inside a real section, and a wholly valid configuration producing nothing. packages/schema/test/config.unknown.test.ts
Write the exemption test — the schema reference is metadata and must never be reported as an unrecognised key, per FR-006. packages/schema/test/config.unknown.test.ts
Build the unrecognised-key scan — set membership against the registry, no validator dependency and no schema file needed at check time. packages/schema/src/config/unknown-keys.ts
Suggest the likely intended key — a near match on small edit distance only, phrased as a question rather than an instruction. packages/schema/src/config/unknown-keys.ts
Fold the scan into validate — cloning the shape the copy-leak and waiver scans already use rather than inventing a fourth. packages/cli/src/commands/validate.ts
 Closes FR-005, FR-006, FR-007 and NFR-002; evidences SC-001.

Phase 2 · US2 — see what may go in the file

Write the generator's tests — every declared section and key present, a defaultless key rendered without an invented default, and byte-identical output across runs. packages/schema/test/config.schema.test.ts
Build the generator — a pure function from the registry to a schema object, keys emitted in sorted order. packages/schema/src/config/schema-gen.ts
Emit and commit the artifact — a build step writing the schema into the shipped directory, so the published package carries it and the address resolves. packages/schema/scripts/gen-schema.mjs
Write the reference at init — the version-pinned address, taken from the package manifest so it can only name a version that exists. packages/cli/src/commands/init.ts
 Closes FR-001, FR-002, FR-003 and FR-004; evidences SC-002.

Phase 3 · US3 — trust that the schema is current

Guard the committed artifact — regenerate from the registry and compare, so a hand edit or a stale build fails rather than ships. packages/schema/test/config.schema.test.ts
Confirm the address actually resolves — fetch the published schema at the pinned version before the reference is written anywhere, since a dangling reference is worse than none. Deliberately unticked: it returns 404 today, because the currently-published version predates the schema file. Repeat at the next release — this is the one thing here that a release, not a commit, can settle. packages/schema/dist/config.schema.json — Correctly waiting, not owed: 087 is still Draft and no schema is published, so there is no address to fetch. This task is a precondition for work that has not started.
Prove the finding on a real misspelling — introduce one into this repository's own configuration, confirm the finding names it, and restore, per SC-001. spectastic.json
 Closes FR-008 and NFR-001; evidences SC-003.
