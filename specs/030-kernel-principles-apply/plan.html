Implementation plan · 030-kernel-principles-apply

Kernel-owned principles apply

One branch inside applyCommand — reuse everything spec-apply already proves, add only what principles need.

Status Accepted Spec 030-kernel-principles-apply Owner Brian Corbin · @briancorbinxyz Branch 030-kernel-principles-apply Created 2 Jul 2026 Read time

Extend applyCommand (packages/core/src/commands/apply.ts) with an early branch on the reserved spec-id principles: resolve root paths (changes/<slug>/, principles.html) instead of specs/<id>/, run three principles-only transforms (insert the principle bare, substitute version + tagline + TL;DR from a new <spec-principles-apply> block, set the amended date), and skip the §6 fold. Everything else — the risk gate, changelog append, deepenArchivePaths, the mkdir-before-rename archive move — is reused unchanged. The one real risk is the substitution editing prose; FR-004 contains it by taking the prose verbatim from the proposal, never guessing.

4 · Approach

Branch applyCommand once, at the top, on input.specId === 'principles'. The branch resolves proposalDir = ${ctx.cwd}/changes/<slug> and targetPath = ${ctx.cwd}/principles.html, then runs the shared preamble (read proposal, risk gate) and a principles-specific fold: parse the single ADD/MODIFY delta and the <spec-principles-apply> block, insert the principle bare after the last <h3 id="P-N"> block in the Core principles section, substitute the version (three sites), tagline, TL;DR, and amended date, then append the changelog entry. It then reuses the shared tail — flip status, deepenArchivePaths, mkdir-before-rename into root changes/archive/ — and returns, without calling foldProposalTasks. The CLI gets a parallel one-line branch: when specId === 'principles', stage principles.html + the archived folder instead of specs/<id>/.

5 · Alternatives considered

Factoring of the principles path (NFR-002 — reuse, don't fork). Criteria: Reuse (least duplicated logic), Isolation (two flows don't entangle), Effort (smallest change to proven code).

OptionReuseIsolationEffortTotal
Branch inside applyCommand53513
Separate applyPrinciplesCommand35311
Generalize resolveTarget(specId)54110

Branch-inside wins on reuse + effort: the shared steps stay a single copy (can't drift, NFR-002), and it's the smallest change to a well-tested function. The generalize-resolveTarget option scores well on reuse but loses on effort — refactoring the proven spec path for one extra target is risk the spec explicitly deferred (§2 defer-to="never").

6 · Decisions

D-001 · Reserved principles spec-id, branched inside applyCommand

Status
Accepted
Context
apply.ts hardcodes specs/<id>/ (apply.ts:43-45); principles proposals live at root. Same CLI arity is desired (FR-001).
Decision
Treat principles as a reserved spec-id; branch at the top of applyCommand to resolve root paths. No new flag, no second entry point.
Consequences
+ Same verb + arity; least surface. + Shared preamble/tail reused. − applyCommand gains a conditional; mitigated by extracting the principles transforms into helpers.

D-002 · <spec-principles-apply> block carries version + tagline + TL;DR; kernel substitutes verbatim

Status
Accepted
Context
FR-004 forbids the kernel guessing prose. principles.html carries a version (3 sites), a tagline, and a TL;DR (principles.html L15/L18/L23/L35). Those edits are content, not structure.
Decision
The proposal declares a <spec-principles-apply> block with <version>, <tagline>, <tldr> children; the kernel reads and substitutes them verbatim. Missing block or child → refuse (FR-004).
Consequences
+ Multi-line HTML prose reads cleanly; greppable; renders as a review panel. + Kernel never invents prose. − One new element to author (deferred: propose auto-emits it, §2 out-of-scope).

D-003 · Insert the principle bare, after the last principle — not <spec-requirement>, not before-first-</section>

Status
Accepted
Context
The spec ADD path wraps in <spec-requirement> and inserts before the first </section> (apply.ts:70-78); principles are bare <h3 id="P-N"> + <p>.
Decision
Extract the principle's <h3> + <p> body from the delta and insert it after the last <h3 id="P-N"> block in the Core principles section. MODIFY replaces that block in place.
Consequences
+ Output matches P-1..P-7 exactly. − A principles-specific insert helper; covered by vitest (D-007).

D-004 · Skip the §6 fold for principles

Status
Accepted
Context
foldProposalTasks scaffolds a tracker from templates/tasks.html (apply.ts:167-183); a principles proposal's §6 is the apply mechanics (FR-002), matching P-7's inline behaviour.
Decision
The principles branch does not call foldProposalTasks; no principles-tasks.html is created; §6 stays frozen in the archive.
Consequences
+ No self-referential unchecked tasks (SC-003). − result.foldedPhase is null for principles; the CLI report omits the fold line.

D-005 · Reuse the risk gate, changelog append, deepenArchivePaths, and archive move

Status
Accepted
Context
These are target-agnostic (apply.ts:31,54,146,340); deepenArchivePaths is depth-agnostic (archive-paths.ts).
Decision
The principles branch calls the same helpers; only the archive path changes to ${ctx.cwd}/changes/archive/<slug>, created via the existing fs.mkdir before fs.rename (the T-007 discipline at root depth).
Consequences
+ NFR-002 satisfied — one copy of the shared logic. + The stale-version guard (FR-005) is the only new gate. − None material.

D-006 · CLI stages principles.html + the archived folder for the commit

Status
Accepted
Context
The CLI stages specs/<specId>/ (cli/apply.ts:84), which doesn't exist for principles.
Decision
When specId === 'principles', pass paths: [principles.html, changes/archive/<slug>] to commitVerbAndExit. The quarantine gate + Acked-by read stay unchanged (harmless no-ops).
Consequences
+ The commit captures exactly the principles patch + archive move. − A second small conditional in the CLI action.

D-007 · Layered tests — pure-core vitest + a real-fs smoke

Status
Accepted
Context
Test-style preference; the codebase already layers this way (apply.test.ts, apply.fold.test.ts).
Decision
Pure-core vitest drives applyCommand(principles) for the happy path + each guard (identified risk, stale version, missing field); a real-fs smoke confirms end-to-end apply archives + validates clean (SC-004).
Consequences
+ Fast unit coverage + a genuine runtime exercise (P-7). − Two test surfaces; both small.

9 · Complexity tracking

One new element beyond pure reuse.

The <spec-principles-apply> block (D-002) is complexity the spec's FR-004 requires: since the kernel must not guess the tagline/TL;DR prose, that prose must arrive in a structured, greppable place. An element beats attributes for multi-line HTML and beats positional parsing for robustness. Justified.
