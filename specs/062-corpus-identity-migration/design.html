Corpus identity migration

How we will build it.

Status Accepted Spec 062-corpus-identity-migration Owner Brian Corbin · @briancorbin Branch main Created 26 Jul 2026 Read time

Reshape both shipped packs to clean slugs, stage each as a source checkout, run 061's real installPack to write the root registry, re-point every live citation to its assigned KB-NNNN, and gate resolveCitation's array-order matchCurrent behind "no registry" so a loaded registry is the sole current-edition authority. Biggest risk: a mechanical re-point corrupting a frozen archive or the KB-002 fixture — mitigated by a precise skip list and a validate-baseline diff.

4 · Approach

Four ordered moves, each a phase. (1) Reshape — add knowledge/marketplace.json, and stage spectastic-concepts as a temp-dir source checkout with its reference renamed to the clean 001-foundations slug (copied out so the import never reads-and-writes the same live dir). The examples/knowledge/finance-settlement/ marketplace source is left as-is — it is the ingester's raw input, and 057's portable-skill test reads it at that shape. (2) Register — run the real corpus import <plugin>@<marketplace> --from … once per pack (concepts from its staged copy into knowledge/spectastic-concepts/; finance from examples/ into a new knowledge/finance-settlement/), writing the single root registry, the two-layer references (legacy id: dropped, slug derived from the filename), and each SKILL.md slug map; then delete the now-redundant per-pack index.md under knowledge/. (3) Re-point — rewrite every live citation to its KB-NNNN@edition, honouring the precise skip list. (4) Flip — gate matchCurrent behind the no-registry path so a loaded registry is the sole current-edition authority, keeping matchSuperseded intact.

5 · Alternatives considered

OptionDogfoods ingesterDeterminismSimplicityTotal
Hand-author the registry rows0336
Import in-place (concepts reads+writes live dir)3227

Hand-authoring would leave the registry unproven against the tool that must maintain it (FR-003 forbids it). In-place import works — installPack reads each file before rewriting it — but staging a source copy removes even the appearance of a read/write-same-dir hazard for the cost of one copy step, which the interview chose.

6 · Decisions

D-001 · Reshape then import from a staged source, never hand-author the registry

Status
Accepted
Context
installPack derives the slug from the reference filename (ingest.ts:251) and drops the legacy id: on rewrite (ingest.ts:130), so a rename-first + real-import path yields a clean two-layer pack with no manual frontmatter edits. FR-003 requires the registry be exactly what the ingester writes.
Decision
Rename references to NNN-topic slugs and run corpus import … --from …. Concepts is staged under a temp dir (copied out so its live dir is never both source and dest); finance imports directly from its examples/ marketplace source, which stays unchanged.
Consequences
+ Registry is provably ingester-written; + the migration is a re-runnable script. − One extra copy/cleanup step per pack.

D-002 · Gate array-order matchCurrent behind the no-registry path

Status
Accepted
Context
The array-order collision is resolve.ts:85-90's matchCurrent; the registry is already consulted first (resolve.ts:81), and superseded resolution lives only in the pack matchSuperseded (resolve.ts:59-74, FR-007). Deleting the pack scan outright would break edition-pinned prior-edition citations.
Decision
When a registry is provided: resolve current via matchRegistry, fall through to pack matchSuperseded only, and return null rather than consulting matchCurrent. When no registry is provided: unchanged full pack scan (the documented back-compat path). So a loaded registry is the sole current-edition authority.
Consequences
+ A current-edition citation never resolves by array order once the registry is loaded (FR-006); + 052 FR-003 superseded resolution preserved (FR-007); + no downstream packs-only caller breaks. − The pack scan isn't fully deleted — that's TBD-resolver-registry-only, scoped out.

D-003 · Leave duplicateIdFindings in place as a documented no-op on migrated packs

Status
Accepted
Context
duplicateIdFindings (validate.ts:95) skips any document with no doc.id (line 98); a migrated two-layer doc has none, so it is already inert on migrated packs. Repo-wide uniqueness is enforced by duplicateRegistryIdFindings (validate.ts:200).
Decision
Do not delete it — it still guards an unmigrated downstream pack that legitimately still carries doc.id. Add a comment marking it a no-op on migrated packs and pointing at the repo-wide gate. FR-008 (SHOULD) is satisfied by documentation, not removal.
Consequences
+ No regression for downstream packs still on the legacy shape; + the two-layer gate is unshadowed. − The function outlives the model it was written for until every consumer migrates.

D-004 · Red-first vitest with a two-colliding-pack resolver fixture

Status
Accepted
Context
A test-style preference, no external fact. Mirrors 061's stub-fetcher precedent and feedback-ai-in-ci-uses-stubs.
Decision
Write failing tests first: (a) two packs sharing a legacy id + a registry → resolves by registry identity, not array order; (b) a superseded-edition citation still resolves post-flip; (c) an idempotent re-import registers nothing new; (d) a validate baseline shows no new error. Real files via --from; no network.
Consequences
+ The flip's regression surface is pinned before the edit; + deterministic in CI. − The colliding-pack fixture is bespoke setup.

8 · Risks & mitigations

9 · Complexity tracking

No complexity beyond the spec. The one judgement call — keeping duplicateIdFindings rather than deleting it (D-003) — is justified by the still-live downstream unmigrated-pack case, and is documented in code.
