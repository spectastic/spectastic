Corpus identity migration

Move the two shipped packs onto the two-layer shape, populate the root registry by dogfooding the ingester, re-point every live citation, and make the registry the sole authority for a current edition — closing the back-compat window the corpus family has carried since 051.

Read time

The knowledge-corpus family (051–059) built everything that reads a root registry — registry-first resolution, the grounding gate, the render label — and 061 built the ingester that writes one. But the two shipped packs (spectastic-concepts, the finance-settlement demo) are still on the legacy 056 shape (pack-minted KB-001, a per-pack index.md), and the root registry is empty, so a citation still resolves by array order. This slice migrates both packs, populates the registry by running the real ingester on them, re-points every live citation to its opaque KB-NNNN, and retires the array-order fallback for a current edition. 1 · Context

The corpus family shipped its reader and its writer, but never crossed them over on its own data. The two shipped packs still carry the retired flat identity — a pack author writes KB-001 into a per-pack index.md, both packs collide on KB-001, and resolveCitation returns the first pack whose id matches, so a citation resolves by array order rather than by intent. The root knowledge/index.md registry — the single source of truth the two-layer model rests on — is empty, because nothing has ever run the ingester against the real packs. Every downstream reader (053's gates, 052's render label) is therefore reading a table that does not yet exist.

This is the maintainer's problem: the tooling dogfoods a convention it does not itself follow. The migration is the one-time cutover that makes the meta-repo obey its own model — and, because 061's ingester assumes the two-layer shape, it is the slice every ingester test has been waiting on to run against real packs rather than fixtures.

2 · User scenarios & testing

Each story MUST be independently testable. US1 stands alone as a viable MVP: the packs are migrated and the registry is populated even if no citation is re-pointed and the resolver is untouched.

US1 · Reshape and register both shipped packs P1

As a meta-repo maintainer, I want to reshape both in-repo packs to the two-layer shape and populate the root registry by running the real ingester on them so that the corpus convention the tooling reads is actually populated, and the ingester is proven on real packs instead of fixtures.

Acceptance: after adding a knowledge/marketplace.json and staging each pack's references on clean NNN-topic slug filenames, running corpus import <plugin>@<marketplace> --from … once per pack writes a single root knowledge/index.md with two repo-unique rows — KB-0001 (spectastic · spectastic-concepts) and KB-0002 (spectastic-examples · finance-settlement) — each installed pack carrying a SKILL.md slug map and no per-pack index.md; spectastic validate introduces no new error over the pre-migration baseline.

US2 · Re-point every live citation P1

As a maintainer, I want to re-point every live grounding citation that names an in-repo pack document from the retired KB-001@edition to its project-assigned KB-NNNN@edition so that no live citation resolves by the retired array-order path.

Acceptance: every live citation in a spec, plan, doc, CLAUDE.md, or worked-example that names an actual in-repo pack document is rewritten to its KB-NNNN@edition; the three non-re-pointable categories — frozen archive proposals, the KB-002 license fixture, and the KB-999/@2017 illustrative hypotheticals — are left verbatim, each skip named with its reason.

US3 · Make the registry the sole authority for a current edition P1

As a corpus consumer, I want resolveCitation to resolve a current-edition KB-NNNN via the registry only, retiring the array-order pack-scan fallback so that two packs can never again resolve a citation by their order in an array.

Acceptance: with a registry present, a current-edition citation resolves via the registry and the array-order matchCurrent pack fallback no longer runs; a fixture of two packs sharing an id proves the resolution is by registry identity, not array order; an edition-pinned citation to a retained superseded edition still resolves (052 FR-003 preserved).

Edge cases

  • In-place import for spectastic-concepts. Its source and destination are both knowledge/spectastic-concepts/; the import reads each reference before it rewrites it, so an in-place run is safe — but the slug filenames must already be clean before the run.
  • Legacy id: frontmatter. The ingester's converter carries only the standard provenance fields, so the retired id: KB-001 is dropped on rewrite and the two-layer slug: is written in its place — no manual frontmatter surgery.
  • Re-running the import. A second run over an already-migrated pack must register nothing new (idempotent), so the migration is safe to repeat and safe to leave in a script.

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional

Every pack that lives under a project's knowledge/ root MUST end on the two-layer shape: each reference on a clean NNN-topic slug filename with slug: frontmatter and no pack-minted id:, a SKILL.md slug map, and no per-pack index.md. Concretely: spectastic-concepts is reshaped in place; finance-settlement is installed under knowledge/ as a two-layer pack by importing it from the examples/knowledge/finance-settlement/ marketplace source, which is deliberately left on its current shape as the ingester's raw input.

Rationale

061's ingester derives a document's slug from its reference filename and converts arbitrary-shaped input to two-layer on install. Leaving the examples/ source unchanged shows the ingester doing its actual job — converting a legacy marketplace pack — and keeps 057's portable-skill contract (which reads that source at its current shape) green. A legacy KB-001-foundations.md filename would otherwise yield the slug KB-001-foundations, carrying exactly the pack-minted id the two-layer model retires — so the reshape (rename before staging) is the precondition for a clean import.

The spectastic-concepts pack MUST be filed in the registry under the project-local namespace spectastic (supplied by the import coordinate spectastic-concepts@spectastic), and MUST NOT be declared in a distributable knowledge/marketplace.json.

Rationale

The pack is spectastic's own dogfood corpus — it legitimately carries <spec-*> tags, verb names, and the word "spectastic". 057's pack-not-portable rule inspects only packs a marketplace.json declares distributable, and its D-002 keeps spectastic's own un-listed packs exempt "by construction, not by an exemption list". Listing concepts as distributable would wrongly assert portability and fire four false errors; the namespace label carries the identity without the distributability claim. A consuming project's knowledge/ is a corpus root, not a marketplace — the demo's examples/knowledge/marketplace.json is the marketplace source, a different role.

The root knowledge/index.md registry MUST be populated by running corpus import <plugin>@<marketplace> --from … against each reshaped pack — dogfooding 061's ingester — SHOULD NOT be hand-authored row by row, so the registry is proven to be exactly what the ingester writes.

Every live grounding citation that names an actual in-repo pack document MUST be re-pointed from the retired three-digit KB-001@edition to its project-assigned four-digit KB-NNNN@edition, across specs, plans, docs, CLAUDE.md, and worked-example prose.

The re-point MUST NOT alter three categories: archived proposals under changes/archive/ (preserved verbatim per P-3), the KB-002 restrictive-license fixture (a distinct id whose 058 tests pin it), and the illustrative KB-999/KB-001@2017-09-05 hypotheticals in 053 (they demonstrate the gates against invented ids with no real target). Each skipped file is named with its reason.

resolveCitation MUST treat the registry as the sole authority for a current-edition match; the array-order pack-scan match for a current edition MUST be retired, so a current-edition citation never resolves by a pack's position in an array.

An edition-pinned citation to a retained superseded edition MUST continue to resolve after the flip (052 FR-003 preserved). The mechanism — a narrow pack lookup kept for superseded editions only, or a registry extension — is a plan decision.

Repo-wide KB-NNNN uniqueness SHOULD be the effective duplicate gate after migration; the per-pack KB-NNN duplicate check keyed on the retired document id SHOULD be retired or explicitly documented as a no-op on a migrated pack, so the two-layer model is not shadowed by a check for the model it replaced.

The migration MUST record the meta-repo's corpus role as consumer-only: its knowledge/ is a corpus root it reads from and dogfoods, MUST NOT carry a distributable root marketplace.json, and does NOT publish spectastic-concepts for external corpus import in this slice.

Rationale

Surfaced by triage T-001: removing the concepts manifest during US1 fixed the consumer role but left the publisher role undecided. The examples marketplace under examples/knowledge/ already demonstrates external import, so publishing the dogfood pack is deferred, not adopted. Publishing would additionally need 057 to gain a first-class exemption for an intentionally tool-specific pack (its pack-not-portable rule assumes distributable ⟹ domain-neutral) — a cross-spec change out of scope here. Deferred to TBD-corpus-publish.

Non-functional

The migration MUST be idempotent and deterministic: re-running corpus import on an already-migrated pack registers nothing new, and no step reads a clock or a network — the result is a pure function of the repo's files.

The migration MUST NOT lose content: every migrated document's body text and every known provenance field is preserved, and no TODO provenance field is fabricated to look verified.

Out of scope (deferred to other slices)

  • Migrating the external repos ~/Code/example-cash-snapshot and ~/Code/spectastic.io — same reshape, different repos, done locally and pushed on the owner's direction.
  • Publishing the corpus for external import (a distributable root marketplace.json + a 057 carve-out for an intentionally tool-specific pack) — FR-009 records this repo as consumer-only for now.
  • Extending the registry to record retained superseded editions so the pack scan can be deleted entirely — FR-007 keeps a narrow superseded lookup for now.
  • The RealPackFetcher remote/object-source gap (061 ceiling) — this slice uses --from local checkouts and never exercises a network fetch.
  • The stale KB-NNN@edition copy in commands/spectastic.explain.md and spectastic.propose.md — a just-do already tracked, not a migration requirement.

4 · Data model

This slice introduces no new entity; it moves existing data from the retired flat shape to the two-layer shape already defined by 051/052. The transformation, per document:

The reshape, per document

Reference file
references/KB-001-foundations.md → references/001-foundations.md. The filename becomes the pack-owned portable slug.
Frontmatter
The pack-minted id: KB-001 is dropped; slug: 001-foundations is written. Provenance (origin, edition, license, content-hash, …) is preserved; the install door stamps status: not-yet-spot-checked.
Pack index
The per-pack index.md is removed; a SKILL.md slug map replaces it as the pack's discovery surface.
Root registry
One new row per document in knowledge/index.md: the project-assigned opaque KB-NNNN keyed on (marketplace, plugin, slug) — the DOI-model layer-2 identity.

Invariant: the KB-NNNN a document is assigned at migration is stable forever — a later rename of the pack or slug re-anchors the same id via the registry, never mints a new one. The re-pointed citations (FR-004) name that id, so the invariant is what keeps them from ever dangling.

5 · Success criteria

Technology-agnostic, measurable outcomes.

After migration, the root knowledge/index.md contains exactly one repo-unique KB-NNNN row per migrated document (two rows: KB-0001, KB-0002), and spectastic validate over the full corpus produces zero new errors relative to the pre-migration baseline.

A <spec-decision grounding="verified"> citing a migrated document's KB-NNNN@edition resolves green through resolveCitation with the registry present; a fixture of two packs sharing a legacy id proves the resolution is by registry identity, not by array order.

Re-running corpus import against an already-migrated pack registers zero new documents and reports the existing ones as already-registered — idempotence observable from the command's own output.

No live grounding citation to an in-repo pack document remains on a three-digit KB-NNN; a repo grep outside the three documented skip categories finds only KB-NNNN.

6 · Assumptions

061's installPack, the --from LocalPathFetcher, and registry-first resolveCitation are built and green (verified in-repo this turn) — this slice runs them, it does not build them.

Neither shipped pack has any retained superseded edition today, so FR-007's guarantee is proven against a fixture rather than a live superseded document — the migration itself creates no superseded content.
