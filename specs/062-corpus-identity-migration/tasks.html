Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 062-corpus-identity-migration Design design Branch main Created 26 Jul 2026 Read time

17 tasks across five phases. Setup → Foundational → US1 (register) · US2 (re-point) · US3 (flip) → Polish. Tasks marked [P] touch a distinct file with no in-flight dependency. US3's resolver change is written test-first; US1/US2's data operations are pinned by a regression test over the committed migration artifacts, plus a validate baseline and an idempotent re-run.

1 · Execution strategy

US1 alone is a viable MVP — the packs are migrated and the root registry is populated even if no citation is re-pointed and the resolver is untouched. Ship US1, then US2, then US3.

Setup → Foundational → US1 → US2 → US3 → Polish. Each story closes its conformance before the next opens. The recommended path for this slice — the phases are genuinely ordered (register before re-point before flip).

Not a fit — one author, strictly ordered phases (a citation can't be re-pointed before the id it names is allocated; the flip can't be verified before the registry exists).

Implementation

Build the citation inventory + skip list — grep every KB-00N occurrence across live (non-archive) files and classify each: re-point (a real grounding citation naming an in-repo pack doc) vs skip (an archived proposal, the KB-002 license fixture, or a KB-999/@2017 hypothetical). Verification

Closes FR-004, FR-005; SC-004.

6 · Phase 3c — US3 · Make the registry the sole current-edition authority

Tests (write & fail first)

Red-first resolver tests — new suite asserting: (a) two packs sharing a legacy id + a registry resolve by registry identity, never by array order; (b) an edition-pinned citation to a retained superseded edition still resolves after the flip; (c) with a registry present, a current-edition id absent from the registry returns null rather than falling to the array-order matchCurrent. All must fail against the current resolve.ts. packages/core/test/knowledge.resolve-registry-only.test.ts

Implementation

Gate matchCurrent behind the no-registry path (D-002) — when a registry is provided, resolve current via matchRegistry, fall through to the pack matchSuperseded only, and return null instead of consulting matchCurrent; leave the no-registry path unchanged. Make T-300 green (FR-006, FR-007). packages/core/src/knowledge/resolve.ts
Document duplicateIdFindings as a migrated-pack no-op (D-003) — add a comment marking the per-pack KB-NNN id check inert on a two-layer doc (no doc.id) and pointing at duplicateRegistryIdFindings as the live repo-wide gate; keep it for still-unmigrated downstream packs (FR-008). packages/core/src/knowledge/validate.ts

Verification

Rebuild core + run the resolver/validate/ingest suites — pnpm --filter @spectastic/core build, then confirm T-300 green, the two-colliding-pack fixture proves registry-identity resolution (SC-002), and no existing packs-only (no-registry) resolver test regresses. packages/core/

Closes FR-006, FR-007, FR-008; SC-002.
