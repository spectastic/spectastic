1 · Context

Today's triage flow lives entirely in commands/spectastic.triage.md, executed by the LLM in-process at /spectastic.triage invocation. The procedure does meaningful work — single-card vs list-intake mode detection, regeneration test, eight-value layer classification, routing to per-spec triage log vs project-root inbox.html, sequential ID assignment — but none of it is reachable from a Tier 2 MCP server, a Tier 3 VS Code extension, or any non-Claude-Code surface. The verb is also Spectastic's most-used at small batch: typo runs, broken-anchor sweeps, list-intake from "a few things in my head."

This slice is the second verb extraction (after validate in 006) and the first that prompts the model. That makes it the natural home for the first concrete AIProvider implementation — the interface that 006 declared but didn't implement. Choosing triage as the AI-adapter pioneer keeps the stakes low (small structured outputs, no multi-turn agents, no sub-agent spawn) while exercising both chat() (the freeform model call for characterisation and diagnosis) and ask<T>() (the typed bounded-choice pattern for layer classification when the model is uncertain). The slice carries more architectural weight than a routine extraction because the adapter ships alongside the verb.

2 · User scenarios & testing

Each story is independently testable: if you implemented only US1, you would still have a viable MVP that proves the shape.

US1 · Maintainer triages a single defect via CLI P1

As a maintainer hitting a defect outside Claude Code (CI red, terminal-only, scripted), I want to run spectastic triage "<description>" --spec 002-validate-cli and get the same triage card the slash command produces so that triage doesn't require a Claude Code session.

Acceptance: CLI produces a <spec-triage> card structurally identical to the slash-command output — same five required fields, same regen-test result, same layer. Exits 0 and prints destination path and ID.

US2 · Maintainer pastes a list and gets routed inbox cards P1

As a maintainer with several small cross-cutting items in head, I want to pipe the list into spectastic triage and have each item land in inbox.html with the right layer= so that the small-batch loop works from the CLI as well as the slash command.

Acceptance: List input triggers list-intake mode, writes one <spec-triage> per item to inbox.html with sequential I-NNN IDs, and prints a per-item summary. Items classified as diagnostic layers route to the per-spec triage log instead.

US3 · Future MCP / VS Code consumer invokes the kernel directly P2

As a future MCP or VS Code author, I want to import triageCommand, inject my own AIProvider (or use the bundled Claude one), and receive a structured TriageResult so that I can render and persist cards however my surface requires.

Acceptance: A test under packages/core/test/ imports triageCommand, passes a stub AIProvider, and asserts TriageResult.cards matches expected shape. No process spawn; no real API call; no filesystem write.

Edge cases

Five tracked failure modes the extraction handles
  • Missing ANTHROPIC_API_KEY — Claude provider must fail fast with an actionable error before any model call is attempted. CLI catches and exits 2 (usage); kernel throws a typed error the caller can match.
  • API key accidentally logged — debug logs, error messages, or stack traces must never echo the key. NFR-002 enforces; a unit test inspects log output for the key prefix.
  • Mode detection ambiguity — input has commas but is one sentence ("I tried X, Y, and Z and it broke"). Heuristic matches today's markdown; when genuinely ambiguous, the CLI prompts the user (matches the slash command's behaviour) and the kernel surfaces a typed result the caller can prompt on.
  • Network failure during model call — Claude provider surfaces a typed error; the CLI exits 1 and prints a clean message without a stack trace; the kernel propagates without partial writes.
  • List-intake card-ID collision — two concurrent CLI invocations against the same inbox.html could both pick the same I-NNN. Out of scope for v1 (single-author tool); the kernel scans for highest ID at write time and the caller serialises writes. Documented assumption.

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional — the verb

triageCommand MUST conform to the kernel contract in 006 FR-003: signature (input: TriageInput, ctx: KernelContext) => Promise<TriageResult>; pure; all IO and AI access via ctx.

The function MUST live at packages/core/src/commands/triage.ts, exposed via subpath export @spectastic/core/commands/triage per 006 FR-002. The umbrella entry MUST NOT eagerly load it.

@spectastic/cli MUST add a triage subcommand that imports triageCommand, constructs a KernelContext with the default Claude AIProvider, accepts the input as positional arg or stdin, accepts --spec <spec-id> for single-card routing, and writes the resulting cards to disk.

Single-card mode MUST follow the procedure in commands/spectastic.triage.md: locate spec, load context, characterise (Expected / Actual / Diagnosis), apply the regeneration test, classify the layer. Kernel returns one TriageCard; caller persists to specs/<spec-id>/triage-log.html.

List-intake mode MUST detect list inputs (newline / comma / explicit list markers per the existing heuristic), produce one TriageCard per item, and classify each independently. Caller routes each card to its appropriate destination (per-spec log for diagnostic layers, inbox.html for routing exits).

A Claude AIProvider implementation MUST ship at packages/core/src/providers/claude.ts using @anthropic-ai/sdk, implementing every method on the interface from 006 FR-007. Exposed via subpath export @spectastic/core/providers/claude and lazy-loaded — never imported from the umbrella entry.

The Claude provider MUST read ANTHROPIC_API_KEY from process.env at construction (or accept it explicitly for testability). Missing key with no explicit argument MUST throw a typed error naming the env var.

The AIProvider interface MUST declare two methods consumed here: chat(prompt, opts?): Promise<string> for freeform calls, and ask<T>(questions): Promise<AskAnswer<T>[]> for typed bounded-choice prompts. The ask<T>() shape MUST mirror Claude Code's AskUserQuestion exactly: {question, header, options[{label, description, preview?}], multiSelect?}; 1–4 questions per call, 2–4 options each. This slice ships the first concrete impl of both methods.

Layer classification MUST cover all eight values: spec, plan, implementation, cross-spec, principles, platform, just-do, defer. When classification is ambiguous, the kernel MUST use ask<T>() to commit the answer rather than hedge in prose.

The kernel MUST return structured TriageCards and MUST NOT hard-code destination paths. The CLI subcommand implements today's routing rules (per-spec for diagnostic layers, inbox for routing exits) as caller logic; other surfaces decide their own destinations.

The kernel function MUST be unit-tested at packages/core/test/triage.test.ts with a stub AIProvider. The CLI subcommand MUST have integration tests under packages/cli/test/ covering both modes. A Claude-provider integration test MAY hit the real API, gated on --network-tests or skipped when ANTHROPIC_API_KEY is unset.

commands/spectastic.triage.md MUST note that the slash command MAY shell out to spectastic triage via Bash, per 006 FR-009. The markdown remains canonical and works end-to-end without the kernel.

The triageCommand docblock MUST link to commands/spectastic.triage.md as the canonical source, per 006 FR-008. Markdown MUST NOT be auto-generated.

Non-functional

The extraction MUST NOT regress any scenario in bench/baselines.json. The Claude provider MUST be lazy-loaded — importing @spectastic/core/commands/triage MUST NOT eagerly load @anthropic-ai/sdk.

ANTHROPIC_API_KEY MUST NOT appear in any log, error, stack trace, or stdout/stderr. The Claude provider MUST redact the key from surfaced errors; a unit test MUST assert this on a deliberately-triggered error path.

Out of scope (deferred to other slices)

  • OpenAI and local-LM AIProvider implementations. v1 ships Claude only; the interface is provider-agnostic so additional implementations land as additive PRs.
  • Rejection support for inbox cards (data-status="rejected" per REQ-CHANGE-005). The kernel returns cards; rejection is a caller-side mutation today and stays so until a dedicated slice formalises it.
  • Extract /spectastic.principles. Smallest of the slash verbs.
  • Extract /spectastic.tasks. Deterministic generation from spec + plan.
  • Extract /spectastic.apply. Mostly deterministic (deltas, archive, changelog).
  • Extract /spectastic.spec. First end-to-end exercise of ask<T>() on a multi-decision verb.
  • Extract /spectastic.plan. Pairs with spec.
  • Extract /spectastic.propose. Adversarial-pass spawn needs a subagent() method on AIProvider; that interface addition lands with propose, not here.
  • Extract /spectastic.implement. Drains the just-do queue this verb fills; obvious co-design but separately specced.

4 · Data model

Four types this slice owns: TriageInput, TriageResult, TriageCard, plus the concrete Claude implementation of the AIProvider interface declared in 006.

Entities

TriageInput
Fields: description: string (the raw user input — single failure description, error, stack trace, or list); mode: 'single' | 'list' (caller-provided when unambiguous; the kernel detects when omitted); specId?: string (required for single-card mode; ignored in list-intake mode where per-card routing depends on layer classification).
TriageResult
Fields: cards: TriageCard[] (one for single-card mode, N for list-intake). The caller decides where to persist each card based on its layer; the kernel does not write to disk.
TriageCard
Fields: id: string (sequential T-NNN or I-NNN assigned by the kernel based on caller-supplied highest-existing-ID hint); layer: 'spec' | 'plan' | 'implementation' | 'cross-spec' | 'principles' | 'platform' | 'just-do' | 'defer'; headline: string; expected: string; actual: string; diagnosis: string; fix: string; regenResult?: 'pass' | 'fail' | 'unsure' (omitted for routing-exit layers); deferTo?: string (set when layer === 'defer'); plus an optional deepDive?: string for the cascade / cross-spec / principles section.
AIProvider (re-affirmed; concrete Claude impl on disk)
Interface methods consumed here: chat(prompt, opts?): Promise<string> and ask<T>(questions): Promise<AskAnswer<T>[]>. ask question shape mirrors AskUserQuestion: {question: string, header: string, options: Array<{label: string, description: string, preview?: string}>, multiSelect?: boolean}. The Claude implementation at packages/core/src/providers/claude.ts wraps @anthropic-ai/sdk; alternative providers (deferred) implement the same interface.

The kernel intentionally does not own card-ID assignment globally — the caller passes the highest existing ID (scanned from the target file) as part of the request context, and the kernel increments from there. This keeps the kernel pure and lets the caller serialise writes against its own destination.

5 · Success criteria

Technology-agnostic, measurable outcomes.

For representative single-failure and list inputs, cards produced by spectastic triage are byte-identical (modulo trivial whitespace) to cards the slash command produces against the same inputs. Diff runs in the integration test suite.

pnpm bench passes all scenarios within their declared budgets. The init-help-cold-start p50 stays within ±20% of the post-006 baseline — proof @anthropic-ai/sdk stayed off the init path.

A test under packages/core/test/ imports triageCommand, passes a stub AIProvider with canned responses, and asserts the returned TriageResult.cards match expected shape. No process spawn, no real API call, no filesystem write.

An integration test (gated on --network-tests or ANTHROPIC_API_KEY) constructs the real Claude provider, calls triageCommand, and asserts cards carry valid layers and required fields. Skipped — not failed — when the env var is unset.

pnpm test passes with the new kernel unit tests and CLI integration tests added; no existing test moves to skipped. ANTHROPIC_API_KEY appears nowhere in captured stdout, stderr, or logs across the full run.

6 · Assumptions

Three preconditions: ANTHROPIC_API_KEY available in dev and CI environments where AI-coupled tests run; @anthropic-ai/sdk remains stable through the planning horizon; single-author concurrency.

ANTHROPIC_API_KEY is available in the developer's local environment (already configured for Claude Code use) and in the CI environment where AI-coupled integration tests run. The kernel and Claude provider treat the env var as the authoritative source; if missing, the constructor throws a typed error rather than silently degrading.

@anthropic-ai/sdk remains the supported official SDK for the Anthropic API through the planning horizon (next ~12 months). Pinning to a major version is sufficient; minor/patch updates are pulled via dependabot.

Spectastic remains a single-author tool for the foreseeable future. Concurrent CLI invocations against the same inbox.html or specs/<spec-id>/triage-log.html are not in scope; the kernel scans for the highest existing ID at write-prep time and the caller serialises writes.
