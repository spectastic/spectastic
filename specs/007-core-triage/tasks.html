4 · Phase 3a — US1 · Maintainer triages a single defect via CLI P1

The smallest demoable: kernel triageCommand + ClaudeProvider + CLI subcommand producing cards byte-identical (structurally) to today's slash command.

Tests (write & fail first)

Write packages/core/test/triage.test.ts with a stub AIProvider serving canned chat() + ask<T>() responses. Cover: (a) single-card mode returns one card with all five required fields + layer; (b) list-intake mode returns N cards with sequential IDs from startingId + 1; (c) ambiguous-layer path invokes ai.ask<T>() and uses its return value. Import via '@spectastic/core/commands/triage' subpath — proves SC-003. No process spawn; no real API call; no filesystem write. Tests fail initially because T-110 + T-111 haven't landed. packages/core/test/triage.test.ts
Write packages/core/test/claude-provider.test.ts — unit test on a deliberately-triggered error path: construct ClaudeProvider with a known fake key (e.g. sk-ant-test-REDACTME), trigger a failing chat() call (network unreachable / invalid model), capture the thrown error's .message + .stack + JSON-serialised form, assert the key substring appears nowhere. Proves D-005 + NFR-002. packages/core/test/claude-provider.test.ts

Implementation

Create packages/core/src/providers/claude.ts exporting ClaudeProvider implements AIProvider. Reads ANTHROPIC_API_KEY from process.env or accepts an explicit constructor arg (per FR-007); missing key throws a typed ClaudeProviderError naming the env var. Implements chat() via messages.create with temperature: 0; implements ask<T>() via structured-prompt + JSON parse + one stricter-prompt retry (per D-002); subagent() throws "not implemented in v1; lands with 013-core-propose" (per D-001). Every SDK error wrapped in ClaudeProviderError whose .message + .stack have the key value scrubbed to [REDACTED] (per D-005). Lazy-loaded; not imported from src/index.ts. packages/core/src/providers/claude.ts
Create packages/core/src/commands/triage.ts implementing triageCommand(input: TriageInput, ctx: KernelContext): Promise<TriageResult>. Calls detectMode when input.mode is unset; branches into single-card or list-intake; characterises each item via ctx.ai.chat() (Expected / Actual / Diagnosis); applies regeneration test; classifies layer in one chat call alongside characterisation and escalates ambiguous results via ctx.ai.ask<T>() per D-004; assigns sequential IDs from input.startingIdT / input.startingIdI per D-003. Returns structured TriageCards; no filesystem writes; no hard-coded destination paths (per FR-010). Docblock links to commands/spectastic.triage.md as canonical source (per FR-013). packages/core/src/commands/triage.ts
Create packages/cli/src/commands/triage.ts — spectastic triage subcommand. Accepts input as positional arg or stdin; accepts --spec <spec-id> for single-card routing. Constructs default ClaudeProvider + KernelContext. Reads target file(s) to scan max existing T-NNN / I-NNN IDs via regex; passes as startingIdT / startingIdI. Invokes triageCommand; routes each returned card by layer (diagnostic → specs/<spec-id>/triage-log.html; just-do / defer → inbox.html) per FR-003 + FR-010. Prints destination path + ID; exit 0 on success, 1 on runtime error, 2 on missing env var / usage error. packages/cli/src/commands/triage.ts
Write packages/cli/test/triage.integration.test.ts covering both modes with a stub AIProvider injected for happy-path determinism. Structural check for SC-001: assert produced cards carry the same five required fields, regen-test result, layer, and ID format as today's slash-command output (compared to fixture). No network calls. packages/cli/test/triage.integration.test.ts
Run pnpm -r build end-to-end. Confirm all three packages build cleanly; types resolve across workspace edges; CLI's typecheck consumes @spectastic/core's emitted .d.ts for both ./commands/triage and ./providers/claude. packages/{core,cli,schema}/dist/
Run pnpm test and confirm: (a) T-100 + T-101 kernel unit tests pass; (b) T-113 CLI integration tests pass; (c) all previously-existing tests stay green; (d) ANTHROPIC_API_KEY appears nowhere in captured stdout / stderr / log output across the full run (per SC-005). (test run)
Run pnpm bench and confirm all scenarios within budget. init-help-cold-start p50 stays within ±20% of the post-006 baseline — proof @anthropic-ai/sdk stayed off the init path (per NFR-001 + SC-002). If the bench regresses, T-002 / T-003 lazy-loading discipline is broken — fix before proceeding. (bench run)
Manual SC-001 smoke (SC-001): capture spectastic triage output for a representative single-failure input + a list input; compare structurally to today's slash-command output on the same inputs. Same five required fields, same regen-test shape, same layer-pill rendering. Document any deliberate divergence. (manual smoke; output comparison)
