Specification · 027-git-trailers

Git trailers — attribution from the artifact

spectastic already captures who authored, reviewed, and acked the work — in the artifact. This slice projects that attribution into the commit footer as git trailers, names humans as authors, and acknowledges the AI as a tool, never an author of record.

1 · Context

spectastic produces attribution as a side effect of its lifecycle — <spec-meta> carries Owner/Author and (now) Reviewers, the risk pass (REQ-CHANGE-004) produces human-confirmed dispositions, every archive leaves a proposal + changelog — but none of it reaches git. 026 ships the commits and deferred trailers to this slice; it omitted Reviewed-by because no field carried the reviewer until the just-applied REQ-LIFECYCLE-004 amendment.

The trailer→source mapping is the git-strategy brief's (see §4). The values stance is refined here: human authorship of record stays human, but the AI is acknowledged distinctly as Assisted-by: <model> — a tool, not a contributor of record. The users are maintainers who want "who wrote / reviewed / acked this" answerable from git history without re-keying.

2 · User scenarios & testing

US1 · Human attribution from the artifact P1

As a maintainer, I want to have commits carry the human authorship and review trailers derived from <spec-meta> so that who wrote and reviewed the work is queryable git history, never re-keyed and never an AI.

Acceptance: With git.trailers=on, an auto-commit carries Author: (from Owner), Refs: (the provenance link on apply), Reviewed-by: (when Reviewers is populated), and Co-authored-by: (when the artifact's human author isn't the git committer). Each absent source omits its trailer; none is ever faked.

US2 · The AI is acknowledged, not credited as author P2

As a project lead, I want to acknowledge the assisting model distinctly from human authorship so that attribution is honest about the tool without overclaiming it as a contributor of record.

Acceptance: A commit for an AI-coupled verb carries Assisted-by: <model>; a deterministic verb's commit carries none. No AI identity ever appears as Author, Co-authored-by, Reviewed-by, or Acked-by.

US3 · Design-time sign-off is attributable P3

As a reviewer, I want to have the apply commit name the human who dispositioned the adversarial risk pass so that risk sign-off is attributable, not anonymous.

Acceptance: Once the risk-pass disposition records its author, an apply commit carries Acked-by: naming that human; absent a recorded dispositioner, it is omitted.

Edge cases

  • Empty / missing field. No Owner, empty Reviewers, no dispositioner → the corresponding trailer is omitted; the commit still succeeds (the artifact write already did).
  • Author is the committer. No Co-authored-by — it would duplicate Author.
  • Stub / unknown model. When the assisting model can't be identified, Assisted-by is omitted rather than guessed.

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional

git.trailers MUST default to off and take effect only when git.auto produces a commit (commit or branch+commit); with no commit there are no trailers. It is an independent opt-in toggle, not coupled to git.auto's value beyond that.

When git.trailers=on, an auto-commit MUST carry Author: derived from the artifact's <spec-meta> Owner/Author (a human), and Refs: pointing at the archived proposal/changelog when the verb has a provenance link (e.g. apply).

When the committed spec's Reviewers field is populated (per REQ-LIFECYCLE-004), the commit MUST carry Reviewed-by: derived from it; an empty Reviewers field MUST omit the trailer — never faked.

When the artifact's human author differs from the git committer identity, the commit SHOULD carry Co-authored-by: naming that human. Co-authored-by is human-only.

For a commit whose verb invoked an AI provider to generate the artifact (the AI-coupled verbs: spec, plan, tasks, triage, principles, propose), the commit MUST carry Assisted-by: <model> naming the assisting model. Deterministic verbs (apply, an implement tick) emit no Assisted-by.

Rationale

The trailer attributes the assistance that actually happened on that artifact; a deterministic verb used no AI, so claiming assistance would be false.

spectastic MUST NOT emit any AI/model identity as Author, Co-authored-by, Reviewed-by, or Acked-by. AI attribution is confined to Assisted-by — the AI is a tool acknowledged, never a contributor of record.

When git.trailers=on, an apply commit SHOULD carry Acked-by: naming the human who dispositioned the adversarial risk pass; absent a recorded dispositioner the trailer MUST be omitted, never faked.

This slice MUST deliver a meta-spec amendment (a /spectastic.propose against 000-spectastic amending REQ-CHANGE-004) so the human who dispositions each <spec-risk> is recorded — the source FR-007 reads.

This slice MUST amend CONTRIBUTING.md's "no AI-attribution trailers" rule to permit Assisted-by as a tool acknowledgment, while preserving "no AI as author of record" (Author/Co-authored-by stay human).

Rationale

The standing rule banned all AI attribution; this refines it — authorship stays human, a distinct Assisted-by semantic acknowledges the tool. The change is explicit, not a silent reversal.

Any trailer whose source is absent MUST be omitted (never a placeholder or faked value), and a missing source MUST NOT fail the commit.

Non-functional

Trailer rendering SHOULD add no measurable network cost and stay within 026's ≤ 1 s p95 git-layer budget — it parses an artifact the layer already read.

Out of scope (deferred to other slices)

  • A validate rule enforcing a non-empty Reviewers field — honesty rests on omit-when-absent (FR-003/FR-010), not static enforcement.
  • Signing / Signed-off-by (DCO) trailers — a separate governance concern, not attribution from the artifact.
  • Splitting under the branch model (git-strategy G-005).

5 · Success criteria

Technology-agnostic, measurable outcomes.

With git.trailers=on, committing a reviewed spec produces a footer carrying Author: and Reviewed-by: taken verbatim from the populated <spec-meta> fields, with zero manual re-keying.

With git.trailers=off (default), no commit carries any trailer.

A commit for an AI-coupled verb carries exactly one Assisted-by: <model> line; a deterministic verb's commit carries none.

No commit carries an AI/model identity in an Author, Co-authored-by, Reviewed-by, or Acked-by line — auditable across a corpus of generated commits.

A trailer whose source field is absent does not appear, and its absence never fails the commit (verified by committing an artifact with an empty Reviewers / no dispositioner).

6 · Assumptions

The git committer identity (git user.name/user.email) is available to compare against the artifact's human author for the Co-authored-by decision (FR-004).

The assisting model's identity is obtainable at commit time (from the AI provider in use, or config) for Assisted-by; when it isn't, the trailer is omitted (FR-005 edge case). The two contract amendments (FR-008, FR-009) land via the normal propose/apply path as this slice's tasks.
