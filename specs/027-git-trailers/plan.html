Implementation plan · 027-git-trailers

Git trailers — attribution from the artifact

How we will build it.

Status Accepted Spec 027-git-trailers Owner Brian Corbin · @briancorbinxyz Branch 027-git-trailers Created 2026-06-30 Read time

Extend 026's git layer with a trailers.ts module that, when git.trailers=on, gathers attribution from the artifact's <spec-meta> + the verb + the assisting model and writes them with git commit --trailer. Three small ripples: extend extractSpecMetadata for the header fields, expose model on the AIProvider interface, and ship two contract amendments (the Acked-by source + the CONTRIBUTING policy) first. Biggest risk: the cross-package AIProvider change.

4 · Approach

Add one module, packages/cli/src/git/trailers.ts, exposing gatherTrailers(ctx) → an ordered list of {key, value}. It reads the written artifact's header via the extended extractSpecMetadata (Author ← Owner; Reviewed-by ← Reviewers; Co-authored-by ← a human author ≠ the git committer), the verb + provenance (Refs ← apply's archivedPath; Acked-by ← the dispositioner once captured), and the assisting model (Assisted-by ← ctx.model, set only by AI-coupled verbs). The human-only rule (FR-006) and omit-when-absent (FR-010) live here. commitForVerb, when git.trailers=on, calls it and passes the result to run.commit(subject, trailers), which emits a --trailer flag each.

Two contract amendments ship first, as tasks, via the normal propose/apply path: REQ-CHANGE-004 gains a dispositioner record (the Acked-by source), and CONTRIBUTING's blanket "no AI-attribution trailers" softens to permit Assisted-by while keeping authorship human. The AIProvider interface gains readonly model so the assisting model is sourced from the provider that actually ran, not a config value that can drift.

6 · Decisions

D-001 · Render trailers with git commit --trailer

Status
Accepted
Context
Verified by spike in a tmp repo (git 2.53; flag is git ≥ 2.32): one --trailer "k: v" per line yields a correct footer. run.ts:66 currently passes a single -m.
Decision
run.commit(subject, trailers) appends one --trailer flag per entry. No manual footer assembly, no second process.
Consequences
+ Git owns RFC-correctness + dedup. − Requires git ≥ 2.32 (R1); interpret-trailers is the documented fallback.

D-002 · Extend extractSpecMetadata for the header fields

Status
Accepted
Context
packages/schema/src/extract.ts:51-83 parses specId/fr/nfr/sc but not the <spec-meta> header (Owner/Author/Reviewers). It already has parse5 helpers (findAll/getAttr/textOf).
Decision
Add owner/author/reviewers to SpecMetadata and populate them from the <b>…</b><span>…</span> header pairs. One canonical extractor, reused by the git layer.
Consequences
+ No fragile regex; benefits any future header consumer. − A schema-package change (covered by its own tests).

D-003 · Expose model on the AIProvider interface

Status
Accepted
Context
ClaudeProvider holds a private model (claude.ts:55,66); the AIProvider interface omits it; StubAIProvider has none. Assisted-by must name the model that actually ran.
Decision
Add readonly model: string to AIProvider. ClaudeProvider returns its configured model; StubAIProvider returns a deterministic id (e.g. stub-model) so Assisted-by presence is testable end-to-end.
Consequences
+ The recorded model can't drift from the one used. − A cross-package interface change rippling to both providers (R2; small, typed, test-caught).

D-004 · A trailers.ts gatherer; commitForVerb passes the result

Status
Accepted
Context
CommitContext (index.ts) lacks the meta/model/provenance trailers need; the layer is otherwise a clean projection.
Decision
New pure gatherTrailers(ctx) → {key,value}[], applying the human-only (FR-006) + omit-absent (FR-010) rules; CommitContext gains optional model + refs; commitForVerb gates on git.trailers and passes the list to run.commit.
Consequences
+ Pure, unit-testable gathering separate from the effectful commit. − Each AI-coupled verb wiring must pass model; apply must pass archivedPath.

D-005 · The two contract amendments ship first, as tasks

Status
Accepted
Context
Acked-by (FR-007) has no source until REQ-CHANGE-004 records the dispositioner (FR-008); Assisted-by contradicts CONTRIBUTING's ban until amended (FR-009). The reviewer-capture amendment this session proved the propose/apply path.
Decision
Phase 1 tasks: a /propose+/apply against 000 amending REQ-CHANGE-004, and the CONTRIBUTING edit. The trailer code reads the new field only after it lands.
Consequences
+ No code reads a field that doesn't exist yet. − 027 spans two contract changes + the feature (the accepted larger slice; complexity §9).

D-006 · Committer + Refs sourcing

Status
Accepted
Context
git config user.name/email reads cleanly (spike); apply's result.archivedPath is the Refs target.
Decision
run.ts gains a committer() read for the Co-authored-by author≠committer test; the apply wiring threads archivedPath into the commit context as the Refs source.
Consequences
+ Both sources are local, no network. − One more read per commit (negligible, NFR-001).
