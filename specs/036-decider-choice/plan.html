Implementation plan · 036-decider-choice

Decider-routed choices

How we will build it.

Status Accepted Spec 036-decider-choice Owner Brian Corbin · @briancorbinxyz Branch 036-decider-choice Created 09 Jul 2026 Read time

Add decideChoice(cfg, questions, ai) to the decider module — human passes through to ai.ask, agent runs one subagent that returns a chosen label per question, panel runs N (effort-sized, concurrent) and majority-votes each. Route confirmRice and escalateLayer's ai.ask calls through it with a human default, so nothing regresses. The CLIs read the project decider config and thread it in. Low risk — a role-dispatch over the existing Question type, guarded by human-default parity tests.

3 · Approach

decideChoice(cfg, questions, ai) dispatches by role. human returns ai.ask(questions) verbatim — the default pass-through, so parity is definitional. agent builds a choice prompt from the Question[] (each header + labelled options), runs one subagent, and parses a {header: label} JSON answer, falling back to the first option on an invalid label. panel runs N (= effortToDepth(effort).voters) such subagents concurrently (mapPool) and majority-votes each header, tie-breaking to declared order. confirmRice and both escalateLayer asks call decideChoice with a cfg threaded from the caller (default human); the triage + slice CLIs resolve the project decider config and pass it.

4 · Decisions

D-001 · decideChoice — a role-dispatch over Question, human = pass-through

Status
Accepted
Context
confirmRice/escalateLayer hard-code ai.ask (rank.ts:24, classify.ts:102). The Question type + arbitration already exist.
Decision
A new decideChoice(cfg, questions, ai): Promise<Record<string,string>>. human → ai.ask (identical result shape → parity, FR-006); agent → one subagent picks; panel → N vote by majority header-wise (FR-001).
Consequences
+ Same return type as ai.ask, so call sites change one line.
− A subagent choice-prompt + label parsing to author.

D-002 · No self-judging by construction

Status
Accepted
Context
An agent accepting its own RICE estimates would be circular (033 FR-006).
Decision
decideChoice only ever runs fresh subagents against the question; it never receives a prior author's own output to ratify. In the slicer pipeline the estimator (panelScore) and the accept-decider (confirmRice) are separate calls — distinct invocations (FR-004).
Consequences
+ The guardrail holds structurally; a test asserts the accept-decider is a separate subagent call.
− none material.

D-003 · Thread cfg from callers; CLIs read project config

Status
Accepted
Context
escalateLayer runs inside triageFanout/triageCommand; confirmRice inside sliceCommand.
Decision
Add an optional DeciderConfig param to confirmRice/escalateLayer (default {role:'human'}), threaded from TriageInput/SliceInput. The triage + slice CLIs call loadDeciderConfig and pass it. Per-verb flags are deferred (spec §3).
Consequences
+ Config-file rollout with no new flags; default human = parity.
− Two Input types gain a decider field.
