Specification · 036-decider-choice

Decider-routed choices

A bounded-choice checkpoint is a role too. Route the kernel's hard-coded ai.ask gates through the Decider, so a human, an agent, or a panel can answer — not just a human.

Status Accepted Spec ID 036-decider-choice Owner Brian Corbin · @briancorbinxyz Reviewers — Created 09 Jul 2026 Principlesv1.3.0 Parent Decider rollout Smallest demoableconfirmRice --decider=panel convenes voters who answer Accept/Adjust by majority instead of a hard-coded human prompt. Read time

033 made the critic checkpoint (propose's risk pass) a configurable Decider, and 035 the scoring panel. But the kernel's bounded-choice gates — confirmRice ("Accept the RICE inputs?") and the triage hedge gate escalateLayer — still hard-code ai.ask, i.e. always a human. This slice adds decideChoice, the ask-shaped sibling of decide: human → ai.ask (unchanged default), agent → one subagent picks, panel → N vote by majority (effort-sized). The two checkpoints route through it. The no-self-judging guardrail matters here: an agent accepting its own RICE estimates would be circular, so the choice-decider is a distinct invocation from the author. The slash-command interviews stay out — they call the harness tool, not the kernel.

1 · Context

033's premise — "a checkpoint is a role, not a person" — was proven for the two generative checkpoints: propose's adversarial critic (033) and the slicer's scoring panel (035). But the kernel also has bounded-choice checkpoints that ask a person to pick an option: confirmRice (slice/rank.ts) asks "Accept the estimated RICE inputs?"; escalateLayer (triage/classify.ts) asks a hedged item's diagnostic-vs-routing category and then its layer. Both hard-code ctx.ai.ask — always a human.

035 wrongly deferred these as "stays a human confirmation." They are exactly the "who decides" seam the Decider exists for — just answering a choice rather than producing findings. This slice corrects that: the choice checkpoints become decider-routed, so a hands-off run can let an agent or panel answer while a human stays the default.

Who this is for: the maintainer configuring an unattended pipeline who needs the RICE-accept and triage-hedge gates answerable by an agent or panel — with a human still the default, and never an agent rubber-stamping its own work.

2 · User scenarios & testing

Each story is independently testable: implementing only US1 still yields a viable MVP.

US1 · A choice checkpoint has a configurable decider P1

As a maintainer, I want the RICE-accept and triage-hedge gates to consult the configured decider so that a human, agent, or panel can answer, not just a human.

Acceptance: decideChoice answers a bounded choice by role — human via ai.ask, agent via one subagent, panel via N effort-sized subagents whose majority option wins; confirmRice and escalateLayer route through it.

US2 · The default stays human, unchanged P1

As a maintainer, I want the default behaviour to be exactly today's human prompt so that nothing regresses for anyone not opting in.

Acceptance: with no decider config, both checkpoints call ai.ask with the same questions as today and return the same result shape (029 + triage parity).

US3 · No agent judges its own work P1

As a maintainer trusting an agent decider, I want the choice-decider to be a distinct invocation from the author so that an agent can't rubber-stamp the estimates it produced.

Acceptance: when confirmRice runs an agent/panel decider, the decider subagent(s) are separate calls from the RICE estimator; the guardrail holds by construction.

Edge cases

  • Panel of one. A panel at an effort yielding 1 voter degrades to a single agent — no empty vote.
  • Tie. A tied choice vote resolves to the first option in declared order (deterministic), or escalates to human under the escalation guardrail.
  • No provider. Without an AIProvider, agent/panel fall back to human.
  • Slash-command interviews. The spec/plan/propose/triage decision-phase interviews call the harness AskUserQuestion tool, not a kernel ai.ask — no seam to route; unchanged, out of scope.

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) per RFC 2119.

Functional

A decideChoice(cfg, questions, ai) capability MUST answer a bounded-choice checkpoint by role: human → ai.ask; agent → one subagent selects an option; panel → N effort-sized subagents whose majority option per question wins.

confirmRice MUST route its Accept/Adjust question through decideChoice.

escalateLayer MUST route its diagnostic-vs-routing and layer questions through decideChoice.

An agent/panel choice-decider MUST be a distinct invocation from the author whose output it judges — an agent MUST NOT accept its own RICE estimates (no self-judging, per 033 FR-006).

Choice deciders MUST resolve role + effort through the same precedence and effort table as the critic checkpoints — one resolution path (033 FR-002, 034), not a parallel one.

With no decider config, both checkpoints SHOULD behave exactly as today — the same ai.ask questions, the same result — so nothing regresses at the default.

Non-functional

Panel choice voting SHOULD be deterministic given fixed votes: a stable majority with a declared-order tie-break.

Out of scope (deferred)

  • The slash-command decision-phase interviews — they call the harness AskUserQuestion tool from the in-host LLM, not a kernel AIProvider.ask, so there is no seam to route.
  • Per-verb --decider/--effort flags on the slice and triage CLIs — this slice reads the project decider config for the choice checkpoints; flags can follow.
  • W-1 consuming the now-uniform choice + critic checkpoints to run unattended.

4 · Data model

No new persisted entity — decideChoice is a role-dispatch over the existing Question type and AIProvider.

Entities

Choice
A bounded question (the existing Question: prompt, header, labelled options) plus the role's answer (the chosen label per question).
Choice verdict
The chosen option(s) + who chose (role, and for a panel the vote tally) — the ask-shaped analogue of the critic Verdict.

The Decider now spans both shapes it always implied: generate-and-arbitrate (decide — critics, scorers) and choose (decideChoice — bounded gates). Same roles, same effort table, same guardrails; two answer shapes.

5 · Success criteria

With --decider=panel, confirmRice convenes the effort-sized voters and returns the majority option — observable by counting subagent invocations and the returned choice.

At the default (human, no config), confirmRice and escalateLayer call ai.ask with the same questions and return the same result as before this slice (parity).

Under an agent decider, confirmRice's accept decision is a distinct subagent invocation from the RICE estimator — no self-judging, observable.

escalateLayer's hedged-layer resolution honours the configured decider — an agent/panel resolves the layer instead of a human, when configured.

6 · Assumptions

The existing Question type (prompt / header / labelled options) is a sufficient contract for a subagent to answer a bounded choice; the agent returns a chosen label per header.

Routing confirmRice/escalateLayer through decideChoice with a human default is behaviour-identical to the current direct ai.ask — the human path is a pass-through.
