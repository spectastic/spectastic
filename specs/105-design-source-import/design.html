Status Accepted Spec 105-design-source-import Owner Brian Corbin · @briancorbinxyz Branch spec/visual-slice-095-098 Created 13 Aug 2026 Read time

An import reads an export already on disk, lands a token file, renders and any annotations into the sidecar, and then disappears — a property proved by deleting the source folder and revalidating. Four rules are transferred from the corpus importer rather than invented, including the one it learned twice: hand edits survive except where the export owns the field, because protecting a field that does have a source of truth silently desynchronises the copy from the thing it copies.

6 · Approach

A fetcher seam resolves a source location to a local directory — for a local export that is the identity function, which is exactly why one code path serves five tools. A single execute pass reads what is there, lands a token file, renders and annotations into the sidecar with provenance on each, and marks everything not-yet-reviewed. Where the source emitted an artifact rather than design data, the AI port derives token candidates from the stylesheet and they land marked as inferred, for confirmation.

Almost nothing here is invented. Four properties are transferred from the corpus importer — the fetcher seam, the never-destructive re-import, the never-guess provenance, and the trust downgrade — and the fifth is the one that repository learned the hard way: hand edits survive except where the export owns the field. Protecting a field that has a real source of truth is how a copy silently stops matching the thing it copies.

The thing deliberately not built is a live read path. Three of the five sources expose one, and using it would make a spec only as available as somebody's seat — and this repository has never built a client for that protocol, which would make the first one a dependency of the visual slice.

The hybrid looks like the safe middle and is the worst of the three to maintain: it needs the client built, tested and kept working against somebody else's API, and the fallback path is the one that actually runs everywhere. The claim that two of five sources have nothing persistent to query was wrong: at least one exposes project, file-listing and file-reading calls, and the editor ships a client for them. The decision stands on portability alone, which is the argument that survives — a spec should not be only as available as somebody's seat.

8 · Decisions

D-001 · A local export only, behind a fetcher seam

Status
Accepted
Context
A live read path exists and is more available than this scored it — the “two have nothing persistent to query” half was asserted and is false, corrected 18 Aug after reading the tool's own contract. The alternatives table scored a live path low partly on that premise; it should have scored low on portability alone. The corpus fetcher is already shaped as a seam whose docstring says it exists so the install door never touches a real network in tests.
Decision
Read a directory already on disk, behind a seam. No protocol client is built.
Consequences
+ One code path for five tools, and no seat, rate limit or API version in a spec's dependency graph. + Nothing to keep working against somebody else's roadmap. − A designer has to export, which is a manual step this cannot remove. − If a tool drops export, that source is lost entirely rather than degraded.

D-002 · Hand edits survive, except where the export owns the field

Status
Accepted
Context
The corpus learned both halves the hard way: a merge policy protected a field that had a real source of truth, and the copy silently stopped matching the thing it copied.
Decision
A field the export owns is re-derived on every import. Everything else is hand-edit-protected.
Consequences
+ A fix in the export reaches the project. + A note somebody added by hand is not clobbered. − Which fields the export owns is a judgment, and getting it wrong fails in one of the two directions this decision exists to name.

D-003 · Everything lands marked not-yet-reviewed, and inferred values doubly so

Status
Accepted
Context
The corpus marks newly registered references not-yet-spot-checked and says so at the command line. An import is a bulk arrival of somebody else's decisions.
Decision
Landed material carries a review marker; derived values additionally carry an inferred marker and never outrank a declared value.
Consequences
+ The moment imported material looks identical to authored material is the moment nobody reviews it. + Declaration over inference stays true in practice and not only in the file. − Two markers is more ceremony than one, and a project that ignores both gets no protection from either.

D-004 · A re-import that would change identity is refused

Status
Accepted
Context
The corpus had a configuration change silently re-key material and mint a second identity for one thing.
Decision
Refuse loudly, naming both identities.
Consequences
+ A fork that happens quietly is worse than a refusal that happens loudly. − An intentional re-identification needs a deliberate step, which is the trade.

11 · Complexity tracking

A fetcher seam for a case that needs none. A local directory needs no fetching, so the seam is pure structure today. It buys two things: the tests never touch a real filesystem layout they do not control, and a future source with a different resolution story is a new implementation rather than a change to the importer. The corpus made the same trade and its docstring records the same reason.

12 · Open questions

None outstanding. The two decisions worth recording are refusals — no live protocol, because it makes a spec only as available as somebody's seat and would make this repository build its first client for that protocol; and no vision, because the sources that emit an artifact emit a stylesheet, which is text.
