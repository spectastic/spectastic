Contract export handover

Ordered, parallelizable work. Tests precede implementation. Drive through with /spectastic.implement — one task per invocation.

Status Accepted Spec 076-contract-export-handover Design design Branch main Created 01 Aug 2026 Read time

21 tasks across five phases. Requires 070's reader and 071's promotion hook — the deepest dependency in the cohort, so drain it last. Foundational refactors 067's URI composer, so its first task is a regression net proving existing spec URIs come out byte-identical.

1 · Execution strategy

US1 — a consumer resolves a contract by coordinate — is the headline and is demoable alone. Notification and routing follow.

Setup → Foundational → US1 → US2 → US3 → Polish. Recommended. The coordinate must be right before anything is emitted against it, since a published address cannot be taken back.

Workable in two after Foundational: the notification half (US2) touches core and promotion, while the resolution command and recipes (US1, US3) touch the CLI and docs.

3 · Phase 2 — Foundational

Generalising a shipped composer that 067's guarantees depend on. The regression net comes first — an existing spec URI must not move by a single byte.

Tests (write & fail first)

Implementation

Lift the kind segment to a parameter — resourceUri(project, kind, name, anchor?), with specResourceUri kept as a wrapper so no existing caller changes, per D-001. packages/schema/src/project-shared.ts
Add contractResourceUri — the sibling kind 067's design anticipated. packages/schema/src/project-shared.ts

Mechanism for FR-001 and NFR-001; the coordinate every other task addresses.
