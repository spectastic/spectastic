Cards

Nothing tells an author where a product principle goes, and one placement breaks numbering

Spec upstream

Debugging where to add a product principle to a profile-seeded constitution, root cause was that the sentinel's semantics are documented nowhere the author looks and the two available placements behave differently; fixed by saying so in the seeded file; regeneration fails, because a careful author reading the artifact today has nothing to go on and a coin-flip decides it.

Expected
An author adding a principle to a seeded principles.html can tell where it belongs.
Actual
The file carries <!-- spectastic:principles-start --> and <!-- spectastic:principles-end --> and says nothing about them. Neither the template nor the principles command mentions them. I guessed wrong twice while authoring a real downstream constitution — first assuming the region was rewritten on upgrade, then finding it is not.
Diagnosis
spliceUpgrade is additive: it inserts before the end marker and never rewrites what is between them, so nothing inside is at risk. But it numbers additions from the highest P-N anywhere in the file, so a principle placed after the end marker is numbered below principles later inserted before it — source order and numeric order disagree from the first tier upgrade onward. Both placements are safe; only one keeps the ordering true, and nothing says which.
Fix
packages/cli/src/commands/init/compose.ts — emit a one-line comment beside the start sentinel in the seeded file saying that hand-authored principles belong inside it, before the end marker, and why. Cheaper and better-targeted than documenting it in the command, since the author is reading the artifact rather than the markdown.
Deep dive — scope

Not a defect in the splice, which behaves correctly and idempotently. The gap is that a machine-managed region in a hand-edited artifact carries no instructions for the hand editing it — and the failure is silent and deferred, appearing only at the next tier upgrade, long after the choice was made.
