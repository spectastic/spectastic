Cards

Composed principles.html used ../assets/ instead of root-relative assets/

Implementation code

Debugging a broken stylesheet/script load in a project scaffolded with init --profile, root cause was implementation drift — the composer never rewrote the template's ../assets/ paths for the project-root destination; fixed by a one-line rewrite in renderPrinciplesHtml; regeneration passes (the 041 spec/plan don't mandate the rewrite, so the gap is code, not contract).

Expected
principles.html at the project root links assets/spec.css (next to the init-copied assets/ dir).
Actual
It linked ../assets/spec.css — one level above the project root — so CSS/JS 404'd when opened.
Diagnosis
compose.ts:renderPrinciplesHtml read templates/principles.html (which previews from one level down, so uses ../assets/) and filled it without the depth rewrite the /spectastic.principles verb documents. FR-002.
Fix
packages/cli/src/commands/init/compose.ts — html.split('../assets/').join('assets/') after reading the template. Landed with a regression test (compose.test.ts). ✓ done.
// rewrite template's ../assets/ to root-relative assets/ for the project-root file html = html.split('../assets/').join('assets/');
Deep dive — verification-discipline note

No cross-spec contract, no invariant, no hotfix needed. Worth recording why the original 041 browser verification missed this: the check served the file over http.server, which clamps a leading ../ back to the web root, so ../assets/spec.css happened to resolve. Presence- when-served is not correctness-in-context (the CLAUDE.md "presence is not containment" lesson). The regression test now asserts the literal path, not a served render.
