Add the contracts axis to every profile

The profile vocabulary names how a project verifies, enforces, toggles, grounds, and frameworks — but not the shape of its public contract. This adds the sixth axis.

Each profile is a preset composition of five axes — verification · enforcement · toggles · grounding · frameworks. The engineering-principles considerations doc found this vocabulary covers verification, enforcement, and grounding but says nothing about the "shape and contract of the system" family — even after contract-first + Library-first landed as principles at standard (the lean-four catalog). This proposal adds the sixth axis, contracts, expressing per-tier contract-rigor posture on a scale (informal → contract-first → contract-checked → versioned+governed), so the vocabulary mirrors the landed principle the way the enforcement axis already mirrors the enforce categories. It is advisory vocabulary (a data label, like the existing five); the machine teeth — a "public interface has a checked-in schema" check — remain the separate TBD-contract-first-enforce. A pure data/content delta (T-018): no requirement changes; the manifest edit + a drift-guard assertion are the §6 tasks.

Add the contracts axis to every profile

Applied

1 · Intent

041's profiles are, by FR-001, preset compositions of a fixed axis vocabulary — the five axes are the tiering language the whole profile system speaks. The engineering-principles considerations pass found that this language has a hole exactly where agent code needs it most: it can express how rigorously a tier verifies or enforces, but nothing about the shape and contract of the system — the public interface a second consumer (or a producer/consumer pair of agents) depends on. Contract-first and Library-first landed as principles at standard in the lean-four catalog, but a principle with no matching axis label leaves the vocabulary lopsided: a reader scanning a profile's axes sees enforcement: lint+types+tests and can infer the enforce posture, but has no axis telling them the contract posture.

This adds the sixth axis, contracts, so the vocabulary is complete and the landed contract-first principle has the axis label it implies — the same relationship the enforcement axis has to the enforce categories. The axis is vocabulary, advisory by construction (like all five existing axes, it is manifest data that no code gates on today); where a guarantee is warranted the durable form is an enforce category or validate rule, which is the separately-tracked TBD-contract-first-enforce, not this label.

2 · Scope

In scope

  • ADD a contracts key to the axes map of all four profiles in spectastic-profiles.json, with a posture-scale value per tier (informal / contract-first / contract-checked / versioned+governed).
  • A drift-guard assertion that every profile carries the contracts axis (extends the existing axes test).

Out of scope

  • The machine teeth — a "public interface has a checked-in OpenAPI/schema" enforce category or validate rule. The axis is advisory vocabulary; the guarantee is a separate slice mirroring the coverage/observability principle→category split.
  • Surfacing the axes anywhere (AGENTS.md, an init summary). The five existing axes are manifest data that nothing renders today; this addition matches that posture. Rendering the whole axis vocabulary is a distinct enhancement, not scoped to closing this hole.

3 · Approach

A single data/content delta whose target= names the manifest key path (all-profiles/axes-contracts, not a requirement id) and embeds a <spec-diff> — so on /spectastic.apply it makes no change to 041's requirements body (T-018 / REQ-CHANGE-002): the real manifest edit is a §6 task drained by /spectastic.implement, and apply only folds the task phase + changelog + archives. No FR is modified because the axes are not behaviorally consumed — adding a key is consistent with the existing profiles-are-axis-compositions contract, not a change to it.

The posture-scale values ladder the way the considerations doc tiers the contract family: lean is a throwaway spike with no stable contract (informal); standard is where contract-first starts earning its keep, the checked-in schema as the interface's spec (contract-first); verified foreshadows the enforce teeth — the schema is machine-verified present (contract-checked); and enterprise ratchets to audited strictness — semver'd and backward-compat governed (versioned+governed). The scale style matches the verification/grounding axes.

No adversarial risk pass: the REQ-CHANGE-004 heuristic does not fire — the delta touches no must-tier requirement (it embeds no requirement at all), carries no removed op, and spans a single topic. An additive, advisory vocabulary label on a manifest is exactly the low-risk shape the heuristic is tuned to skip.

4 · Deltas

What's added: a contracts key in each profile's axes map in spectastic-profiles.json. A data/content delta (target names the manifest key, embeds a <spec-diff>, no requirement-body change). Purely additive and revert-safe — no existing axis or enforce value is touched.

lean.axes.contracts: "informal" standard.axes.contracts: "contract-first" verified.axes.contracts: "contract-checked" enterprise.axes.contracts: "versioned+governed"
Rationale — the posture ladder

informal: a spike has no stable public contract. contract-first: at standard, once a second consumer exists, a checked-in schema is the interface's spec (the landed principle). contract-checked: at verified, the schema is machine-verified present — the axis foreshadowing TBD-contract-first-enforce. versioned+governed: at enterprise, semver'd and backward-compat governed to audited strictness. The vocabulary now mirrors the contract-first principle the way enforcement mirrors the enforce categories.

5 · Risk register

No adversarial pass ran (see §3): the heuristic does not fire on a single additive data/content delta that embeds no requirement, touches no must-tier requirement, and spans one topic.

None — an advisory vocabulary label with no behavioral consumer carries no regret surface beyond the value wording, which was anchored in the interview (name contracts, posture scale).
