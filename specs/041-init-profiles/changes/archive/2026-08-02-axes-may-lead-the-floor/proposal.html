Change proposal · 041-init-profiles

Axes declare posture and may lead the floor

Two specs own two halves of one idea and neither owns their relationship. This gives the relationship a home, and says which half is a promise.

Status Applied Change ID 2026-08-02-axes-may-lead-the-floor Spec 041-init-profiles Source Triage: 042 T-004 (cross-spec, regen fail); resolution (c) of the three the card names Author Brian Corbin · @briancorbinxyz Created 02 Aug 2026 Targets 1 added (FR-010); no manifest data changes Read time

The contracts axis says contract-first at standard, but the contract-first enforcement category only enters enforce.required at verified — so a standard-profile project is told it holds a posture no gate enforces. Triage 042 T-004 named three resolutions and left the choice to the owner. This takes the third: state the relationship rather than move either value. Axes are declared posture and MAY run ahead of the enforced floor; where they diverge that is deliberate, and an axis value alone is never a guarantee. Adds one requirement, changes no manifest data, and moves no drift-guard assertion — the axis already leads the floor at verified and enterprise too, so this is the only resolution that describes the ladder as it actually is rather than truncating it at one rung.

Axes declare posture and may lead the floor

Applied

1 · Intent

041 landed the six-axis vocabulary as advisory — the manifest's own $comment says so, and the contracts axis in particular arrived as a pure data delta with its machine teeth explicitly deferred. 042 independently set the enforcement floor per tier. Both are internally correct. Neither states what the other means for it, and the gap shows most sharply at standard:

Tiercontracts axiscontract-first in enforce.required
leaninformalnoconsistent
standardcontract-firstnoa full rung with nothing beneath it
verifiedcontract-checkedyesaxis leads by a rung
enterpriseversioned+governedyesaxis leads by two rungs

The triage card's regeneration test fails, and the reason is the point of this change: neither spec states that the axis and the floor must agree, so any future session would re-seed exactly this mismatch. The defect is not a wrong value — it is a missing relationship. Fixing a value would leave the relationship still unstated and the same bug free to recur under a different axis.

Note also that the axis leads the floor at three of the four tiers, not one. Truncating standard to informal would make one row consistent and leave two rows in exactly the condition being called a defect. Only stating the relationship addresses all three.

2 · Scope

In scope

  • One new requirement in 041 giving the axis-to-floor relationship an owner: axes declare posture, MAY lead the floor, and are never a guarantee on their own.
  • A drift-guard confirming no enforcement path consumes an axis value, so the "never a guarantee" clause has a machine floor rather than only prose (P-8).
  • A check that composed profile output does not describe an axis in language implying a gate enforces it.

Out of scope

  • Changing any manifest value. spectastic-profiles.json is untouched, and the per-tier drift-guard assertions in packages/cli/test/init/profiles.test.ts stay exactly as they are.
  • Tightening any enforcement rung. Admitting contract-first to the standard floor is resolution (b), deliberately not taken — it would newly gap real projects. 074 already sharpened the verified rung on its own terms.
  • Making axes machine-consumed. The whole point of the requirement is that they are not.

3 · Approach

State the relationship in the spec that owns the vocabulary. 041 defines the axes, so 041 is where their epistemic status belongs — what an axis value claims, and what it does not. 042 keeps sole ownership of what is enforced, and needs no amendment: nothing it says becomes untrue.

The requirement is a semantic clause, but it is not unfalsifiable. It has one directly checkable consequence — no enforcement path may read an axis value — and today that already holds: a repository-wide search for .axes finds exactly one non-test reference, an unvalidated pass-through in the profile loader. A drift-guard pinning that keeps a future session from quietly wiring an axis into a gate and re-creating the confusion in the opposite direction, where a value does gate but only sometimes. That is the P-8 half: the clause is advisory about intent, and the one mechanical consequence it implies is enforced rather than trusted.

4 · Deltas

One delta. target= names the new requirement id in the live spec.

A profile's axis values MUST be read as declared posture — the rigor a tier aspires to — and MAY run ahead of the enforcement floor that tier requires. Where an axis leads the floor the divergence is deliberate and MUST NOT be treated as a defect in either spec. An axis value alone MUST NOT be read as a guarantee that a gate enforces it, and no enforcement decision MUST be derived from one.

Rationale

041 owns the axis vocabulary and 042 owns the enforced floor; before this, nothing owned their relationship, so a tier could advertise a posture with no gate behind it and no spec was wrong. Surfaced by triage 042 T-004, whose regeneration test fails precisely because the relationship is unstated — a future session reading either spec alone would re-seed the same mismatch. Stating that axes lead deliberately keeps the ladder aspirational (its purpose: a tier's axis is what a project is working toward, which is why versioned+governed can sit at enterprise before any tooling checks governance) while removing the implication that a value is a promise. The final clause is the machine-checkable half: an axis that never drives an enforcement decision cannot silently become a gate.

5 · Risk register

The proposal adds a must-tier requirement, so the adversarial pass applies. Two findings survived; the third candidate — that the change is merely cosmetic — was dropped after the drift-guard consequence made it falsifiable.

Legitimising the gap at every tier removes the pressure to ever close it, so an axis could stay decorative indefinitely — versioned+governed at enterprise with nothing checking "governed" becomes permanently acceptable rather than a known debt.

"Where an axis leads the floor the divergence is deliberate and MUST NOT be treated as a defect in either spec."

Real, and partly intended — an aspirational ladder that may never be fully backed is what an aspirational ladder is. The mitigation is that stating the relationship makes a rung's backing a deliberate, per-rung decision rather than an accident: 074 tightened contract-checked at verified on exactly that footing, and it could do so because the rung's meaning was nameable. The alternative reading — that every axis value must eventually be gated — was never 041's intent and would make the vocabulary unable to describe anything not yet buildable.

A downstream project reading contracts: contract-first in its own composed profile will reasonably believe a gate enforces it. The requirement binds how this project's specs are read; it does nothing about the copy a downstream reader actually sees.

"An axis value alone MUST NOT be read as a guarantee that a gate enforces it."

The sharper of the two. A requirement about interpretation is worth little if the surface implies the opposite, and this is the same class of gap P-10 records about copy generally. Addressed as a task rather than a second requirement: the composed profile output is checked for language implying enforcement, and reworded where it does. Scoped to output this project generates — a downstream project's own prose remains unseeable, which is the honest ceiling and the same one the copy-leak rule already records about itself.
