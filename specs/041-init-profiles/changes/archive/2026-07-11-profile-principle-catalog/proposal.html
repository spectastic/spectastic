Change proposal · 041-init-profiles

Seed the shape-of-system engineering principles at standard

A profile already ladders rigor. Give it a lean constitution to ladder — the four principles that hand an agent a fixed target and bound its blast radius.

Status Applied Change ID 2026-07-11-profile-principle-catalog Spec 041-init-profiles Source Considerations: engineering-principles §6 · ranked in roadmap R-001 Phase 1 Author Brian Corbin · @briancorbinxyz Created 11 Jul 2026 Targets 1 added (standard principle preset in spectastic-profiles.json; no numbered FR changes) Read time

The profile manifest ladders five axes but its seeded principles[] presets carry almost none of the engineering canon that shapes a maintainable system. This change adds the lean-four shape-of-system principles to the standard preset — contract-first interfaces, Library-first boundaries, secure by default, least privilege — repeated into verified and enterprise so the ladder stays cumulative. These are the ones that hand an agent a checkable target (a contract, a testable core) or bound its blast radius (safe defaults, least privilege). All are advisory (P-8 / T-009); the machine-checkable teeth ship later in their own phases. No numbered requirement changes: FR-001..FR-009 govern the profile mechanism; this changes the seeded profile data. The broader §6 rows (semver, supply-chain, accessibility) and the observability/SLO rows are deferred to their own passes after the adversarial review below argued the full set fights this spec's own "lean skeleton" founding.

Seed the shape-of-system engineering principles at standard

Applied

1 · Intent

Spectastic is the one SDD tool whose profiles can tier a constitution by rigor — yet the bundles ship a near-empty principle set, so the capability sits unused. The engineering-principles survey found that the canon most worth seeding for agent-authored code is the set that hands the agent a fixed, inspectable target: contract-first interfaces and Library-first boundaries above all, then the blast-radius bounds — secure-by-default and least-privilege — that matter the moment an agent holds tools. Those four are the highest-value, lowest-controversy additions, and they lead the §6 table.

The survey lists more at standard (semver, supply-chain hygiene, accessibility) and the observability survey adds an operate-it-in-production layer (golden signals at verified, SLOs at enterprise). The adversarial pass on the first draft of this proposal argued — citing this spec's own §1 finding that "generated guidance files measurably hurt" — that seeding all of it at once inflates the standard constitution against the very "lean skeleton" 041 was built to protect, and that folding a second survey's topic in erodes single-topic reviewability. Both were accepted: this proposal is trimmed to the lean-four catalog, and the remaining rows are deferred to their own passes (see §2).

Everything here is a principle: advisory, per the P-8 / T-009 discipline that a principle nudges and a gate guarantees. This ships the nudge; the enforce categories and validate rules that give these principles teeth are built against them in later phases.

3 · Approach

Pure data. combinedPrinciples() composes a profile's seeded principles.html as base + thisProfile.principles, deduped by name — there is no standard→verified→enterprise inheritance in the data (which is why the current verified and enterprise presets already restate "Tests accompany behavior"). So "contract-first at standard, cumulative upward" is achieved by repeating the entry in the standard, verified, and enterprise arrays. The four principles therefore appear in all three tiers. Composed lengths stay modest — standard ~10, verified ~12, enterprise ~14 — well short of the ~19 the full-seven draft would have produced.

The statements are written in the manifest's established voice — one or two sentences, imperative, agent-aware, no attribution, no internal ids — so they read as a project's own constitution once seeded. They restate rules in principles.html, not AGENTS.md: per FR-004, AGENTS points at enforcement commands, and the commands for these principles do not exist yet. That keeps this change honest about what it is — the advisory nudge — and leaves the guarantee to the later enforce/validate phases.

On SC-002. The criterion asks that pairwise principles.html diffs be non-empty and "trace to axis differences (e.g. …)". The four added here are constant across the upper tiers, so they are not inter-tier differentiators — the existing differentiators (the verification principle at verified, and the enterprise set) still carry the pairwise diffs, which stay non-empty. Read the "e.g." as illustrative: SC-002 is met. The one gap the repetition opens — three hand-maintained copies drifting — is closed by the drift-guard test in §2.

4 · Deltas

One additive delta: the four principles appended to the standard preset (data governed by FR-003, not a numbered requirement), repeated into verified and enterprise for cumulative inheritance. The drift guard is tooling (a test), tracked in §6, not a requirement delta.

What's added: four principles appended to the standard preset's principles[] in spectastic-profiles.json, and repeated into the verified and enterprise presets so the ladder stays cumulative.

Contract-first interfaces — A component that exposes an interface ships a checked-in contract (OpenAPI, JSON Schema, or a typed signature) before the code behind it. The contract is the agent's target and the consumer's guarantee. Library-first boundaries — Keep the reusable core separate from its entry point. Logic lives in a testable, importable library; the CLI, endpoint, or UI is a thin adapter over it. Secure by default — Safe defaults are the floor: no hardcoded credentials, secrets from the environment, authorization on by default. Every insecurity is an explicit, reviewed exception, never an accident. Least privilege — Grant the narrowest capability that does the job — to a service, a token, and an autonomous agent alike. Bound the blast radius before you widen the access.
Rationale — why these four, why standard

Contract-first and Library-first lead because a checkable contract and a testable core are exactly what an agent needs to aim at; secure-by-default and least-privilege bound the blast radius the moment an agent holds tools. All four are the always-on-for-agents subset of the §6 standard-tier rows, and the least controversial to seed by default. The maturity markers (semver, supply-chain, accessibility) and the operate-in-production layer (observability, SLOs) are deferred to their own passes — see §2. Secure-by-default hardens up the ladder through the existing security enforce category, not through a duplicated statement.

5 · Risk register

From the opt-in adversarial pass (the change seeds the constitution of every downstream project, so it earned a skeptic even though the auto-heuristic was borderline). All three findings were dispositioned in the review interview; each records the human who committed the transition.

Seeding all seven principles at the standard tier — the common default — inflates every standard project's constitution to ~13 principles (and the composed enterprise file to ~19), against this spec's own founding finding that "generated guidance files measurably hurt"; "Accessible by default" in particular lands as constitutional noise for the many standard-tier CLI/library/backend projects with no user-facing surface at all.

Mitigated. The standard set is trimmed to the lean-four — contract-first, Library-first, secure-by-default, least-privilege — the always-on-for-agents subset. Semantic versioning, supply-chain hygiene, and accessible-by-default are deferred to a later catalog pass (TBD-profile-principle-catalog-next). Composed enterprise principles.html drops from ~19 to ~14; the accessibility-noise-for-non-UI-projects concern is removed entirely.

The new inter-tier differentiators added here — structured observability at verified, SLOs at enterprise — trace to none of the five named axes (verification, enforcement, toggles, grounding, frameworks), straining SC-002's "trace to axis differences"; and the standard principles, hand-repeated across three arrays and deduped by name only, have no drift guard, so a later wording fix to one copy silently diverges.

SC-002 — pairwise diffs … trace to axis differences — versus the deferred TBD-profile-interfaces-axis and repeated-by-name array data.

Mitigated. The axis-trace half is defused by splitting observability/SLO out (Risk 3) — the remaining four are constant across tiers, not differentiators, so they need not trace to an axis; SC-002's "e.g." is read as illustrative and pairwise diffs stay non-empty (recorded in §3). The drift half is closed by a task adding a test that same-named principles carry identical statements across tiers (§2, §6).

Scope folds a second survey's topic — observability and SLOs, owned by observability-slo-considerations with its own TBD- slugs — into an engineering-principles §6 catalog change, justified by "one edit, not two," which is exactly the ≥2-topic-prefix condition that marks a proposal non-trivial and erodes single-topic reviewability.

§2 In-scope (draft) — ADD structured observability to the verified preset and ADD service-level objectives to the enterprise preset, sourced from a different survey than the standard principles.

Mitigated. The two observability/SLO deltas are removed from this proposal and deferred to a separate propose resolving TBD-observability-slo-principle (§2 out-of-scope). This proposal is now the single-topic engineering-principles catalog only.
