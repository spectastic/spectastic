Init profiles & agent guidance

Pick a profile at setup; get a constitution and an agent operating manual that match the project's ambition.

Spectastic authors principles, then stops — it never writes the AGENTS.md/CLAUDE.md a coding agent reads, and has no dial for ambition. This feature adds profiles — Lean · Standard · Verified · Enterprise, chosen at init --profile, each a preset composition of axes. Selecting one deterministically seeds a profile-shaped principles.html, a lean command-first AGENTS.md (canonical), and a thin CLAUDE.md pointer. Re-running is brownfield-safe: it amends in place (additive Lean→Verified upgrades included), never blind-overwrites. Enforcement teeth — resolving a profile's policy to real linters and gating on it — are a named follow-on; 041 scaffolds and advises.

1 · Context

spectastic init is a pure file-copy that points at /spectastic.principles. That verb authors a constitution, but the chain then breaks twice: nothing translates those principles into the AGENTS.md/CLAUDE.md a coding agent reads every session, and there is no dial for ambition — a throwaway script and a regulated service get identical (absent) treatment.

The design space is mapped in the considerations doc, whose pivotal finding is that the field has independently converged on P-8: guidance prose can't guarantee behaviour, and generated guidance files measurably hurt. So this spec builds the advisory, deterministic half — profiles that scaffold a lean skeleton — and defers the enforced half to a follow-on. Users are developers standing up a new project (greenfield) or retrofitting an existing one (brownfield).

2 · User scenarios & testing

Each story MUST be independently testable: if you implemented only US1, you would still have a viable MVP.

US1 · Pick a profile, get matching artifacts P1

As a developer starting a new project, I want to choose a profile at init so that my principles and agent guidance match the project's ambition from day one.

Acceptance: init --profile standard on an empty directory writes a seeded principles.html (with P-N anchors), a lean command-first AGENTS.md, and a CLAUDE.md pointing at it — no model call. This one profile end-to-end is the smallest demoable.

US2 · Choose from the full dial P2

As a developer, I want to select from Lean / Standard / Verified / Enterprise (or be prompted when I pass no flag) so that I can match ceremony to the project.

Acceptance: each profile yields a materially different principles preset and AGENTS.md skeleton; init with no --profile in a terminal prompts for one.

US3 · Re-run without clobbering (and upgrade) P2

As a developer on an existing project, I want to re-run a profile — including upgrading Lean→Verified — without losing my edits so that profiles are a dial I can turn as the project matures.

Acceptance: re-running against hand-edited artifacts surfaces any collision through init's existing per-file resolution and never blind-overwrites; a Lean→Verified re-run adds Verified's content additively.

Edge cases

  • Unknown profile name → init errors and lists the valid names.
  • Non-TTY with no --profile (CI) → init applies no profile (today's behaviour) and notes the skip, so existing CI calls don't break.
  • Existing richer CLAUDE.md → the thin pointer must not clobber it; the collision is surfaced.
  • Both --profile and --tools → each runs independently.

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional

init MUST accept --profile <name> for one of the four profiles; an unrecognised name MUST error and list the valid names.

Given a profile, init MUST deterministically write three artifacts — a principles.html seeded with that profile's principle preset, a lean AGENTS.md (canonical), and a thin CLAUDE.md pointing at AGENTS.md — with no AI/model call on this path (keeping init deterministic and CI-stub-testable; a curated skeleton, not a generated dump).

All four profiles MUST ship as data (a manifest), each a preset composition of the axes (verification rigor, enforcement posture, feature-toggle policy, grounding depth, framework expectations). Adding or editing a profile MUST NOT require code changes to a verb.

The generated AGENTS.md MUST be command-first and MUST point at enforcement commands rather than restate enforceable rules in prose (P-8); the CLAUDE.md MUST be a thin pointer to AGENTS.md, not a duplicate.

With no --profile: in an interactive (TTY) session init MUST prompt for one; in a non-TTY session it MUST apply no profile and note the skip.

Re-running where principles.html/AGENTS.md/CLAUDE.md already exist MUST amend in place — never blind-overwrite — surfacing collisions through init's existing per-file resolution.

Re-running with a different --profile SHOULD support an additive upgrade (e.g. Lean→Verified): the new profile's principles and guidance are added without discarding the user's edits.

--profile SHOULD be independent of the 031 --tools installer; passing both applies each, and a profile MUST NOT implicitly install the guarantee layer in this spec.

init SHOULD record the selected profile in a marker so re-runs (FR-007) and downstream tooling can read it.

Non-functional

The profiled init path MUST be deterministic and stub-testable — no network or model dependency — so CI runs it without a live LLM.

A generated AGENTS.md MUST stay within the guidance-file ceiling — no more than 150 lines and 32 KiB — carrying only what an agent can't infer from the code and manifests.

The profiled path SHOULD add under 500 ms p95 to greenfield init over baseline (excluding install/network).

Out of scope (deferred to other slices)

  • Plan-time enforcement resolver — the "Toolchain / enforcement" section that maps a profile's policy to the chosen stack's real linters/gates. Follow-on spec (042).
  • Per-promise gates (feature-toggle check, all-levels-tested, build-a-checker duty) — advisory prose in 041; enforced in 042.
  • Category-aware tool gap-fill — a plan-time enforcement concern; defers with the resolver (042).
  • /spectastic.principles becoming profile-aware. 041 bakes the preset deterministically; the verb stays unchanged.
  • Cross-tool guidance pointers (.cursor/rules, GEMINI.md). AGENTS.md is the cross-tool standard; per-tool pointers wait.

4 · Data model

Only the entities this feature owns or substantially changes.

Entities

Profile
A named record (one of the four) carrying axis values, a principles preset (starter P-* set), and an AGENTS.md skeleton. Ships as manifest data (FR-003).
Profile marker
A project-level pointer recording the selected profile (FR-009), read on re-run to drive the additive upgrade and later tooling.
Generated artifacts
The three files init emits/amends — principles.html (seeded), AGENTS.md (canonical), CLAUDE.md (thin pointer).

Invariant: profiles are data, not code, and are additive compositions of a shared base — an upgrade adds, never silently rewrites. Presets differ in content (e.g. Verified seeds an "every level tested; build a checker if none exists" principle that Lean omits). Exact preset content is a plan concern.

5 · Success criteria

Technology-agnostic, measurable outcomes.

init --profile standard on an empty directory produces exactly three files matching the Standard profile: a principles.html with P-N anchors, a command-first AGENTS.md within the NFR-002 ceiling, and a CLAUDE.md referencing AGENTS.md. (The smallest demoable.)

The four profiles yield materially different output: pairwise diffs of the seeded principles.html and AGENTS.md are non-empty and trace to axis differences (e.g. Verified carries a verification principle Lean omits).

Re-running against a hand-edited artifact never silently overwrites it: an introduced edit marker survives, or the collision is surfaced for the user to resolve.

An additive Lean→Verified re-run leaves earlier edits intact and adds Verified's principles — the post-upgrade principles.html contains both.

The profiled init path runs green in CI through the stub with no live model invoked.

6 · Assumptions

The existing init pipeline and its per-file conflict prompt are the right host for --profile, mirroring how --tools was added in 031.

Reversing the 021 AGENTS.md deferral is warranted now that it is a cross-tool standard read natively by 30+ agents — the trigger that deferral waited for.
