Implementation plan · 041-init-profiles

Init profiles & agent guidance

How we will build it.

Status Draft Spec 041-init-profiles Owner Brian Corbin · @briancorbinxyz Branch main Created 09 Jul 2026 Read time

Extend the existing init pipeline (buildPlan → resolveConflicts → executeWrites) with a --profile mode that composes three content-based writes from a data manifest (profiles.json) — a profile-seeded principles.html, a lean AGENTS.md, and a thin CLAUDE.md — reusing the current conflict prompt so it never blind-overwrites. The single biggest risk is the additive Lean→Verified upgrade (FR-007): merging principle blocks into an existing HTML file is the one non-trivial, fragile step, so it's marker-guarded and sentinel-anchored.

4 · Approach

Add a --profile <name> option to init. When present (or chosen via an interactive prompt when a TTY session passes no flag), the action resolves the profile from a bundled profiles.json, composes three files in memory — a seeded principles.html, a lean AGENTS.md, a thin CLAUDE.md — and appends them to the write plan as content-based decisions. The existing findConflicts → resolveConflicts → executeWrites path runs unchanged, so pre-existing files trigger the current y/N/skip prompt (FR-006). A .spectastic/profile.json marker records the choice; on a re-run with a different profile it drives the additive upgrade (FR-007). The profiled path never touches the AI factory (NFR-001).

6 · Decisions

D-001 · Profiles ship as a bundled data manifest

Status
Accepted
Context
FR-003 requires profiles as data, editable without touching a verb. commands.json (init/manifest.ts:24) is the precedent.
Decision
A repo-root profiles.json, copied into the bundle by prebuild alongside commands.json. Each entry: name, axes (the five axis values), principles (ordered preset blocks, each with a stable P-* id + statement), agents (the profile-specific AGENTS.md section fragments). A missing/malformed manifest fails safe to "no profiles" (unknown-name error), mirroring loadManifest.
Consequences
+ Adding/editing a profile is a data edit. + Shared base lives once. − A new bundled file the prebuild must copy (add to bundle.ts inventory + prebuild).

D-002 · Content-based writes extend FileWriteDecision

Status
Accepted
Context
Profiles emit composed files; the writer only copyFiles a source path today (init/write.ts:25, types.ts:13).
Decision
Add optional content?: string to FileWriteDecision. executeWrites writes content via writeFile when present, else falls back to copyFile(source). The composer produces content-based decisions; everything else (conflict detection, summary counts) is untouched.
Consequences
+ Minimal, additive change to the wire format. + Composed files flow through the exact conflict path (FR-006 for free). − A decision must carry either source or content; enforce with a type guard + test.

D-003 · Principles = shared base + additive per-profile blocks

Status
Accepted
Context
SC-002 needs profiles to differ materially; FR-007 needs upgrades to be additive; the data-model invariant is "additive compositions of a shared base."
Decision
Compose principles.html from templates/principles.html filled with a base principle set plus the profile's extra blocks, inserted before a stable <!-- spectastic:principles-end --> sentinel. Emitted as Draft v0.1.0 (P-6). Verified/Enterprise carry a "done means verified / build a checker when none exists" principle that Lean omits.
Consequences
+ One base to maintain. + Upgrade = splice new blocks at the sentinel. − Preset content must be authored once (in profiles.json); that copy is the feature's editorial surface.

D-004 · AGENTS.md lean skeleton; CLAUDE.md fixed thin pointer

Status
Accepted
Context
FR-004 + NFR-002: command-first, ≤150 lines, points at gates not rules; CLAUDE.md a thin pointer, not a duplicate.
Decision
AGENTS.md = a base skeleton (project overview · setup/build/test commands · code style · testing · "done" criteria) plus profile-specific lines from the manifest, assembled to markdown. CLAUDE.md is a constant ~5-line file pointing at AGENTS.md. A unit test asserts the line/byte ceiling.
Consequences
+ Honours the "lean hand-written skeleton beats generated" evidence. − The base skeleton has placeholders the user fills (stack, exact commands) — acceptable; that's what a human refines.

D-005 · Profile marker at .spectastic/profile.json

Status
Accepted
Context
FR-009 + FR-007: re-runs need to know the current profile to upgrade additively.
Decision
Write .spectastic/profile.json = { "profile": "<name>", "schema": 1 }. Read on re-run: same profile ⇒ refresh; different ⇒ additive upgrade path (D-006). The .spectastic/ dir is a namespaced home for future tooling state.
Consequences
+ Structured, discoverable, extensible. − A new project artifact to document.

D-006 · Brownfield: conflict prompt for never-clobber; sentinel splice for upgrade

Status
Accepted
Context
FR-006 (MUST, never blind-overwrite) and FR-007 (SHOULD, additive upgrade) are different-weight asks.
Decision
FR-006: route composed writes through the existing conflict prompt — a pre-existing file yields y/N/skip, no clobber. FR-007: when the marker shows a different prior profile and principles.html carries the sentinel, splice the new profile's blocks in before it, preserving everything above (the user's edits). If the sentinel is absent (hand-authored file), fall back to the conflict prompt rather than guess.
Consequences
+ MUST-tier safety is reused, not reinvented. − The splice is the one fragile step; spike it (§3) and cover with an edit-survives test (SC-003/SC-004). Graceful fallback bounds the risk.

D-007 · --profile plumbing; prompt-on-omit; orthogonal to --tools

Status
Accepted
Context
FR-001/FR-005/FR-008: accept a name, prompt in a TTY when omitted, no-op in non-TTY, independent of the 031 installer.
Decision
Add .option('--profile <name>'). In the bootstrap action (after the --tools early-return, so the two are independent): resolve the name — explicit flag, else a @clack select when process.stdout.isTTY, else none (with a printed note). Unknown name ⇒ exit 2 listing valid names. A resolved profile appends composed decisions to the plan before findConflicts.
Consequences
+ Backward-compatible (no flag, non-TTY ⇒ today's behaviour). + --profile and --tools compose by running independently. − One more branch in the action; keep resolution in a testable pure helper.

9 · Complexity tracking

Where 041 adds complexity beyond a plain copy.

The one genuine complexity is the additive-upgrade splice (D-006/FR-007, a SHOULD). It's justified because it is the mechanism that makes profiles a dial rather than a one-shot — the feature's stated value. It is bounded: guarded by a marker + sentinel, with a conflict-prompt fallback, and it is the only non-additive-safe operation in the spec.
