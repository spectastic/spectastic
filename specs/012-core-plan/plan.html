Core plan — implementation plan

How planCommand ships — fresh + re-entry, estimability gate, principles walk, ADR scaffolding — reusing the kernel surface 006 + 007 + 011 established.

Status Accepted Spec 012-core-plan Owner Brian Corbin · @briancorbinxyz Branch main (squashed-snapshot pattern) Created 16 Jun 2026 Read time

Extract /spectastic.plan into @spectastic/core/commands/plan following 006's kernel contract and 011's interview pattern. Fresh + re-entry in scope. Estimability gate is a pure pre-flight scan; principles walk is ai.ask<T>()-driven and halts on VIOLATION; ADR D-NNN IDs preserved across re-entry. 3 · Approach

Three moves, one PR. One: implement planCommand at packages/core/src/commands/plan.ts. The function reads the source spec via ctx.fs, runs the estimability gate, branches fresh-vs-re-entry on existence of plan.html, runs the two-phase interview through ctx.ai, walks principles (when present), assigns ADR IDs deterministically, returns assembled HTML. Two: factor 011's interview primitives into packages/core/src/helpers/interview.ts so both verbs share them. Three: add a spectastic plan <spec-id> CLI subcommand that wires up ClaudeProvider + KernelContext, invokes the kernel, writes the result, and translates blocker lists to a readable non-zero exit.

The estimability gate is the architecturally-interesting piece. Rather than failing on the first blocker, it runs to completion and returns every offence in one structured list — four kinds per FR-005, each with parse5 line/column. Fully deterministic; no AI call; the natural Bash-escalation target per FR-014.

4 · Alternatives considered

OptionFaithfulnessDeterminismEffortTotal
Gate as part of the AI loop (LLM judges blockers)3137
Gate as separate preflightCommand verb44210
Gate inline in planCommand, pure scan — chosen44412

An LLM-judged gate loses determinism and burns tokens every invocation. A separate preflightCommand verb is cleanly composable but doubles the API surface — a future verb that wants it can extract then. Inline + pure: same answer every run, no AI call, no new export.

5 · Decisions

D-001 · Estimability gate inline, pure, exhaustive

Status
Accepted
Context
FR-005 requires four blocker checks; SC-002 requires every blocker named with location. Must be deterministic (CI-runnable, Bash-escalation per FR-014).
Decision
Pure runEstimabilityGate(specHtml): Blocker[] inside plan.ts; walks parse5 AST once, collects all four kinds with {kind, location, snippet}. planCommand calls it first; non-empty → structured EstimabilityError, no write. No AI call; no early-exit.
Consequences
+ Same fixture → same list; + cheap. − Adds ~100 LOC of parse5 walker; reusable if another verb needs it.

D-002 · Principles walk via ai.ask<T>(); VIOLATION halts

Status
Accepted
Context
FR-007 requires per-principle OK/EXCEPTION/VIOLATION; VIOLATION halts, EXCEPTION logs §8. Judgement is irreducibly AI-driven.
Decision
Per principle: ask<T>() with three options; non-OK triggers a follow-up chat() for the note. VIOLATION → PrinciplesViolationError immediately; EXCEPTION logs §8 and continues. Absent principles.html → walk skipped, §1 records "no principles defined".
Consequences
+ Each verdict is a typed commitment, not prose hedging. − N+1 AI calls per principles file; − walk order matters for early-halt UX.

D-003 · ADR ID assignment deterministic; re-entry preserves

Status
Accepted
Context
FR-008: D-NNN in encounter order, stable forever. FR-011: re-entry never renumbers. One ID space per plan, scoped to one file — kernel-side assignment is safe.
Decision
Fresh: assign D-001 upward in interview encounter order. Re-entry: parse existing plan.html via parse5, extract every <spec-decision id="D-NNN">, compute maxId, assign new ADRs from maxId + 1. Existing ADRs round-trip unchanged unless explicitly enhanced (D-006); superseded ones keep ID + status.
Consequences
+ Stable IDs are closed-form; no external state. − Re-entry adds a parse step; cost negligible for plan-sized files.

D-004 · Architecture SVG — template + LLM-filled labels

Status
Accepted
Context
FR-009: SVG SHOULD for multi-component, skip for trivial. LLM-generated SVG is unreliable (coord math, marker arrows); template + LLM-supplied labels splits the work.
Decision
Three pre-baked templates (2-box, 3-box-linear, 4-box-tree) as string constants; ask<T>() picks template-or-none from the user's component count; one chat() extracts labels + figcaption. Trivial features get a one-sentence paragraph instead.
Consequences
+ SVG always renders; + LLM only owns text. − Smaller palette than hand-rolled plans (006/007); expand via follow-up if it bites.

D-005 · Alternatives matrix — LLM proposes; user confirms; one data-winner

Status
Accepted
Context
Slash-command step-7 asks chat for "1–3 alternatives + the criteria that mattered" — narrative. The matrix needs numeric scores and exactly one winner.
Decision
One chat() surfaces alternatives; a structured chat() scores them (3 criteria, integers 1–4); ask<T>() commits the winner (default: highest total). Kernel asserts exactly one data-winner per FR-010; throws otherwise. Winner MUST match §3's chosen approach and the lead ADR.
Consequences
+ Auditable; + winner constraint structural. − Three-pass chat; can collapse if slow.

D-006 · Re-entry mode — ADD or ENHANCE, never RENUMBER

Status
Accepted
Context
FR-011 mandates preservation of every existing <spec-decision>. 011's re-entry pattern (parse, diff, ADD-or-ENHANCE) applies directly.
Decision
Triggered by existing plan.html (no flag — FR-003). Kernel parses ADRs (D-003); per-ADR ask<T>() menu: keep / enhance (dated note) / supersede (status flip + forward link). New ADRs append at maxId + 1. §1 (principles) and §7 (risks) re-walk fully — those represent current state.
Consequences
+ Safe iteration; + same UX shape as 011. − ENHANCE-notes grow the plan over time; clean rewrites route through /spectastic.propose.

D-007 · Two-phase interview — shared helpers extracted from 011

Status
Accepted
Context
011 implemented two-phase interview directly in spec.ts; 012 needs the same shape; propose + triage list-intake will too. Copy-paste invites drift.
Decision
Extract to packages/core/src/helpers/interview.ts: askBatch, chatNarrative, skipKnown, loopUntilExhausted. spec.ts migrates in the same PR to prove the abstraction; net diff there is small.
Consequences
+ One source of truth; + future verbs inherit free. − Cross-cutting refactor inside the plan slice; existing 011 tests catch regressions.

D-008 · Single-PR migration, bench-gated; ships as v0.1.0-pre.14

Status
Accepted
Context
012 lands verb extraction + shared interview helper + slash-command markdown update. Staging would fragment the helper refactor.
Decision
Single PR per 006/007 precedent. Ships as v0.1.0-pre.14 (adjust if other slices land first). Bench enforces lazy-load; CLI tests prove wiring; 011 tests validate the helper extraction.
Consequences
+ Atomic; + abstraction proven with a first user, not speculative. − Larger diff; bench/test failure blocks the whole slice.

7 · Risks & mitigations

RiskLikelihoodImpactMitigation
Estimability gate misses a blocker shape the slash command would catch (exotic [NEEDS CLARIFICATION] formatting).MMUnit tests cover all four kinds with variant fixtures; gate extensible via Blocker[]; bugs → new fixture + check.
Helper extraction (D-007) regresses 011's behaviour.LH011 tests stay verbatim; failures surface immediately. Migrate in small commits.
Re-entry parsing fails on hand-authored ADRs (extra whitespace, wrapped attrs).MMparse5 (tolerant) over regex; round-trip test re-parses 006/007/011 plans cleanly.
Principles walk burns tokens on every re-entry.MLD-002 walks only when principles.html exists; re-entry preserves §1 verdicts unless user requests a re-walk.
SVG templates (D-004) don't fit the feature shape.ML"None" is an ask<T>() option, falling back to a one-sentence paragraph. Palette expandable.

8 · Complexity tracking

Two deliberate additions warrant flagging:

Shared interview helpers extracted in this slice (D-007). Cleaner sequencing would be a standalone helper slice first. Inline-justified: one-consumer abstractions are speculation; 011's tests guard the migration; splitting adds version-bookkeeping cost without behavioural benefit.

SVG via three pre-baked templates (D-004). Costs visual variety vs. the hand-rolled diagrams in 006/007. Justified: LLM-generated SVG is unreliable at the coord-math level, and "write a sentence instead" covers the no-fit case. Expand the palette via follow-up if it bites.
