Whose .claude/agents

One sentence, read three ways in one day, in opposite directions. It names no repository — so say which one.

Status Applied Change ID 2026-08-15-whose-claude-agents Spec 044-verb-model-policy Author Brian Corbin · @briancorbinxyz Created 15 Aug 2026 Targets 1 requirement — 1 modified Read time

FR-004's second sentence requires agent definitions be "tracked and synced to .claude/agents/, mirroring the commands/ → .claude/commands/ convention." It names no owning repository. Two withdrawn proposals read it as already obliging spectastic init to install the definitions into every downstream project; a third read it as governing only this repo's dev-time sync. All three marked their reading verified.

This scopes the sentence to the authoring repository, which is what it has always meant and what CLAUDE.md documents. What a downstream project receives is 003 FR-002's business, and 003's sibling proposal decides it. Two questions, currently answered by one ambiguous sentence.

1 · Intent

The sentence was written to record a real convention: the agents/*.md sources are tracked in git and hand-copied to a gitignored .claude/agents/ so the harness loads them, exactly as commands/*.md are. That is a statement about how this repository is maintained, and it sits in a spec about model pins because that is where the definitions were introduced.

It has since been read as a distribution requirement. The reading is not unreasonable — init does install the command adapters the parallel clause names, so "mirroring the commands/ convention" plausibly implies mirroring the install too. But 003 FR-002 enumerates exactly what init writes and the agents are not in it, so the two requirements disagree and neither says so. That disagreement is the whole reason two proposals were authored, argued and withdrawn today.

Scoping the sentence does not decide whether the install should happen. It stops the sentence being cited as evidence that it already must.

2 · Scope

In scope

  • The second sentence of FR-004 — an explicit owning repository, and an explicit statement that it governs authoring rather than distribution.

Out of scope

  • The model pins in FR-004's first sentence. Untouched.
  • Whether init installs the definitions. That is 003 FR-002's, and its sibling proposal decides it. This proposal is deliberately silent on the answer so that it presupposes neither outcome. defer-to=003-init-node-port.
  • Whether the hand-copy should be automated, and the fact that the scoped MUST still has nothing checking it — packages/schema/src/rules/ matches "agent" nowhere, and packages/cli/test/agents-defs.test.ts reads the agents/*.md sources without ever opening .claude/agents/. So the sync half is unchecked before and after, which is the P-8 shape §1 complains about. The natural home is an agents-drift sibling to 031 FR-007's commands-drift, not a new slug here. defer-to=031-init-tools.
  • Closing TBD-agent-sync-scope, filed by the 003 sibling for exactly this work. It is answered by this proposal and should be struck when this applies, which is an edit to that proposal's risk response rather than work here.

4 · Deltas

What changes — the sync clause gains an owning repository and an explicit authoring-not-distribution scope. Nothing else: the three model pins in the first sentence are carried through verbatim, and the rationale is unchanged.

The fan-out subagents MUST declare model pins via agent definitions: spectastic-classifier (triage list-intake) and spectastic-impl-task (implement [P] + escape hatch) set sonnet; spectastic-critic (propose adversarial pass) sets inherit. Within the repository that authors agent definitions, those sources MUST be tracked and synced to that repository's own .claude/agents/, by the same hand-copy that keeps that repository's commands/ and .claude/commands/ in step — not by 031 FR-007's drift-proof install into a consuming project, which this sentence does not invoke. This clause is about authoring; what spectastic init writes into a project is 003 FR-002's to say.

Rationale

Subagent model is isolated — the pinned tier runs independently while the main loop keeps its own model. The critic stays on the session model because adversarial risk-finding is where depth pays off and it runs rarely.

The scoping sentence exists because the clause was cited, in one day, as evidence for and against an install obligation it never mentioned. A requirement that names no actor will be assigned one by whoever needs it to have one — and each reading was marked verified, which is how an ambiguity becomes three confident and incompatible facts.

The mirror had to be halved rather than kept. "Mirroring the commands/ convention" has two live referents and they point opposite ways: the hand-copy CLAUDE.md documents, and 031 FR-007's must-tier requirement that init --tools install adapters into a project so they cannot drift — the phrase the installer itself uses for its remap. So the original sentence disclaimed nothing: a reader following its own analogy landed on a distribution obligation. Naming the half is the fix; a disclaimer beside an unqualified pointer is not one, which is P-8's point.

The last clause is a pointer rather than an answer — it says where the question is settled, not how — and carries no conformance keyword, because no artifact can satisfy or violate an instruction about how to read a sentence. A MUST whose absence is not a defect is not a requirement.

5 · Risk register

The delta scoped the subject but carried the analogy that caused the ambiguity through verbatim — and its primary referent in the estate is a distribution requirement

"Mirroring the commands/ → .claude/commands/ convention" has two live referents pointing opposite ways. One is the hand-copy CLAUDE.md documents. The other is 031 FR-007, a must-tier requirement that init --tools install adapters into a project so they cannot drift — machine-enforced by the commands-drift rule, and the phrase bundle.ts itself uses for the installer's remap. So a fourth reader follows the sentence's own pointer, lands on a live distribution obligation, and reconstructs exactly the reading this proposal exists to retire.

Decisive, and fixed by halving the analogy rather than keeping it. The post-state now names the hand-copy explicitly and says not 031 FR-007's install. I had diagnosed the ambiguity as a missing subject; it was the analogy, and the subject was the lesser half. A disclaimer standing beside an unqualified pointer is not a fix — which is P-8's point, made against my own draft.

Scoping FR-004 to authoring converts a live ambiguity into a stated hole under FR-003

FR-003 is must-tier: --model opus must escalate by delegating to an Opus-pinned subagent, and SC-002 restates it observably. That binds wherever the verb runs and is satisfiable only where the definition is present. After this delta, 044 carries a must-tier behaviour on one side and an explicit disclaimer of the artifact delivering it on the other, with the gap owned by an unapplied sibling whose two predecessors were withdrawn today. The draft also wrote "This requirement governs authoring", which scoped the model pins to authoring as well — not intended.

The drafting error is fixed — "This clause", so the pins are untouched. The hole is real and deliberate. It exists today; the proposal makes it visible rather than creating it, which is the point, and 000/T-026 already records it. The honest consequence is a sequencing constraint rather than a wording change: this may apply before 003, but leaving it applied while 003 stays unlanded means FR-003's dependency is stated as unowned. A conformance keyword was attached to an act of interpretation, against the corpus definition of MUST

KB-0001@2026-07-25 defines MUST as an absolute requirement whose absence is a defect, and says the <spec-rule> wrapper exists so a tool can find every must-tier requirement. The draft's "MUST NOT be read as requiring any particular distribution" attaches that keyword to a reader's interpretation: no artifact, behaviour or file state can satisfy or violate it, so it has no absence and no defect — yet it became machine-greppable as must-tier beside nine checkable siblings. The same entry catches a second slip: §3 stamped 003 FR-002's enumeration exhaustive as verified, which is a reading rather than a source read.

Both fixed. The scope clause keeps its place in the normative text — it is a scope statement and belongs there — but carries no keyword, with the reason written into the rationale so a later reader finds the argument rather than an inconsistency. The stamp is now assumed, which is the third time today the same overstatement has been corrected in the same cluster; that it recurred after being caught twice is the finding worth keeping.
