Design · 044-verb-model-policy

Verb model policy

How we will build it.

Status Accepted Spec 044-verb-model-policy Owner Brian Corbin · me@briancorbin.co.uk Branch main Created 10 Jul 2026 Read time

One core module (@spectastic/core/model-policy) owns the legal alias set, the alias→model-id table, and the per-verb tier map — the single source of truth. Tier A writes model: into the command frontmatter (three copies: source, .claude/, _bundled/); Tier C adds isolated subagent definitions; Tier D wires --model / SPECTASTIC_MODEL into createAIProvider() through a decider-style precedence resolver, and a drift-guard validate rule enforces frontmatter well-formedness against the map. Biggest risk: the sync fan-out across three frontmatter copies (the T-006 footgun) — mitigated by the drift-guard rule.

4 · Approach

Build the core policy module first — it is the single source of truth every tier reads. It exports MODEL_TIER_ALIASES (the legal set: opus/sonnet/haiku/inherit), an aliasToModelId table for the resolvable tiers, and VERB_MODEL_POLICY (the per-verb tier map). A resolveVerbModel(verb, override, projectCfg) function mirrors resolveDecider's precedence exactly.

Then the three tiers hang off it. Tier A is a mechanical edit: add model: to each command's frontmatter (values matching the map) across all three copies, then cp commands/*.md .claude/commands/ and into _bundled/. Tier C adds tracked agents/*.md sources (critic inherit, classifier + impl-task sonnet), synced to .claude/agents/ and _bundled/.claude/agents/; the propose/triage/implement command bodies point their Agent/Task spawns at the new agentTypes, and implement's --model opus path spawns the impl-task agent pinned to the escalated tier. Tier D reads --model (commander global option) and SPECTASTIC_MODEL in createAIProvider(), resolves through the new top-level models section of spectastic.json (loaded fail-fast, decider-style) and VERB_MODEL_POLICY, and passes the resolved id into new ClaudeProvider({ model }) — which already flows into the spec-027 Assisted-by: trailer. Finally the drift-guard validate rule scans the command frontmatter and flags any model: that isn't a legal alias or disagrees with the map.

6 · Decisions

D-001 · Core model-policy module is the single source of truth

Status
Accepted
Context
Fat-core (P-8, 000/T-016); the frozen-map precedent is DECISION_TAXONOMY (packages/core/src/decider/taxonomy.ts:19); adding a module = tsup entry + exports subpath (tsup.config.ts:15).
Decision
New src/model-policy/index.ts exporting MODEL_TIER_ALIASES, aliasToModelId (opus→claude-opus-4-8, sonnet→claude-sonnet-5, haiku→claude-haiku-4-5), VERB_MODEL_POLICY, and resolveVerbModel. Registered as the ./model-policy export subpath.
Consequences
+ One place defines legality, tiers, and ids. + Frontmatter and CLI both derive/verify against it. − A new export subpath to maintain.

D-002 · Reuse the decider precedence shape

Status
Accepted
Context
resolveDecider (packages/core/src/decider/decider.ts:28-35) already implements override ?? projectCfg ?? default; 036 FR-006 mandates one resolution path.
Decision
resolveVerbModel(verb, override, projectCfg) mirrors that precedence: per-run override (--model/SPECTASTIC_MODEL) > project config > VERB_MODEL_POLICY[verb] > global default.
Consequences
+ No parallel resolver. + Familiar to anyone who knows the decider. − Model and effort stay separate functions (correct — orthogonal axes).

D-003 · Tier D config lives in a new top-level models section

Status
Accepted
Context
The decider section (packages/cli/src/config/decider.ts:20) is per-checkpoint role/effort; model tier is per-verb — a different granularity. The loader's fail-fast validation (:60) is the pattern to copy.
Decision
A sibling models block in spectastic.json: { default?, verbs?: Record<verb, tier> }, read by loadModelsConfig(cwd) that reuses the decider loader's fail-fast shape (throw on unknown key / illegal alias).
Consequences
+ Clean separation of the two axes. + Same validation rigor. − A second config section + loader (small).

D-004 · Escape hatch = subagent delegation, not a body-level model swap

Status
Accepted
Context
A slash-command model: is fixed at skill activation for the turn (Claude Code docs); a body arg can't change it. Subagent model: is isolated (resolution order: env > per-invocation > frontmatter > main).
Decision
/spectastic.implement stays sonnet; --model opus makes it delegate the task's authoring to the spectastic-impl-task agent pinned (per-invocation) to the escalated tier, while the Sonnet main loop orchestrates. Implements FR-003.
Consequences
+ Honest to the mechanism; reuses the Tier C agent. − Escalated tasks run in an isolated context (the status-flip AskUserQuestion stays in the main loop).

D-005 · Agent-def sync mirrors the commands convention

Status
Accepted
Context
No .claude/agents/ exists; commands already ship as source → .claude/commands/ (gitignored) → _bundled/.claude/commands/ (init ships).
Decision
Tracked agents/*.md sources; sync to .claude/agents/ and packages/cli/_bundled/.claude/agents/; extend the manual cp note in CLAUDE.md. (The eventual init --tools installer, 031, will own this — deferred.)
Consequences
+ One convention for both surfaces. − Adds to the manual-sync footgun surface until 031 lands — mitigated by D-006.

D-006 · Drift-guard is a validate scan alongside skill-metadata-shape

Status
Accepted
Context
commandsDriftFinding (packages/core/src/commands/validate.ts:26) is the byte-drift precedent; skillMetadataFinding (:61) only checks required keys, so a stray model: already passes — well-formedness needs its own rule.
Decision
A verb-model-policy rule: for each command, if model: is present and (a) not in MODEL_TIER_ALIASES or (b) ≠ VERB_MODEL_POLICY[verb], emit a finding. Folds into the always-run scan (P-9). Satisfies FR-009 / SC-003.
Consequences
+ The permitted key gains machine coverage (closes the 000 adversarial-pass gap). − One more rule to keep in step with the map (it reads the same map, so it can't disagree).

D-007 · Refresh the stale default; frontmatter uses aliases only

Status
Accepted
Context
DEFAULT_MODEL='claude-sonnet-4-6' (claude.ts:33) is stale; current Sonnet is claude-sonnet-5 (claude-api catalog); aliases are complete-as-is, never date-suffixed.
Decision
Frontmatter/agent-defs carry aliases (sonnet/inherit/…); the CLI resolves alias→id via aliasToModelId; refresh DEFAULT_MODEL to the resolved sonnet id and source it from the table (no second literal).
Consequences
+ Aliases track the latest model; one id literal in the codebase. − The alias table needs a bump when the model line advances (a single, obvious edit).
