Cards

The guarantee layer (--tools) is invisible at interactive init — auto-commits silently never installed

Spec upstream

Debugging "auto-commits never happened" on a dogfooded project, root cause was a spec gap — init --tools is opt-in-by-flag only and is never surfaced during interactive init the way --profile now is; fixed by requiring init to offer the tools install interactively; regeneration fails at implementation (the code does what it says) — the guarantee only exists behind a flag nobody was told about.

Expected
A user running interactive init is offered the guarantee layer (pre-commit gate + auto-commit) the same way they're now offered a profile, so the guarantee gets installed by default-visible choice.
Actual
--tools is discoverable only if you already know the flag; interactive init never mentions it, so a user who didn't pass it gets no gate and no auto-commit — and doesn't know why.
Diagnosis
031 shipped --tools as a flag mode (FR-001) with no interactive surface. 041 later added an interactive profile prompt; tools never got the equivalent. The asymmetry is the defect: profiles are discoverable, tools are not.
Fix
specs/031-init-tools/spec.html — add a requirement that interactive init offers the tools install (TTY prompt; non-TTY unchanged). Reuse 041's prompt seam (init/prompt.ts). Then /spectastic.plan + /spectastic.tasks re-run for 031.
Deep dive — cross-spec (031 × 041)

Cross-spec contract touched. The fix lives at the seam 041 introduced (the interactive init prompt, init/prompt.ts + init.ts bootstrap) but the owning behaviour is 031's guarantee layer. The two must agree on one interactive init flow that offers both profile and tools, rather than 041 owning "prompt" and 031 owning "tools" in isolation. Sequence: amend 031's spec (this card), then a small implementation change threads a tools prompt through the same bootstrap path that already resolves a profile. No principle implicated; no deferred scope promoted.
