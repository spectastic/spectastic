Status Accepted Spec 031-init-tools Plan plan Branch 031-init-tools Created 07 Jul 2026 Read time

23 tasks across five phases for two stories — US1 the pre-commit validate gate, US2 the drift-proof adapters. Test-first: each story's integration + unit tests are written and failing before its implementation. Tasks marked [P] touch distinct files and parallelize. US2's drift-block depends on US1's gate, so US1 lands first; US1 alone is a viable MVP.

1 · Execution strategy

The natural fit — solo work, one keystone story. Build the foundational orchestrator, land US1 (the gate) end-to-end so SC-001 is provable, then add US2's generated adapters and the commands-drift block that the gate enforces.

Setup → Foundational → US1 → US2 → Polish, closing each story's tests before its implementation and the US1 integration suite before US2 opens.

Overkill for one installer. If staffed, split the hook writer (US1) from the adapter generator (US2) after the foundational orchestrator lands — distinct files — then converge on --uninstall.

4 · Phase 3a — US1 · Pre-commit validate gate

Tests (write & fail first)

Integration test — error blocks, clean passes — after init --tools, a commit including a validate-erroring artifact exits non-zero with a message; a clean commit succeeds (SC-001). packages/cli/test/init.tools.integration.test.ts
Integration test — Accepted-only open-question gate — an open <spec-question> in an Accepted spec blocks the commit; the same in a Draft spec does not (SC-002, FR-004). packages/cli/test/init.tools.integration.test.ts
Integration test — existing hook preserved — with a prior pre-commit present, after init --tools both it and the spectastic gate run on commit (SC-006, FR-006). packages/cli/test/init.tools.integration.test.ts
Unit-test the generated hook script — shellout to spectastic validate, chain call, and core.hooksPath target are well-formed. packages/cli/test/hook.test.ts

Implementation

Write the executable pre-commit hook — install to .git/hooks/pre-commit, chmod +x (FR-002, D-003). packages/cli/src/commands/init/hook.ts
Chain a preserved existing hook — move any prior hook aside, call it first, propagate its exit; never overwrite (FR-006). packages/cli/src/commands/init/hook.ts
Author the gate script body — shell spectastic validate <artifact globs> and block on non-zero exit; --no-verify is git's own bypass, no custom escape (FR-002/003/004/005, D-002). packages/cli/src/commands/init/hook.ts
Honour core.hooksPath — install into the configured dir when set, else .git/hooks (D-003). packages/cli/src/commands/init/hook.ts
Handle the non-git case — skip the hook with a loud warning and still install the adapters (FR-009). packages/cli/src/commands/init/tools.ts

Closes FR-002, FR-003, FR-004, FR-005, FR-006, FR-009; SC-001, SC-002, SC-006.

5 · Phase 3b — US2 · Drift-proof command adapters

Tests (write & fail first)

Add the commands-drift fixtures — positive (installed adapter ≠ source → error) + negative (adapter == source → clean). Red until the check lands. packages/cli/test/fixtures/commands-drift/
Unit-test the adapter generator — reproduces source verbatim, including the committed skill-tuned description (FR-008). packages/cli/test/adapters.test.ts

Implementation

Implement the adapter generator — regenerate .claude/commands/*.md from commands/*.md on each run, description verbatim (FR-007/008, D-001). packages/cli/src/commands/init/adapters.ts
Add the commands-drift check to validate — compare installed adapters against source, emit an error on divergence, modelled on the quarantine-marker scan so the gate blocks a stale commit (D-001). packages/cli/src/commands/validate.ts
Implement --uninstall — remove the hook (restoring any chained prior) and the generated adapters, reversibly (FR-010). packages/cli/src/commands/init/tools.ts

Closes FR-007, FR-008, FR-010; SC-003.
