Implementation plan · 031-init-tools

The guarantee-layer installer — init --tools

How we will build it.

Status Draft Spec 031-init-tools Owner Brian Corbin · @briancorbinxyz Branch 031-init-tools Created 07 Jul 2026 Read time

Extend the existing init command with a --tools mode that installs two things at the git boundary: a pre-commit gate that shells spectastic validate and blocks the commit on any error — which, because validate already errors on structural findings and on open questions in Accepted specs, delivers FR-003+FR-004 with no new gate logic — and generate-on-demand command adapters so the installed .claude/commands can't ship stale (a new commands-drift error the gate catches). Biggest risk: whole-repo validate latency as the corpus grows (R-1).

4 · Approach

Extend the existing init command with a --tools mode (plus --hooks-only, --commands-only, --uninstall) that reuses the buildPlan → executeWrites → printSummary pipeline, adding two new write-decision kinds. The gate writes an executable .git/hooks/pre-commit (or into core.hooksPath) that shells spectastic validate <artifact globs> and blocks on non-zero exit; because validate already emits errors for structural findings and for open questions in Accepted specs, this is the whole of FR-003+FR-004. The adapters stop being one-time copies: the CLI regenerates .claude/commands/*.md from commands/*.md on each run, and a new commands-drift error (surfaced through validate over the installed adapters) makes the gate reject a commit while an adapter diverges from source — so a stale copy can't ship (FR-007), Windows-free.

5 · Alternatives considered

The load-bearing choice is the cannot-drift mechanism (D-001). Scored 1 (poor) – 3 (good).

OptionCan't ship staleCross-platformSimplicitySlash-path safeTotal
Symlink adapters → source313310
Generate-on-demand + commands-drift gate332311

Symlink is the simplest structural guarantee but Windows-hostile (deferred harnesses will want it); the status quo is the T-006 bug itself. Generate-on-demand wins on portability at the cost of one new validate check.

6 · Decisions

D-001 · Cannot-drift adapters via generate-on-demand + a commands-drift gate

Status
Accepted
Context
init copies .claude/commands once today (init/bundle.ts:85, init/write.ts:1) — the T-006 stale-copy class. Symlink (the runner-up) is Windows-hostile.
Decision
The CLI regenerates .claude/commands/*.md from commands/*.md on each spectastic run, and a new commands-drift error (surfaced through validate over the installed adapters) makes the pre-commit gate reject a commit while any adapter diverges from source. Realises FR-007 as "cannot ship stale".
Consequences
+ Windows-free (no symlinks); + drift is caught at the commit boundary and self-heals on the next run; + one source of truth. − A transient local stale adapter can exist between a source edit and the next run/commit — weaker than a live link (R-2); − adds a validate check over gitignored markdown, a new check shape.

D-002 · The gate is spectastic validate, exit-code-gated — no new gate logic

Status
Accepted
Context
validate.ts:116 exits 1 on any error finding; no-unresolved-question.ts:10 already emits an error for an open question in an Accepted spec and only a warning in Draft.
Decision
The hook shells spectastic validate <artifact globs> over the whole corpus and blocks the commit on non-zero exit. FR-003 (structural errors) and FR-004 (open questions, Accepted-only) are delivered by the existing rule engine — no bespoke gate code.
Consequences
+ Reuses the entire rule set; + FR-004's status-gating is free and correct; + hook and manual validate share one path. − Whole-repo validate on every commit (latency R-1); − the gate is exactly as strong as validate's error set.

D-003 · Hook install into .git/hooks (or core.hooksPath), chaining any prior hook

Status
Accepted
Context
The git layer has no hook primitive; the mechanism was spiked in /tmp/hookspike — an executable pre-commit fires, chains a preserved prior hook, and exit 1 blocks (1 of 2 commits landed).
Decision
Write an executable hook to .git/hooks/pre-commit, or into core.hooksPath when set (honour it). If a hook already exists, preserve it (move to a *.prior, call it first and propagate its exit) — never overwrite (FR-006).
Consequences
+ Preserves existing hooks and honours git config; + standard, dependency-free. − Hook-manager frameworks (husky, pre-commit) may own the hook dir and conflict (R-3); − .git/hooks isn't versioned, so init --tools must be run per clone (its reason to exist).

D-004 · Extend the existing init command with --tools

Status
Accepted
Context
init.ts:33 already owns the bootstrap pipeline (buildPlan / findConflicts / executeWrites / printSummary, --force, non-TTY handling).
Decision
Add --tools (default: both halves) plus --hooks-only, --commands-only, --uninstall. Reuse the plan/execute/summary pipeline; add write-decision kinds for the generated adapters and the chained hook.
Consequences
+ Idempotent reconcile + conflict/summary UX for free (FR-001); + one command surface. − The pipeline's copy-based write model needs a new decision type (generate/hook), not just copy.

8 · Risks & mitigations

RiskLikelihoodImpactMitigation
R-1 · Whole-repo validate latency grows with the corpus, breaching NFR-001's ≤ 1 s.MMAn integration perf test asserts ≤ 1 s p95 @ 200 artifacts; ~0.5 s + ~0.25 s startup today. If breached, incremental (staged-set) validation or a resident checker — deferred follow-on.
R-2 · Generate-on-demand permits a transient local stale adapter; FR-007's "structurally impossible" is realised as "can't be committed stale", not a live link.LMRegenerate on every CLI run + block at commit. If the residual gap matters to a reviewer, revisit symlink (matrix runner-up) or reword FR-007 via a propose. Surfaced, not silently narrowed.
R-3 · A hook-manager framework (husky, pre-commit) owns the hook dir / core.hooksPath and conflicts with chaining.MMDetect known managers; honour core.hooksPath; chain conservatively. On an unrecognised complex setup, refuse the hook with guidance (partial install, like the non-git case) — never clobber (FR-006).

9 · Complexity tracking

One deliberate complexity beyond a plain installer:

The commands-drift validate check is complexity the spec doesn't name, introduced because the interview chose generate-on-demand over the simpler symlink to stay Windows-friendly (deferred harnesses will want it). The drift check is what lets generate-on-demand still honour FR-007's "can't ship stale" — without it, generate-on-demand would be strictly weaker than the copy it replaces. Acceptable: it is one new rule modelled on the existing drift-guards (verify-view-stale, format-band-coupling).
