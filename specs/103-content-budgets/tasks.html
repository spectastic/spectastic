Status Accepted Spec 103-content-budgets Design design Branch spec/visual-slice-095-098 Created 13 Aug 2026 Read time

15 tasks across five phases. Setup → Foundational → User stories (US1·US2·US3) → Polish. Tasks marked [P] can run in parallel — different files, no dependency. Tests for a story MUST be written and failing before its implementation tasks start.

1 · Execution strategy

Implement US1 end-to-end. Ship. Iterate to US2 and US3 only after US1 is verified.

Setup → Foundational → US1 → US2 → US3 → Polish. Each story closes its conformance before the next opens.

One team on each user story after Foundational. Coordinate at shared seams (data model, API contracts) via the spec, not Slack.

2 · Phase 1 — Setup

Name the budget, refusal and message-shape elements packages/schema/src/visual-vocabulary.ts
Add the build entry and export subpath packages/schema/tsup.config.ts

3 · Phase 2 — Foundational

One pure reader for all three declarations.

Write the reader's tests red — a budget's number and unit come back separately; a refusal's reason is content; voice is read as prose and never parsed. packages/schema/test/content-budget.test.ts
Read budgets, refusals and the message shape packages/schema/src/content-budget.ts

4 · Phase 3a — US1 · An element carries a budget

Write the budget check's tests red — a budget with a number and a unit is silent; one missing either is reported; a document with none costs nothing. packages/schema/test/content-budget.test.ts
Require a number and a unit — "short" records an opinion and constrains nothing. packages/schema/src/rules/content-budget.ts
Assert nothing is ever checked against running text — a test that pins a refusal, since FR-003 forbids a check rather than requiring one and only an assertion stops it being added later. packages/schema/test/content-budget.test.ts

5 · Phase 3b — US2 · A product records what it will not say

Write the refusal tests red — a refusal with a reason is silent; one without is reported; a context-scoped refusal is silent. packages/schema/test/content-budget.test.ts
Require a reason on a refusal — content rather than an attribute, closing the empty-string hole the grid already closed. packages/schema/src/rules/content-budget.ts
Register the rule and add its fixtures packages/schema/fixtures/content-budget/

6 · Phase 3c — US3 · An error message has a declared shape

Write the message-shape tests red — a shape declared once and referenced by a state is silent; a reference to no declared shape is reported. packages/schema/test/content-budget.test.ts
Resolve a message-shape reference within the document — per-file and pure, like every other reference in this family. packages/schema/src/rules/content-budget.ts

7 · Phase 4 — Polish

Style the budget and the refusal — the budget renders its unit; the refusal must read as a prohibition rather than an example. assets/spec.css
Drive both in a browser — both themes, asserting the unit renders and a refusal is not mistakable for a suggestion. tests/visual-content-budget.spec.ts
Scaffold a budget and a refusal templates/screen.html
