Spec data-model layering

How we will build it.

Status Accepted Spec 075-spec-data-model-layering Owner Brian Corbin · @briancorbinxyz Branch main Created 01 Aug 2026 Read time

The smallest slice in the cohort, and the one most easily over-built. NFR-001 caps it at 0 new validate rules, 0 new elements, 0 structural changes — so the entire design is: revise two pieces of authored guidance so the spec's §4 says it holds the conceptual model, and name where the physical model and the contract go now that 069 has given them a home. The one real decision is not to build a check, and to say why rather than leaving it looking like an omission.

5 · Approach

Two files. The spec template's §4 gains a short framing sentence stating that it holds the conceptual model — entities, relationships, invariants and state transitions, independent of storage and wire format — and a redirect naming where the physical model and the consumer-facing contract belong now that the design has a section for both. commands/spectastic.spec.md gains the same framing in its authoring guidance, so the interview asks for concepts and invariants rather than fields.

Two things the guidance must avoid, both of which the spec anticipates. It must not read as a prohibition on precision: FR-004 explicitly permits a concrete constraint where an invariant genuinely requires one — a range, a precision, a uniqueness rule — and the wording says so, because an author told only "no fields" will strip real invariants out of the spec. And it must be forward-only in effect: since the guidance codifies what 67 of 69 specs already do, no existing spec becomes non-conforming, which is asserted by a full validate sweep rather than assumed.

There is no architecture sketch. The feature has one moving part — authored prose — and the design procedure asks for a sketch only when there is more than one; drawing a two-box diagram of "template" and "command markdown" would be data-ink with no signal.

6 · Alternatives considered

The load-bearing choice is how strongly to enforce the layering. Scored 1–5, higher is better.

OptionRespects NFR-001False-positive riskHelps the authorTotal
A validate rule flagging field-shaped §4 content1135
A new element wrapping the conceptual model1438
Guidance in the template and the command — chosen55414

A rule is the reflex and is doubly wrong here: NFR-001 forbids it outright, and the distinction is genuinely unlintable — "the settlement window is 2 hours" is a legitimate invariant, while "window_hours INT NOT NULL" is a layer violation, and no pattern separates them without reading intent. A rule would fire on good specs and miss clever bad ones. A new element scores better on precision and still breaks NFR-001's zero-new-elements clause, while asking every author to learn a tag for something prose already conveys.

7 · Decisions

D-001 · Guidance only — deliberately no machine check

Status
Accepted
Context
NFR-001 caps the slice at 0 new validate rules and 0 new elements, and the spec's out-of-scope list names a layer-violation check as "deliberately not attempted, since the distinction requires judgment". The judgment is real: an invariant may legitimately carry a number.
Decision drivers
The NFR-001 cap · false-positive risk on legitimate invariants · usefulness to an author
Considered options
  • A validate rule — + deterministic. − Forbidden by NFR-001, and unlintable without reading intent.
  • A new wrapping element — + precise. − Also forbidden, and adds vocabulary for what prose conveys.
  • Guidance in template and command — chosen — + within the cap, no false positives. − Advisory only.
Decision
Ship the framing as authored guidance in both places. Add no rule, no element, no structural change.
Consequences
+ Zero risk of false-failing a well-written spec. + Nothing to maintain as conventions shift. − The layering is review-caught only; recorded as a P-8 exception in §10 rather than presented as enforced.

D-002 · Redirect rather than forbid, and permit precision

Status
Accepted
Context
FR-002 requires the guidance name where the physical model and contract belong; templates/design.html:72-92 now provides that home. FR-004 requires a concrete constraint stay allowed where an invariant needs one.
Decision
Phrase the guidance as a redirect — "field types and wire format belong in the design's data-model and contracts section" — and state explicitly that a precision, range or uniqueness rule is welcome when it is the invariant.
Consequences
+ An author is told where to put the detail, not merely to delete it. + Real invariants survive into the spec, where they belong. − Slightly longer guidance; the alternative is authors stripping genuine constraints, which is worse than a sentence.

D-003 · Forward-only, verified by a sweep rather than assumed

Status
Accepted
Context
FR-005 requires at most 0 existing specs become non-conforming. 67 of 69 already write §4 conceptually, and the spec records that none carries physical detail — but "we believe none does" is an assumption unless it is checked.
Decision
The guidance binds specs authored from here on; no existing spec is revised. A corpus-wide validate sweep is a task, confirming 0 new findings rather than reasoning that there can be none.
Consequences
+ No P-6 problem, since no past-Draft spec is touched. + The claim is evidenced. − Since the change adds no rule, the sweep can only confirm nothing broke; it cannot confirm the guidance is being followed. That is inherent to D-001 and is stated in §10.

10 · Complexity tracking

P-8 exception — guidance with no deterministic backstop. P-8 requires a mandatory step's guarantee live in the kernel or CI. This slice ships guidance and stops. Three things justify it. The spec mandates the cap (NFR-001: 0 new rules). The distinction is genuinely unlintable — a number in §4 may be an invariant or a leak, separable only by intent, so a rule would false-positive on good specs. And P-8 itself permits this shape: where a judgment step leaves no detectable residue, it requires the strongest available check, which here is review. Recorded as an exception rather than waved through, because "documentation-only" is exactly the phrase that hides an unenforced promise.

Success is not measurable by the tool. SC-001 asks that a reviewer can read a spec with no reference to a language, framework or storage engine — a human judgment. The tests can only assert the guidance is present and that nothing regressed; whether specs actually improve is observable over time in review, not in CI. Stated so the green tests are not mistaken for evidence the layering is holding.

The sizing note stays optional. FR-006 is a MAY, and it is honoured as one: a sentence noting that an outsized data model signals detail belongs downstream rather than that the spec should split. It is not elevated into a rule of thumb about section length, which would collide with the budget gauge that already owns sizing.
