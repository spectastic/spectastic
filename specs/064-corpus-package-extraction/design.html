Design · 064-corpus-package-extraction

Corpus package extraction

How we will build it.

Status Accepted Spec 064-corpus-package-extraction Owner Brian Corbin · @briancorbin Branch 064-corpus-package-extraction Created 27 Jul 2026 Read time

Lift packages/core/src/knowledge/ plus its two node-only core dependencies into a new @spectastic/corpus package with a spectastic-corpus binary, depending only on the existing @spectastic/schema (which already holds Finding, the parser, and the citation grammar) — so no third types package is invented and the graph stays acyclic. The move is wrap-don't-rewrite: the existing test suites are the parity harness (SC-001), a dependency-cruiser forbidden rule machine-proves the one-way boundary (SC-002), and only the new read path (get/query/grep) and the standalone binary get fresh tests. Biggest risk: a hidden coupling the two-seam audit missed surfacing mid-move — mitigated by the parity suite failing loudly and the boundary check catching any back-edge.

2 · Technical context

Language(s)
TypeScript (ESM), Node ≥ 20 (repo verified on v25).
Frameworks
None — a library plus a commander CLI. Build: tsup 8.3 (multi-entry). Workspace: pnpm.
Architecture
Layered package graph — @spectastic/schema (foundational types + grammar) ← @spectastic/corpus (fat library + thin CLI/bin) ← consumed by @spectastic/core (injection) and @spectastic/cli (validate). Fat-library / thin-CLI, mirroring 006. See D-004.
Storage
None new — a filesystem markdown corpus under knowledge/; document/registry/index formats unchanged (that invariance is what parity guards).
Testing
vitest (existing suites as the parity harness) + Playwright (unchanged); TDD for the new read verbs + binary; dependency-cruiser 17.4.3 for the boundary check.
Coverage
Not in scope as a threshold (no profile / no coverage floor). Standing rule still applies: the move must not lower coverage of the code it touches — the parity suite stays green.
Perf targets
No quantified NFR in the spec. grep prioritises speed: shell out to ripgrep when present on PATH, else a pure-Node scan — both paths return identical results (parity-tested).
Constraints
Byte-identical prompt injection (SC-004); one-way boundary, zero corpus→core edges (SC-002); no embeddings/vector store; graceful absence preserved.

4 · Approach

Create packages/corpus/ as a fourth workspace package. Move the whole packages/core/src/knowledge/ tree into it verbatim, plus providers/pack-fetcher.ts (+ stub) — grounding confirms it imports only node builtins and its only callers are corpus's own import verb, so the move creates no back-edge. Schema stays the floor, and gains one file: the citation grammar (citation-shared.ts) and the corpus-citation-form HTML rule remain in @spectastic/schema as planned, and security/fence.ts — found during tasks-grounding to be a genuinely shared, dependency-free primitive six core AI-verb files import, not a corpus-only one — relocates there too as a new @spectastic/schema/fence subpath (D-002). Corpus then depends on @spectastic/schema alone; @spectastic/core's AI verbs (both for injection and for their own fence calls) and @spectastic/cli's validate scans repoint their imports from the deleted @spectastic/core/knowledge/security/fence to @spectastic/corpus and @spectastic/schema/fence respectively.

On top of the moved logic, add the thin new surface: a spectastic-corpus binary exposing the existing curation verbs plus get (a shim over resolveCitation), query (a substring scan of the metadata fields), and grep (rg-if-present-else-Node over document bodies), and a corpus-intrinsic validate (well-formed / registry / license). Parity is the guardrail throughout: existing suites must pass with import-path edits only, and a dependency-cruiser rule fails CI on any corpus→core edge.

5 · Alternatives considered

The load-bearing choice was where the shared types live (spec FR-002). Scored on churn (less is better), acyclicity (does it keep the graph one-way), and conceptual clarity.

OptionLow churnAcyclicClarityTotal
Reuse @spectastic/schema + relocate fence/pack-fetcher55414
New @spectastic/corpus-types package25411
Keep fence/pack-fetcher in core, corpus imports them4127

Reuse wins because schema already is the lower layer corpus needs (Finding, parser, grammar), so a new types package would host what schema already hosts; and leaving fence/pack-fetcher in core recreates the very corpus→core edge the slice exists to remove.

6 · Decisions

D-001 · @spectastic/corpus as a fourth workspace package

Status
Accepted
Context
The add-a-package pattern is established: pnpm packages/*, tsup multi-entry, a package.json exports subpath per entry (packages/core/tsup.config.ts, 006 D-002).
Decision
Create packages/corpus/ with the same tsup multi-entry + subpath-exports shape, and a bin mapping spectastic-corpus → ./bin/spectastic-corpus (mirroring packages/cli).
Consequences
+ Consumers import narrow subpaths, unchanged from today's @spectastic/core/knowledge ergonomics. + Reuses proven build config. − One more package to version in the workspace.

D-002 · Reuse @spectastic/schema as the shared-types floor; schema keeps its rules and gains fence.ts

Status
Accepted
Context
Finding lives in packages/schema/src/types.ts:26; corpus already imports it and the citation grammar from @spectastic/schema (knowledge/license.ts:13). Schema is the lowest layer. Amended after a tasks-grounding correction (§3): security/fence.ts's fenceArtifactText is imported by six core AI-verb files, not just knowledge/ — a genuinely shared, dependency-free (zero imports) primitive, exactly the shape that belongs on the floor.
Decision
Corpus depends on @spectastic/schema for Finding/parser/grammar — no new types package (FR-002 satisfied). The corpus-citation-form HTML rule and citation-shared.ts stay in schema. security/fence.ts relocates to a new @spectastic/schema/fence subpath (unchanged content — fenceArtifactText/sanitizeArtifactText); both @spectastic/core (its six AI-verb callers) and @spectastic/corpus (knowledge/fence.ts's fenceCorpusDocument) import it from there.
Consequences
+ Zero new package; the graph floor gains one dependency-free file, no new risk. + Honours the spec's "lower types package" intent (FR-002 names the IO port/Finding/grammar as the shared set; fence.ts is the same kind of shared floor primitive). − FR-001's "its schema rules" is refined twice: the HTML citation rule stays put, and fence.ts was corpus-scoped in the original plan pass and is now schema-scoped (recorded in §9); six core call sites repoint their import, one line each.

D-003 · Relocate pack-fetcher.ts into corpus (fence.ts moves to schema instead — see D-002)

Status
Accepted
Context
pack-fetcher.ts imports only node builtins and its only callers are knowledge/ingest.ts and the CLI's pack-fetcher-factory.ts — both corpus's own import verb, confirmed by a repo-wide importer grep this turn.
Decision
Move providers/pack-fetcher.ts + its stub into @spectastic/corpus; the CLI's pack-fetcher-factory.ts repoints its import to the new location.
Consequences
+ Removes the only remaining would-be corpus→core edge. + Co-locates corpus-only code with corpus, with every caller confirmed. − None beyond the mechanical import-path edit.

D-004 · One-way graph, machine-enforced by dependency-cruiser

Status
Accepted
Context
The import audit shows the post-move graph is acyclic (corpus → schema only; core/cli → corpus). The repo has no dep-graph tooling today; NFR-002 requires the boundary be machine-verified.
Decision
Add dependency-cruiser@17.4.3 as a devDep with a single forbidden rule: no module under packages/corpus may import one under packages/core. Run it in CI (SC-002). The rule-wiring is the §3 spike — proven by planting and catching an edge as task 1.
Consequences
+ The boundary is a P-8 CI guarantee, not convention. + Catches a missed relocation automatically. − A new devDep + config the repo otherwise lacks (the reason the minimal-custom-check alternative was weighed and set aside for a purpose-built tool).

D-005 · Read path — get / query / grep, deterministic

Status
Accepted
Context
get has a ready implementation in resolveCitation (knowledge/resolve.ts:82); query and grep are new but must stay deterministic, no embeddings (FR-005).
Decision
get <id> = a shim over resolveCitation. query <term> = case-insensitive substring over id/slug/title/description from the loaded index/registry. grep <pattern> = shell out to ripgrep when on PATH, else a pure-Node body scan; a test asserts the two paths agree. Every hit carries coordinate + provenance.
Consequences
+ get reuses proven resolution; grep gets rg's speed where available without a hard dependency. − The rg/Node dual path is two code paths to keep in lockstep (guarded by the parity test); noted in §9.

D-006 · Wrap-don't-rewrite; existing suites are the parity harness

Status
Accepted
Context
006 D-006/D-007/D-008: move logic verbatim, keep the existing tests as the regression detector, add unit tests only for genuinely-new surface.
Decision
Move code unchanged; the corpus/validate/AI-verb suites pass with import-path edits only (SC-001); write tests test-first only for get/query/grep, the binary, and the byte-identical-injection assertion (SC-004).
Consequences
+ Parity is evidenced by a suite that predates the move. + Minimal new test surface. − If a hidden coupling exists, it surfaces as a suite failure mid-move (the intended loud signal, §8).

9 · Complexity tracking

FR-001 refinement. The spec says the extraction takes knowledge/ "plus its schema rules." Grounding narrows that: the corpus-citation-form HTML rule and citation-shared.ts grammar stay in @spectastic/schema (moving a schema rule into corpus would create a schema→corpus edge and break the floor). Corpus owns corpus-document validation; schema keeps spec-artifact rules. This honours FR-001's intent (corpus owns its logic) without a spec change — a data point for review, not a contradiction.

D-002/D-003 correction (found during tasks-grounding, not the original plan pass). security/fence.ts was first scoped to move into corpus alongside pack-fetcher.ts; a repo-wide importer check ahead of task derivation found it imported by six core AI-verb files (triage/classify.ts and commands/{spec,plan,propose,tasks,graduate}.ts), not just knowledge/. Being dependency-free (146 lines, zero imports), it relocates to @spectastic/schema/fence instead — the same "reuse the floor" move D-002 already made for Finding/parser/grammar, just caught one file later. No spec requirement changes; this is an implementation-detail correction the grounding discipline is meant to catch before it reaches code.

grep's dual path. The rg-if-present-else-Node design is deliberate complexity in service of the "speed is essential" steer. It is bounded by a parity test that pins the two paths to identical, normalised output — the only acceptable form of a dual implementation.
