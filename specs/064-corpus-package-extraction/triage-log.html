Cards

The grep read-path's rg/Node parity test hard-requires ripgrep, turning CI red on a runner without it

Implementation code

Debugging a red build-and-test on an unrelated PR, root cause was implementation drift — read.grep-parity.test.ts forces { mode: 'rg' } and asserts rgAvailable() === true, but the GitHub runner image no longer bundles rg, so every rg-forced case threw spawnSync rg ENOENT; fixed by making the rg-parity cases skip when rg is absent and installing ripgrep in CI; regeneration passes — the plan's own design (rg when present, else a pure-Node scan) means a faithful test would never have hard-required the optional accelerator.

Expected
pnpm test passes on any runner: the grep read-path treats ripgrep as an optional accelerator (auto mode falls back to a pure-Node scan), so its tests should too.
Actual
Four tests in packages/corpus/test/read.grep-parity.test.ts fail with spawnSync rg ENOENT (and one expected false to be true on rgAvailable()) whenever rg isn't on PATH — which is now the case on the CI runner, silently reddening build-and-test (and, by the same pnpm test gate, blocking the publish job).
Diagnosis
The test contradicts its own design contract (plan D-005: ripgrep optional, Node fallback): it forces rg mode unconditionally and asserts rgAvailable() is always true. When 064 merged, the runner still bundled rg, masking the coupling; a later runner-image change removed it.
Fix
packages/corpus/test/read.grep-parity.test.ts — split the always-available Node-mode assertions from the rg-parity block, gate the latter on rgAvailable() (describe.skipIf), add a complementary no-rg fallback test; plus .github/workflows/ci.yml and publish.yml install ripgrep so the parity leg still runs in CI.
Fixed
Both halves: the parity test is describe.skipIf-guarded so an rg-less runner degrades to the Node path instead of turning red, and CI installs ripgrep explicitly so the parity leg stays live.
describe('grep — rg/Node parity', () => { ... grep(..., { mode: 'rg' }) ... expect(rgAvailable()).toBe(true) }) const HAS_RG = rgAvailable(); describe('grep — Node mode', () => { /* always runs */ }) describe.skipIf(!HAS_RG)('grep — rg/Node parity — requires ripgrep on PATH', () => { ... }) describe.skipIf(HAS_RG)('grep — auto mode falls back to Node when rg absent', () => { ... })
Deep dive — no cross-spec contract, no invariant, no hotfix (but a coverage-visibility note)

Not a cross-spec gap — the design already says ripgrep is optional; only the test disagreed. Worth recording one thing: skipping the rg-parity block when rg is absent means an environment without ripgrep gets no parity coverage — acceptable (you can't test rg parity without rg), but the reason CI installs ripgrep is precisely to keep that coverage live rather than silently skipped. The silent-skip-vs-hard-fail trade is deliberate: a skip is visible in the test summary, whereas the ENOENT was a hard red that masked which leg actually broke. No production code changed; the moved grep.ts was already correct.
