1 · Execution strategy

Setup → Foundational → US1 → US2 → US3 → Polish, in order. This slice is a single coherent move (per plan D-006, wrap- don't-rewrite) — Foundational's code relocation is what US1's parity/boundary checks verify, so running phases out of order leaves nothing to test against.

Setup → Foundational → US1 only, ship, then US2/US3. Valid since US1 alone (parity + boundary) is a complete, mergeable slice; US2/US3 add the new read/binary surface on top.

Not recommended here — Foundational's moves are the shared seam every story depends on; splitting teams before it lands just recreates the coordination the plan's parity harness already automates.

6 · Phase 3c — US3 · Get cited knowledge out, deterministically

Tests (write & fail first)

Write get's resolution tests — a known id resolves via resolveCitation with coordinate + provenance; an unknown id returns not-found. packages/corpus/test/read.get.test.ts
Write query's substring-match tests — a case-insensitive term matches across id/slug/title/description; no match returns empty, not an error. packages/corpus/test/read.query.test.ts
Write grep's rg/Node parity test — on a fixture corpus, the ripgrep path and the pure-Node path return identical, normalised hit sets (plan D-005, the risk in plan §8). packages/corpus/test/read.grep-parity.test.ts

Implementation

Implement get — a thin shim over resolveCitation returning the document's coordinate and provenance. packages/corpus/src/read/get.ts
Implement query — case-insensitive substring scan over the loaded index/registry's id, slug, title, and description fields. packages/corpus/src/read/query.ts
Implement grep — both paths search the exact same in-memory document bodies (rg receives each over stdin, never touching disk) with the same case-insensitive fixed-string semantics, so output is identical by construction; verified directly by the parity test. packages/corpus/src/read/grep.ts
Register get/query/grep on the CLI — three commander subcommands wired to the read-path implementations. Caught and worked around a real pre-existing bug in the moved (unchanged) resolveCitation here: it checks if (registry), and an empty array is truthy, so loadRegistry()'s []-on-no-file return silently skipped pack-scan resolution for any project without a root registry — the common, pre-migration case. Worked around in get.ts (never the moved resolver); flagged for triage as a latent defect in existing production code, not fixed inline. packages/corpus/src/cli/read.ts, packages/corpus/src/read/get.ts

Closes FR-005, FR-006, SC-003.
