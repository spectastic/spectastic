Implementation plan · 014-core-implement

Core implement — implementation plan

How implementCommand ships in its smallest demoable shape — one task per invocation, estimability-gated, with the bundled flip prompt mandated by REQ-LIFECYCLE-005 wired through ctx.ai.ask<T>(). Drain modes wait their turn.

Status Accepted Spec 014-core-implement Owner Brian Corbin · @briancorbinxyz Branch main (squashed-snapshot pattern) Created 16 Jun 2026 Read time

Extract /spectastic.implement into @spectastic/core/commands/implement per 006's contract — single-task only. Drain modes (--all, --phase=<id>, --parallel) carve out to TBD-core-implement-drain. The kernel resolves one target, applies the estimability gate (matching 012's), orchestrates the work, runs scoped verification, ticks one checkbox or one <spec-triage> via ctx.fs, and on last-tick of a Draft spec surfaces the three-sibling bundled flip prompt via ctx.ai.ask<T>(). Kernel never auto-flips; partial bundle flips forbidden. Reuses the 007 ClaudeProvider. Single PR; ships as v0.1.0-pre.16. Biggest risk: interface must stay drain-extensible when the sibling slice lands.

3 · Approach

Three moves, one PR. One: implement implementCommand at packages/core/src/commands/implement.ts per 006's signature — target resolution, gate, work orchestration via ctx.ai.chat(), verification via caller callback (D-007), tick via ctx.fs, bundled flip via ctx.ai.ask<T>(). Two: add a spectastic implement <target> CLI subcommand that constructs ClaudeProvider + KernelContext, supplies the default verify callback, translates ImplementResult to exit codes (0 / 1 / 2), and rejects drain flags with a typed error pointing at the sibling slice. Three: update commands/spectastic.implement.md with the MAY-Bash-to-CLI note (006 FR-009) and a line on the carve-out.

The architecturally-interesting piece is the bundled flip prompt. Today's markdown (step 8) relies on the LLM noticing "last tick"; the extraction makes it deterministic. After every successful tick, the kernel re-reads the file, parses the matching spec.html's <spec-status>, counts remaining unchecked checkboxes; predicate (status === 'draft') AND (count === 0) triggers one ctx.ai.ask<T>() call naming the spec, transition, three sibling files, and test-pass reminder. On Confirm: write value="accepted" to all three siblings plus matching <spec-changelog> entries — one logical gesture, no partial commits.

5 · Decisions

D-001 · Single-task target resolution — three shapes, one slot

Status
Accepted
Context
FR-004 requires resolving a single positional to a specific task or inbox card. Three input shapes need disambiguation.
Decision
Match precedence: (1) ^T-\d+$ → scan every specs/<id>/tasks.html via ctx.fs; locate the unique <input type="checkbox"> whose parent <spec-task id="T-NNN"> matches. (2) ^I-\d+$ → open ./inbox.html; locate <spec-triage id="I-NNN" layer="just-do">. (3) else → treat as spec ID; pick first unchecked checkbox in specs/<target>/tasks.html. Multi-match on (1) is a typed IDCollisionError; no match is TargetNotFoundError.
Consequences
+ One slot, three shapes — matches today's slash flow. − Cold T-NNN lookup walks every spec's tasks.html; acceptable at workspace scale.

D-002 · Estimability gate scan — same pattern as 012's gate

Status
Accepted
Context
FR-005 requires halting before any work if the source spec / plan has blockers. Check shape matches 012's gate; sharing avoids drift.
Decision
Read spec.html + plan.html via ctx.fs; parse via parse5 (already on the verb path); scan for three blocker patterns: (a) unresolved <spec-question> inside the task's section; (b) [NEEDS CLARIFICATION] marker referenced by the task; (c) <spec-out-of-scope> <li> the task touches missing defer-to=. Any hit yields EstimabilityBlockedError with the full structured blocker list (not just the first). CLI exits 2.
Consequences
+ Behavioural parity with 012's gate; shared helper extractable. + Structured list lets the caller render every blocker at once.

D-003 · Task-tick mechanism — minimal-edit string write for byte-identity

Status
Accepted
Context
FR-006 + SC-001 require byte-identical output vs today's slash flow. parse5-serialise renormalises whitespace differently, breaking SC-001.
Decision
Locate the target's <input type="checkbox"> by string-walking — not by serialising the parsed tree. Find the <spec-task id="T-NNN"> opening tag, find the first following <input type="checkbox" (single or double quote), splice checked before > if not already present. Write back via ctx.fs.writeFile. No whitespace renormalisation; idempotent.
Consequences
+ Byte-identical by construction; + idempotent re-tick. − String-walking is more fragile than tree edits; offset by exhaustive unit tests on quote-style + whitespace variants.

D-004 · Inbox card tick — same minimal-edit approach

Status
Accepted
Context
FR-007 requires writing data-status="done" to a single <spec-triage>; same byte-identity discipline.
Decision
Locate <spec-triage id="I-NNN" via string match; rewrite an existing data-status= to "done", or splice data-status="done" before >. Card stays in place — never removed or moved.
Consequences
+ History preserved (faded card + DONE pill via existing CSS); + idempotent. − Same string-walking fragility as D-003.

D-005 · Bundled flip prompt — deterministic predicate, single ask<T>()

Status
Accepted
Context
FR-008 + REQ-LIFECYCLE-005 require deterministic evaluation after every tick taken while status is Draft; today's LLM-heuristic detection is the fragility being closed.
Decision
After every successful tick, re-read the tasks.html, parse the matching spec.html's <spec-status>, count remaining unchecked checkboxes. Predicate: (status === 'draft') AND (count === 0). On true, construct one Question (Confirm flip / Decline) naming spec + transition + three siblings + trigger + test-pass reminder (D-006); call ctx.ai.ask<T>(). Skip when status is past Draft — matches REQ-LIFECYCLE-005's scoping.
Consequences
+ Deterministic; re-ticks on flipped specs don't re-prompt. − Extra read + parse per tick; negligible vs AI cost.

D-006 · Flip-prompt UX — reminder in prose; no auto-flip; decline is no-op

Status
Accepted
Context
FR-009 + FR-010 require the prompt to remind about SC integration tests, forbid auto-flip, and require declined / interrupted prompts to leave statuses unchanged.
Decision
Reminder rides in the Question's prose ("Before confirming: have you verified the integration tests covering this spec's Success Criteria pass?"). The two-option surface is the gate — only Confirm writes. On Decline or interrupted ask<T>(), kernel returns ImplementResult { ..., flipPromptFired: true, flipConfirmed: false } and writes nothing to status pills or changelogs. Tick stays landed regardless.
Consequences
+ Reminder is part of the gesture. + Author judgment stays the gate. + Declined flips can be re-done manually later.

D-007 · Verification — caller-supplied callback, not ctx.shell

Status
Accepted
Context
FR-011 requires scoped verification before ticking; runner choice deferred to the plan. Adding ctx.shell just for this verb would over-extend KernelContext.
Decision
Extend ImplementInput with optional verify?: (task: ResolvedTask) => Promise<VerifyResult>. CLI supplies a default that shells pnpm test --filter <package> (or whichever scoped check the task names); MCP / VS Code pass their own. Kernel runs the callback after work, before tick. On passed === false, halt with VerificationFailedError; CLI exits 1. Callers handling verification externally pass verify: undefined.
Consequences
+ Kernel stays pure-with-respect-to-process. + No new KernelContext field for one verb. + Each surface picks its runner.

D-008 · Drain modes carved out — interface drain-extensible

Status
Accepted
Context
FR-003 carves drain modes out to TBD-core-implement-drain; the sibling must land additively.
Decision
v1 ImplementInput declares target: string + optional verify?. Sibling will add optional all?, phase?: 'setup' | 'foundation' | 'us1' | 'us2' | 'us3' | 'polish', parallel? — defaults preserve v1 behaviour. ImplementResult v1 returns a single ticked field; sibling introduces ticks: TickResult[] alongside, with ticked as a pointer to the first. v1 CLI rejects drain flags with a typed error pointing at the sibling spec.
Consequences
+ Sibling slice is purely additive; consumers pinning ~0.x.y stay safe. − ticks-vs-ticked dual surface is mildly awkward until sibling lands.

D-009 · Single-PR migration; ships as v0.1.0-pre.16

Status
Accepted
Context
Eighth kernel-verb extraction; verb + CLI + markdown + tests are tightly coupled and need to land together.
Decision
Single PR per 006 D-008 + 007 D-008 precedent. Bump to v0.1.0-pre.16 synced across cli + core + schema per 004. CHANGELOG entry names the carve-out. Bench-gated; CLI integration tests prove SC-001.
Consequences
+ Atomic; reverts cleanly. + Carve-out visible in CHANGELOG. − Bench / test failure blocks the whole slice.

7 · Risks & mitigations

RiskLikelihoodImpactMitigation
String-walking tick writer (D-003 / D-004) breaks on a quote-style or whitespace variant not in the test corpus.MMExhaustive unit tests on quote, attribute-order, and pre-existing-checked variants; integration test asserts byte-identity vs today's slash output.
Drain-modes interface (D-008) needs adjustment when the sibling slice implements it.MLPre-1.0 versioning permits minor-bump breakage; shape documented as provisional in the kernel docblock.
Bundled flip predicate (D-005) fires spuriously on missing / malformed <spec-status>.LMFail-closed: unparseable status defaults to "not Draft"; unit test covers the malformed case.
Verification callback (D-007) is skipped and a buggy task ticks without verification.LHCLI default verify callback always runs; only explicit opt-out skips. Integration test asserts the default fires.
SC-001 byte-identity fails on incidental whitespace today's slash flow happens to renormalise.LMSC-001 explicitly admits "modulo trivial whitespace"; integration test canonicalises both sides via a single helper before diff.

8 · Complexity tracking

Two deliberate additions warrant flagging:

String-walking tick writer (D-003 / D-004) over parse5-serialise. Byte-identity (SC-001) is a hard requirement; parse5 renormalises whitespace in ways that fail it. Cost is a fragile edit path; mitigated by exhaustive unit tests on quote / whitespace / attribute-order variants. Cheaper than negotiating SC-001 down.

Provisional ticks: TickResult[] shape (D-008). The drain slice isn't specced; array-shape is decided now to keep the sibling PR additive, but actual shape may need adjustment (ordering, partial-failure, fan-out aggregation). Documented as provisional in the kernel docblock; acceptable under the pre-1.0 versioning policy.
