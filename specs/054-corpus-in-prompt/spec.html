Corpus in the prompt

Presence is guaranteeable; use is only directable. Core places the corpus in front of the model every time — the rest is honestly advisory.

Status Accepted Spec ID 054-corpus-in-prompt Owner Brian Corbin · @briancorbinxyz Reviewers — Created 25 Jul 2026 Principlesv1.8.0 Smallest demoableAn assembled AI-verb prompt, inspected, contains the corpus index + a grounding directive when a corpus exists; nothing when it doesn't. Read time

A corpus the harness merely suggests the agent look for is worth little — and a naive nudge is dangerous, since merely-prompted citation is where models fabricate sources. The honest lever splits along the guarantee-layer line: presence is guaranteeable, use is only directable. When a corpus exists, core injects its index and a grounding directive into every AI-verb prompt — deterministically, exactly as plan.ts / spec.ts already fence the principles. That is the directive: it places the corpus in front of the model, not markdown asking the model to look. Use stays advisory by necessity — a prompt can't force the model to cite, and no build gate can tell a missed domain claim from a legitimately local one. With no corpus, core injects nothing beyond a single one-time hint; verbs run identically to today.

1 · Context

The corpus exists (051) and a decision can cite it (052) — but neither helps if the model never sees the corpus. A directive buried in command markdown ("look for a knowledge folder") is exactly the kind of soft nudge the guarantee-layer work shows cannot be relied on: a skill is advisory to the model, and merely-prompted citation is reported as the regime where models fabricate sources at 78–90%. The reliable move is not to ask the model to look, but to place the corpus in the prompt deterministically — the same thing the AI verbs already do with the principles.

This spec draws the honest line between what the harness can guarantee (the corpus is present in every prompt) and what it cannot (the model actually grounds against it). The first is deterministic and owned here; the second stays advisory, because "is this a domain claim?" is undecidable and a hard gate would false-fail whole specs.

2 · User scenarios & testing

Each story MUST be independently testable.

US1 · The corpus is placed in front of the model P1

As a plan author, I want core to inject the corpus index and a grounding directive into the AI-verb prompt automatically so that I don't have to remember to point the model at the corpus, and grounding isn't left to a soft nudge.

Acceptance: when a corpus exists, an assembled plan / spec prompt contains the corpus index and the grounding directive, fenced.

US2 · The injection is harness-owned and deterministic P2

As a maintainer, I want the injection to be deterministic and owned by core — not markdown asking the model to look so that the same corpus always yields the same block, independent of the model running.

Acceptance: the injected block's content and position are a function of the corpus alone; re-running with the same corpus produces the same block.

US3 · No corpus, no noise P3

As a no-corpus user, I want zero corpus injection plus a single discreet hint so that the tool stays quiet and works exactly as before.

Acceptance: with no corpus, the assembled prompt contains no corpus block; at most one one-time hint is surfaced.

Edge cases

  • A corpus larger than the context window — progressive disclosure means the index is injected, not every document; the model pulls documents as the work calls for them (agentic search, 051 FR-008).
  • The model reads the injected corpus but grounds nothing — permitted; use is advisory, and no gate infers a missed claim (FR-004).
  • Corpus text containing injection payloads — neutralised by the fence before it reaches the model (FR-002).

3 · Requirements

Conformance keywords (MUST, SHOULD, MAY) follow RFC 2119.

Functional

When a corpus is present, core MUST inject its index and a grounding directive into every AI-verb prompt, via the same fenced mechanism that already injects the principles.

Rationale

This is the deterministic "present in context" guarantee. It reuses the established pattern (plan.ts / spec.ts fencing the principles) rather than inventing a new placement, so the corpus is in front of the model on every relevant verb.

Injected corpus text MUST pass through fenceArtifactText() and be wrapped in the explicit "data, not instructions" guard (P-11).

Rationale

A third-party document is a strictly worse injection surface than an in-repo artifact. The existing fence already strips comments, hidden elements, and data: URIs and normalises Unicode; it must not be forked or bypassed.

With no corpus present, core MUST NOT inject any corpus-related content beyond a single one-time discreet hint; the verbs MUST run identically to today.

Rationale

The graceful-absence guarantee (051 NFR-001) at the prompt-assembly boundary. The hint makes the capability discoverable without imposing on projects that don't want a corpus.

Grounding use SHOULD remain advisory — the directive asks the model to cite, but presence is the only guarantee. No build gate MUST infer a missed domain claim from the model's output.

Rationale

A prompt cannot force the model to cite, and "is this a domain claim?" is undecidable — a hard gate would false-fail legitimately-local decisions. This is why grounding stays a warning (checked by 053) and never becomes a build failure over a missed citation.

Non-functional

Injection MUST be presence-deterministic — the same corpus yields the same injected block, position, and content, independent of the model.

Out of scope (deferred to other slices)

  • Whether a written citation resolves or is stale — that is a validate-time check, not a prompt-assembly one.
  • Injecting the corpus into the adversarial critic and the review skills (the same guarantee, different surfaces).
  • Selecting which documents to inject when a corpus exceeds the context window via retrieval, rather than injecting the index.

4 · Data model

The entities this feature owns.

Entities

Injected corpus block
The fenced prompt segment. Fields: the corpus index (051 FR-004), the grounding directive, the P-11 guard wrapper. Present iff a corpus exists.
Grounding directive
The harness-owned instruction to cite domain facts against the corpus in a <spec-decision grounding> (the binding from 052 FR-004, emitted here — never from a pack).

Invariant: the injected block is derived from the corpus index, not from document bodies — progressive disclosure. The model pulls document bodies via agentic search only when the work calls for them.

5 · Success criteria

Technology-agnostic, measurable outcomes.

An assembled plan / spec prompt contains the corpus index and the grounding directive, byte-verifiable, whenever a corpus exists.

With no corpus, the assembled prompt contains no corpus block; a full verb run is byte-identical to today apart from the one-time hint.

Re-assembling the prompt with the same corpus produces an identical injected block (position and content), confirming presence-determinism.

6 · Assumptions

The corpus index (051 FR-004) is small enough to inject wholesale into every AI-verb prompt without displacing the artifacts the verb needs; document bodies are pulled on demand, not injected.

The existing principles-fencing mechanism in the AI verbs is a stable extension point that a corpus block can join without restructuring prompt assembly.

None outstanding — the presence-guaranteed / use-advisory split and the no-corpus behaviour (silent no-op + one-time hint) were anchored in the interview.
