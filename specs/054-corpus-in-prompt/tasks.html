16 tasks across five phases. Setup → Foundational → User stories (US1·US2·US3) → Polish. Tasks marked [P] can run in parallel — different files, no dependency. Tests for a story MUST be written and failing before its implementation tasks start.

1 · Execution strategy

Implement US1 end-to-end — the presence guarantee across all five verbs. Ship. US2's determinism-hardening and US3's no-corpus hint follow once US1 is verified.

Setup → Foundational → US1 → US2 → US3 → Polish. Each story closes its conformance before the next opens.

Not applicable at this size — this is a small, solo-scoped kernel change (one pure builder, five mechanical joins). Use MVP-first or Incremental.

2 · Phase 1 — Setup

Scaffold the CLI one-time-hint marker module — the file shell (imports, exported function signatures) for reading/writing .spectastic/corpus-hint-shown.json, mirroring init/marker.ts's existsSync/readFileSync/mkdir/writeFile shape; the logic itself lands in T-310. packages/cli/src/knowledge/corpus-hint-marker.ts
Add the optional corpusHint result field — corpusHint?: string on DesignResult, SpecResult, ProposeResult, TasksResult, and GraduateExtract. packages/core/src/types.ts

3 · Phase 2 — Foundational

The one shared builder every story depends on. Sequential — the barrel export needs the builder's real name.

Implement buildCorpusPromptBlock(packs) — render the loaded index rows into compact text, wrap it via fenceArtifactText(indexText, 'Knowledge corpus index'), prepend the fixed, unfenced grounding directive; return '' when packs is empty (D-001–D-003). packages/core/src/knowledge/prompt.ts
Export buildCorpusPromptBlock from the knowledge barrel packages/core/src/knowledge/index.ts

4 · Phase 3a — US1 · The corpus is placed in front of the model

Tests (write & fail first)

Unit-test the builder's present case — every IndexEntry row appears in the fenced output, alongside the grounding directive text. packages/core/test/knowledge/prompt.test.ts
Integration-test the five-verb join — a stub AIProvider.chat captures its prompt argument; assert the corpus block appears for plan, spec, propose, tasks, and graduate when a corpus is loaded. packages/core/test/corpus-prompt-injection.test.ts

Implementation

Join the corpus block into all five AI-coupled verbs — loadCorpus(ctx.cwd) then buildCorpusPromptBlock(...) dropped into the existing [...].filter(Boolean).join('\n') prompt array of plan, spec, propose (both prompt sites), tasks (both prompt sites), and graduate's extract leg. packages/core/src/commands/

Closes FR-001, FR-002, SC-001.

5 · Phase 3b — US2 · The injection is harness-owned and deterministic

Tests (write & fail first)

Test presence-determinism — building the block twice from the same (unsorted-input) packs yields byte-identical output; the directive text is present verbatim regardless of pack content. packages/core/test/knowledge/prompt.test.ts

Implementation

Sort packs and rows inside the builder — order by pack name then row id before rendering, so determinism holds independent of caller order rather than relying on loadCorpus's own sort. packages/core/src/knowledge/prompt.ts

Closes NFR-001, SC-003.

6 · Phase 3c — US3 · No corpus, no noise

Tests (write & fail first)

Test the empty-corpus path — buildCorpusPromptBlock([]) returns ''; each of the five commands' assembled prompt is byte-identical to a pre-054 snapshot when loadCorpus returns []. packages/core/test/corpus-prompt-injection.test.ts
Test the marker helper — an unshown marker reads as "not yet shown"; after a write, a second read reads as "already shown"; a write creates .spectastic/ when absent. packages/cli/test/corpus-hint.test.ts

Implementation

Implement the marker helper's read/write logic packages/cli/src/knowledge/corpus-hint-marker.ts
Set corpusHint on the empty-corpus path — in all five core commands, when loadCorpus(ctx.cwd) is empty, set result.corpusHint to the fixed discoverability string; otherwise leave it unset. packages/core/src/commands/
Print corpusHint at most once from the CLI — the plan, spec, propose, tasks registrars and the explore --graduate leg print result.corpusHint guarded by the marker helper, then write the marker. packages/cli/src/commands/

FR-004 (grounding use stays advisory; no gate infers a missed citation) has no implementing task here by design — it is a SHOULD-not, satisfied by deliberately adding no new gate. The citation-resolution check already exists at warning severity in 053; this spec introduces nothing that could harden it into a build failure.

Closes FR-003, SC-002.
