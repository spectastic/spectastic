3 · Approach

Three moves, one PR. One: implement proposeCommand at packages/core/src/commands/propose.ts per 006's signature — two-phase interview via ctx.io.prompt() + ctx.ai.ask<T>(), live spec read via ctx.fs, delta-target validation, sibling-folder scan, render to HTML. Two: replace the ClaudeProvider.subagent() stub (007) with a real @anthropic-ai/sdk call that declares the critic role via a system prompt. Three: add a spectastic propose <spec-id> "<description>" CLI subcommand with --no-adversarial / --adversarial flags; writes the returned HTML to specs/<spec-id>/changes/<date>-<slug>/proposal.html.

Adversarial pass is the distinctive piece. The FR-008 heuristic fires when the proposal touches a priority="must" requirement, contains op="removed", or spans ≥2 topic prefixes. The kernel calls ctx.ai.subagent() with the canonical critic prompt from commands/spectastic.propose.md §8 reproduced verbatim (markdown stays canonical per 006 FR-008); the sub-agent returns three findings; the kernel embeds each as <spec-risk target="…" status="identified"> in §5 and MAY draft a starter response per FR-011. Status transitions are author commitment — the apply-time gate in REQ-CHANGE-004 gives the identified default its teeth.

4 · Alternatives considered

OptionReuseAdversarial fidelityEffortTotal
Spawn child claude CLI process for subagent()2327
Skip adversarial pass — base flow only, defer pass to 0144149
Separate @anthropic-ai/sdk call with critic system prompt — chosen44311

Child-process (option 1) matches Claude Code's sub-agent semantics most literally but adds operational complexity (spawn, IPC, lifecycle) for marginal fidelity gain. Deferring the pass (option 2) tempts on effort but leaves the verb half-defined — the spec anchored "base flow + adversarial pass together" as the slice boundary. The chosen approach reuses 007's SDK dependency, isolates the critic role via system prompt, and keeps AIProvider portable. Upgrading to true sub-agent semantics later is a provider-internal change with no kernel surface impact.

5 · Decisions

D-001 · ClaudeProvider.subagent() — separate SDK call with critic-role system prompt

Status
Accepted
Context
007 D-001 stubbed subagent() as throw "not implemented; lands with 013-core-propose". This slice fills it in. Interface from 006 D-004: (prompt, opts?) => Promise<unknown>.
Decision
Fresh messages.create call (separate client or fresh conversation state). Critic role declared via system prompt: "You are an adversarial reviewer. Identify exactly three risks in the proposal below." Proposal + live spec + principles concatenated as user input. temperature: 0. Returns raw text; caller parses into RiskFinding[].
Consequences
+ Reuses 007's SDK dep; + system-prompt isolation; + 007 D-005 key-redaction applies. − Not true sub-agent semantics; − critic prompt is the only role boundary — drift risk if it erodes.

D-002 · Adversarial-pass heuristic

Status
Accepted
Context
FR-008 codifies the REQ-CHANGE-004 heuristic; must be testable in isolation so unit tests cover each branch.
Decision
Pure function shouldFireAdversarial(deltas, liveSpec, override?): boolean at helpers/adversarial-heuristic.ts. Tri-state override (true forces, false skips, undefined evaluates). For undefined: short-circuit must-tier check (lookup target against parsed priority=), then removed-op check, then topic-prefix count (regex on leading REQ-<TOPIC>- segment; threshold ≥2).
Consequences
+ Auditable + testable without AI mocks. − Topic-prefix detection assumes REQ-<TOPIC>-NNN shape; non-conforming IDs bucket as "no prefix".

D-003 · Critic prompt as TS constant, verbatim from canonical markdown

Status
Accepted
Context
Critic prompt at commands/spectastic.propose.md §8 is canonical per 006 FR-008. Kernel must reproduce without drift but without runtime markdown read.
Decision
TS string constant in commands/propose.ts with docblock linking to §8. Carries the three-finding block (regret-in-30-days, contradiction citation, scope concern), the "empty findings forbidden" clause, and the <spec-risk status="no-value-found"> escape. Drift-detector unit test asserts the constant contains all three finding-shape phrases.
Consequences
+ No runtime IO; + portable to non-Node runtimes; + drift detector. − Two sources of truth require manual sync.

D-004 · RiskFinding parsed from critic JSON

Status
Accepted
Context
Spec §4 locks RiskFinding = { target, status, concern, response? }. Critic returns text; kernel extracts three structured findings.
Decision
Critic prompt instructs JSON output: array of three {target, concern, response?}. Status fixed to 'identified' on emit (kernel sets it, never critic — supports D-005). Reuse 007 D-002's JSON-parse + one-retry pattern. Validation: length === 3, non-empty target + concern per entry. Failure after retry throws typed AdversarialPassError.
Consequences
+ Aligns with 007's JSON-parse pattern; + deterministic render. − Prompt carries JSON-schema description; − one extra round-trip on parse failure.

D-005 · Author-response discipline — render helper hard-codes status="identified"

Status
Accepted
Context
FR-011: kernel MAY draft response prose; MUST leave status="identified". The apply-time gate in REQ-CHANGE-004 refuses on identified — the default forces author touch before archive.
Decision
renderRiskBlock(finding): string always emits <spec-risk target="…" status="identified">; the input's status field is ignored on render (defensive default). Empty finding.response renders <div class="response"><em>Author response not yet recorded.</em></div>; non-empty passes through the critic draft. Unit test asserts every emitted block carries status="identified" regardless of input.
Consequences
+ Apply-time gate stays meaningful; + author commitment structurally enforced. − Critic's draft response passes through unfiltered — quality depends on the critic, not the kernel.

D-006 · Sibling-proposal scan via ctx.fs.readdir

Status
Accepted
Context
FR-012: scan specs/<spec-id>/changes/ for sibling proposals overlapping new deltas. SHOULD report via ctx.io.prompt(); MUST NOT auto-block.
Decision
scanSiblings(specId, ctx, targets): Promise<SiblingConflict[]> reads the changes folder via ctx.fs.readdir, filters YYYY-MM-DD-<slug> entries, reads each proposal.html, extracts <spec-delta target="…"> via regex, returns intersection conflicts. Skips the new proposal's own folder. Called pre-render; conflicts surface via prompt without gating the write.
Consequences
+ Stays within 006 D-005's FileSystem interface (no new methods). − Regex on HTML is fragile to template change; a future structural parse helper would harden it.

D-007 · Delta-target validation pre-write, typed error on mismatch

Status
Accepted
Context
FR-004: existence-required ops must hit an extant target; added must miss. FR-005's "no silent failure" demands a loud raise, not a comment in output.
Decision
validateDeltaTargets(deltas, liveSpecHtml): void parses <spec-requirement id="…"> via regex, iterates deltas, throws DeltaTargetError on mismatch — error carries offending target + op + closest existing ID (Levenshtein ≤ 3) as a suggestion. Called pre-render; render proceeds only on clean pass.
Consequences
+ Hallucinated IDs caught before write; + suggestion accelerates fixup. − Regex misses non-canonical attribute orderings; schema lint catches that separately.

D-008 · Two-phase interview reuses 011's helpers

Status
Accepted
Context
Interview shape mirrors 011 / 012: narrative via ctx.io.prompt(), decisions via ctx.ai.ask<T>(). 011 lands the helpers; reuse, don't re-implement.
Decision
Import from @spectastic/core/helpers/interview (011's subpath). If 011 hasn't landed at integration time, ship parallel helpers at helpers/propose-interview.ts with a doc-comment marking the merge target. Skip-what's-known per FR-006: each ask<T>() checks input + live spec + sibling folders first and short-circuits when an answer is already known.
Consequences
+ One source of truth for interview UX. − Coupling to 011's API; breaking changes ripple. Mitigated by 006 FR-012's pre-1.0 versioning.

D-009 · Single-PR migration; ships as v0.1.0-pre.15

Status
Accepted
Context
Four things land together: verb extraction, subagent() impl, CLI subcommand, markdown update. Tightly coupled — no impl means no pass tests, no CLI means no end-to-end SC verification.
Decision
Single PR per 006 / 007 precedent. Synced version bump across @spectastic/{cli,core,schema} to 0.1.0-pre.15 per 004. Bench + CLI integration tests gate the merge.
Consequences
+ Atomic; reverts cleanly; simple version bookkeeping. − Larger diff; bench/test failure blocks the whole slice.

7 · Risks & mitigations

RiskLikelihoodImpactMitigation
propose.ts creeps onto the init path through an eager re-export in src/index.ts, defeating subpath enforcement.MHBench's init-help-cold-start (150 ms) catches it on the first PR; 006 D-002's per-verb subpath discipline forbids it explicitly.
Critic returns malformed JSON or wrong number of findings; D-004's one-retry doesn't recover.MMTyped AdversarialPassError surfaces verbatim to the CLI; user re-runs with --no-adversarial or accepts the failure. Unit test exercises the failure path with a stub returning malformed text.
Critic-role-via-system-prompt produces weak findings vs. a true sub-agent.MMPrompt quality is iterable; D-001's note explicitly permits upgrading to true sub-agent semantics later without changing the kernel surface. Drift detector test (D-003) catches prompt erosion.
Sibling-scan regex misses deltas embedded in unusual markup (e.g. inside <details> with attributes).LMRegex targets <spec-delta[^>]*target="([^"]+)" — robust to attribute order and surrounding markup. A future structural parse would harden it further.
Author-response discipline bypassed by future kernel code emitting status="accepted" directly.LHD-005's render helper hard-codes status="identified" on emit; unit test asserts every emitted block carries it. Apply-time gate in REQ-CHANGE-004 is the second line.
011's interview helpers haven't landed at integration time, forcing parallel helpers in 013.LLD-008 anticipates this — parallel helpers in helpers/propose-interview.ts with a doc-comment naming the merge target; cleanup is a follow-up PR after 011 ships.

8 · Complexity tracking

Two deliberate additions warrant flagging:

Critic prompt as TS constant, not markdown read at runtime (D-003). Trades two-sources-of-truth maintenance cost for runtime portability (no file IO; works in MCP / VS Code). Drift-detector unit test on the three finding-shape phrases is the safety net.

Sub-agent via separate SDK call, not child-process agent (D-001). True sub-agent semantics (separate process, distinct agent identity) would match Claude Code most faithfully. The chosen fresh messages.create + critic-role system prompt reuses 007's SDK dep and keeps the kernel portable. Upgrade path documented; revisit only if SC-002 can't be delivered via prompt isolation.
