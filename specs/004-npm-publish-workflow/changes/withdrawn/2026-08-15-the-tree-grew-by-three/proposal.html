The tree grew by three

Withdrawn

1 · Intent

044 FR-004 requires, in its second sentence, that "Agent-definition sources MUST be tracked and synced to .claude/agents/, mirroring the commands/ → .claude/commands/ convention." The bundle carried them from the day 044 landed; init's walk never copied them. So the obligation has been unmet since, and every project scaffolded in that window ran /spectastic.propose with no spectastic-critic — the adversarial risk pass silently absent rather than failing.

That is now fixed, and the fix needed no proposal of its own: it implements an existing must-tier requirement rather than adding behaviour. What it does need is this — the default scaffold is 32 files rather than 29, and SC-001 states the number.

The number is stated deliberately rather than left implicit, and a test reads this requirement to enforce it: it extracts "yields a (\d+)-file tree" from SC-001 and fails when the constant disagrees. That guard exists because these counts drifted three ways once before — "spec said 16, the init docblock said 17, the tests asserted 20, the real tree was 21" — and it did its job here, turning a three-file addition into a red test rather than a number quietly rotting.

2 · Scope

In scope

  • Moving SC-001's stated tree count from 29 to 32, so the criterion matches the scaffold and its drift guard passes.

Out of scope

  • FR-007, which enumerates the bundle as "commands/, assets/, and templates/" and omits agents/ and the two root manifests. A real staleness, found by the adversarial pass on a sibling proposal, and a different defect from a count — it is an enumeration that will go stale again, which is its own argument. defer-to=TBD-bundle-enumeration.
  • 003 FR-002 and 003 SC-001, which both still describe a 16-file scaffold and the latter of which measures it against a Python script 003 itself required be deleted. Worse than this and in another spec, so it needs its own propose covering all five sites in that document rather than the one a first draft reached for. defer-to=003-init-node-port.
  • Whether the bundle should carry what it carries. That is the build's decision and no requirement here should re-litigate it. defer-to=never.

4 · Deltas

What changes: the stated tree count, 29 → 32. Every other clause is untouched.

Post-publish, an outside user with Node 20+ and no clone runs npm i -g @spectastic/cli, then spectastic init in an empty directory yields a 32-file tree byte-identical to the local-clone install; spectastic validate against a sample spec.html produces correct findings or a clean pass.

Rationale

Unchanged in substance: an outside user with no clone gets the same tree a contributor does, which is the property publishing exists to deliver.

The count moved from 29 because init now installs the three subagent definitions 044 FR-004 requires be synced to .claude/agents/ — an obligation the bundle walk never implemented, so the definitions shipped and were dropped (meta-spec T-026). The consequence was invisible: a missing subagent does not error, so every downstream project ran the propose verb with its adversarial pass silently absent.

The number stays stated rather than derived, deliberately. A test reads it out of this requirement and fails when it disagrees with the scaffold, which is what turned this three-file change into a red test instead of a quiet rot — and these counts drifted three ways before that guard existed.
